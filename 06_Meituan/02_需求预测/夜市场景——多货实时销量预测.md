### 一、项目背景

美团优选经营品类中，生鲜销售比例占48%左右，生鲜商品的特点是货架期短，生鲜商品在排期上架售卖一天，供应链管理复杂度高，容易出现售罄和损耗双高。为避免多送货带来的损耗，商家对生鲜商品的备货不足，在销售晚高峰（17-22点）可能就买不到要用的蔬菜，客户体验不好。因此需在接近T日售卖档期结束之前，尽可能地加快有多货风险的库存的预先出清，考虑到竞对以及传统生鲜零售行业的做法，建议通过夜市清仓、会员方案等多渠道来降低多货，挽回售罄损失，降低损耗挽回商家损失。

1. DD华东现状

   - DD策略思考：观察DD活动策略、商品售价变化、上下架、库存变动趋势，基本排除夜市属于清理多货打法；属于仓域范围内晚高峰的流量提效及用户承接的测试性打法，主要诉求是加强补强生鲜品类在区域的发展；（截止至11月8日，浙江开展3周夜市后仅温州仓坚持在做）
   - DD商品思考：以蔬菜占比43%、水果占比19%、水产占比15%、肉禽占比13%，生鲜占比超过91%；价格策略主要采用直降0.01元，占比接近90%；营促销投入几乎没有
   - DD供应链思考：夜市活动主要采用阶梯预测方法策略，让生鲜的售罄率控制在极低水平，保障夜市活动稳定开展

2. MT华东试点情况

   - 夜市试点仓生鲜在夜间，对生鲜销售有一定拉动作用；其中温州仓销售额+11.1pp、用户数增幅+6.96pp；金华仓负向表现；AB对比（晚18-23点，85%用户投放/15%用户不投放夜市）中温州仓实验组访购率+0.82pp，点击率+1.18pp，由于增量不大，物流整体表现平稳
   - 试点仓生鲜在活动日期间，对生鲜品类渗透率无明显拉动作用。受其他品类的活动影响明显，用户习惯难以在一周内短期见效，需要拉长周期培养心智

### 二、业务目标及方案

#### 2.1 项目整体目标：

- 定性：搭建“夜市”营销阵地和工具，帮助商家倾销多货，降低损耗；

- 定量：

  - **（一期）在平台生鲜 ΔGMV >= 0 的情况下，参加夜市的商家商品的 ΔGMV 提升10%，多货倾销达到30%，用户渗透率提升 1%（暂拍，需与业务确定）；**

  - **（二期）参加夜市的商家商品的 ΔGMV 增长 X，带动平台生鲜 ΔGMV 增长 Y**

    - 商家侧监测指标：参与夜市商家数量，参与夜市商品数量，分层（ΔGMV）查看商家表现；

    - 商家维度分层查看效果

      | ΔGMV   | 商家数量 | 夜市商品数 | 售卖PCS数 | 平均价格 |
      | ------ | -------- | ---------- | --------- | -------- |
      | >=10%  |          |            |           |          |
      | 0~10%  |          |            |           |          |
      | -10%~0 |          |            |           |          |
      | <=-10% |          |            |           |          |

    - 用户侧监控指标：夜市访问用户数，用户访购率，用户退货率；

    - 供应链侧监控指标：多货倾销率，预测准确率；

#### **2.2 约束指标**

- **评估：会不会影响主业务？用户都等夜市购买，导致整体GMV降低？**

  - 通过ABtest，监测平台生鲜 ΔGMV，来判断对主业务的影响，夜市的约束为 “平台生鲜 ΔGMV >= 0” ；

    - 将用户分为实验组（可见夜市）和对照组，流量比例为 X：Y ；
    - 平台生鲜 ΔGMV = 实验组GMV / X - 对照组GMV / Y = （实验组）用户UV * 访购率 *客单价 / X - （对照组）用户UV * 访购率 *客单价 / Y
      - 进一步分析访购率、客单价、 用户ARPU的变化；

  - 监测“用户退款重购”的情况；

    

### 三、夜市选品规则

- 业务选品池建议期望：清仓夜市选品建议，需预测T日截单后有高多货风险的品，重点考虑次日不可售的类目，如蔬菜、水果、肉禽（冷藏）、加工食品（面食）、水产（淡水活鲜、海水活鲜、水产冰鲜）、花卉绿植（花卉）等，具体规则如下：
- 供应链选品规则设计：根据类目潜在多货及售罄风险，综合考虑品/量特性提供选品清单
  - 选品时间：暂定每天每小时进行预测，产出一份潜在多货清单；
  - 商品库存规则（可选）：
    - 【必选】最大售卖量大于销量预测值；
    - 【可选】供应商锁量操作标记；[针对生鲜品锁量较晚的情况，系统支持业务自定义阈值，剔除由于锁量较晚带来的虚高多货]
    - 【可选】单品单仓本小时销售量占比（实际销量/最大售卖量）小于历史3天该品该小时实际销售量平均占比，且幅度小于10%以上（例如今天销售占比30%，历史3天销售占比是50%），属于有多货风险。反之属于没有多货风险，可以剔除；
    - 【可选】商品属性：试跑阶段类目定义为生鲜全部类目；
    - 【可选】夜市商品！= 超级秒杀或万人团；
    - 【必选】商家是否签约夜市合同；[To do：依赖财务团队合同信息标记]
    - 【必选】毛利信息：根据业务规定的毛利规则，选取符合毛利标准的商品；[To do：依赖营销团队提供毛利额计算结果]
  - 仓库定义：支持by仓库维度权限控制和展示；

- 多货透传：需建立透传T日多货情况和预计损耗数等给商家的能力，加深商家侧的感知；

- 数据过滤清洗：该部分销售数据需在其他销量预测或涉及到历史销售数据因子的产品中清洗剔除；

- 清理折扣或建议定价：针对预测的多货库存量，如果需清理完毕的建议折扣力度；
