### 流程说明

```
特征工程 → XGBoost 主模型 → 场景子模型 → 人工修正 → 多维输出
                                              ↓
                        ┌────────────────────────────────────────┐
                        │  TN大盘  │  TN提前  │  T0实时  │  量价  │
                        │ T7/T14  │ T1/T2   │ 30min滚动 │ 价格弹性│
                        └────────────────────────────────────────┘
                               ↓ 应用于
              S&OP目标 → 备货目标 → 预约锁库 → 物流排程 → 直发/拣播
```

- **TN 大盘预测**（T7/T14）：国家/省/仓级，1-MAPE ≥95%，用于 S&OP 资源规划
- **TN 提前预测**（T-1）：SKU+仓维度，1-WMAPE 目标 70%，用于备货和调拨
- **T0 实时预测**：SKU+仓+小时维度，每 30 分钟滚动更新，目标 1am ≥90%、1pm ≥93%
- **量价预测**：给定价格点预测销量，支持促销定价决策

### 注意事项

| 要点 | 详情 |
|---|---|
| **预测精度公式** | `1 - ABS(预测-实际)/实际`；"达标率"= 达标仓占比 |
| **长周期信息缺口** | TN 预测面临营销补贴、SKU 排期、仓网变更等信息缺失 |
| **极端日冲击** | 中秋（9/21）T-1 精度暴跌至 13.48%；A 级大促（3/8）实际销量远低于均值 |
| **温层差异** | 冻品表现最差：27 仓连续 5 天+未达标 |
| **限流干扰** | 疫情期间 ~10% 网格站被限流，限流数据仅从 2021.11.16 开始可追溯 |
| **夜市数据清洗** | 夜市清仓销量必须从其他模型训练数据中剔除 |

### 算法特性

| 算法/模型 | 用途 | 核心特征 |
|---|---|---|
| **XGBoost** | 主模型 | 数百棵决策树集成投票，特征：实时销量、秒杀标记、价格、历史匹配、N日统计量 |
| **概率分布模型** | T0 实时 | 基于实时销售比率+限流触发信息的后处理校正 |
| **节假日模型** | 假日预测 | "剔除历史信息"策略，中秋提升 +6.12pp |
| **场景子模型** | 长尾/新品/季节品/品类/品牌 | 信息迁移+后处理调整层，季节品需人工介入 |
| **NN 模型（预研）** | 未来替代 XGBoost | 尚在实验阶段 |

### 流程说明

```
总部策略 → 战区品类策略 → 周滚动计划 → 资源计划
    ↓              ↓              ↓            ↓
算法预测    战区人工修正    加权融合      物流产能转化
    ↓              ↓              ↓            ↓
    └────── 计划偏差告警推送 ────────── 排程管理 ──→ 供应商预约到货
```

- **烽火台项目**四阶段：总部目标管理 → 战区目标管理 → TN 周排程 → 目标管理复盘
- **计划融合公式**：`加权预测 = 算法预测×w₁ + 战区预测×w₂ + 历史实际×w₃`（权重基于历史精度配置）
- **能力中心**：产能注册 → 查询 → 预占 → 释放，支持长周期 + 短周期管理
- **排程算法**：在满足库存策略（多货/售罄优化）前提下最大化商家送货请求满足率

### 注意事项

| 要点 | 详情 |
|---|---|
| **目标达成率低** | 早期 ~60%；产品化后提升至 79% 仓日达标（85% 阈值） |
| **多数据源冲突** | 总部商分、区域商分、商品侧三套计划口径不一致 |
| **仓容弹性** | T 日可承受计划量的 119% |
| **S1-S9 严重等级** | 基于履约缺货率和售罄 GMV 损失分级 |
| **组织变革冲击** | 从 7 省到 5 战区的重组破坏了原有协调机制 |

### 流程说明

**备货目标生命周期**：

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 售前      │───→│ 售中      │───→│ 售后      │───→│ 反馈闭环  │
│ 算法算量  │    │ 系统锁库  │    │ 多货处置  │    │ 归因分析  │

└──────────┘    └──────────┘    └──────────┘    └──────────┘
```

**双擎备货**（算法 + 人工协同）：
1. **算法引擎**：OR 模型计算最优备货量（多货率 vs 售罄率 trade-off）
2. **人工引擎**：运营在算法上下界内审核/修正
3. **关键发现**：人工有效修正率仅 36.3%，无效修改造成 97.3 万/天成本损失

**备调退全链路文档流**：

```
备货计划单 → 采购补货单 → ASN 单 → 物流单
调拨计划   → 调拨单     → 调拨出库单
退供计划   → 退供/销毁单 → 物流退供出库单
```

**出库优先级**：中心仓 → 协同仓 → 转运 → 商家

### 注意事项

| 要点 | 详情 |
|---|---|
| **算人对比** | 算法多货率 228.82% vs 人工 247.39%；算法售罄率 4.31% vs 人工 16.2% |
| **人为锁库反制** | 20% 销量转移到早间预约时段以规避 12 点锁库控制 |
| **商家满意度** | 4 月 4.02（最低）→ 10 月 4.46（最高） |
| **T1 备货不足** | 占售罄归因的 46% |
| **协同仓周转** | 18 天 → 目标 14 天（渗透率 45%） |
| **PC 加工** | 申请审批率仅 60%；线上预约率仅 10% |

### 算法特性

| 算法 | 用途 | 特点 |
|---|---|---|
| **OR 模型（TN）** | 备货量优化 | 约束：多货率 + 售罄率；按品类+温层+网店+统采维度配置参数 |
| **NewsVendor 模型** | 生鲜单期补货 | 经典报童模型，适配短保质期商品 |
| **Shrunken SAA** | 大规模小样本补货 | 收缩减模拟，解决长尾 SKU 数据稀疏问题 |
| **两阶段 SP** | 协同仓批量调拨 | 随机规划，考虑需求不确定性 |
| **Primal-Dual** | T0 预约制备货 | 在线算法，实时决策 |
