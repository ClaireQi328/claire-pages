---## 优化策略

### 原则
- **不改变采购供应链资料包**
- **合并相似主题的文件夹**
- **保持层级扁平**
- **创建清晰的索引**

### 优化方案

#### 1. 合并操作手册（3 → 1）
**原结构**：
```
操作手册/
商采操作手册/
直采操作手册/
```

**新结构**：
```
操作手册/
├── index.md（总览）
├── 商采/
│   └── 商采.md
├── 直采/
│   └── 直采.md
└── 其他/
```

**优势**：
- 集中管理所有操作手册
- 便于查找和维护
- 减少文件夹数量

#### 2. 合并审计相关（2 → 1）
**原结构**：
```
审计-GR/
审计报告/
```

**新结构**：
```
审计/
├── index.md（总览）
├── GR/
│   └── 相关文档
└── 报告/
    └── 相关文档
```

**优势**：
- 统一审计相关文档
- 便于审计工作查阅
- 结构更清晰

#### 3. 合并合作伙伴管理（3 → 1）
**原结构**：
```
合作伙伴数据分析基础数据/
合作伙伴生命周期-绩效/
合作伙伴风险管理/
```

**新结构**：
```
合作伙伴管理/
├── index.md（总览）
├── 数据分析/
│   └── 基础数据
├── 生命周期/
│   └── 绩效考核
└── 风险管理/
    └── 风险评估
```

**优势**：
- 完整的合作伙伴管理视角
- 便于全生命周期管理
- 减少文件夹数量

#### 4. 保持上会相关（2 个独立）
**原结构**：
```
上会模板/
VP Table/
```

**保持原样**，因为：
- VP Table 是独立的产品项目
- 上会模板是通用模板
- 两者关联度不高

## 实施步骤

### 第一阶段：合并操作手册（30 分钟）

1. **创建新的目录结构**
   ```bash
   mkdir -p "NIO/操作手册/商采"
   mkdir -p "NIO/操作手册/直采"
   ```

2. **移动文件**
   ```bash
# 移动商采操作手册内容
   mv "NIO/商采操作手册/"* "NIO/操作手册/商采/"
   
# 移动直采操作手册内容
   mv "NIO/直采操作手册/"* "NIO/操作手册/直采/"
   
# 删除空文件夹
   rmdir "NIO/商采操作手册" "NIO/直采操作手册"
   ```

3. **创建综合索引**
   - 更新 NIO/操作手册/index.md
   - 添加商采和直采的链接

### 第二阶段：合并审计相关（20 分钟）

3. **创建综合索引**
   - 创建 NIO/审计/index.md

### 第三阶段：合并合作伙伴管理（30 分钟）

1. **创建新的目录结构**
   ```bash
   mkdir -p "NIO/合作伙伴管理/数据分析"
   mkdir -p "NIO/合作伙伴管理/生命周期"
   mkdir -p "NIO/合作伙伴管理/风险管理"
   ```

   ```bash

# 移动合作伙伴生命周期-绩效
   mv "NIO/合作伙伴生命周期-绩效/"* "NIO/合作伙伴管理/生命周期/"
   
# 移动合作伙伴风险管理
   mv "NIO/合作伙伴风险管理/"* "NIO/合作伙伴管理/风险管理/"
   
# 删除空文件夹
   rmdir "NIO/合作伙伴数据分析基础数据" "NIO/合作伙伴生命周期-绩效" "NIO/合作伙伴风险管理"
   ```

3. **创建综合索引**
   - 创建 NIO/合作伙伴管理/index.md
   - 添加各子模块的链接

### 第四阶段：更新导航（15 分钟）

1. **更新 NIO.md**
   - 调整操作手册链接
   - 添加审计链接

   - 确保所有链接有效

2. **验证链接**
   - 检查所有 wiki 链接
   - 确保 Obsidian 能正确解析
