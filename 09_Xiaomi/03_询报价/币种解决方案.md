# 币种解决方案

企业ERP系统多币种与汇率完整设计方案

一、核心数据模型设计

1.1 币种主数据（Currency Master）

多币种体系的基础是三层币种架构，这也是SAP的底层设计逻辑：

┌─────────────────────────────────────────────────────────┐│                    币种三层架构                           │├──────────────────┬──────────────────┬───────────────────┤│  交易币种         │  公司代码币种      │  集团/硬通货币种   ││ Transaction       │  Local Currency   │  Group Currency   ││ Currency (TC)     │  (LC / 本位币)    │  (GC / 硬通货)    ││                   │                  │                   ││ 业务发生时的实际   │ 法人实体的报告    │ 集团合并报告用    ││ 结算货币          │ 货币，法律要求    │ 通常为USD/EUR     │└──────────────────┴──────────────────┴───────────────────┘

每笔业务凭证同时记录三套金额，这是"平行货币"（Parallel Currency）的核心思想。

1.2 汇率主数据

二、定价币种 ≠ 结算币种的处理方案

2.1 场景描述

典型场景：  采购合同用 USD 报价  →  实际用 CNY 结算  销售订单用 EUR 定价  →  客户用 GBP 付款  跨境电商 USD 标价    →  多币种收单

2.2 文档级双币种设计

每张业务单据（PO/SO/Invoice）需要承载双币种字段：

2.3 差额的会计处理：汇兑损益

当结算汇率与入账汇率不同时，差额必须作为汇兑损益单独核算：

例：  采购入库时（4月1日）：USD 10,000，汇率 7.18 → CNY 71,800 入库存  付款时（4月30日）：    USD 10,000，汇率 7.25 → CNY 72,500 实付  差额 CNY 700 → 计入「汇兑损失」科目（财务费用）

会计分录设计：

【采购入库时】  Dr. 库存商品        71,800 CNY（本位币）      Cr. 应付账款/USD  10,000 USD（=71,800 CNY @ 7.18）【付款时】  Dr. 应付账款/USD    10,000 USD（=71,800 CNY @ 7.18）  ← 原汇率冲销      汇兑损失            700 CNY                       ← 差额      Cr. 银行/CNY       72,500 CNY

三、同币种、不同汇率时的平衡方案

3.1 场景：同是 USD，但汇率不同

典型场景：  - SRM系统合同汇率 vs ERP系统当日汇率不一致  - 月初预算汇率 vs 月末实际结算汇率  - 集团内部结算汇率 vs 市场汇率

3.2 分层汇率优先级设计

建立明确的汇率取值优先级规则（类似SAP定价条件的Condition Technique思路）：

汇率取值优先级（从高到低）：1. 合同/订单手工锁定汇率           ← 最高优先级2. 套保合约关联汇率3. 客户/供应商主数据约定汇率4. 公司代码级配置汇率5. 系统汇率表（按rate_type + 日期）  ← 兜底

-- 汇率解析函数伪代码FUNCTION resolve_exchange_rate(    doc_type, vendor_id, company_code,    from_currency, to_currency, rate_date) RETURNS rate_record  -- Step 1: 检查单据头手工覆盖  IF doc.manual_rate IS NOT NULL THEN RETURN doc.manual_rate  -- Step 2: 检查套保合约  hedge := find_hedge_contract(vendor_id, from_currency, to_currency, rate_date)  IF hedge FOUND THEN RETURN hedge.rate  -- Step 3: 供应商主数据约定  vendor_rate := vendor_master.preferred_rate_type  IF vendor_rate FOUND THEN RETURN lookup_rate(vendor_rate, ...)  -- Step 4: 公司代码默认汇率类型  RETURN lookup_rate(company_code.default_rate_type, ...)END

3.3 汇率差异的暂存与消化

当两个系统汇率不一致时，引入汇率差异暂存科目：

SRM合同价：USD 100 @ 7.10 = CNY 710  （合同时锁定）ERP入库时：USD 100 @ 7.18 = CNY 718  （当日汇率）差额 CNY 8 → 进入「采购价格差异」或「汇率暂估差异」科目月结时统一结转至汇兑损益

四、内部记账的平衡设计

4.1 集团内部交易（Intercompany）双向平衡

场景：中国子公司（CNY）向美国子公司（USD）销售商品┌─────────────────────┐      内部对冲        ┌─────────────────────┐│   CN-Company (CNY)  │ ─────────────────── │   US-Company (USD)  ││                     │  内部发票: USD 1000  │                     ││ 内部应收: USD 1000  │  @7.18 = CNY 7180   │ 内部应付: USD 1000  ││ 本位币:   CNY 7180  │                     │ 本位币:   USD 1000  │└─────────────────────┘                     └─────────────────────┘集团合并时：内部应收/应付必须对消问题：CN侧本位币CNY，US侧本位币USD，折算集团货币(GC)时汇率不同？

解决方案：统一以集团货币（GC）作为内部交易计价基准

内部交易规则：1. 内部单据必须同时记录 TC（交易币种）+ LC（各自本位币）+ GC（集团货币）2. 内部对冲以 GC 金额为准，LC差额各自在本公司计汇兑损益3. 集团汇率（GC Rate）每月月初由集团财务统一发布，不允许各子公司自定义

4.3 月结汇兑损益重估（Revaluation）

这是平衡内部记账的关键月末操作：

月末重估流程：1. 识别所有外币余额科目（应收、应付、银行、内部往来）2. 用月末收盘汇率重新折算余额3. 差额计入「未实现汇兑损益」（Unrealized FX Gain/Loss）4. 对冲科目：外币折算调整科目（OCI or P&L，取决于会计准则）┌──────────────────────────────────────────────────────────┐│  重估示例：                                              ││  应付USD账户余额：USD 100,000                            ││  账面本位币：CNY 710,000（@ 7.10，月初汇率）            ││  月末汇率：7.25                                         ││  重估后本位币：CNY 725,000                              ││                                                         ││  Dr. 汇兑损失（财务费用）  15,000 CNY                  ││      Cr. 应付账款/外币调整 15,000 CNY                  ││                                                         ││  下月初反向冲回（可选，取决于准则）                      │└──────────────────────────────────────────────────────────┘

五、SRM采购场景专项设计

5.1 合同-订单-发票三级汇率继承

SRM合同（Contract）  └── 锁定汇率: USD/CNY = 7.10，有效期 2026-01-01 ~ 2026-06-30       │       ├── 采购订单（PO）继承合同汇率 7.10       │    └── 收货（GR）按PO汇率 7.10 记库存       │         └── 供应商发票（IR）↗       │       └── 发票差异处理：            - 数量差异 → 补/退货            - 价格差异 → 价差科目            - 汇率差异 → 汇兑损益科目（不冲库存！）

关键原则：汇率差异不回溯影响库存价值，只影响财务损益。

5.2 SRM与ERP的汇率同步机制

┌─────────────────┐   汇率同步接口    ┌─────────────────┐│   SRM系统       │ ◄──────────────► │   ERP/SAP       ││                 │  每日T+1 00:00   │                 ││ 合同管理        │  推送全量汇率表   │ FI汇率主数据    ││ 询报价          │                  │ (OB08)          ││ 采购申请        │  合同创建时快照   │                 │└─────────────────┘  锁定当时汇率    └─────────────────┘同步规则：- ERP为汇率主系统（Master），SRM为从系统（Slave）- SRM合同汇率一经锁定，不随ERP汇率更新而变化- 若合同续签/修订，才重新取最新汇率

七、设计要点与最佳实践

① 永远不要只记一套币种金额 凭证至少记录 TC + LC，跨国集团必须加 GC，这是一切对账的基础。

② 汇率差异必须有归宿，不能让它"消失" 所有因汇率产生的差额，必须明确归属到对应科目（汇兑损益/价差/OCI），绝不允许用四舍五入或强制平账掩盖。

③ 汇率变动不回溯影响库存/成本 已确认入库的库存价值以入库时汇率为准，后续汇率变动只影响财务损益，不重算库存。（这是SAP标准也是会计准则要求）

④ 合同汇率与系统汇率要物理隔离 SRM合同锁定的汇率要作为单据属性存储，与每日更新的系统汇率表分开，防止汇率更新导致历史合同数据变化。

⑤ 汇兑损益要区分已实现与未实现

已实现（Realized）：交易完成后的实际差额，计入当期损益未实现（Unrealized）：月末持仓重估差，需关注是否走OCI（其他综合收益）

⑥ 高通胀国家需要第四套货币 针对土耳其、阿根廷等高通胀经济体，SAP额外支持"硬通货"（Hard Currency，通常为USD）作为第四套平行记账货币，防止本位币贬值导致财务数据失真。
