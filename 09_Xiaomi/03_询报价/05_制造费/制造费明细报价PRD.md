## **2 需求背景与目标**

  

### **2.1 背景**

  

制造费用需要包含半成品，原自制件维度无法完整计算制造费。一期版本中采购员在EP端手动维护制造费的方式已无法满足精度要求，需要基于BOM结构和VSM工艺工序进行明细报价。

  

### **2.2 变更点**

  

- 制造费报价场景限定为：BOM结构OK **且** VSM OK时，进行明细报价

- 关闭EP端手动维护制造费入口，采购端不再手动维护
    

  

### **2.3 目标**

  

- 实现基于工艺工序视角的制造费用明细报价
    
- 通过BOM+VSM双维度校验确保报价数据准确性
    

  

  

## **3 功能概述**

  

### **3.1 核心决策流程**

  

```Plain
flowchart TD
    A[RFQ零件报价] --> B{是否打开制造成本？}
    B -- 否 --> C[场景一：中粗项手动报价]
    B -- 是 --> D{BOM+VSM是否审批OK？}
    D -- 否 --> C[场景一：中粗项手动报价]
    D -- 是 --> F[场景三：明细报价 - SVC数据自动带出
    F --> G[制造费总价汇总]
```

  

### **3.2 三种报价场景速览**

  

|   |   |   |   |
|---|---|---|---|
|场景|前提条件|报价模式|输入方式|
|场景一|关闭制造成本|中粗项手动填写|供应商手动输入中粗项|
|场景二|打开制造成本 + BOM/VSM非全部OK|中粗项手动填写|供应商手动输入中粗项|
|场景三|打开制造成本 + BOM+VSM均OK|明细项 + 中粗项自动汇总|SVC自动带出，用户填写/确认|

  

  

## **4 详细功能需求**

  

### **4.1 内网 - 报价列表增加「打开制造成本」字段**

  

**用户故事：** 作为采购员，我希望在报价列表中能看到每个零件是否打开了制造成本，以便了解该零件的报价模式。

  

**功能说明：**

  

- 报价列表新增列：`是否打开制造``费``成本`
    
- 可见阶段：RFQ草稿 / 报价中 / 轮次结束 / 报价结束（全生命周期可见）
    
- 默认值：**打开**
    
- 变化：供应商可在报价过程中打开/关闭开关，采购员端查看报价时可见开关状态
    

**验收标准：**

1. [ ] 列表页展示「是否打开制造成本」列
    
2. [ ] 默认状态为"打开"
    
3. [ ] 四个阶段（草稿/报价中(发出状态)/轮次结束(供应商更新状态)/报价结束）均可查看

**用户故事：** 作为供应商，我希望能控制是否打开制造成本，以便选择适合的报价方式。

  

**功能说明：**

- **可编辑时机：** 供应商在轮次中可随时编辑

- 控制范围：报价详情中制造费模块的展示方式
    

**状态切换规则：**

  

|   |   |
|---|---|
|切换方向|操作后果|
|不打开 → 打开|已报价中粗项**清空**，按制造明细重新计算|

**验收标准：**

1. [ ] 外网报价弹框页展示「是否打开制造费成本」按钮

#### **4.4.1 模块一：中粗项汇总（"自动计算 + 手动覆盖"）**

  

中粗项**自动计算 + 手动覆盖**

  

|   |   |   |   |
|---|---|---|---|
|费用项|状态|计算公式|是否必填|
|是否打开制造费成本|手动选择||是|
|设备费用|自动计算，但支持手动更新|= sum（所有行的设备费）|是|
|能耗费用|自动计算，但支持手动更新|= sum（所有行的能耗费）|是|
|报废费用|自动计算，但支持手动更新|= sum（所有行的报废费）|是|
|耗材费用|自动计算，但支持手动更新|= sum（所有行的耗材费）|是|
|人员费用|自动计算，但支持手动更新|= sum（所有行的人员费）|是|
|**制造费总价**|自动计算，但支持手动更新|= 设备费用 + 能耗费用 + 报废费用 + 耗材费用 + 人员费用|是|

  

**中粗项汇总规则：**

  

```Plain
设备费用合计 = 零件1设备费(设备1+设备2+...+设备n) + 零件2设备费(...) + ...
能耗费用合计 = 零件1能耗费(能耗1+能耗2+...+能耗n) + 零件2能耗费(...) + ...
报废费用合计 = 零件1报废费 
耗材费用合计 = 零件1耗材费(耗材1+耗材2+...+耗材n) + 零件2耗材费(...) + ...
人员费用合计 = 零件1直接人工+零件1间接人工
```

  

> 注：一个零件可能有多条产线，同一费用项需先按产线求和，再按零件求和。

  

**新增的"自动计算 + 手动覆盖"机制**

**两种字段状态：**

|   |   |   |
|---|---|---|
|状态|行为|视觉样式|
|auto|跟随明细行自动联动|浅绿背景|
|overridden|手动输入值，与明细行解耦|浅橙背景|

**关键交互流程：**

1. 初始加载 → 所有中粗项为 `auto`，值 = SUM(明细行)
    
2. 用户编辑某个费用项 → 该字段变为 `overridden`，不再跟随明细联动
    
3. 提交报价时 → 统一以 `displayValue` 提交，不区分来源

### **4.6 可视化****VSM**

  

**用户故事：** 作为供应商，我希望看到VSM工艺流程图，以便直观了解制造工艺结构。

  

**功能说明：**

  

- 根据零件号+供应商从SVC获取可视化VSM结构
    
- VSM结构状态OK：显示VSM图
    
- VSM结构状态NOK：不显示（空白）
    
- 多个VSM存储在多个JSON中，渲染为多个效果图
    

**验收标准：**

1. [ ] VSM状态OK时正确渲染流程图
    
2. [ ] VSM状态NOK时显示空白区域
    
3. [ ] 多VSM场景下分别渲染

### **4.7** **VSM****版本校验**

  

**触发时机：** 以下三个操作均触发BOM版本校验：

  

1. 点击报价
    
2. 手动获取最新VSM
    
3. 提交报价
    

**校验逻辑与弹窗提示：**

  

|   |   |   |
|---|---|---|
|**校验结果**|**弹窗内容**|**后续操作**|
|SVC不存在审批通过的VSM|"无已审批通过的VSM，请手动维护制造费"|阻断操作|
|EP SVC VSM版本 = SVC最新版本|"当前VSM无更新，请在当前版本上进行更新"|放行操作|
|存在更高版本|"无已审批通过的VSM，请手动维护制造费"|**覆盖前强提示**，确认后覆盖，不支持回退|

  

**验收标准：**

1. [ ] 三个触发时机均执行版本校验
    
2. [ ] 三种校验结果分别展示对应弹窗
    
3. [ ] 高版本覆盖前有强提示，确认后覆盖
    
4. [ ] 覆盖操作不支持回退
    

  

  

## **5 校验规则汇总**

  

### **5.1 制造费维护完成校验**

  

- 每行最后的价格数据：**可以为0，不能为空**

- 任意一行存在空值 → 无法计算 → 「制造费维护完成」按钮**无法点亮**

  

### **5.2 提交完整性校验**

  

**校验规则：** 必填字段非空，为空值则提交报价时报错。

  

**错误提示格式：** `零件X-工厂1制造费未填写完整，xx,xx,xx`（定位到字段名即可，无需提醒到具体零件-工厂行）

  

**完整性校验字段清单：**

  

|   |   |
|---|---|
|类别|校验字段|

## **6 异常场景与处理**

  

### **6.1** **BOM****变更对制造费的影响**

  

**大原则：** SVC零件来源为材料费的BOM零件，BOM端变化会影响SVC。

  

|   |   |   |
|---|---|---|
|BOM状态|制造费要求|行项目规则|
|BOM NOK|仅要求RFQ零件|子件+自制件用户自由编辑，不强制要求下级零件|
|BOM OK|要求RFQ零件 + 下级自制件|材料工艺中下级零件属性为自制件的默认带出，可删除，不做要求|

  

### **6.2 一个零件多产线场景**

  

- 可能出现一个自制件对应多条产线
    
- 报价过程中不区分供应商工厂
    
- 不同工厂但产线名称相同时，EP端不做区分
    

### **6.3** **SVC****工序NOK时的用户自主维护**

  

- 支持用户从自制件工艺工序视角自主添加工段/线体及其关键要素信息
    
- 支持用户手动添加和删除行项目
    
- 每个线体有对应的产能、设备、人工、报废、能耗、耗材关键要素
