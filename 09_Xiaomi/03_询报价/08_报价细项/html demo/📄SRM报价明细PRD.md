## 2. 背景与目标

### 2.1 背景
在SRM（供应商关系管理）系统中，采购方需要对供应商提供的报价进行系统化管理。报价明细涉及多项费用拆解（材料费、制造费、模具费等），需要标准化的数据结构和清晰的审批流程，以支持成本分析和供应商比价决策。

### 2.2 目标
- 建立标准化的报价明细结构，支持多维度费用拆解
- 提供清晰的报价录入、审核、对比流程
- 支持历史报价查询和成本趋势分析
- 提升采购方与供应商之间的协作效率

### 2.3 目标用户

| 角色 | 说明 |
|------|------|
| 供应商 | 录入和提交报价明细 |
| 采购员 | 发起询价、审核报价、进行比价 |
| 采购主管 | 审批报价、确定最终定价 |
| 成本分析师 | 分析报价数据、生成成本报告 |

## 3. 费用项定义

### 3.1 费用结构总览

```
报价总价 = 材料费 + 制造费 + 模具费 + 开发费 + 管理费 + 样件费
```

### 3.2 各费用项说明

#### 3.2.1 材料费用（Material Cost）

| 字段 | 说明 |
|------|------|
| 定义 | 直接用于产品生产的原材料和辅料成本 |
| 计算方式 | 单价 × 用量 × (1 + 损耗率) |
| 必填字段 | 材料名称、规格型号、材质、单位、单价、用量、损耗率、材料产地 |

**字段明细：**

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| material_name | String | 是 | 材料名称 |
| spec_model | String | 是 | 规格型号 |
| material_type | String | 是 | 材质/牌号 |
| unit | String | 是 | 计量单位 |
| unit_price | Decimal | 是 | 单价（元） |
| usage_qty | Decimal | 是 | 用量 |
| loss_rate | Decimal | 否 | 损耗率（%），默认0 |
| origin | String | 否 | 材料产地/供应商 |
| material_cost | Decimal | 系统计算 | 小计 = 单价 × 用量 × (1 + 损耗率) |

#### 3.2.2 制造费用（Manufacturing Cost）

| 字段 | 说明 |
|------|------|
| 定义 | 产品加工制造过程中产生的各项费用 |
| 计算方式 | 按工序拆分，各工序（设备费 + 人工费 + 能源费 + 其他）汇总 |
| 必填字段 | 工序名称、设备折旧、人工工时、人工单价、能耗 |

**字段明细：**

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| process_name | String | 是 | 工序名称 |
| process_order | Integer | 是 | 工序顺序 |
| equipment_cost | Decimal | 是 | 设备折旧费（元） |
| labor_hours | Decimal | 是 | 人工工时（小时） |
| labor_price | Decimal | 是 | 人工单价（元/小时） |
| energy_cost | Decimal | 否 | 能源费（元） |
| other_cost | Decimal | 否 | 其他制造费用（元） |
| process_total | Decimal | 系统计算 | 工序小计 |
| defect_rate | Decimal | 否 | 不良率（%） |
| mfg_cost | Decimal | 系统计算 | 制造费总计 = 各工序小计 × (1 + 不良率) |

#### 3.2.3 模具费用（Mold Cost）

| 字段 | 说明 |
|------|------|
| 定义 | 产品生产所需模具的开发、制造和维护费用 |
| 计算方式 | 模具总价可按产量分摊，或一次性计入 |
| 必填字段 | 模具名称、模具类型、数量、单价、分摊方式 |

**字段明细：**

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| mold_name | String | 是 | 模具名称 |
| mold_type | Enum | 是 | 模具类型（注塑模/冲压模/压铸模/锻造模/其他） |
| cavity_count | Integer | 否 | 型腔数量 |
| quantity | Integer | 是 | 模具数量 |
| unit_price | Decimal | 是 | 单套模具价格（元） |
| mold_life | Integer | 否 | 模具寿命（万次） |
| amort_method | Enum | 是 | 分摊方式（一次性计入/按产量分摊/按金额分摊） |
| amort_qty | Integer | 条件 | 分摊产量（当分摊方式为按产量分摊时必填） |
| mold_total | Decimal | 系统计算 | 模具费总计 |
| per_unit_amort | Decimal | 系统计算 | 单件分摊模具费 |

#### 3.2.4 开发费用（Development Cost）

| 字段 | 说明 |
|------|------|
| 定义 | 产品设计、工艺开发、试验验证等前期开发投入 |
| 计算方式 | 各开发项费用汇总，可分摊至单件 |
| 必填字段 | 开发项目名称、费用类型、金额 |

**字段明细：**

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| dev_item | String | 是 | 开发项目名称 |
| dev_type | Enum | 是 | 费用类型（产品设计/工艺开发/检测试验/认证费用/其他） |
| amount | Decimal | 是 | 金额（元） |
| amort_method | Enum | 否 | 分摊方式（一次性计入/按产量分摊） |
| amort_qty | Integer | 条件 | 分摊产量 |
| dev_total | Decimal | 系统计算 | 开发费总计 |
| per_unit_amort | Decimal | 系统计算 | 单件分摊开发费 |

#### 3.2.5 管理费用（Management Cost）

| 字段 | 说明 |
|------|------|
| 定义 | 供应商为完成交易所产生的管理运营间接费用 |
| 计算方式 | 按照报价基数的一定比例计算 |
| 必填字段 | 费用项目、费率 |

**字段明细：**

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| mgmt_item | String | 是 | 费用项目（如：管理费、财务费、包装运输费） |
| rate_base | Enum | 是 | 计算基数（材料费/制造费/报价基数合计） |
| rate | Decimal | 是 | 费率（%） |
| amount | Decimal | 系统计算 | 金额 = 基数 × 费率 |
| remark | String | 否 | 备注说明 |

**常见管理费子项：**

| 子项 | 说明 | 建议费率范围 |
|------|------|-------------|
| 管理费 | 供应商运营管理分摊 | 3%~8% |
| 财务费 | 资金占用、账期成本 | 1%~3% |
| 包装费 | 产品包装材料及工费 | 按实际计算 |
| 运输费 | 从供应商到指定地点的物流费用 | 按实际计算 |
| 利润 | 供应商合理利润 | 5%~15% |
| 税金 | 增值税等税费 | 按法定税率 |

#### 3.2.6 样件费用（Sample Cost）

| 字段 | 说明 |
|------|------|
| 定义 | 开发阶段和量产前提供的样品/样件费用 |
| 计算方式 | 按样件数量和单价计算 |
| 必填字段 | 样件类型、数量、单价 |

**字段明细：**

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| sample_type | Enum | 是 | 样件类型（功能样件/外观样件/工装样件/OTS样件/PPAP样件） |
| phase | Enum | 否 | 开发阶段（AP1~AP5） |
| quantity | Integer | 是 | 数量 |
| unit_price | Decimal | 是 | 单价（元/件） |
| delivery_date | Date | 否 | 要求交付日期 |
| sample_total | Decimal | 系统计算 | 样件费总计 |
| is_free | Boolean | 否 | 是否免费提供（默认否） |

## 5. 状态机定义

### 5.1 询价单（RFQ）状态机

| 状态 | 说明 | 可触发动作 |
|------|------|-----------|
| 草稿 | 采购员新建询价单，尚未发布 | 编辑、删除、发布 |
| 已发布 | 询价单已发送给供应商，等待报价 | 查看、关闭 |
| 报价中 | 已有≥1家供应商提交报价，但未达到截止条件 | 查看、催报、关闭 |
| 已完成 | 满足截止条件（截止时间到 或 ≥3家报价），进入比价阶段 | 查看、导出、定价 |
| 已关闭 | 手动关闭或项目取消，不再接受报价 | 查看（只读） |

#### RFQ状态流转图

```
草稿 ──发布──→ 已发布 ──有供应商报价──→ 报价中 ──截止条件满足──→ 已完成
  │                │                      │                        │
  │ 删除          │ 关闭                 │ 关闭                   │ 定价
  ▼                ▼                      ▼                        ▼
 (删除)         已关闭                已关闭                    已冻结
```

#### RFQ状态流转规则

| 编号 | 当前状态 | 触发条件 | 目标状态 | 操作人 |
|------|---------|---------|---------|-------|
| RF-S01 | 草稿 | 点击「发布」 | 已发布 | 采购员 |
| RF-S02 | 草稿 | 点击「删除」 | 已删除 | 采购员 |
| RF-S03 | 已发布 | 第1家供应商提交报价 | 报价中 | 系统自动 |
| RF-S04 | 已发布 | 手动关闭 | 已关闭 | 采购员 |
| RF-S05 | 报价中 | 报价截止时间到达 **或** 报价供应商数≥3 | 已完成 | 系统自动 |
| RF-S06 | 报价中 | 手动关闭 | 已关闭 | 采购员/主管 |
| RF-S07 | 已完成 | 定价确认（选定中标供应商） | 已冻结 | 采购主管 |
| RF-S08 | 已关闭 | 无（终态） | — | — |
| RF-S09 | 已冻结 | 无（终态） | — | — |

> **截止条件说明：** 满足以下任一条件，RFQ从「报价中」自动流转到「已完成」：
> 1. 报价截止时间到达（由采购员设定）；
> 2. 已收到≥3家供应商的有效报价（BR-002）。

### 5.2 报价单（Quotation）状态机

| 状态 | 说明 | 可触发动作 |
|------|------|-----------|
| 草稿 | 供应商已创建报价单但未提交 | 编辑、删除、提交 |
| 待审核 | 供应商已提交，等待采购员初审 | 查看、初审、驳回 |
| 审核中 | 采购员已通过初审，进入主管/经理/总监审批 | 查看、审批、驳回 |
| 已批准 | 审批通过，报价生效 | 查看、冻结 |
| 已驳回 | 审批未通过，需供应商修改重提 | 查看、修改重提 |
| 已过期 | 超过报价有效期，自动失效 | 查看（只读） |
| 已冻结 | 定价后锁定，不可修改 | 查看（只读） |

                    ▼                                                  │
               ┌─────────┐    提交     ┌─────────┐   初审通过    ┌─────────┐

               └────┬────┘           └────┬────┘              └────┬────┘
                    │ 删除                 │ 驳回                    │

                                    └────┬────┘
                                         │ 修改重提

                                    ┌────▼────┐    提交     ┌─────────┐
                                    │  草稿    │──────────→│  待审核  │

               ┌─────────┐    审批通过   ┌─────────┐   定价确认   ┌─────────┐

#### 报价单状态流转规则

| 编号 | 当前状态 | 触发条件 | 目标状态 | 操作人 |
|------|---------|---------|---------|-------|
| QT-S01 | 草稿 | 点击「提交报价」 | 待审核 | 供应商 |
| QT-S02 | 草稿 | 点击「删除」 | 已删除 | 供应商 |
| QT-S03 | 待审核 | 采购员初审通过 | 审核中 | 采购员 |
| QT-S04 | 待审核 | 采购员点击「驳回」（需填写驳回原因） | 已驳回 | 采购员 |
| QT-S05 | 审核中 | 审批人点击「批准」 | 已批准 | 采购主管/经理/总监 |
| QT-S06 | 审核中 | 审批人点击「驳回」（需填写驳回原因） | 已驳回 | 采购主管/经理/总监 |
| QT-S07 | 已驳回 | 供应商修改后点击「重新提交」 | 草稿→待审核 | 供应商 |
| QT-S08 | 已批准 | RFQ定价确认（选定中标供应商） | 已冻结 | 系统自动 |
| QT-S09 | 已批准 | 报价有效期到期（超过validity_days） | 已过期 | 系统自动 |
| QT-S10 | 已过期 | 无（终态） | — | — |
| QT-S11 | 已冻结 | 无（终态） | — | — |

> **驳回后重提规则：**
> - 供应商只能在「已驳回」状态下修改报价并重新提交；
> - 重新提交后，报价单回到「待审核」状态，重新走审批流程；
> - 每次重提，版本号（version）+1；
> - 已驳回的报价仍保留在系统中，支持历史追溯。

### 5.3 两套状态机联动关系

| 事件 | RFQ状态变化 | 报价单状态变化 | 说明 |
|------|-----------|-------------|------|
| 供应商提交报价 | 已发布→报价中（若首次） | 草稿→待审核 | RFQ自动感知报价状态 |
| 报价被驳回后重提 | — | 已驳回→草稿→待审核 | RFQ状态不变 |
| RFQ截止条件满足 | 报价中→已完成 | 各报价单维持当前状态 | 截止后新报价不可提交 |
| RFQ手动关闭 | 当前→已关闭 | 所有「草稿」报价单自动关闭 | 未提交的报价不再可编辑 |
| RFQ定价确认 | 已完成→已冻结 | 中标报价→已冻结；其他已批准→已过期 | 系统自动处理 |

#### 6.1.2 采购端

## 7. 业务规则

### 7.1 报价规则

| 编号 | 规则 | 说明 |
|------|------|------|
| BR-001 | 报价有效期 | 默认90天，最少30天，最多365天 |
| BR-002 | 最少供应商数 | 每次询价至少3家供应商参与报价，否则RFQ不可进入「已完成」状态 |
| BR-003 | 报价修改 | 草稿状态可自由修改；已驳回可修改重提；其他状态不可修改 |
| BR-004 | 并行报价 | 同一询价单下多个供应商报价互不可见 |
| BR-005 | 汇率转换 | 非人民币报价需按指定汇率转换为人民币进行对比 |

### 7.2 费用计算规则

| 编号 | 规则 | 说明 |
|------|------|------|
| BR-006 | 材料费 | = Σ(单价 × 用量 × (1 + 损耗率)) |
| BR-007 | 制造费 | = Σ(各工序费用) × (1 + 不良率) |
| BR-008 | 模具费分摊 | 一次性计入：直接加总价；按产量分摊：总价 / 分摊产量 |
| BR-009 | 管理费基数 | 可选材料费或（材料费+制造费）作为计算基数 |
| BR-010 | 报价总价 | = 材料费 + 制造费 + 模具费 + 开发费 + 管理费 + 样件费 |
| BR-011 | 单件价格 | = 报价总价 / 批量数量（考虑模具/开发分摊后） |

### 7.3 审批规则

| 编号 | 规则 | 说明 |
|------|------|------|
| BR-012 | 审批权限 | 总价≤50万：采购主管审批；50万~200万：采购经理审批；>200万：总监审批 |
| BR-013 | 自动审批 | 非首次合作且价格低于历史均价5%以内，可自动审批（跳过人工审批节点） |
| BR-014 | 审批时效 | 审批节点48小时内未处理自动催办，72小时升级至上一级审批人 |

### 7.4 报价截止规则

| 编号 | 规则 | 说明 |
|------|------|------|
| BR-015 | 截止条件 | 满足以下任一条件，RFQ自动流转到「已完成」：(1) 报价截止时间到达；(2) 已收到≥3家有效报价 |
| BR-016 | 截止后限制 | RFQ进入「已完成」后，未提交的报价单不可再提交 |
| BR-017 | 关闭联动 | RFQ关闭时，所有处于「草稿」状态的报价单自动关闭，供应商不可再编辑 |

### 7.5 过期规则

| 编号 | 规则 | 说明 |
|------|------|------|
| BR-018 | 自动过期 | 报价单处于「已批准」状态超过validity_days，系统自动将其置为「已过期」 |
| BR-019 | 过期通知 | 报价到期前7天向供应商和采购员发送提醒通知 |
| BR-020 | 过期后操作 | 已过期的报价单不可修改、不可重提，如需报价需新建报价单 |

## 9. 非功能需求

### 9.1 性能要求

| 指标 | 要求 |
|------|------|
| 页面加载 | 报价录入页面加载时间 ≤ 2秒 |
| 费用计算 | 费用自动计算响应时间 ≤ 500ms |
| 比价查询 | 10家供应商比价查询响应 ≤ 3秒 |
| 并发支持 | 支持500用户同时在线操作 |

### 9.2 安全要求

- 报价数据按供应商隔离，供应商之间报价互不可见
- 敏感价格数据传输加密（HTTPS）
- 操作日志完整记录，支持审计追溯
- 报价单修改需留有完整版本记录

### 9.3 兼容性要求

- 支持Chrome、Edge、Firefox最新两个主要版本
- 支持PC端和移动端（响应式布局）
- 支持Excel模板导入导出
