## 2. 背景与目标

### 2.1 背景
在SRM系统的定点流程中，采购员发起RFQ询报价后，需要CE（Cost Engineer）人员对供应商报价进行成本核价分析，确认各费用项（材料费、制造费、管理费等）的合理性，为最终定价提供成本依据。当前EP系统中缺少标准化的CE核价流程，核价过程依赖线下沟通，效率低且缺乏可追溯性。

### 2.2 目标
- 在RFQ询报价管理下新增「成本管理」模块，实现CE核价任务的标准化管理
- CE核价任务与RFQ 1:1绑定，支持多轮次零件更新时自动触发核价
- 支持CE核价数据的录入、导入导出、审批和历史追溯
- 通过飞书通知和待办任务提升协作效率

### 2.3 角色定义

| 角色 | 说明 | 来源 |
|------|------|------|
| CE（Cost Engineer） | 负责成本核价分析的财务人员 | EP系统角色【Finance】 |
| 采购员 | 发起RFQ、查看核价结果 | EP系统角色【采购】 |
| 管理员 | 全量数据查看、转派操作 | EP系统角色【管理员】 |

> **注意：** EP系统中存在三个财务相关角色，本次使用 **Finance** 角色（对应业务的CE角色），而非Finance BP角色。

| 场景 | 规则 |

## 5. 核价任务管理

### 5.1 核价任务生成规则

| 规则 | 说明 |
|------|------|
| 生成时机 | RFQ发布**第一轮**后，根据定点RFQ 1:1生成CE核价任务 |
| 绑定关系 | RFQ : CE核价任务 = 1:1（核价任务本身无轮次概念） |
| 轮次更新 | RFQ发布新轮次时，零件信息同步更新到核价任务，不生成新任务 |
| 生成范围 | 仅针对**定点类型**的RFQ |

### 5.2 核价任务编号规则

```
编码格式：CE-YYYYMMDD-XXX
示例：CE-20260303-001
说明：CE-日期8位码(年+月+日)-当日三位顺序号
```

| 序号 | 系统 | 按零件号个数顺序排列 |

| RFQ编号 | 同RFQ | |
| RFQ名称 | 同RFQ | |
| 是否多项目 | 同RFQ | |
| 采购项目编码 | 同RFQ | |
| 关联单号 | 同RFQ | 关联SOR号码 |
| 核价状态 | 系统计算 | 见状态机定义 |
| 小米工厂 | 同RFQ | |
| 是否多工厂 | 同RFQ | |
| 采购工程师 | 同RFQ | |
| 零部件号 | 同RFQ | |
| 零部件名称 | 同RFQ | |

### 5.4 列表操作

| 操作 | 条件 | 说明 |

## 6. 状态机定义

### 6.1 核价任务状态机

| 状态 | 说明 | 触发条件 |
|------|------|---------|
| 待核价 | 核价任务已生成，尚未提交 | 任务生成时；新轮次有零件更新时；审批被驳回时 |
| 审批中 | CE已提交核价，等待审批人审批 | CE点击「提交核价」 |
| 已核价 | 核价任务已提交且审批通过，不存在未核价零件 | 审批人点击「同意」 |

#### 状态流转图

```
                    ┌──────────────────────────────────────────┐
                    │                                          │
                    ▼                                          │
               ┌─────────┐   提交核价   ┌─────────┐  同意    ┌─────────┐
               │  待核价  │───────────→│  审批中  │────────→│  已核价  │
               └────┬────┘            └────┬────┘         └─────────┘
                    │                      │ 驳回
                    │                      │
                    │   ┌──────────────────┘
                    │   │
                    │   ▼
                    │ ┌─────────┐
                    │ │  已驳回  │
                    │ └────┬────┘
                    │      │ CE修改后重新提交
                    │      │
                    │      ▼
                    │ ┌─────────┐   提交核价   ┌─────────┐
                    └─│  待核价  │◄──重置状态──│  审批中  │
                      └─────────┘            └─────────┘

     触发条件（自动流转到「待核价」）：
     ├── 新轮次发布 + 零件有更新 → 关闭旧审批流，状态重置为「待核价」
     └── 审批被驳回 → 状态重置为「待核价」
```

#### 状态流转规则表

| 编号 | 当前状态 | 触发条件 | 目标状态 | 操作人 | 说明 |
|------|---------|---------|---------|-------|------|
| CE-S01 | — | RFQ发布第一轮 | 待核价 | 系统 | 自动生成核价任务 |
| CE-S02 | 待核价 | CE点击「提交核价」（必填项校验通过） | 审批中 | CE | 同时生成审批待办 |
| CE-S03 | 审批中 | 审批人点击「同意」 | 已核价 | CE审批人 | 审批通过 |
| CE-S04 | 审批中 | 审批人点击「驳回」 | 待核价 | CE审批人 | 驳回后CE可重新修改提交 |
| CE-S05 | 审批中 | RFQ发布新轮次 + 零件有更新 | 待核价 | 系统 | 自动关闭旧审批流 |
| CE-S06 | 已核价 | RFQ发布新轮次 + 零件有更新 | 待核价 | 系统 | 重新进入核价流程 |
| CE-S07 | 已核价 | 生成定点上会单 | 已核价（锁定） | 系统 | 核价按钮置灰，不可再编辑 |
| CE-S08 | 任意状态 | RFQ生成定点通知单 | 已完成 | 系统 | 终态，不可操作 |

> **关键逻辑：**
> - 新轮次发布时，仅当**零件有更新**（增加/减少/变更）才触发状态重置；
> - 新轮次发布但**零件无变化**时，核价任务状态不变；
> - 零件减少不发送飞书通知，零件+工厂维度新增/变更时发送通知。

### 6.2 与RFQ轮次的联动关系

| RFQ事件 | 核价任务变化 | 说明 |
|---------|------------|------|
| RFQ发布第一轮 | 生成核价任务（状态：待核价） | 1:1生成 |
| RFQ发布新轮次，零件有更新 | 关闭旧审批流，状态重置为「待核价」 | 审批人无需再审 |
| RFQ发布新轮次，零件无变化 | 核价任务状态不变 | 不触发任何操作 |
| RFQ生成定点上会单 | 核价按钮置灰，不可编辑 | 但可转派CE |
| RFQ生成定点通知单 | 核价任务状态→「已完成」 | 终态 |

### 7.2 RFQ基本信息

| 字段 | 说明 |
|------|------|

| 管理费 | Decimal | 是 | 用户输入，金额，三位小数，可以为0 |
| 出厂价 | Decimal | 是 | 计算/输入，三位小数，**不可以为0** |
| 模具总费用 | Decimal | 是 | 用户输入，金额，三位小数，可以为0 |
| 开发总费用 | Decimal | 否 | 用户输入，金额，三位小数，可以为0；未填写时默认为0 |
| 备注 | String | 否 | 文本框，支持CE编辑，500字符 |

### 7.4 出厂价计算逻辑

```
出厂价计算优先级：接口导入 ＞ 手动输入 ＞ 前端自动计算

自动计算规则：
出厂价 = 材料费 + 制造费 + 管理费

触发时机：
  - 任意一次修改材料费/制造费/管理费均会触发自动计算
  - 如果手动填写了出厂价，再次修改子项时也会触发自动计算（覆盖手动值）
```

### 7.5 数据初始化规则

| 场景 | 规则 |
|------|------|
| 首次生成 | 所有费用字段初始化为空 |
| 新轮次零件-工厂已有上轮核价 | 默认带出上一轮次核价结果 |
| 新轮次零件-工厂无上轮核价 | 该行用特殊颜色高亮标示 |
| 列表去重 | 零件-工厂维度始终为一行（轮次中已实现聚合） |

### 7.6 CE核价历史

每次提交时记录日志：

| 字段 | 说明 |
|------|------|
| 提交时间 | yyyy-mm-dd hh:mm:ss |
| 提交人 | CE核价人员姓名 |
| 提交轮次 | 第X轮 |
| 备注 | 同提交时填写的备注 |

### 7.7 按钮操作

| 按钮 | 说明 |
|------|------|

## 8. 提交核价

### 8.1 提交校验

| 校验项 | 规则 | 失败提示 |
|--------|------|---------|
| 必填项检查 | 材料费、制造费、管理费、出厂价、模具总费用不为空 | "您有必核价项未填写，请完成填写后再提交" |
| 出厂价校验 | 出厂价 > 0 | 同上 |
| 出厂价一致性 | 出厂价 = 材料费 + 制造费 + 管理费（若未手动输入） | 同上 |

校验失败时，页面红框高亮标示必填项。

### 8.2 审批流程

```
CE提交核价
    │
    ▼
弹框选择审批人（CE自行选择，可选范围：角色【Finance】，过滤CE自己）
    │
    ▼
进入审批流
    │
    ├── 审批人点击「同意」 → 状态变为「已核价」
    │
    └── 审批人点击「驳回」 → 状态回退为「待核价」，CE可修改后重新提交
```

### 8.3 审批页面内容

| 区域 | 内容 |
|------|------|
| RFQ基本信息 | RFQ编号、RFQ名称、关联SOR单号、是否多项目、采购工程师、当前轮次 |
| 核价列表 | 零件号 + 各项核价数据 |
| 备注 | CE提交时填写的备注 |

### 8.4 审批过程中的转单

> 如果审批过程中发生转单（转派CE核价人员），按照最新的核价人员来展示审批页面。

## 9. 导入导出

### 9.1 导出

| 项目 | 说明 |
|------|------|
| 范围 | 导出包含所有零件的核价任务 |
| 格式 | Excel (.xlsx) |
| 命名规则 | CE-YYYYMMDD-XXX.xlsx（同核价任务编号） |
| 触发 | CE在核价详情页点击「导出」 |

### 9.2 导入

| 项目 | 说明 |
|------|------|
| 格式 | Excel (.xlsx)，使用CE核价模板 |
| 唯一键 | 以**零件号**为导入的唯一key值 |
| 命名规则 | CE核价模板.xlsx（无模具/开发总费用版） |

**导入流程：**

```
选择文件 → 点击导入
    │
    ├── 无文件 → 报错提示
    │
    └── 有文件
         │
         ├── 解析成功 → 页面反馈"导入完成"，数据自动填充
         │
         └── 解析失败 → 页面反馈"解析失败，请下载报错文件"
                        报错文件命名：CE-YYYYMMDD-XXX-fail.xlsx
```

**导入期间限制：** 页面不允许操作，解析完成后恢复。

### 9.3 导入校验规则

| 校验项 | 规则 |
|--------|------|
| 必填项 | 材料费、制造费、管理费、出厂价不为空 |
| 数值格式 | 金额字段保留三位小数 |
| 出厂价 | 必须 > 0 |

## 11. 飞书通知

### 11.1 通知场景汇总

| 编号 | 场景 | 通知对象 | 通知时机 | 通知内容 |

## 13. 业务规则汇总

| 编号 | 规则 | 说明 |
|------|------|------|
| BR-001 | 任务生成 | RFQ发布第一轮后，定点类型RFQ自动生成CE核价任务，1:1绑定 |
| BR-002 | 轮次联动 | 新轮次有零件更新时，关闭旧审批流，状态重置为「待核价」 |
| BR-003 | 轮次无变化 | 新轮次零件无变化时，核价任务状态不变 |
| BR-004 | 出厂价计算 | 出厂价 = 材料费 + 制造费 + 管理费（自动计算） |
| BR-005 | 出厂价优先级 | 接口导入 ＞ 手动输入 ＞ 前端自动计算 |
| BR-006 | 出厂价限制 | 出厂价不可以为0，其他费用可以为0 |
| BR-007 | 提交校验 | 所有必填项不为空且出厂价>0才可提交 |
| BR-008 | 审批人选 | CE自行选择，范围为角色【Finance】，过滤CE自己 |
| BR-009 | 转派限制 | 任意状态下均可转派（含定点通知单已生成后） |
| BR-010 | 定点上会单 | 生成后核价按钮置灰，不可编辑，但可转派 |
| BR-011 | 定点通知单 | 生成后核价任务进入终态「已完成」 |
| BR-012 | 导入唯一键 | 以零件号为导入的唯一key值 |
| BR-013 | 数据去重 | 零件-工厂维度始终为一行 |
| BR-014 | 费用精度 | 金额字段保留三位小数 |
