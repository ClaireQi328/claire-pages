# 🎉 总结

**会议目的**：本次会议围绕**样件采购自动下单系统优化**展开，讨论当前采购流程中的效率瓶颈、数据整合方案及系统改造方向，旨在明确自动下单的可行路径与关键卡点。

**会议共识**：

1. **需求聚合可行性**：确认**不同来源的需求（如DRE、试制、散件）存在按供应商或成本中心聚合的可能性**，但需考虑项目独立性与更新频率的冲突。

2. **供应商选择机制**：针对**一品多点（占比约10%）** 场景，共识在采购审批环节**增加强制选择界面**，由采购员基于询价结果或咨询研发后确认供应商，避免需求方填写不准的问题。

3. **数据字段优化**：明确**项目名称/车型信息需从米Tab系统映射至采购界面**，替代当前依赖备注文本的混乱状态，提升采购判断效率；**项目编号（预算相关）与采购决策无关，仅作为预算标识**。

4. **台账数据清洗**：基于现有台账分析，**通过删除价格为0且含软模费的无效记录、合并重复项（同零件号同供应商同价格）**，可提升约40%订单的自动下单覆盖率。

5. **价格逻辑补全**：指出当前自动下单逻辑**未考虑工厂维度导致的物流价格差异**，需在报价与下单环节补充送货地信息以确保成本准确性。

2. **供应商匹配与人工介入边界**

3. **系统字段与数据映射问题**

    - **赵小丫**指出项目编号（预算相关）无法反映实际车型/项目，采购依赖混乱的备注文本；**曹冬梅**建议从米Tab系统映射统一项目编码至采购界面，或新增备注列规范信息。

4. **自动下单卡点与台账分析**

    - **赵小丫**基于台账数据提出清理策略：删除**价格为0但含软模费的无效记录**、合并重复项（同零件号同供应商同价格），可覆盖40%自动下单场景；剩余60%因一品多点或一供应商多价格需人工处理。

    - **齐岳**强调需补全工厂维度逻辑（物流价格按送货地差异），当前自动下单未考虑此要素；**李文俊**确认自动下单需保留人工确认环节（如价格最低逻辑校验）。
