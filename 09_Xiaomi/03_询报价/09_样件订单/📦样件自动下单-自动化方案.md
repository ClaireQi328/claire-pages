# 样件自动下单 — 自动化方案

> 小米汽车采购数字化 · 2026-06-10
> 基于业务期望与现有 Agent 融合版原型，形成端到端自动化落地方案

---

## 一、方案概述

### 1.1 目标

实现样件采购从 **需求创建 → 订单履约** 的端到端自动化闭环，覆盖三大核心能力：

| 能力 | 目标 | 量化指标 |
|------|------|----------|
| **批量自动下单** | 多维度需求聚合，一键批量生成采购订单 | 下单效率提升 80%，人工介入率 ≤10% |
| **订单自动更新** | 价格、状态、供应商信息实时同步 | 数据同步延迟 ≤5min，异常告警覆盖率 100% |
| **订单进度可视化** | 全流程状态追踪，异常自动预警 | 看板实时刷新，未处理需求 T+1 闭环率 ≥95% |

### 1.2 核心业务场景

样车/试制BOX/量产试制 → MI-PEC触发需求 → EP系统BOM解析 → 需求池汇聚 → 智能聚合 → 价格匹配/定价任务 → 批量下单 → 进度追踪 → 验收付款

### 2.2 四大 Agent 协同

| Agent | 职责 | 触发方式 | 输出 |
|-------|------|----------|------|
| **Agent1 · 需求导入** | 监听 MI-PEC/EP 系统，自动解析 BOM，导入需求池 | Webhook 实时触发 + 定时轮询 | 统一需求池 |
| **Agent1.5 · 智能聚合定价** | 需求多维聚合，价格检索，无价格触发 RFQ | 需求池变更触发 | 聚合订单 + 定价任务 |
| **Agent2 · 自动下单** | 匹配价格后自动创建订单草稿，推送审批 | 价格就绪触发 | 采购订单 |
| **Agent3 · 进度追踪通知** | 日报生成、异常预警、全流程状态看板 | 定时(每日18:00) + 事件触发 | 日报 + 看板 |

## 三、核心流程详解

### 3.1 阶段一：需求创建与汇聚

#### 3.1.1 需求来源

| 来源 | 触发方式 | 数据内容 | 频率 |
|------|----------|----------|------|
| **MI-PEC 样件生产订单** | Webhook 推送 | 零件号、数量、项目代码、需求日期 | 实时 |
| **EP 试制 BOM 发布** | Agent1 轮询监听 | BOM 零件清单、配置信息 | 日均 2-3 次 |
| **手动需求录入** | 采购工程师手动提交 | 补充/紧急需求 | 按需 |

#### 3.1.2 需求标准化处理

```
原始需求 → 字段解析 → 数据校验 → 缺失补全/告警 → 写入统一需求池
```

**标准化字段：**

| 字段 | 来源 | 校验规则 | 缺失处理 |
|------|------|----------|----------|
| 零件号 | MI-PEC/EP | 格式校验 + 存在性校验 | 告警，人工补全 |
| 零件名称 | 主数据关联 | 自动关联 | - |
| 需求数量 | 需求单 | 正整数校验 | 告警 |
| 项目代码 | MI-PEC | 项目代码库校验 | 告警 |
| 需求日期 | 需求单 | ≥ 当前日期 + 7天 | 自动设定默认值 |
| 采购品类 | MVPS映射 | 品类库校验 | 自动映射，失败则人工 |
| 供应商 | 供应商资源池 | 资源池校验 | 触发寻源流程 |

### 3.2 阶段二：智能需求聚合与订单聚类

#### 3.2.1 聚合维度

```
零散需求 ──┬── 按项目聚合 (MX13B / KUN30 / MS12B)
           ├── 按物料聚合 (同零件号合并)
           ├── 按时间聚合 (同一周/同一月需求合并)
           └── 按供应商聚合 (同供应商需求合并下单)
```

#### 3.2.2 聚合策略

| 策略 | 适用场景 | 合并规则 | 优势 |
|------|----------|----------|------|
| **同零件合并** | 同一零件多批次需求 | 合并为一张订单，分行体现不同交期 | 减少订单数量，提升议价权 |
| **同供应商合并** | 同一供应商多个零件 | 合并为一张框架订单 | 降低物流成本，简化对账 |
| **项目维度聚合** | 同一车型项目所有需求 | 按项目打包，统一管理 | 项目视角完整可控 |
| **紧急需求优先** | 交期紧迫的需求 | 独立成单，优先处理 | 保障紧急交付 |

#### 3.2.3 聚合输出示例

```json
{
  "order_cluster_id": "OC-2026-0610-001",
  "project": "MX13B",
  "supplier": "供应商A",
  "items": [
    {
      "part_no": "P000056656001",
      "part_name": "仪表板饰板总成",
      "quantity": 50,
      "delivery_date": "2026-07-15",
      "unit_price": null,
      "price_status": "pending_rfq"
    }
  ],
  "total_amount": null,
  "aggregation_type": "supplier_merge",
  "urgency": "normal"
}
```

### 3.3 阶段三：智能价格检索与定价任务

#### 3.3.1 价格匹配逻辑

```
需求零件 ──┬── 历史价格库查询 → 匹配成功 → 比价分析
           ├── 供应商报价库查询 → 匹配成功 → 比价分析
           └── 均未匹配 → 自动生成 RFQ 定价任务
```

#### 3.3.2 比价规则

| 场景 | 处理方式 | 自动化决策 |
|------|----------|------------|
| **有历史价 + 有报价** | 历史价 vs 报价比对 | 偏差 ≤15% → 取低价自动下单；偏差 >15% → 人工确认 |
| **有历史价 + 无报价** | 参考历史价 | 历史价 ≤6个月有效 → 自动引用下单；>6个月 → 重新询价 |
| **无历史价 + 有报价** | 使用报价 | 报价在有效期内 → 自动下单 |
| **无价格** | 生成 RFQ | 自动触发询价流程，报价截止后自动比价下单 |
| **一品多点** | 多家供应商报价 | 自动排序(价格40%+质量30%+交付30%)，推送采购工程师决策 |

#### 3.3.3 定价任务自动生成

当价格检索失败时，系统自动创建定价任务：

```json
{
  "pricing_task_id": "PT-2026-0610-001",
  "part_no": "P000046758001",
  "category": "全景显示器",
  "assigned_to": "采购工程师-张三",
  "supplier_candidates": ["供应商B", "供应商C"],
  "rfq_deadline": "2026-06-17",
  "priority": "high",
  "source_demand": ["DR-2026-0610-045", "DR-2026-0610-067"],
  "status": "pending_rfq"
}
```

### 3.4 阶段四：批量自动下单

#### 3.4.1 下单决策矩阵

| 条件 | 价格状态 | 供应商确认 | 审批要求 | 系统动作 |
|------|----------|------------|----------|----------|
| 自动下单 | ✅ 价格就绪 | ✅ 供应商在库 | 免审(≤5万) | 直接创建订单 |
| 审批下单 | ✅ 价格就绪 | ✅ 供应商在库 | 需审(>5万) | 创建草稿→推送审批 |
| 暂停下单 | ⚠️ 价格偏差大 | ✅ 供应商在库 | 人工确认 | 告警通知→等待处理 |
| 阻塞下单 | ❌ 无价格 | - | - | 触发定价任务 |
| 寻源下单 | ✅ 价格就绪 | ❌ 无供应商 | 触发寻源 | 推送寻源任务 |

#### 3.4.3 批量操作

- **一键批量下单**: 勾选多条需求 → 聚合校验 → 批量生成订单
- **模板化下单**: 高频零件设置下单模板，下次直接引用
- **定时批量**: 设置定时任务，每日固定时间批量处理已就绪需求

### 3.5 阶段五：订单自动更新

#### 3.5.1 更新触发机制

| 事件 | 触发源 | 更新内容 | 通知对象 |
|------|--------|----------|----------|
| 供应商确认订单 | SRM 供应商回执 | 订单状态→已确认 | 采购工程师 |
| 物流发货 | SRM/物流系统 | 物流单号、预计到货 | 项目负责人 |
| 到货签收 | MI-PEC 入库 | 入库数量、时间 | 采购工程师 |
| 质检结果 | MI-PEC 质检 | 合格/不合格 | 采购工程师 + SQE |
| 价格变更 | 供应商/SRM | 新价格、生效日期 | 采购工程师 |
| 订单变更 | 采购工程师 | 数量/交期变更 | 供应商 + 项目组 |

#### 3.5.2 异常自动处理

```
异常检测 ──┬── 交期预警 (距交期 ≤7天未发货) → 自动通知供应商 + 采购工程师
           ├── 价格异常 (价格波动 >20%) → 暂停下单 + 人工确认
           ├── 数量异常 (入库数量 ≠ 订单数量) → 告警 + 差异报告
           └── 供应商异常 (供应商未确认超48h) → 升级通知 + 备选方案
```

## 四、数据模型

### 4.1 核心实体关系

```
需求单(Demand)
  ├── PK: demand_id
  ├── part_no → 零件主数据
  ├── project_code → 项目主数据
  ├── quantity, delivery_date
  ├── category → 采购品类
  ├── price_status: pending | matched | rfq_sent | priced
  └── order_status: pending | clustered | ordered | confirmed | delivered | accepted

聚合订单簇(OrderCluster)
  ├── PK: cluster_id
  ├── aggregation_type: part_merge | supplier_merge | project_merge
  ├── supplier_id → 供应商主数据
  ├── demand_ids[] → 需求单
  └── total_amount, status

采购订单(PurchaseOrder)
  ├── PK: po_number (4900037xxx)
  ├── cluster_id → 聚合订单簇
  ├── supplier_id, project_code
  ├── items[]: part_no, quantity, unit_price, delivery_date
  ├── total_amount, currency
  ├── approval_status: draft | pending | approved | rejected
  └── order_status: created | confirmed | shipped | received | closed

价格库(PriceRecord)
  ├── PK: price_id
  ├── part_no, supplier_id
  ├── price, currency, validity_period
  ├── source: historical | rfq | manual
  └── version, effective_date

定价任务(PricingTask)
  ├── PK: task_id
  ├── part_no, category
  ├── assigned_to → 采购工程师
  ├── supplier_candidates[]
  ├── rfq_deadline, priority
  └── status: pending | in_progress | completed
```

### 4.2 状态机

**需求单生命周期：**

```
pending → clustered → ordered → confirmed → delivered → accepted
   ↓          ↓          ↓
 rfq_sent  pricing    exception
   ↓          ↓          ↓
 priced   ordered    resolved
```

**采购订单生命周期：**

```
draft → pending_approval → approved → sent_to_supplier
  ↓                              ↓
 rejected                      confirmed → shipped → received → closed
  ↓                              ↓
 revised                     exception → resolved
```

## 六、异常处理与人工介入

### 6.1 异常分级

| 级别 | 场景 | 响应时间 | 处理方式 |
|------|------|----------|----------|
| 🔴 P0 紧急 | 系统故障、大批量订单异常 | 15min | 自动告警 + 电话通知 + 人工处理 |
| 🟠 P1 高 | 价格偏差大、供应商拒绝 | 2h | 企微告警 + 采购工程师介入 |
| 🟡 P2 中 | 交期预警、数据缺失 | 4h | 站内通知 + 日报汇总 |
| 🟢 P3 低 | 信息不完整、格式问题 | 24h | 日报汇总 + 批量处理 |

### 6.2 人工介入触发条件

| 触发条件 | 介入角色 | 操作 |
|----------|----------|------|
| 价格偏差 >15% | 采购工程师 | 确认/拒绝价格 |
| 供应商无响应 >48h | 采购工程师 | 催单/更换供应商 |
| 订单金额 >5万 | 采购经理 | 审批订单 |
| 订单金额 >20万 | 采购总监 | 二级审批 |
| 异常持续 >3天 | 项目负责人 | 升级处理 |

## 七、MVP 分期规划

### Phase 1: 需求导入与价格匹配 (4周)

**目标**: 实现需求自动导入 + 价格自动匹配

- MI-PEC Webhook 对接，需求自动导入
- EP BOM 解析与标准化
- 历史价格库查询接口
- 价格匹配引擎 (有价自动匹配，无价生成RFQ)
- 基础需求池看板

**交付物**: 需求自动导入率 ≥90%，价格匹配率 ≥70%

### Phase 2: 智能聚合与自动下单 (4周)

**目标**: 实现需求聚合 + 批量下单

- 需求聚合引擎 (按零件/供应商/项目)
- 订单聚类算法
- 自动下单决策矩阵
- SRM 订单创建接口
- 审批流集成
- 批量下单操作界面

**交付物**: 聚合后订单量减少 40%，自动下单率 ≥60%

### Phase 3: 订单追踪与可视化 (3周)

**目标**: 实现订单全生命周期追踪

- 订单状态实时同步 (SRM → 平台)
- 异常检测与告警引擎
- 进度可视化看板 (全局/项目/供应商/品类)
- Agent3 日报自动生成
- 企微/邮件/站内信多渠道推送

**交付物**: 异常响应时间 ≤2h，看板实时刷新

### Phase 4: 智能优化与扩展 (持续迭代)

- 价格预测模型 (基于历史趋势)
- 供应商推荐引擎
- 订单合并优化算法
- 与品类管理/人员树系统打通
- 数据分析与决策支持看板

## 八、关键指标 (KPI)

### 效率指标

| 指标 | 当前基线 | 目标值 | 衡量方式 |
|------|----------|--------|----------|
| 需求导入自动化率 | 0% (手工) | ≥95% | 自动导入数/总需求数 |
| 价格匹配自动化率 | 0% (手工) | ≥80% | 自动匹配数/总需求数 |
| 自动下单率 | 0% (手工) | ≥70% | 自动下单数/总订单数 |
| 下单周期(需求→订单) | 3-5天 | ≤4小时 | 平均处理时间 |
| 人工介入率 | 100% | ≤15% | 人工处理数/总处理数 |

### 质量指标

| 指标 | 目标值 | 衡量方式 |
|------|--------|----------|
| 订单准确率 | ≥99% | 正确订单数/总订单数 |
| 异常发现及时率 | ≥95% | 自动发现数/总异常数 |
| 供应商确认率(48h内) | ≥90% | 48h内确认数/总订单数 |
| 需求T+1闭环率 | ≥95% | T+1处理数/总需求数 |

### 成本指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 聚合后订单量减少 | ≥40% | 对比聚合前后 |
| 采购人员效率提升 | ≥60% | 人均处理订单量 |
| 异常处理成本降低 | ≥50% | 异常处理工时 |

## 九、风险与应对

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| MI-PEC/EP 接口不稳定 | 需求导入中断 | 中 | 重试机制 + 手动兜底入口 |

## 十、与现有系统的协同

### 10.1 与 MVPS 品类管理的协同

- 品类-MVPS 主数据为自动下单提供 **品类映射基础**
- 人员树配置决定 **任务路由和审批链路**
- 品类采购策略影响 **下单决策阈值**

### 10.2 与采购任务分发的协同

- SOR 发布 → 触发样件需求 → 进入自动下单流程
- BDL 预选 → 确定供应商候选 → 影响价格匹配范围
- EWO/CWO/SWO → 变更需求 → 触发订单更新

### 10.3 数据流向

```
MVPS品类管理 ──→ 品类映射 ──→ 自动下单(品类决定策略)
     │
人员树配置 ──→ 任务路由 ──→ 自动下单(人员决定审批)
     │
采购任务分发 ──→ 需求来源 ──→ 自动下单(任务触发需求)
     │
样件自动下单 ──→ 订单数据 ──→ 进度看板 + 日报
     │
样件自动下单 ──→ 交付数据 ──→ 财务结算 + 品类绩效
```
