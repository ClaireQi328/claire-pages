# A\+B管理调研需求报告

# 业务背景

## 业务现状

1. 当DB件价格变化时，总成件采购需要人工去对总成件进行调价，会出现信息同步不及时，价格无法及时变更，经常会出现补差业务；

2. 总成件采购无法看到DB件的价格，需要线下手工计算总成件价格，数据准确性以及效率低下

## 业务目标

实现A\+B总成件的价格自动汇总与联动，减少人工干预，提升数据准确性和设变处理效率。

## BOM调研

1. **仪表板：**仪表板总成与下级DB件的关系，通过合件码找到总成件号？

2. **结构解析目标**：需从BOM系统（EBOM）解析总成件与DB件的结构关系（含零件号、用量、生效时间），以支持采购价格管理。

2. **本体件结构识别：**目前需要在总成架构中，识别哪个零件是本体件，进行本体件与DB件卷积

    1. 情况一：本体件是A，DB件是B，总成件是C；

    2. 情况二：本体件是A，DB件是B，总成件是A'；

3. **数据源选择难点**：

    - **EBOM问题**：变更若不换号，则EBOM生效时间与实物切换时间可能不一致，导致价格卷集时机不准。

    - **MBOM问题**：当前MBOM过滤DB件结构，需调整规则才能承接数据，且可能增加工程师工作量。

4. **业务规范前提**：自动卷集需满足**每次变更总成件换号**，否则无法精准匹配价格与实物切换时间。

5. **分步推进策略**：优先实现**结构展示与变更提醒**功能（如提醒采购员DB件价格变化），待业务规范后再考虑**自动卷集价格**。

**会议目的**：了解 EBOM 中总成与 DB 件的结构搭建现状，识别实现自动价格卷集的关键卡点，评估是否可通过系统自动化或提醒机制解决当前采购价格管理依赖手工账的问题。

**会议共识**：

- 当前 EBOM 中存在多种总成与 DB 件的挂接结构（如直接挂接、中间跳层、平铺等），部分结构复杂且不规范，影响系统自动解析。

- 实现自动价格卷集的核心前提为：BOM 结构规范、每次变更均换号、MBOM 完整承接 EBOM 结构并维护断点时间。

- 在当前业务无法完全满足上述前提的情况下，优先采用“系统提醒”模式（如提醒采购确认结构完整性、DB件价格更新）更为可行，避免因自动计算错误引发责任争议。

- 采购端普遍依赖手工台账管理总成件价格，存在效率低、易出错、难追溯等问题，亟需系统支持。

**待办事项**：

- 梳理实现自动价格卷集所需的业务前提条件清单（如结构规范、换号规则、MBOM 数据要求等），用于后续推动相关部门对齐标准。

- 基于现有数据场景，设计分层级的系统提醒方案（如每一层结构变更提醒对应责任人），明确提醒范围和触发逻辑。

- 调研采购员手工台账的实际使用方式，收集典型样例，为系统功能设计提供参考依据。

- 推动与 MBOM 团队沟通，评估在 MBOM 中保留 DB 件结构的可行性及所需工作量。

**会议议题**：

- **EBOM 中总成与 DB 件的结构现状与数据可获取性**：

    - EBOM 中记录了总成与 DB 件的结构关系，包含生效时间、用量等信息，具备一定结构化基础。

    - 存在多种挂接模式：① 总成下直接挂 DB 件（最简单）；② 总成下挂 C 件和 DB 件；③ 中间跳层（如总成→S→DB）；④ 仪表板类平铺结构；⑤ DB 件下再挂 DB 件（需卷两次）。

    - 合件分组编码可辅助识别逻辑结构，但仅为视图，非实际 BOM 结构。

- **自动价格卷集的主要卡点**：

    - **结构识别难**：无法准确识别“本体件”，难以区分哪些 DB 件应计入总成成本。

    - **变更不换号**：SOP 前变更频繁且常不换号，导致 EBOM 生效时间与实际生产断点不一致，价格更新滞后或超前。

    - **MBOM 数据缺失**：MBOM 当前过滤掉 DB 件结构，无法直接用于价格卷集，需人工维护断点时间。

    - **颜色件影响价格**：不同颜色漆面价格不同，但 EBOM 无颜色件，需依赖总基线数据。

- **现有业务模式与系统支持矛盾**：

    - 采购依赖线下台账记录本体件与 DB 件价格变化，工作量大且易出错。

    - 若系统自动计算价格，一旦出错易引发责任纠纷；若仅做提醒，则可降低风险，逐步推动流程规范化。
