# EP 系统全球化扩展 PRD

> 小米汽车采购系统（EP）支持海外/全球化运营的产品需求文档

---

## 一、背景与目标

### 1.1 为什么 EP 需要全球化

小米汽车已启动海外出口战略。当前 EP 系统完全围绕国内业务构建（人民币定价、国内供应商、单一法域合同），无法支撑以下场景：

| 挑战 | 现状痛点 |
|------|----------|
| 多币种 | EP 仅支持人民币，无法处理美元/欧元/泰铢等报价和结算 |
| 海外供应商 | 供应商门户仅中文界面，注册流程仅适配国内企业资质 |
| 跨境合规 | 无出口管制、制裁名单、ESG 合规检查能力 |
| CKD BOM | 无散件/模块级 BOM 管理，无包装规格和装箱方案 |
| 国际物流 | 无 Incoterms 管理、运费估算、报关数据生成 |
| 多法域合同 | 合同模板仅适配中国法律，无多语言生成能力 |

### 1.2 业务场景

| 模式 | 说明 | 典型市场 | EP 系统需求 |
|------|------|----------|------------|
| **CBU 整车出口** | 国内生产整车直接出口 | 中东、东南亚 | 多币种定价、出口合规、物流集成 |
| **CKD 散件出口** | 零部件以散件形式出口，在海外 KD 工厂组装 | 泰国、印尼、巴西 | CKD BOM 管理、模块拆分、装箱方案、报关数据 |
| **DKD 深度本地化** | 关键零部件海外本地采购，仅核心模块从国内出口 | 欧洲、印度 | 海外供应商管理、本地化采购、TCO 分析 |

### 1.3 关键干系人

| 角色 | 职责 | 核心诉求 |
|------|------|----------|
| 海外事业部 | 制定出口策略、选择目标市场 | 全链路可视化、成本可控 |
| 国际采购工程师 | 海外供应商开发、本地化寻源 | 多语言 RFQ、供应商门户 |
| 成本分析师 | 海外车型成本核算 | Landed Cost、TCO、汇率影响分析 |
| 物流/关务 | 国际物流、报关、清关 | 报关数据自动生成、Incoterms 管理 |
| 法务/合规 | 跨境合同、出口管制、ESG | 多法域合同模板、合规检查 |
| 财务 | 多币种结算、汇率风险 | 多币种台账、汇率锁定、损益分析 |

### 1.4 成功指标

| 指标 | 目标值 | 衡量方式 |
|------|--------|----------|
| 海外供应商注册周期 | ≤ 7 个工作日 | 从提交到审核通过 |
| RFQ 多币种支持率 | 100% | 所有海外 RFQ 均支持多币种 |
| Landed Cost 计算准确率 | ±3% | 与实际到岸成本对比 |
| CKD BOM 数据完整率 | 100% | 所有 CKD 项目 BOM 数据无缺失 |
| 合同多语言生成覆盖率 | 100% | 所有海外合同均支持目标语言 |

|------|------|--------|
| 多语言注册页面 | 支持 EN/TH/ID/DE/PT 等语言，根据浏览器语言自动切换 | P0 |
| 海外企业资质适配 | 支持各国企业注册号（如泰国 DBD 注册号、印尼 NIB、德国 HRB） | P0 |

| 注册审核工作流 | 适配海外供应商审核流程，支持区域采购经理审核 | P1 |

#### 2.2.2 供应商门户（海外版）

| 功能 | 说明 | 优先级 |

## 三、模块 2：国际 RFQ 与报价

### 3.1 业务目标

支持多币种 RFQ 创建、Landed Cost 计算、汇率管理、关税查询，实现全球采购成本透明化。

### 3.2 功能需求

#### 3.2.1 多币种 RFQ 创建

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 币种选择 | RFQ 创建时可选择报价币种（USD/EUR/THB/IDR 等） | P0 |
| 汇率锁定 | RFQ 发布时自动获取并锁定当日汇率，报价期间汇率不变 | P0 |
| 多币种报价单 | 供应商以本币报价，系统自动换算为指定币种 | P0 |
| 汇率有效期 | 支持设置汇率有效期，过期自动刷新 | P1 |
| 历史汇率查询 | 支持查询历史汇率，用于趋势分析 | P2 |

#### 3.2.2 Landed Cost 计算

Landed Cost（到岸成本）= FOB 价格 + 国际运费 + 保险费 + 关税 + 进口增值税 + 港口杂费 + 清关费 + 内陆运输费

| 成本项 | 说明 | 数据来源 |
|--------|------|----------|
| FOB 价格 | 供应商报价（离岸价） | RFQ 报价 |
| 国际运费 | 海运/空运/陆运费用 | 物流系统/手动输入 |
| 保险费 | 货物运输保险 | 按货值比例计算（通常 0.3%-0.5%） |
| 关税 | 基于 HS Code 的进口关税 | 关税数据库/API |
| 进口增值税 | 目标国家进口增值税 | 关税数据库 |
| 港口杂费 | 码头操作费、堆存费等 | 物流系统/手动输入 |
| 清关费 | 报关行服务费 | 物流系统/手动输入 |
| 内陆运输 | 港口到工厂运输费 | 物流系统/手动输入 |

**计算公式**：
```
Landed Cost = FOB × (1 + 运费率) × (1 + 保险率) × (1 + 关税率) × (1 + 增值税率)
            + 港口杂费 + 清关费 + 内陆运输费
```

#### 3.2.3 汇率管理

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 自动汇率获取 | 集成汇率 API（如 XE、OANDA），每日自动更新 | P0 |
| 手动汇率录入 | 支持财务手动录入指定汇率（用于锁定汇率场景） | P0 |
| 汇率波动预警 | 汇率波动超过阈值（如 ±3%）自动预警 | P1 |
| 汇率历史趋势 | 汇率历史趋势图表，辅助采购决策 | P2 |
| 多币种台账 | 零件价格台账同时显示本币和目标币种价格 | P0 |

#### 3.2.4 关税/HS Code 集成

| 功能 | 说明 | 优先级 |
|------|------|--------|
| HS Code 数据库 | 维护常用零部件 HS Code 映射表 | P0 |
| 关税税率查询 | 根据 HS Code + 原产国 + 目标国查询适用关税税率 | P0 |
| 原产地规则 | 支持原产地证明管理，影响关税适用 | P1 |
| 关税变化预警 | 关税政策变化时自动预警受影响的零件 | P2 |

#### 3.2.5 比价分析（本地 vs 进口）

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 本地 vs 进口比价 | 同一零件的本地采购成本 vs 进口 Landed Cost 对比 | P0 |
| TCO 对比 | 考虑质量、交期、库存等因素的总拥有成本对比 | P1 |
| 敏感性分析 | 汇率/关税变化对成本的影响模拟 | P1 |
| 比价报告 | 自动生成比价分析报告 | P1 |

### 3.3 数据模型扩展

```
RFQ（询价单）
```

## 四、模块 3：跨境订单管理

### 4.1 业务目标

支持 CKD 散件订单、模块级拆分、包装规格管理、物流订单集成、报关数据生成。

### 4.2 功能需求

#### 4.2.1 CKD Kit BOM 管理

| 功能 | 说明 | 优先级 |
|------|------|--------|
| CKD BOM 创建 | 基于整车 BOM 创建 CKD 散件 BOM，支持模块化拆分 | P0 |
| 模块级管理 | 按模块（动力总成、底盘、内饰、外饰等）管理 CKD 零件 | P0 |
| BOM 版本管理 | CKD BOM 版本控制，支持 EWO/CWO 变更 | P0 |
| 本地化标记 | 标记哪些零件本地采购、哪些从国内出口 | P1 |
| BOM 成本汇总 | 按模块汇总 CKD 零件成本（FOB + Landed Cost） | P0 |

**CKD BOM 结构示例**：
```
整车 BOM (SU7 CKD - 泰国)
├── 动力总成模块
│   ├── 电池包总成          [国内出口]
│   ├── 电驱总成            [国内出口]
│   └── 电控系统            [国内出口]
├── 底盘模块
│   ├── 前副车架总成        [国内出口]
│   ├── 后副车架总成        [国内出口]
│   └── 制动系统            [本地采购]
├── 内饰模块
│   ├── 仪表板总成          [国内出口]
│   ├── 座椅总成            [本地采购]
│   └── 门板总成            [国内出口]
└── 外饰模块
    ├── 前保险杠总成        [本地采购]
    ├── 后保险杠总成        [本地采购]
    └── 灯具总成            [国内出口]
```

#### 4.2.4 物流订单集成

| 功能 | 说明 | 优先级 |
|------|------|--------|

## 五、模块 4：合同管理

### 5.1 业务目标

支持多法域合同模板、电子签章、多语言合同生成、合同风险预警。

### 5.2 功能需求

#### 5.2.1 多法域合同模板

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 模板库 | 按国家/地区维护合同模板（中国法、泰国法、德国法等） | P0 |
| 条款库 | 维护标准条款库（管辖法律、争议解决、不可抗力等） | P0 |
| 模板配置 | 支持配置不同法域的合同要素差异 | P1 |
| 模板版本管理 | 合同模板版本控制 | P1 |

**关键法域差异**：

| 法域 | 关键差异 | 系统应对 |
|------|----------|----------|
| 中国 | 合同法、电子签名法 | 现有模板 |
| 泰国 | 民商法典、泰语强制 | 泰语模板、本地法律顾问审核 |
| 印尼 | 民法典、Bahasa Indonesia 强制 | 印尼语模板、公证要求 |
| 德国 | BGB、EU 法规 | 德语模板、GDPR 条款 |
| 巴西 | 消费者法典、葡萄牙语 | 葡语模板、本地化条款 |

#### 5.2.2 电子签章（跨境合规）

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 电子签章集成 | 集成国际电子签章服务（如 DocuSign、Adobe Sign） | P0 |
| 跨境法律效力 | 确保电子签章在目标国家具有法律效力 | P0 |
