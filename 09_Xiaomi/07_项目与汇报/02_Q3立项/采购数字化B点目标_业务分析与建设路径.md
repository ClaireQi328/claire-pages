# 2.2 采购数字化 B 点目标

> **成本 ✖️ 效率 ✖️ 合规　|　四层架构 ✖️ 两大闭环**
>
> 一句话：让采购从"**系统记录人决策**"的执行工具，升级为"**会自己进化的采购大脑**"——
> 以成本/效率/合规三轴为牵引，以四层架构为承载、两大闭环为引擎，完成 L1（看板辅助）→ L3（常规自治）的能力跃迁。

---

## 一、为什么是「成本 × 效率 × 合规」

供应链全局用 DQCC（交付/质量/成本/合规）四域衡量，但**交付与质量的主战场在制造与计划侧**，采购能直接握住的杠杆只有三根：

| 轴 | 采购的角色 | 杠杆本质 |
|---|---|---|
| **成本** | 价格的第一责任人 | 决定"花多少钱买"——直接计入毛利 |
| **效率** | 流程的执行中枢 | 决定"用多少人、多久买到"——决定可扩展性 |
| **合规** | 出海的守门人 | 决定"能不能合法交付"——一票否决项 |

三轴不是并列，而是**乘法关系**：合规是 0/1 的资格门槛（漏一项即出口受阻），效率是放大器（人均产能决定能管多大盘子），成本是利润底盘。**任一轴塌陷，另外两轴的成果都会清零**——这正是用"✖️"而非"+"表达的原因。

---

## 二、三轴的 A 点痛点 → B 点目标

### 2.1 成本 C — 「事后核价」→「设计期锁定 + 全周期闭环」

**最核心的结构性矛盾：**
> 整车 **70-80% 的成本在设计期就被锁定**，而采购当前只在**量产期**介入定价（询比价、核价、行情调价）。
> **省成本的窗口在左段（设计期），花钱的动作却在右段（量产期）**——错过窗口，量产期再努力也只能抠边角。

| A 点现状 | B 点目标 |
|---|---|
| 成本未作为独立价值流设计，散落在各子系统 | Should-cost 标尺贯穿，从功能→工艺→材料→工时/费率推出"该花多少" |
| 报价靠经验、靠大宗行情，无历史可比基线 | 报价组项结构化 + 成本因子库，量产期 5 算子自动判断 |
| A+B 价格联动靠人工，一轮 3-5 天，谁改都不知道 | DB 件变更自动触发总成件重算、自动确认、自动刷台账 |
| 偏差只是"一个差异率"数字，说不清谁的责任 | 偏差自动归因到设计变更/材料波动/工艺/份额，回写因子库 |

**衡量指标**：设计期锁定 70-80% 成本结构；A+B 联动从 3-5 天 → 秒级自动卷积；Should-cost 因子库年级自迭代。

**5 个算子（量产期）**：A 设计成本预评估 · B 报价异常检测 · C A+B 联动卷积 · D 降本机会识别 · E 成本核算归因。其中 A/B/C 是"算尺子穿透价"（主动发现问题），D/E 是"用尺子追溯价"（拆解归因），结果经基线回写让 Should-cost 持续更新——**这是成本域唯一带"♻️"标记的活主数据**。

### 2.2 效率 E — 「系统记录人决策」→「机器执行人例外」

**核心矛盾：系统能记录，但不能管控；人在做机器本可以做的事。**

主干流程（寻源→定点→订单→交付）2021-2023 已线上化，但本质仍是"线上化的人工"。典型样本——**样件订单**：

| 指标 | 现状 |
|---|---|
| 日均订单数 | 200 单 |
| 每单处理时间 | 5 分钟 |
| 日总耗时 | 16.7 小时（≈2 个全职人力纯做重复操作） |
| 可自动化比例 | 40%（单一供应商、零件已定价仍靠人工逐笔下单） |

| A 点现状 | B 点目标 |
|---|---|
| 框架协议预批量/量产分开维护，碎且重复 | 框架自动化合并，统一台账为唯一主动数据源 |
| 合同线下流转，"签得乱、查找难、管理散" | 合同全生命周期在线，统一签署入口，结构化沉淀 |
| 订单逐笔人工，多/无供应商异常件混在常规件里易遗漏 | 订单自动化：可自动单系统下单，异常件自动识别升级 |
| 定点/设变/变价任务散落，进度看不全 | 任务中台统一纳管，进度一览无余 |

**B 点抓手——AI Agent / FDE 模式**：以"采购员数字化工"为定位，构建主动智能体（非 Chatbot）。
人机协同公式：**决策质量 = min(人工操作) × max(决策质量) × min(流程长度)**。
即 Agent 汇集信息生成草稿→人确认；Agent 识别风险→人决定阻断；Agent 给建议→人做最终决策。分层落地：Phase 1 半自动（Agent 建议+人工确认）→ Phase 2 条件自动（低风险场景全自动）。

**衡量指标**：样件订单 40% 自动化 → 释放约 1 FTE；框架/合同/订单流转周期显著缩短，任务零遗漏、零延误。

### 2.3 合规 C — 「分散应对 + 人工举证」→「体系化 + 数据级合规」

**核心矛盾：欧盟监管逻辑是"有罪推定 + 企业自证清白"——不是被动应付检查，而是随时要能证明"我没问题"。**
任何一项数据断点都可能"漏绿"，导致整车合规失败。出海是 **2027 年硬节点，不可前移**。

| A 点现状 | B 点目标 |
|---|---|
| 汽车供应链 ESG 合规体系基本空白，需从 0 搭建 | 12 项法规整合为 4 条单一项线：尽调 / 碳足迹 / 电池护照 / 禁用物质 |
| 17 项工作按法规维度散落，多头交叉重复调研同一供应商 | 三统一（标准/数据/流程）+ 统一问卷，"一次采集、多场景复用" |
| 碳数据靠 Excel 手算，尽调靠线上问卷，数据未验证 | 碳核算引擎（因子库×活动数据自动算）；多源风险整合（CAMDS/天眼查/穆迪） |
| 高风险供应商溯源不全，缺关键矿产矿山级链路 | 整车→Tier1→Tier2→矿山全链路；高风险供应商 100% 覆盖 |

**衡量指标**：出海车型合规交付 100%（2027.7 硬节点）；管制物项问卷 100% 回收（26H1 已达 268 份）；风险尽调能力 > 欧盟官方。

**已验证的起点**：26H1 完成 268 份管制物项问卷 100% 回收，识别出 2 项法雷奥高风险管制物项、3 项含美国来源物料——证明"统一问卷 → 数据回流 → 风险识别"链路可跑通。

## 三、三轴 ✖️ 四层架构（建什么）

> 四层依赖：① 采得到信得过 → ② 端到端融数据 → ③ 看得见算得出 → ④ 根因决策回写。
> 横轴是三个价值方向，纵轴是四层能力——交叉处即每个方向在每一层要补的料。

| | **成本 C** | **效率 E** | **合规 C** |
|---|---|---|---|
| **④ 协同决策** 根因+决策+回写 | DFC 评审机制、偏差→基线回写、成本因子库自迭代 | Agent 自治/人确认、任务异常升级、流程自优化 | 风险尽调闭环、口径冲突校验、标准/方法学随法规升级 |
| **③ 分析模型** 看得见+算得出 | Should-cost 偏差、报价异常、A+B 卷积、降本机会 | 智能定价匹配、供应商匹配决策、需求归集 | 碳核算引擎、风险评分、合规差距自动评估 |
| **② 数据汇聚** 端到端+融合 | 成本因子库、报价组项、历史价格、CE 核价 | 框架统一台账、订单主数据、任务中台 | 法规主数据、排放因子库、供应商合规档案 |
| **① 数据采集** 采得到+信得过 | 大宗行情、CE 目标价直连、BOM/VSM 结构化 | MIPEC 需求、多维表格、定点台账 | 统一问卷、CAMDS/天眼查/穆迪、关键原材料碳数据 |

**关键原则：底层夯实，逐层加码。** 数据没采可信就别急着上模型，主数据没建好就别急着上决策——三轴在每一层"对齐着往上爬"，避免单轴冒进。

## 四、三轴 ✖️ 两大闭环（怎么转）

```
┌─────────────────── 实时执行闭环（秒-时级，①②③ 持续运行）───────────────────┐
│  感知数据 → 聚合汇集 → 模型判断 → 输出正常/异常                              │
│  · 成本：DB 件变更 → 总成件自动重算 → 刷台账                                 │
│  · 效率：需求归集 → 智能匹配价格 → 可自动单直接下单                          │
│  · 合规：供应商填报 → 多源校验 → 风险分级实时呈现                            │
└──────────────────────────────────────────────────────────────────────────┘
                                   │ 异常落入
                                   ▼
┌─────────────── 分析进化闭环（日-周-月级，③④②① 反向控制）──────────────────┐
│  判断/异常 → 根因 → 人机协同决策 → 执行 → 回写基线                          │
│  · 成本：偏差归因 → DFC 评审 → 成本因子库更新 → 下一轮计算用新基线          │
│  · 效率：异常件升级 → 人工处置 → 规则沉淀 → Agent 下次自动处理              │
│  · 合规：风险发现 → 整改/复核 → 标准/方法学升级 → 新法规一键复用            │
└──────────────────────────────────────────────────────────────────────────┘
```

- **实时执行闭环**让三轴日常"自己跑"，正常即直接执行，无需人介入；
- **分析进化闭环**让每一次异常关闭都沉淀为下一轮的更优基线——**让经验在系统"长住"，而不是"用一次就过期"**。

## 五、数字化建设路径（三年 × 落地节奏）

**大原则：夯底座 → 装模型 → 串闭环。** 不是继续加功能，而是补齐"数据底座→分析模型→决策闭环"，让系统从记录工具变成驱动引擎。

| | **Y1** 26H2~27H1 夯底座 | **Y2** 27H2~28H1 装模型 | **Y3** 28H2~29H1 串闭环 |
|---|---|---|---|
| **能力级** | L1 → L1.5 数据能用、流程能跑 | L1.5 → L2 系统产生判断 | L2 → L3 常规自治、异常给人 |
| **成本 C** | 报价组项沉淀 · CE 对接 · A+B 联动线上 | 卷积自动 · 报价异常检测 · 偏差归因 · 因子库骨架 | DFC 评审机制落地 · 基线自动回写 |
| **效率 E** | 框架自动化 · 合同在线 · 订单自动化 · 任务中台 | 智能匹配下单 · 多源需求归集 · Agent 半自动 | Agent 条件自治 · 低风险全自动 |
| **合规 C** | 统一问卷上线 · 多源风险整合 · 碳数据采集 | 碳核算引擎 · 风险评分模型 · 合规差距评估 | 一键多法规输出 · 口径自动校验 · 标准随法规迭代 |

### 5.1 当前落点：EP 二阶段（2026.7-9）

> 建设策略：固定主力（2 前端 + 1 后端）+ 弹性资源池；优先级 **合规 & 成本价格 > 供应商管理 > 体验提升**。

| 项目 | 周期 | 主攻轴 | 价值 |
|---|---|---|---|
| **MVPS 分类与主数据管理** | 0704-0801 | 效率（底座） | 采购分类主数据 + "分类-MVPS-人员"自动路由，替代人工派活 |
| **样件订单自动下单** | 0801-0822 | 效率 | 多来源归集 + 智能定价 + 批量下单，端到端自动闭环（释放 ~1 FTE） |
