## 1. 采购 B 点规划说明

### 1.1 什么是 B 点

**B 点 = "会自己进化的供应链大脑"。**

让大供应链从"**系统记录人决策**"的执行工具，升级为"**基于闭环供应链的业务自进化**"——
即能自动发现偏离、给出处置建议、确认执行、验证结果，并自动沉淀回写基线的管理闭环。

以 **D / Q / C / C 四域指标**牵引 + **统一分层架构**为承载，完成类比自动驾驶
**L1（辅助提示）→ L3（有条件自治）** 的能力升级。

### 1.2 四域指标牵引（DQCC）

| 域 | 牵引指标 | 核心命题 |
|---|---|---|
| **D 交付** | 100% 准时齐入（保供）+ 0 浪费库存（控库） | PSI/配置波动柔性 ≤ 周/分钟级；变更影响 ECN/PCN ≤ 小时-日级 |
| **Q 质量** | GP12 ≤ 50 PPM | 缺陷在供应商车间内被拦截；问题追溯 ≤ 工位级 + 根因回写 CC/PPAP/APQP |
| **C 成本** | 设计期锁定 70-80% 成本结构 | A+B 联动从 3-5 天 → 自动卷积；Should-cost 因子库年级自迭代 |
| **C 合规** | 出海车型合规交付 100% | 数据级合规：三统一（标准/数据/流程）+ 单一项线，风险前置管控发现 |

### 1.3 统一分层架构（四层）

> 依赖关系：① 是 ② 的数据源 → ② 是 ③ 可信的承接节点 → ③ 是 ④ 的触发条件。

```
┌──────────────────────────────────────────────────────────────┐
│ ④ 复盘决策层  根因 + 决策 + 回写                                  │
│    异常触发 → 机器自治/人机协同处置 → 标准/基线回写 ②主数据         │
├──────────────────────────────────────────────────────────────┤
│ ③ 分析模型层  看得见 + 算得出                                     │
│    DQCC 四域判断分析模型：规则 + 学习两类模型，输出正常/异常两路       │
├──────────────────────────────────────────────────────────────┤
│ ② 数据汇聚层  端到端 + 数据融合                                   │
│    主数据底座 + 业务运行时（"活主数据"）                            │
├──────────────────────────────────────────────────────────────┤
│ ① 数据采集层  链路短 + 信得过                                     │
│    供应商源头/车间/整车上线：计划·执行·质量·合规 数据可信回传          │
└──────────────────────────────────────────────────────────────┘
```

### 1.4 两大闭环

- **实时执行闭环（秒-时级）**：感知 + 数据聚合汇集 + 模型判断执行（①②③ 持续运行，正常即进入运行环执行）。
- **分析进化闭环（日-周-月级）**：判断/异常 → 根因 → 决策 → 执行 → 回写基线（③④②① 反向控制，以经验沉淀进化基线，避免"用一次就过期"）。

### 1.5 能力分级（类比自动驾驶）

| 级别 | 表现 | 小米位置 |
|---|---|---|
| L0 | 纯人工（线下 Excel） | 少量场景 |
| **L1** | **看板展示，人看了再做决策** | **← 当前大部分在这** |
| L2 | 系统主动报警，规则引擎处理简单场景 | 少量尝试 |
| **L3** | **常规场景机器自治，异常升级给人；基线持续迭代** | **← 核心场景目标** |
| L4 / L5 | 人仅例外/AI 自主运营 | 遥远 |

### 2.1 DQCC 四域 × 四层 全景

```
                          ┌─ D 交付 ─┬─ Q 质量 ─┬─ C 成本 ─┬─ C 合规 ─┐

 ─────────────────────────┼──────────┼──────────┼──────────┼──────────┤
 ③ 分析模型（看得见+算得出）│ 波动甄性 │ SPC剔值  │Should成本│ 碳核算   │ ↑
 ─────────────────────────┼──────────┼──────────┼──────────┼──────────┤
 ② 数据汇聚（端到端+融合）  │ PFEP/    │ CC-SC-CP │ 成本因子 │ 法规/排放│ ↑
                          │ P-BOM    │          │ 库       │ 因子库   │
 ─────────────────────────┼──────────┼──────────┼──────────┼──────────┤
 ① 数据采集（链路短+信得过）│ 供应商   │ 内部质量 │ 报价组项 │ ESG合规  │ ↑
                          │ 直连/API │ 部/SPC   │          │ 问卷     │
                          └──────────┴──────────┴──────────┴──────────┘
```

### 2.2 与自动驾驶的对应

| 自动驾驶 | 供应链对应 | 架构层 |
|---|---|---|
| 传感器（摄像头/雷达） | 数据采集：供应商直连、IoT、系统对接 | ① 数据采集 |
| 高精地图 + 车辆状态 | 主数据（SSOT）+ 业务运行时 | ② 数据汇聚 |
| 感知算法 | 异常检测、偏差归因、机会识别 | ③ 分析模型 |
| 决策规控 | 预警→决策→执行→基线回写 | ④ 复盘决策 |

**关键原则：底层夯实，逐层加码。** 传感器没装好就别急着上算法，地图没绘好就别急着上规控。

## 3. 实施路径

### 3.1 从 A 点到 B 点的关键路径

> **采集可信 → 汇聚补齐 → 模型判断 → 决策回写**（一件事一件事做）

1. **第一层 采集可信**：核心/风险供应商过程数据（生产计划、在制库存、SPC、内部质量部、报价组项）从"线上/末站/偏差"升级为"实时/直连/可信"——没有可信数据，后面的模型和闭环全是空转。
2. **第二层 汇聚补齐**：主数据从"分散/缺失/未结构化"升级为"完整 + 关联 + 自迭代"；业务主流程从"有功能但管理链路没串起来"升级为"端到端系统化管理"。
3. **第三层 模型判断**：从 0 到 1 搭建 DQCC 四域分析模型（波动甄性、SPC 剔值、成本偏差归因等），让数据从"展示给人看"变成"系统自动判断正常 or 异常"。
4. **第四层 决策回写**：每一次异常关闭都回写主数据/控制规则/标准基线，让系统"自我迭代"。

### 3.2 三年阶段主题

| | **Y1** 26H2~27H1 | **Y2** 27H2~28H1 | **Y3** 28H2~29H1 |
|---|---|---|---|
| **阶段主题** | **夯底座**：数据能用、流程能跑 | **装模型**：数据产生判断 | **串闭环**：系统能闭环、能进化 |
| **能力分级** | L1 → L1.5 | L1.5 → L2 | L2 → L3 |
| **交付 D** | PSI线上+中期计划 | 超纲/超规划波动预警 | 配置波动→LT 迭代回写 |
| **质量 Q** | CC/SC 关联 CP 骨架 | SPC 失控自动剔值 | 机器自治：CPK 破→冻结/8D |
| **成本 C** | 报价组项+CE对接 | 卷积自动+偏差归因 | DFC 评审机制+基线回写 |
| **合规 C** | 统一问卷+多源风险整合 | 碳核算引擎+风险识别 | 一键多法规输出+口径校验 |

### 5.2 AI Agent / FDE 模式提效

**定位**：以"采购员数字化工"形成，构建一个主动智能体（而非 Chatbot）。

- **Agent（FDE）**：理解业务目标、动态编排、处理异常路径
- **Skill（FDE & 研发）**：把确定性业务规则封装为可复用能力
- **CLI（研发）**：与 EP/MIPEC/飞书等系统的原子级 API 对接

**人机协同公式**：决策 = min(人工操作) × max(决策质量) × min(流程长度)
即：Agent 汇集信息生成草稿 → 人确认；Agent 识别风险 → 人决定是否阻断；Agent 给决策建议 → 人做最终决策。

**样件订单场景测算**：日均 200 单，每单 5 分钟，日总耗时 16.7 小时；
可自动化比例约 40%（单一供应商）→ 释放约 1 个全职人力（FTE）投入更高价值工作。
