# B 点目标

## **供应链数字化B点目标**

**B 点 = "会自己进化的供应链大脑"**：**让大供应链从"系统记录人决策"的执行工具，升级为"基于透明供应链的业务自进化”**

以 D/Q/C/C 四域指标牵引 \+ 统一四层架构，完成类比自动驾驶 L1\(辅助提示\)→ L3\(有条件自治\)的能力升级

- **D 交付**：100% 准时齐套\(保供\)\+ 0 浪费库存\(控存\)，PSI/配置波动闸控 ≤分钟级，变更影响 ECN/PCN ≤小时\-日级

- **Q 质量**：GP12 ≤ 50 PPM，缺陷在供应商车间内拦截，反向追溯 ≤工位级 \+ 根因回写 CC/PPAP/APQP

- **C 成本**：设计期锁定 70\-80% 成本结构，A\+B 联动从 3\-5 天 → 自动卷积，Should\-cost 因子库周级自迭代

- **C 合规**：出海车型合规交付100%，数据即合规——三统一（标准/数据/流程）\+ 四专项线，风险先于监管发现

这四个指标通过**四层架构，两大闭环**，实现秒\-时的**实时执行闭环**：感知\+数据融合汇聚\+模型判断执行；日\-周\-月级的**分析进化闭环**：判断/异常\-根因\-决策\-执行，以经验沉淀进化基线。

- **数据采集层： 采得到 \+ 信得过****，**从供应商源头、车间到整车下线的过程（计划、执行、质量、合规）数据**可信回传**

- **数据汇聚层**：**端到端 \+ 数据融合**，企业内部端到端价值流**系统化管理，**共建一条**跨企业 \& 跨领域**的数据底座

- **分析模型层：看得见 \+ 算得出**，DQCC四域判断分析模型**，**通过规则 \+ 学习两类模型把数据翻译成可执行的判断，模型挂决策，输出正常或异常两路，正常进入运行环执行

- **协同决策层：根因\+决策\+回写，**异常时进入根因分析，人机协同决策，让经验在系统"长住"，每一次偏差关闭即自动回写基线，以及共用的品类策略 / 供应商九宫格 / 供应商BOM// 法规基线，**让基线随业务跑随时校准，而不是"用一次就过期"**

## **供应链A 点现状**

供应链数字化今天处在三层架构\.半成品的状态，采集、汇聚、分析层都有但没有站稳，协同决策层缺失；

- **采集：**供应商产品主数据SVC刚上线（交付域数据连接31家，质量域数据连接16家），供应链直连数据可信度任重道远；合规域数据靠线下收集，ESG数据未验证，多源未整合。

- **汇聚：**数字化系统主干流程完成0→1覆盖，处于"流程线上化\+看板展示"阶段，系统能记录，但不能管控；

- **分析：**目前在采购管理、质量指标\(PPM\\DPU\\IPTV\\DPV\)、供应商数据直连等领域有部分看板，数据分析过程中嵌套了部分规则模型用于预警

- **决策：**闭环和基线自进化为0**。**一次 PSI 超量纲波动，线下从识别到处置数天到数周，无过程记录；一次质量反向追溯，人工排 VIN → 批次 →工位 数小时到数天，归因分析全靠人；LT / 安全库存 / LCR / 缺陷库都是静态数字，"用一次就过期"；合规交付物互不衔接，口径冲突无校验。

## **3\.【A→B 解法】**

- **数字化模式变革：**转变数字化模式，**从响应业务需求做功能**，**到驱动业务自迭代**；**从解决具体问题、到建立"快速闭环验证 \+ 沉淀基线"的进化机制**。

- **关键路径\(四层架构 → 七件事\)：采集可信→汇聚补齐→模型判断→决策回写**

    - **第一层：采集可信**

        - **供应链数据采集\&可信**：通过SIE新品量产导入，供应商主数据进入SVC系统、产线生产数据API无感连接进企业数据湖，同时与企业运行数据结合实时预警数据可认度风险；合规数据统一问卷在线发放 \+ 多源风险整合\(CAMDS/天眼查/舆情\)

    - **第二层：汇聚补齐**

        - **主数据底座补齐**：单一主数据源治理\(品类/MVPS、CC\-SC关联CP、供应商画像九宫格、PFEP、Should\-cost因子库、P\-BOM、、法规主数据库、排放因子库\)

        - **主价值链流程系统化**：PSI线上化、预测和主计划管理、供应商产能\&供应管理、关键二级件管理、品类管理、A\+B联动、供应商绩效评价、尽调/碳足迹/电池护照三专项线流程在线化

    - **第三层：模型判断**

        - **分析判断模型**：PSI/配置波动闸控分析、Should\-cost偏差分析、三道质量门SPC分析、碳核算\+合规差距评估

        - **归因决策模型**：反向追溯样板\(VIN→工位→变化点→上游批次→CC/PPAP/APQP 回写\)\& 红黄牌触发

    - **第四层：决策回写**

        - **基线自进化**：因子库\(Should\-cost因子/材料基准价\)、PFEP\(LT/安全库存/LCR/拉动策略\)、CC/CP、供应商质量档案、法规标准/排放因子库——周期性校准\+事件触发更新

        - **ECN/PCN变更联动：** 事件总线统一 \& 供应链影响分析模型 \& 调度/价格/检验策略自动联动

- **交付域：**

供应商生产计划、在制、库存数据直连刚起步，可信度低——拿到的数据不敢直接用来做决策。

- **成本域：**

- **合规域：**

供应商ESG数据靠线下问卷，获取少且未验证；CAMDS/天眼查/舆情三源数据未整合；关键原材料碳数据缺失；不同部门重复采集同一供应商。

    - **交付域**：计划不闭环

    产销计划以线下手工为主，无数字化支撑。

    GP12/OQC/IQC三道质量门口径未贯通，各做各的标准。

    首件确认仍在线下。

    - **成本域**：成本不闭环

    成本没有作为一条独立价值流设计过——从整车目标到预实闭环，散落在各系统各功能里。

    降本无在线跟踪，设计期无成本介入机制。

    - **成本域**：合规不闭环

    合规没有作为一条独立价值流设计过——法规按维度拆分各做各的，4项问题已暴露（协调量大、多头重复、标准不统一、数据不可信）

#### 1\.2\.3 分析模型层：以数据看板为主，分析链条不够深，看到问题但闭不了环

大数据团队已围绕各业务域搭建BI看板体系，并在数据分析过程中嵌套了部分规则模型用于预警。

但看板能"展示"，不能"指导执行"——缺的是从分析结论到执行系统的闭环联动。

- **闭环不足：**

|应有能力|现状|分领域|
|---|---|---|
|阈值超限 → 自动预警 → 触发处理流程|只展示数字，人看到再决策|- **交付域：**<br>PSI偏差人工计算预警，产供被动接收解决。<br>齐套计算计划下达后不再实时计算。<br>ETA追踪可视，但异常触发后无自动调度/闸控能力。<br>- **质量域：**<br>SPC部分场景有数据采集能力，但缺自动判异和行动闭环。<br>反向追溯靠人工排查（VIN→工位→批次→根因全程手动）。<br>红黄牌触发规则未数字化，缺陷聚类靠经验。<br>- **成本域：**<br>无任何成本分析模型。<br>A\+B联动靠线下手工卷积。<br>预实偏差无法归因，降本机会识别靠经验。<br>- **合规域：**<br>法规变化靠人工跟踪，无系统性响应；<br>各法规交付物独立手工编制，口径冲突无校验；<br>合规证明各做各的无法复用。|
|趋势分析 → 提前干预建议|除少量场景（如SPC）外，无系统化分析模型，事后复盘为主||
|分析结论 → 执行落地 → 验证关闭|看板与执行系统割裂，无闭环||

- **共性根因：** 

主数据不全 \+ 采集范围有限，看板的覆盖面和准确度撑不起"管理抓手"的定位。

#### 1\.2\.4 协同决策层：闭环缺失，基线自进化为0

当前无任何异常→归因→决策→基线回写的闭环机制：

- **交付域**：PSI偏差人工计算预警，产供被动接收解决；齐套异常无自动调度/闸控能力。

- **质量域**：反向追溯靠人工排查（VIN→工位→批次→根因全程手动），红黄牌触发规则未数字化。

- **成本域**：无任何成本分析模型，预实偏差无法归因。

- **合规域**：合规交付物各做各的（尽调/碳足迹/电池护照/禁限用互不衔接），口径冲突无校验。

- **共性**：LT/安全库存/LCR/缺陷库/CP等基线数据都是静态数字，无自进化机制。

## 二、B点目标愿景和关键路径

1. **核心结论**：

B点是让大供应链从"**系统记录人决策**"升级为"**基于透明供应链的业务自进化"\-\-即能自动发现偏离、给出处置建议、确认执行、验证结果自动沉淀回基线的管理闭环**——以D/Q/C/C 四域指标牵引 \+ 统一四层架构为承载，完成L1→L3的能力升级。

架构逻辑：①②③是运行时（持续运行），④是协同决策（异常触发→决策→回写主数据）。

2. **四域指标牵引：**

    - **D 交付**：100%准时齐套（保供）\+ 0浪费库存（控存）—— 6道关键控制点主动管控波动

    - **Q 质量**：GP12 ≤ 50 PPM —— 左移 \+ 双层防线（过程/实物）\+ 归因闭环 \+ 红黄牌档案

    - **C 成本**：设计期锁定70\-80%成本结构 —— Should\-cost标尺驱动，设计期锁结构、量产期守偏差、基准持续更新

    - **C 合规**：出海车型合规交付100% —— 三统一\+四专项线\+数据即合规，风险先于监管发现，系统自证清白

3. **统一四层架构升级：**

    - **① 数据采集**：扩面 \+ 可信回传（供应商直连、IoT、内部质量门、工艺参数、ESG合规问卷）

    - **② 数据汇聚**：主数据底座 \+ 业务运行时态（CC/SC分级关联CP、报价细项、品类/MVPS、Should\-cost 因子库等"活主数据"）

    - **③ 分析模型**：异常检测 / 偏差归因 / 机会识别 / 合规差距评估——持续运行，发现偏离即上升决策

    - **④ 决策闭环**：异常触发→机器自治/人机协同处置→标准/基线回写②主数据，每次关闭都让下一轮运行基准更优

4. **能力优先补齐**（按层×域展开）：

    - **采集可信（①层）**

        - **D 交付**：供应商生产计划\+在制\+库存数据100%可信回传

        - **Q 质量**：Top核心/风险供应商关键工序参数\+SPC\+首件\+内部质量门\+缺陷数据回传

        - **C 成本**：CE对接（目标价\+核价）\+ 大宗行情自动订阅

**四层架构：**采集可信→汇聚补齐→模型判断→决策回写

- **数据采集可信**：核心/风险供应商的过程数据（生产计划、在制库存、SPC、内部质量门、报价细项）从"线下/末站/参差"升级为"实时/直连/可信"——没有可信数据，后面的模型和闭环全是空转

- **数据汇聚补齐**：主数据从"分散/缺失/未结构化"升级为"完整\+关联\+自迭代"，业务主流程从"有功能但管理链路没串起来"升级为"端到端系统化管理"——是所有上层模型与闭环的基准

- **分析模型判断**：从0到1构建DQCC四域分析模型（波动闸控、SPC判异、成本偏差归因等），让数据从"展示给人看"变成"系统自动判断正常or异常"——有判断才有闭环的触发条件

- **决策闭环回写**：每一次异常关闭都回写主数据/控制规则/标准基线——让系统"自我迭代"

### 2\.2 建设方向

**核心变化：不是继续堆功能，而是补齐"数据底座→分析模型→决策闭环"，让系统从记录工具变成驱动引擎。**


**设计理念：把供应链数字化当自动驾驶系统来设计，实现L3人机自治。**

#### 自动驾驶 vs 供应链数字化

|---|---|---|

|感知算法|异常检测、偏差归因、机会识别|③ 分析模型|
|决策规控|预警→决策→执行→基线回写|④ 协同决策闭环|

#### 当前处于L1，目标核心场景到L3

|级别|供应链表现|小米位置|
|---|---|---|
|L0|线下Excel，纯人工|少量场景|
|**L1**|**看板展示，人看了再决策**|**← 大部分在这**|

|L5|AI自主运营|\-|

#### 从L1到L3要补的四件事

|缺什么|类比|建设方向|
|---|---|---|
|传感器不够|摄像头少、盲区大|①层：扩采集范围，提数据质量和实时性|

**关键原则：底层夯实→逐层叠加。** 传感器没装好就别急着写算法，地图没画好就别急着上规控。一层一层往上叠。

2. **关键控制点**

    > 应对 SKU 量大 \+ PSI 动 \+ RS 抖
    > 
    > 

    - **PSI/配置波动闸控**（秒\~分钟级）：超量纲/超规则波动即时拦截，超规则的拒收或退回上游重新决策。

3. **核心控制点**

    在SKU量大 \+ PSI 总量变 \+ RS配置波动的综合情况下，供应链不能只被动吸收抖动，必须主动控制波动规则，同时做好分层分级策略，有6 个关键控制点：

    1. **PSI/配置波动闸控**：PSI超量纲/配置比例超规则波动时即时拦截，超规则的拒收或退回上游重新决策，不接收、不排产、不释放供应商。

    3. **更影响分析 ECN/PCN**：ECN/PCN/EWO变更发布后系统自动计算采购在途/库存/产能影响面，影响面未评估完成不允许执行变更。

    4. **排产/调度重排**：插单/改换单/产能缺口时APS自动重排并更新承诺交付日期，重排结果自动同步供应商要货计划，人工只做例外确认。

    5. **运输ETA实时风险**：在途ETA预计超MRD红线时自动触发路由切换或启用备份供应商，MRD已不可挽回时自动上升至排产重排。

    6. **标准沉淀·规则进化**：超规则波动事件按周/月统计后反推PSI端和RS端收敛，PFEP/LT/安全库存自动更新，下周期生效。

这把标尺叫 **Should\-cost（应该成本）**——从功能→工艺→材料→工时/费率/良率逐层拆出"理论该花多少"，是后续所有穿透议价、价格联动、偏差归因的共同基准；它必须和"系统选型/DFC评审"在 M4 一起完成 2 道采购×研发握手，这是 C 域唯一逼采购离开报价单、走进设计评审的强制对齐机制。进入量产期之后，5 个算子分两段守岗——**A/B/C 是算尺给穿透力**（设计成本预评估、报价结构异常、价格联动），**D/E 是监尺给追溯力**（降本机会、预实偏差）；所有结果通过 **④ 基线回写**持续更新 ②a "成本因子/基准库"——这是 SVG 上**唯一带 ⟳ 标记的活主数据**，让 Should\-cost 持续更新。

3. **关键控制点：沿价值链选出真正卡住成本命运的闸口**

    1. **约束**：

    70\-80%成本在设计期锁定，但采购当前只在量产期介入定价。等报价单出来再谈，已经晚了。

    > **锁成本的窗口在左段（设计期），花力气的动作全在右段（量产期）。**
    > 
    > 

    1. **6个关键控制点（对应④协同决策·闭环执行）**

        1. **整车目标成本→分解线上化**（⚠️待CE共创）

        新车型K0启动时，整车目标→系统→总成→零件逐级拆解线上化。目前CE线下做无系统支撑，是成本管理链路的"第一公里"缺失。

        2. **DFC成本评审闸**（M4节点）

        M4节点采购必须带Should\-cost进设计评审，功能/方案/成本三方同口径对齐。不对齐不放行定点。这是把成本管控能力从量产期往设计期推的唯一强制机制——70\-80%成本在这个节点锁定。

        3. **穿透议价决策**（定点期）

        供应商报价必须拆到材料\+制造\+管理\+利润\+物流，拆不开的不进比价池。穿透既是谈判武器（知道哪里贵），也是因子库的数据来源——每一次穿透都在给基准库喂数据。

        4. **A\+B联动确认\+台账刷新**（量产期）

        DB件调价后，总成价格自动重算、自动触发确认流程、自动刷新台账。目标是断掉"人算一次要3\-5天、涉及数千总成件、漏联动没人知道"的隐患。

        5. **降本立项\+目标分解**（量产期）

        基于降本机会清单量化空间（大宗行情vs合同价、跨供价差、VAVE验证、模具到期剥离），立项→分解到品类/供应商→在线跟踪达成。不再靠采购员经验和供应商主动提案。

        6. **偏差处置\+基线校准**（季度/年度）

        目标价vs实际价vs应该价三线拉通，偏差自动归因到设计变更/材料波动/工艺损耗/份额变化四个维度。不是看一个"偏差率"数字，而是知道钱多花在哪、谁的责任、能不能追回。每一轮归因结果回写因子库，校准材料基准价/工时/良率系数。

4. **偏差分析：**

基于关键控制点进行差距分析：

**A点是"执行视角的采购流程工具"**——询报价→定点→签约→结算链路能跑通，但成本没有作为一条独立价值流被设计过。系统记录采购动作，不管控成本结果。

**B点是"Should\-cost标尺驱动的全生命周期成本闭环"**——设计期锁结构、量产期5算子看偏差、基线回写让标尺基准自进化。

跨度对应自动驾驶L1→L3：从"人算价格、系统记账"到"系统算价格、人管例外"。要补的不是更多采购流程，而是把 **②a成本因子基准库、③ 5算子计算能力、④基线回写闭环** 三块做到可运行。

#### 2\.3\.4 供应链合规（C）

1. **核心结论：**

合规不是"交付前补材料"，是**在源头被体系化采集 \+ 在多法规被统一复用 \+ 被监管变化持续驱动迭代**出来的。

供应链合规领域以 **2027年7月出海车型合规交付 100%** 为硬节点牵引，承载「**三统一（标准/数据/流程）\+ 四条专项线（尽调/碳足迹/电池护照/禁限用物质）\+ 风险先于监管发现 \+ 数据一次采集多场景复用**」

**终局目标**：从人工举证 → 系统自证 → **数据即合规**。

架构逻辑：①②③是运行时（采集→汇聚→分析持续运行），④是协同决策闭环（法规变化/风险事件触发→评估→回写②主数据\+①采集策略）。

2. **5 个关键控制点**

    - **出海准入闸**：四条专项线交付物全部就位才放行出口——缺一项不进入出口计划，以电池法案为核心，合规铁三角为组织

    - **统一标准标尺**：问卷 \+ 方法学 \+ 排放因子库——各部门共用一把尺子，"一次采集，多场景复用"的公共基座

    - **供应链多层级溯源** ★：关键矿产（钴/锂/镍）\+ 轮胎 \+ 皮革，整车→Tier1→Tier2→矿山完整链路——事前预防、事中举证、事后补救

    - **碳核算线**：电池碳足迹声明（三方认证）\+ 整车LCA \+ CBAM申报——从数据采集到三方认证的全链路；电池护照碳足迹公开后需确保至少行业中游

    - **风险监控闭环**：整合CAMDS \+ 天眼查 \+ 舆情监控，风险背调能力 \> 欧盟官方——先于监管方发现问题并解决

3. **优先补齐**（按依赖顺序）

    - **先①采集可信**：统一问卷上线（一次发放覆盖3类政策）\+ 关键原材料（钢/铝/塑料/镍/钴/锂）供应商数据获取 \+ 多源风险数据整合（CAMDS\+天眼查\+舆情）\+ 高风险供应商100%覆盖

    - **并行②汇聚补齐**：

        - 法规主数据结构化 \+ 排放因子库初始化 \+ 供应商合规档案多维化；

        - 尽调4步循环在线化 \+ 碳足迹5步循环流程化 \+ 电池护照数据定义 \+ 管理流程 \+ 尽调体系文件交付

    - **再③模型判断**（①②就位后）：碳核算引擎（条件最先满足）→ 风险评分模型（多源整合后）→ 合规差距自动评估

    - **最后④决策回写**（③就位后）：三方认证获取（2027硬节点）→ 电池护照三方验证 → 合规交付物自动集成（一套数据多法规输出）→ 口径冲突自动校验 → 风险监控常态化\+标准迭代回写

|**① 数据采集**|供应商数据靠线下收集少且未验证（能力不足\+缺程序文件）；<br>不同部门重复采集同一供应商（浪费供应商人天）；<br>CAMDS/天眼查/舆情数据未整合|统一问卷在线发放\+回收\+自动校验；<br>关键原材料（钢/铝/塑料/镍/钴/锂）供应商数据全获取；<br>多源数据整合（CAMDS\+天眼查\+舆情）；<br>高风险供应商100%覆盖|最高：统一问卷\+关键材料数据获取|

2. **建设路径依赖关系：**

    1. **数据采集可信（①层为主）**

        1. 统一问卷上线：整合尽调\+碳足迹\+ESG评级数据需求，一次发放覆盖3类政策，避免同一供应商被多次重复调查

        2. 关键原材料供应商碳数据获取：钢/铝/塑料/镍/钴/锂，钢铝优先（支撑CBAM碳关税成本评估）

        3. 多源风险数据整合：CAMDS（禁限用物质）\+ 天眼查（工商/司法风险）\+ 舆情监控，打通三源数据通道

        4. 高风险供应商100%覆盖：关键矿产（钴/锂/镍）\+ 轮胎 \+ 皮革，清单确认→问卷全覆盖→数据回收校验

    2. **夯实基础补功能 \+ 建底座（②层为主）**

        1. 法规主数据结构化：原文引用→要求解读，各部门有法可依（②a层）

        2. 排放因子库初始化：ecoinvent/DEFRA/行业特定因子，先用文献数据填充"够用的初版基线"（②a层）

        3. 供应商合规档案多维化：从仅注册信息→尽调状态/碳数据/禁限用/矿产溯源/风险等级全维度（②a层）

        4. 电池护照字段定义 \+ 数据来源映射（2026年7月底）→ 数据采集模板上线 \+ 供应商填报通道打通→ 注册

        5. 尽调4步循环在线化：获取信息→审核/监督→整改→闭环验证，体系合规部牵头\+各部门本职嵌入（②b层）

        6. 碳足迹5步循环流程化：边界定义→数据采集→核算→校验→认证，整合多个涉碳政策以一套动作实现（②b层）

        7. 尽调体系文件交付（2027年硬节点）：程序文件\+标准问卷\+方法学定稿（②b层）

    3. **构建分析模型（③层为主）**

        - 碳核算引擎：因子库\+采集数据就绪后即可运行，排放因子×活动数据→碳足迹自动计算（电池\+整车LCA\+CBAM申报三个出口）

        - 风险评分模型：多源数据整合后上线，CAMDS\+天眼查\+舆情→量化风险等级→先于监管方发现问题（成本\~20万）

        - 合规差距自动评估：法规要求主数据 vs 当前完备度自动比对，输出缺口清单\+优先级建议

    4. **上闭环 \+ 三方认证（④层为主）**

        - 三方认证获取（2027年硬节点）：电池碳足迹声明认证 \+ 尽调审核报告（事前预防\+事中举证\+事后补救三阶段文件完备）

        - 合规交付物自动集成：一套数据→尽调报告/碳声明/电池护照/CBAM申报/ESG评级多法规自动输出

        - 口径冲突自动校验：同一指标在不同法规交付物中自动比对，冲突即告警（防"漂绿"舆情核心机制）

        - 风险监控常态化 \+ 标准/方法学逐步升级：法规变化→影响评估→系统适配→新版标准回写
