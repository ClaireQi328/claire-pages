> 看板文件：`rfq-analysis-dashboard.html`

---

## 一、基础概念

### 1.1 三种分析粒度

本看板从粗到细分三个层级，每一层回答一个核心问题：

```
┌─────────────────────────────────────────────────────┐
│ L1 · RFQ 维度                                        │
│ "有多少报价包？整体分布如何？"                           │
│ 输入：一个 RFQ 对象，不含供应商明细                      │
│ 例：26 个 RFQ、品类分布、RFQ 最高场景层级                │
├─────────────────────────────────────────────────────┤
│ L2 · RFQ + 供应商 维度                                │
│ "每个报价包里的供应商达到了什么拆解程度？"                 │
│ 输入：RFQ 对象 + 其下各供应商的最新轮次状态                │
│ 例：某 RFQ 场景4占比、品类×场景交叉表、改善/退出计数        │
├─────────────────────────────────────────────────────┤
│ L3 · RFQ + 供应商 + 轮次 维度                          │
│ "供应商在多轮报价中经历了怎样的状态变化？"                  │
│ 输入：RFQ 对象 + 其下各供应商的逐轮状态序列                │
│ 例：迁移路径、轮次间迁移图、改善评价、逐轮场景分布           │
└─────────────────────────────────────────────────────┘
```

### 1.2 数据模型

| 概念 | 标识 | 定义 |
|------|------|------|
| **RFQ** | $r$ | 一个报价包，对应一个零件/组件的采购询价，包含 1~N 轮报价 |
| **供应商** | $s$ | 参与报价的企业实体，在一个 RFQ 中可经历多轮 |
| **轮次** | $t \in \{1, 2, ..., T_r\}$ | RFQ 中的报价次序，$T_r$ 为总轮数 |
| **报价单元** | $(r, s, t)$ | 最小粒度：某个 RFQ 的某个供应商在某轮次的报价状态 |
| **品类** | $c$ | 零件所属分类：内外饰件、电池系统、电驱总成、热管理 |

### 1.3 四种报价场景

场景按拆解深度由低到高，rank 值越大越接近 SVC 目标：

| 数据键值 | 场景名称 | Rank | 含义 |
|----------|----------|:----:|------|
| `场景1` | 未拆解报价明细 | 1 | 供应商未做任何拆解，按整件报价 |
| `场景2` | 自行拆解报价明细 | 2 | 供应商自行拆解到子件，但未按 SVC 结构 |
| `场景3` | 按SVC BOM结构报价 | 3 | 供应商按 SVC BOM 层级拆解报价 |
| `场景4` | 按SVC BOM+VSM报价 | 4 | 供应商按 SVC BOM+VSM 维度报价 |
| `退出` | 中途退出 | — | 供应商在后续轮次不再参与报价 |

### 1.4 核心函数定义（全文复用）

| 函数 | 输入 | 定义 |
|------|------|------|
| $\text{rank}(状态)$ | 场景键值 | 场景1→1, 场景2→2, 场景3→3, 场景4→4 |
| $\text{last}(s)$ | 供应商 $s$ | $s$ 在最新轮次中的状态（若轮次数 < $T_r$ 且末轮为退出则取退出前的最后一轮） |
| $A_r$ | RFQ $r$ | $r$ 的活跃供应商数 = 最新轮次未退出的供应商数 |
| $C_{r}^{(k)}$ | RFQ $r$, 场景 $k$ | $r$ 中最新轮次处于场景 $k$ 的供应商计数 |
| $U_{r}$ | RFQ $r$ | $r$ 的总报价单元数 = $\sum_{s \in r} \text{count\_valid\_rounds}(s)$ |

## 二、L1 · RFQ 维度（纯 RFQ 级别的统计）

> **分析粒度**：一个 RFQ 作为不可拆的整体  
> **回答的问题**：全局有多少报价包？品类分布如何？RFQ 整体达到什么层级？

### 2.1 指标总览

| 指标 | 公式 | 看板位置 |
|------|------|----------|
| RFQ 报价包总数 | $\sum 1$ | 全局统计卡片 |
| 覆盖供应商总数 | $\text{count\_distinct}(s.\text{name})$ | 全局统计卡片 |
| 按品类 RFQ 分布 | $\forall c, \text{count}(r \mid r.\text{cat} = c)$ | 隐含在品类交叉表中 |
| RFQ 最高到达层级分布 | 见 2.2 | RFQ维度四场景环形图 |
| RFQ 按轮次数分布 | $\text{count}(r \mid T_r = t)$ | 隐含在明细表中 |

### 2.2 RFQ 最高到达层级

对每个 RFQ，取所有活跃供应商的最新轮次中 $rank$ 最高的场景，作为该 RFQ 的"最高到达层级"：

$$
\text{RFQ最高层级}(r) = \max_{\substack{s \in r \\ s.\text{last} \neq \text{退出}}} \text{rank}\bigl(s.\text{last}\bigr)
$$

然后将 RFQ 归入对应类别：

| 归入类别 | 判定条件 | 环形图颜色 |
|----------|----------|:----------:|
| 达到 BOM+VSM 报价 | @sup 中至少 1 家末轮为场景4 | `#22c55e` |
| 达到 BOM 结构报价 | 无场景4 但至少 1 家末轮为场景3 | `#3b82f6` |
| 达到自行拆解 | 无场景3/4 但至少 1 家末轮为场景2 | `#f59e0b` |
| 停留在未拆解 | 所有活跃供应商末轮均为场景1 | `#94a3b8` |

$$
\text{占比}_i = \frac{\text{归入第}i\text{类的RFQ数}}{\text{RFQ总数}} \times 100\%
$$

**数据来源**：此指标仅依赖每个 RFQ 下供应商的 `last` 状态，不进入逐轮明细。

---

### 2.3 L1 各指标间的关系

```
RFQ总数 (26)
  ├── 按品类拆分 → 内外饰件(9) + 电池系统(7) + 电驱总成(5) + 热管理(5)
  ├── 按最高层级 → BOM+VSM(X) + BOM结构(Y) + 自行拆解(Z) + 未拆解(W)
  └── 按轮次数  → 2轮(XX) + 3轮(YY)
```

L1 不涉及任何供应商粒度的占比计算，不涉及任何轮次间迁移分析。

## 三、L2 · RFQ + 供应商维度（报价包 × 供应商，仅看最新轮次）

> **分析粒度**：RFQ 下的每个供应商，只取**最新完成轮次**的状态  
> **回答的问题**：每个报价包里哪些供应商达到了目标？各品类整体表现如何？

### 3.1 指标总览

| 指标 | 公式 | 看板位置 |
|------|------|----------|
| 全局四场景供应商占比 | 见 3.2 | 全局统计卡片 (6 KPI) |
| 全量报价单元场景分布 | 见 3.3 | 全量报价单元环形图 |
| 各品类四场景供应商数 | 见 3.4 | 品类 × 场景交叉统计表 |
| 各品类场景归一化占比 | 见 3.5 | 各品类四场景堆叠柱状图 |
| 单 RFQ 场景4占比 | 见 3.6 | RFQ 明细表、散点图 Y 轴 |
| 单 RFQ 四场景供应商计数 | 见 3.7 | RFQ 明细表、RFQ 检索表 |
| RFQ 供应商数 vs 场景4占比 | 见 3.8 | 散点图 |

### 3.2 全局四场景供应商占比（L2 核心指标）

将每个 RFQ 的各个供应商按最新轮次状态汇总到全局：

$$
P_k^{(全局)} = \frac{ \displaystyle \sum_{r \in RFQ} C_r^{(k)} }{ \displaystyle \sum_{r \in RFQ} A_r } \times 100\%, \quad k \in \{1,2,3,4\}
$$

其中：
- $C_r^{(k)}$ = RFQ $r$ 中最新轮次处于场景 $k$ 的供应商数
- $A_r = C_r^{(1)} + C_r^{(2)} + C_r^{(3)} + C_r^{(4)}$（排除退出）

**计算示例**（假设 26 个 RFQ、48 个供应商·次）：
- $P_4 = 55.1\%$ → 超半数供应商已覆盖 VSM（38个供应商×最高轮次 / 69 总计）
- $P_3 = 13.0\%$
- $P_2 = 26.1\%$
- $P_1 = 5.8\%$

**L1 → L2 跃迁**：L1 只知道「某个 RFQ 有供应商达到场景4」，L2 才知道「该 RFQ 里到底有几家达到场景4、占多少比例」。

### 3.3 全量报价单元场景分布（环形图）

每个活跃供应商的最新轮次视为一个"报价单元"。按场景分组统计：

$$
U_k = \sum_{r \in RFQ} \sum_{s \in r} \mathbb{1}\bigl[ s.\text{last} = k \bigr], \quad k = 1,2,3,4
$$

$$
\text{占比}_k = \frac{U_k}{U_1 + U_2 + U_3 + U_4} \times 100\%
$$

**与 L1 最高层级环形图的区别**：L1 环形图计 RFQ 个数（26），L2 环形图计供应商×最高轮次报价单元个数（69）。注意：全部报价单元（所有轮次累计）为 161 个。L2 仅统计每个供应商的最高轮次状态，不含中间轮次。

| 维度 | L1 环形图 | L2 环形图 |
|------|-----------|-----------|
| 粒度 | RFQ | 报价单元 |
| 计数对象 | RFQ 最高层级 | 供应商最新状态 |
| 举例 | 某 RFQ 有 1 家场景4，仍计为「达到 BOM+VSM」 | 该 RFQ 的 5 家供应商各计一次 |

### 3.4 品类 × 场景交叉统计表

按品类聚合 L2 数据。不是按 RFQ 平均，而是**将品类下所有 RFQ 的供应商池合并后计算**：

| 列 | 公式 |
|----|------|
| 品类 RFQ 数 | $\text{count}(r \mid r.\text{cat} = c)$ |
| 供应商数 | $\text{count\_distinct}(s.\text{name} \mid r.\text{cat} = c)$ |
| 场景 k 供应商·次 | $\sum_{r.\text{cat}=c} C_r^{(k)}$ |
| 场景 k 占比 | $\frac{\sum_{r.\text{cat}=c} C_r^{(k)}}{\sum_{r.\text{cat}=c} A_r} \times 100\%$ |

### 3.5 各品类四场景供应商归一化占比（堆叠柱状图）

将 3.4 中的占比以堆叠柱状图呈现，每根柱子 = 100%：

$$
\text{堆叠占比}_{c,k} = \frac{\sum_{r.\text{cat}=c} C_r^{(k)}}{\sum_{r.\text{cat}=c} A_r} \times 100\%
$$

### 3.6 单 RFQ 场景4占比

每个 RFQ 的 BOM+VSM 覆盖率：

$$
P_{\text{场景4}}(r) = \frac{C_r^{(4)}}{A_r} \times 100\%
$$

用于：
- KPI 卡片中的全局均值（3.2 的分解到 RFQ 层面取平均）
- RFQ 明细表的进度条
- 散点图的 Y 轴
- 检索表的占比列

### 3.7 单 RFQ 四场景供应商计数

直接输出 $C_r^{(1)}, C_r^{(2)}, C_r^{(3)}, C_r^{(4)}$，用于：
- RFQ 明细表各场景列（tag 标签）
- RFQ 检索表各场景列（tag 标签）

### 3.8 RFQ 供应商数 vs 场景4占比散点图

| 维度 | 取值 |
|------|------|
| X 轴 | $\text{supplier\_count}(r)$ — 该 RFQ 的供应商数量 |
| Y 轴 | $P_{\text{场景4}}(r)$ — 同 3.6 |
| 气泡大小 | $U_r$ — 该 RFQ 总报价单元数（各供应商各轮次有效状态累计）|
| 颜色 | 按品类着色 |

> 气泡大小已涉及到 L3 数据（轮次数），但 X/Y 轴仍是纯 L2 指标。

### 3.9 L2 各指标间的层级关系

```
全局四场景占比 (3.2) ← 上游聚合自——
  ├── 单RFQ四场景计数 C_r(k) (3.7) ← 每个RFQ独立计算
  │     ├── 单RFQ场景4占比 (3.6) → KPI均值、散点图、进度条
  │     └── 品类场景占比 (3.4/3.5) → 按品类聚合
  └── 全量报价单元统计 (3.3) → 环形图
```

L2 的下钻前提：需要进入 L3 才能解释「为什么某个 RFQ 的场景4占比低」，比如看供应商在逐轮中卡在哪个节点。

## 四、L3 · RFQ + 供应商 + 轮次维度（全轮次时间序列）

> **分析粒度**：每个供应商的每一轮报价状态，形成完整时间线  
> **回答的问题**：供应商在哪一轮发生转变？改善路径是什么？哪些轮次是关键节点？

### 4.1 指标总览

| 指标 | 公式 | 看板位置 |
|------|------|----------|
| 单 RFQ 逐轮场景计数 | 见 4.2 | RFQ 详情 — 逐轮网格 |
| 供应商变化路径 | 见 4.3 | RFQ 详情 — 供应商明细表 |
| 改善/退出/稳定评价 | 见 4.4 | RFQ 详情 — 改善评价列 |
| RFQ 改善供应商数 | 见 4.5 | RFQ 明细表、检索表 |
| RFQ 退出供应商数 | 见 4.6 | RFQ 检索表 |
| 轮次间迁移统计 | 见 4.7 | RFQ 详情 — 迁移柱状图 |
| 全局改善趋势汇总 | 见 4.8 | 隐含在明细/检索表中 |

### 4.2 单 RFQ 逐轮场景计数

对 RFQ $r$ 的第 $t$ 轮（$t = 1,2,...,T_r$），统计每个场景的供应商数：

$$
N_{r,t}^{(k)} = \sum_{s \in r} \mathbb{1} \bigl[ s.\text{rounds}[t] = \text{场景}k \bigr]
$$

在详情面板中以轮次列卡片展示，每列显示该轮下各供应商的状态（dot 颜色 + 短标签）。

### 4.3 供应商变化路径

将供应商 $s$ 在 RFQ $r$ 中的有效轮次串联为路径字符串：

$$
\text{路径}(s) = \text{short}(s.\text{rounds}[0]) \to \text{short}(s.\text{rounds}[1]) \to \cdots \to \text{short}(s.\text{rounds}[n])
$$

其中 $\text{short}$ 将场景键值映射为短标签（BOM+VSM / BOM结构 / 自行拆解 / 未拆解），退出节点不纳入路径。

**示例**：
- `自行拆解 → BOM结构 → BOM+VSM` 表示供应商逐步改善
- `BOM+VSM → BOM+VSM → BOM+VSM` 表示全程稳定

### 4.4 供应商改善评价（四分类）

基于全轮次序列的综合判定：

| 评价 | 判定条件 | 标签颜色 |
|------|----------|:--------:|
| **全程稳定** | $\forall t, s.\text{rounds}[t] = \text{场景4}$ | 绿色 |
| **已改善** | $s.\text{rounds}[T] = \text{场景4} \land s.\text{rounds}[0] \neq \text{场景4}$ | 绿色 |
| **未改善** | $s.\text{rounds}[T] \neq \text{场景4} \land s.\text{rounds}[T] \neq \text{退出}$ | 黄色 |
| **中途退出** | $s.\text{rounds}[T] = \text{退出}$ | 红色 |

### 4.5 RFQ 改善供应商数

统计一个 RFQ 中首轮 → 末轮 rank 提升的供应商数：

$$
\text{ImprovedCount}(r) = \sum_{s \in r} \mathbb{1}\bigl[ \text{rank}(s.\text{last}) > \text{rank}(s.\text{first}) \land s.\text{last} \neq \text{退出} \land T_r \geq 2 \bigr]
$$

### 4.6 RFQ 退出供应商数

$$
\text{DroppedCount}(r) = \sum_{s \in r} \mathbb{1}\bigl[ s.\text{last} = \text{退出} \bigr]
$$

### 4.7 轮次间迁移统计

对 RFQ $r$，扫描每个供应商的相邻轮次对，提取发生变化的迁移：

$$
\text{MigrationPair}(s) = \bigl\{ (s.\text{rounds}[i-1],\ s.\text{rounds}[i]) \ \big|\ i=1..n,\ s.\text{rounds}[i-1] \neq s.\text{rounds}[i] \bigr\}
$$

聚合到每个迁移对的次数：

$$
\text{MigrationCount}(a \to b) = \sum_{s \in r} \mathbb{1}\bigl[ (a \to b) \in \text{MigrationPair}(s) \bigr]
$$

以横向柱状图展示，柱子颜色 = 目标场景的颜色。只呈现状态发生了变化的迁移，同状态不变不统计。

**典型迁移模式**：
- `未拆解 → 自行拆解` — 供应商开始配合拆解
- `BOM结构 → BOM+VSM` — SVC 推广的关键一步
- `自行拆解 → BOM结构` — 供应商接受了 SVC BOM

### 4.8 全局改善趋势汇总

将所有 RFQ 的改善/退出数据汇总，得到全平台供应商行为画像：

$$
\text{平台改善率} = \frac{\sum_r \text{ImprovedCount}(r)}{\sum_r \text{参与多轮报价的供应商总数}} \times 100\%
$$

### 4.9 L3 各指标的上下游关系

```
供应商全轮次序列 (原始数据)
  ├→ 逐轮场景计数 (4.2)  → 轮次网格面板
  ├→ 变化路径 (4.3)      → 供应商明细表「路径」列
  ├→ 改善评价 (4.4)      → 供应商明细表「评价」列
  │     └→ 改善供应商数 (4.5) → L2 RFQ明细表的「改善趋势」列
  ├→ 退出供应商数 (4.6)  → L2 RFQ检索表的「退出数」列
  └→ 迁移统计 (4.7)      → 迁移柱状图
```

> L2 中显示的改善数/退出数，本质上是 L3 的聚合产物——必须先有逐轮序列，才能判断首轮 → 末轮是否改善。

## 五、三层粒度融合总览

### 5.1 三层间的数据流

```
                    ┌────────────────────────────┐
                    │  L1 · RFQ 维度              │
                    │  26个RFQ → 按品类/层级分布    │
                    └────────────┬───────────────┘
                                 │
                    ┌────────────▼───────────────┐
                    │  L2 · RFQ + 供应商 维度      │
                    │  每个RFQ下各供应商的末轮状态    │
                    │  → 全局占比、品类交叉表、散点图  │
                    └────────────┬───────────────┘
                                 │
                    ┌────────────▼───────────────┐
                    │  L3 · RFQ + 供应商 + 轮次维度 │
                    │  每个供应商的逐轮状态序列       │
                    │  → 迁移路径、改善评价、轮次变化  │
                    └────────────────────────────┘
```

### 5.2 从看板操作映射到三层粒度

| 看板模块 | 所属层级 | 用户看到的信息 |
|----------|:------:|---------------|
| 顶部 6 个 KPI 卡片 | L1 + L2 | RFQ数(纯L1) + 四场景占比(L2) + 供应商数(L1) |
| RFQ 维度四场景环形图 | **L1** | 26 个 RFQ 的最高层级分布 |
| 全量报价单元环形图 | **L2** | 69 个供应商×最高轮次报价单元的场景占比 |
| 品类 × 场景交叉表 | **L2** | 按品类拆解各场景供应商数及占比 |
| 散点图 | **L2** | 每个 RFQ 的供应商数 vs 场景4占比 |
| 品类堆叠柱状图 | **L2** | 各品类四个场景的归一化占比 |
| RFQ 明细表 | **L2** + L3 | 场景计数(L2) + 改善趋势(L3聚合) |
| RFQ 检索表 | **L2** + L3 | 场景计数(L2) + 改善/退出数(L3聚合) |
| RFQ 详情 — 逐轮网格 | **L3** | 每个轮次各场景供应商分布 |
| RFQ 详情 — 供应商明细 | **L3** | 路径、逐轮状态、改善评价 |
| RFQ 详情 — 迁移图 | **L3** | 轮次间状态转移次数 |

### 5.3 典型分析路径（三层穿透）

从粗到细的分析流程：

```
Step 1 [L1]  看环形图 → 「热管理品类只有 X% 的 RFQ 达到 BOM+VSM」
Step 2 [L2]  看品类交叉表 → 「热管理品类场景4占比 23.5%，自拆解占比 47.1%」
Step 3 [L2]  看散点图 → 「哪些 RFQ 供应商多但场景4占比低？哪些已经覆盖？」
Step 4 [L2]  点击 RFQ 明细表行 → 跳转到检索视图
Step 5 [L3]  看该 RFQ 逐轮网格 → 「R1有3家未拆解，R2时1家改善了」
Step 6 [L3]  看迁移图 → 「主要发生在 未拆解→自行拆解 这一步」
Step 7 [L3]  看供应商明细 → 「A供应商卡在自行拆解，B供应商已到BOM+VSM」
```
