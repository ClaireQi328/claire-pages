## **1 背景与目标**

### **1\.1 背景**



制造费明细报价依赖 BOM 和 VSM 的结构状态：BOM结构OK **且** VSM审批OK时，系统自动从SVC带出数据进入明细报价，但各类场景报价数据难以收集和分析，无法验证报价细项上线后结果；业务端无法感知明细报价的真实情况。目前缺乏对以下问题的量化度量：



- 有多少供应商仍在EP端自行拆解BOM结构

- SVC BOM/VSM的覆盖率和通过率是多少

- 随着轮次推进，供应商的结构数据质量是否在改善



报价细项已支持

1. BOM NOK , VSM NOK 场景下，用户不拆解进行报价

2. BOM NOK , VSM NOK 场景下，用户自行拆解BOM结构进行报价

3. BOM OK，VSM NOK场景下，根据按照BOM结构进行报价

4. BOM OK，VSM OK场景下，根据按照BOM结构\+VSM结构进行报价

5. ~~BOM NOK，VSM OK场景不存在~~



### **1\.2 目标**

在 `供应商 × RFQ × 轮次` 粒度上建立埋点，量化BOM/VSM结构数据的来源分布与质量趋势，为SVC推广决策提供数据支撑。

### **1\.3 核心度量问题**

|**\#**|**问题**|**对应事件**|**接口**|
|---|---|---|---|
|1|有多少 供应商\\\|RFQ\\\|轮次 **未拆解BOM结构\-\-\-\-\-\-\-\-\-\-\-\-\-\-BOM单层\+BOM NOK**|bom\_self\_no\_decomposed
|2|有多少 供应商\\\|RFQ\\\|轮次 **自行拆解了BOM结构\-\-\-\-\-\-\-\-\-BOM多层\+BOM NOK**|bom\_self\_decomposed
|3|有多少 供应商\\\|RFQ\\\|轮次 **SVC BOM结构OK,VSM NOK**|svc\_bom\_structure\_ok
|4|有多少 供应商\\\|RFQ\\\|轮次 **SVC BOM 结构OK，VSM结构OK**|svc\_vsm\_structure\_ok

## **2 数据模型**

### **2\.1 报价单元**

一个 RFQ 内部的结构是：

```Plain Text
RFQ-2026-00123（前保险杠，共3轮报价）
├── 供应商A
│   ├── Round 1: BOM自拆解=是, SVC BOM=NOK, SVC VSM=NOK
│   ├── Round 2: BOM自拆解=否, SVC BOM=OK,  SVC VSM=NOK
│   └── Round 3: BOM自拆解=否, SVC BOM=OK,  SVC VSM=OK
├── 供应商B
│   ├── Round 1: BOM自拆解=否, SVC BOM=OK,  SVC VSM=OK
│   ├── Round 2: BOM自拆解=否, SVC BOM=OK,  SVC VSM=OK
│   └── Round 3: BOM自拆解=否, SVC BOM=OK,  SVC VSM=OK
└── 供应商C
    ├── Round 1: BOM自拆解=是, SVC BOM=NOK, SVC VSM=NOK
    └── Round 2: BOM自拆解=是, SVC BOM=NOK, SVC VSM=NOK
        （未进入Round 3，中途退出）
```

**最小统计单元**：\`\(RFQ, 供应商, 轮次\)\` 称为一个**报价单元**。





## **3 埋点事件定义**



### **统一触发时机**



**所有三个事件均在供应商轮次提交报价时触发**，统一埋点位置为 \`POST /api/rfq/round\-submit\`。



供应商点击"提交报价"后，系统在提交校验通过、事务提交前，快照当前轮次的BOM结构和SVC状态，根据判定条件决定触发哪些事件。一次提交可能同时触发多个事件（如既有自拆解又有SVC BOM OK），也可能一个都不触发（无结构数据）。



```Plain Text
供应商提交报价
    │
    ▼
┌─────────────────────────────┐
│  快照当前轮次状态             │
│  · BOM结构（层级、节点数）    │
│  · SVC BOM状态               │
│  · SVC VSM状态               │
└─────────────────────────────┘
    │
    ├─ BOM单层级 AND BOM≠OK → 触发 bom_self_no_decomposed
    ├─ BOM多层级 AND BOM≠OK → 触发 bom_self_decomposed
    ├─ BOM = OK  AND VSM ≠OK            → 触发 svc_bom_structure_ok
    └─ BOM = OK  AND VSM = OK             → 触发 svc_vsm_structure_ok
```



### **3\.1 事件1：bom\_self\_decomposed**



**含义**：该供应商在EP端自行维护了多层级BOM结构（SVC未提供数据时的兜底路径）。



**触发条件**：提交的BOM存在多层级（任意零件 \`parent\_part\_number\` 不为空，或存在 Level ≥ 2 的节点），**且** SVC BOM状态 ≠ OK。



```JSON
{
  "event": "bom_self_decomposed",
  "timestamp": "2026-06-17T10:30:00+08:00",
  "properties": {
    "supplier_id": "SUP-2024001",
    "supplier_name": "XX汽车零部件有限公司",
    "rfq_id": "RFQ-2026-00123",
    "rfq_type": "RFQ-Standard",
    "round_number": 1,
    "bom_total_nodes": 5,
    "bom_max_depth": 3,
    "bom_level_distribution": {
      "level_1": 1,
      "level_2": 3,
      "level_3": 1
    },
    "self_decomposed_node_count": 4,
    "svc_bom_status": "NOK",
    "svc_vsm_status": "NOK"
  }
}
```

|字段|类型|说明|
|---|---|---|
|`supplier_id`|string|供应商ID|
|`supplier_name`|string|供应商名称|
|`rfq_id`|string|RFQ编号|

## **6 数据聚合 SQL**



### **6\.1 报价单元状态判定**



```SQL
WITH unit_status AS (
    SELECT
        r.rfq_id,
        s.supplier_id,
        r.round_number,
        MAX(CASE WHEN e.event = 'bom_self_decomposed' THEN 1 ELSE 0 END)
            AS has_self_decomposed,
        MAX(CASE WHEN e.event = 'svc_bom_structure_ok' THEN 1 ELSE 0 END)
            AS has_bom_ok,
        MAX(CASE WHEN e.event = 'svc_vsm_structure_ok' THEN 1 ELSE 0 END)
            AS has_vsm_ok
    FROM rfq r
    JOIN rfq_supplier rs ON r.rfq_id = rs.rfq_id
    JOIN supplier s ON rs.supplier_id = s.supplier_id
    LEFT JOIN tracking_events e
        ON  e.properties->>'rfq_id' = r.rfq_id
        AND e.properties->>'supplier_id' = s.supplier_id
        AND e.properties->>'round_number' = r.round_number
    GROUP BY r.rfq_id, s.supplier_id, r.round_number
)
SELECT
    *,
    CASE
        WHEN has_bom_ok = 1 AND has_vsm_ok = 1 THEN '双OK'
        WHEN has_bom_ok = 1 AND has_vsm_ok = 0 THEN '仅BOM OK'
        WHEN has_self_decomposed = 1 THEN '自拆解'
        ELSE '无结构数据'
    END AS unit_scenario
FROM unit_status;
```



### **6\.2 跨轮次迁移分析**



```SQL
WITH ranked AS (
    SELECT *,
        LAG(unit_scenario) OVER (
            PARTITION BY rfq_id, supplier_id
            ORDER BY round_number
        ) AS prev_scenario
    FROM unit_status
)
SELECT
    prev_scenario AS from_state,
    unit_scenario AS to_state,
    COUNT(*) AS transition_count
FROM ranked
WHERE prev_scenario IS NOT NULL
GROUP BY prev_scenario, unit_scenario
ORDER BY prev_scenario, transition_count DESC;
```



### **6\.3 RFQ维度场景三覆盖率**



```SQL
SELECT
    us.rfq_id,
    r.rfq_name,
    COUNT(DISTINCT us.supplier_id) AS total_suppliers,
    COUNT(DISTINCT CASE WHEN us.unit_scenario = '双OK'
                        THEN us.supplier_id END) AS dual_ok_suppliers,
    ROUND(
        COUNT(DISTINCT CASE WHEN us.unit_scenario = '双OK'
                            THEN us.supplier_id END) * 100.0
        / COUNT(DISTINCT us.supplier_id), 1
    ) AS scenario_3_coverage_pct
FROM unit_status us
JOIN rfq r ON us.rfq_id = r.rfq_id
GROUP BY us.rfq_id, r.rfq_name
ORDER BY scenario_3_coverage_pct ASC;
```



### **6\.4 供应商维度覆盖率（按品类）**



```SQL
SELECT
    c.category_name,
    s.supplier_name,
    COUNT(DISTINCT us.rfq_id) AS rfq_count,
    ROUND(
        COUNT(DISTINCT CASE WHEN us.unit_scenario = '双OK'
                            THEN us.rfq_id END) * 100.0
        / COUNT(DISTINCT us.rfq_id), 1
    ) AS dual_ok_pct,
    ROUND(
        COUNT(DISTINCT CASE WHEN us.has_self_decomposed = 1
                            THEN us.rfq_id END) * 100.0
        / COUNT(DISTINCT us.rfq_id), 1
    ) AS self_decomposed_pct
FROM unit_status us
JOIN supplier s ON us.supplier_id = s.supplier_id
JOIN supplier_category sc ON s.supplier_id = sc.supplier_id
JOIN category c ON sc.category_id = c.category_id
GROUP BY c.category_name, s.supplier_name
ORDER BY dual_ok_pct ASC;
```
