环节Skill说明
① 需求导入demand-import飞书需求表 → 30 字段映射 + 校验（含预算黑名单）→ 确认页 → 引导确认 → import-json 导入
② 需求检查demand-check本地校验（必填 / 数量 / EP 账号 / 行号连续 / 日期 / 预算 / 样件用途），输出 PASS / FAIL
③ 查询分组demand-query60 天窗口 + 分组（一品一点 / 一品多点 / 无供应商）→ 生成确认页
④ 人工确认Agent 对话一品多点需选定供应商；确认动作回 AgentSpace 对话框完成（飞书卡片不可回调）
⑤ 下单demand-order按订单组合并批量下单、幂等；dry-run → 确认 → 真实下单
⑥ 通知统计daily-report群机器人通知 + 统计报告 + 工作台多维表格日志 / 进度表

三种触发方式

AgentSpace 对话框
启动任务后在窗口中交互，确认环节在这里完成（推荐日常使用）
工作流 / 定时任务
需求进度表每日 2 次刷新；需求导入推送工作日 09:30（明细 + 预览链接）
独立 Agent
需求导入 Agent 可单独运行（06-Agent-需求导入），职责单一

人工确认规则

  1. 飞书卡片无法回调交互，所有确认引导回 AgentSpace 对话框完成；
  2. 数据变更操作（导入 / 下单）必须等用户明确确认（回复「确认导入」「确认下单」）；
  3. 确认页展示无效记录关键信息：零部件号、名称、数量、预算编号/行号、申请人、到货日期、错误原因。

5常见问题
历史踩坑沉淀 —— 现象 / 根因 / 处理
导入被拒「预算在系统中不存在」
根因：预算编号未在 EP 建主数据（数据侧问题，非代码）。处理：预算侧创建后，从 config budget_blacklist 删项即恢复；当前已做本地黑名单校验，不再打无效 EP 调用。
导入被拒「预算金额必须为正数」
根因：需求表未填「样件预算总金额(不含税)」或字段映射缺失。处理：需求侧补金额；映射已修复（飞书数值型字段自动提取）。
--records 超长报错
根因：CLI 上限 1000 字符。处理：分批提交（脚本已自动分批）。
query-ready 返回 0 条
根因：窗口内无可下单需求（业务常态）。处理：属正常，等新需求导入 EP。
多维表格搜不到新日志
根因：视图过滤。处理：切换视图查看（记录实际已写入，可按 record_id 读到）。
飞书卡片无法点击确认
根因：AgentSpace 不支持卡片回调。处理：回 AgentSpace 对话框回复确认指令。
