PART 1

背景：我们在做什么

先讲清楚业务场景和拆解层级，再看数据

业务场景：报价成本透明化

汽车零部件采购中，每个零件需要供应商报价。供应商报回来一个总价，但这个总价是黑盒——材料费多少、制造费多少、利润多少，采购方看不到。

如果只看总价比价，采购方处于信息劣势。所以我们需要供应商把报价拆开，让成本结构可见。这就是"报价细项拆解"。

💡 一句话
拆解 = 把供应商报的"一口价"变成"看得见的成本结构"。拆得越深，成本越透明，谈判时越有底。

报价本身有粗细之分

在拆解之前，先要理解一个前提：供应商提交的报价本身就有粒度差异。有些报价只到中粗项（比如只拆到材料费、加工费几个大类），有些能到细项（每个零件、每道工序的成本都列出来）。报价粒度直接决定了能拆到哪个层级——给的是中粗项，L3/L4 就无从谈起。所以拆解率不只是采购方的努力程度，还受限于供应商愿意提供多细的报价。

L1-L4：拆解的四个层级

拆解是一个从浅到深的渐进过程。我们定义了四个层级：

L1
未拆解
供应商只报一个总价。成本黑盒。
材料费 ✕
制造费 ✕
权威性：无
L2
EP 自行拆解
采购员在 EP 系统自行拆出材料费。初步透明，但无外部校验。
材料费 ✓
制造费 ✕
权威性：采购员自报
L3
联动 SVC + 业务审批
联动 SVC 数据，经业务审批确认。权威性更高，但 L3 仍无制造费明细。
材料费 ✓（SVC 校验）
制造费 ✕
权威性：SVC 联动 + 审批
L4
BOM + VSM
BOM + 价值流分析，材料费 + 制造费全透明，可追溯到工序级。
材料费 ✓
制造费 ✓
工序/价值流 ✓
权威性：全透明
图 1｜L1→L4：L2 到 L3 的跃升在于权威性（SVC 联动 + 审批），L3 到 L4 的跃升在于深度（制造费 + VSM）

为什么这么定义

四个层级对应两个维度的递进：成本要素的可见度和数据的权威性。

层级数据来源材料费制造费权威性
L1供应商报总价✕✕无拆解
L2采购员在 EP 自行拆✓（自报）✕采购员个人判断
L3联动 SVC 数据 + 业务审批✓（SVC 校验）✕经审批，可追溯，权威性高
L4BOM + VSM 全拆解✓✓全透明，工序级可追溯

L2 和 L3 看到的成本要素一样（都是材料费），区别在权威性：L2 是采购员自己在 EP 里拆的，L3 联动了 SVC 数据并经过业务审批，数据更可信。L3 到 L4 的跨越则在于深度：L4 把制造费也拆开了，还能追溯到工序级。

🏭 链路已经跑通：戈尔德做到了 L4
浙江戈尔德智能悬架（减振器供应商）在 RFQ-20260518-001（MX1127B-1 被动减振器）报出了 L4-BOM+VSM，同一报价包里的汇众萨克斯、天纳克还停在 L1。这说明从 L1 黑盒到 L4 全透明，不是画在纸上的理想，是真实能跑通的——供应商肯配合细项报价、CE 做 VSM 分析，这条路就走得通。这是报告里"该做的都能做到"最直接的证据。
📌 方向是对的，但要多方协调
拆解这件事，不是采购员一个人能完成的。L2 需要采购员在 EP 操作；L3 需要联动 SVC 数据、走业务审批流程；L4 需要供应商配合提供细项报价、CE 团队做 VSM 分析。机械架构组已经跑通了整条流程（拆解率 40% + 6 个深度包），试点效果验证了可行性。后续推广需要采购、CE、供应商、EP 系统四方一起配合——方向是对的，配合机制还得慢慢建。
PART 2

指标怎么定的：从业务目标到可执行定义

指标不是拍出来的，是从业务问题倒推出来的

第一步：找到北极星

拿到 3 个月报价明细（1209 行、12 列）时，第一件事不是画图，而是问：老板到底想回答什么问题？

答案不是"拆解率是多少"，而是"报价成本透明化做到哪一步了"。拆解率只是回答这个问题的量化手段。所以北极星指标不是"拆解率"，而是"报价成本透明化程度"——拆解率是它的代理变量。

💡 这一步为什么重要
如果北极星定成"拆解率达到 X%"，团队会为了拆而拆——紧固件也硬拆、胶水也硬拆，数字好看了但没意义。定成"成本透明化"，团队自然会区分"该拆的"和"不该拆的"。

第二步：指标分层——一个金字塔

有了北极星，往下层层拆解，形成金字塔结构：

北极星
报价成本透明化（拆解是手段，不是目的）
结果指标
拆解率（该拆的都拆了吗）
过程指标
周新增拆解 · 积压数 · L2→L3+ 转化率
个体指标
采购组 × 采购员 × 品类 三维交叉

每一层回答不同问题：北极星回答"方向对不对"，结果指标回答"做到了没有"，过程指标回答"节奏跟上了吗"，个体指标回答"谁落后、哪类特殊"。老板看顶层，采购员看底层，各取所需。

金字塔是指标的分层；数据本身也要分层看。拆解率把 L2/L3/L4 合并成"已拆解"，是为了给老板一个总数；但每一层的数据我们都能单独拉出来，不是一个聚合口径盖住所有：

图 1b｜同一份数据：聚合口径（56）和分层视角（每层各多少）并存，互不冲突
层级当前包数单独看它，回答什么问题对应的动作
L1128哪些包还没动、卡在谁手里派单清积压（92 个超 1 月优先）
L244材料费拆出来了，但没走审批，权威性不够推升 L3 的候选池——深度增长就靠这一层
L310过了 SVC 审批，数据可放心用于核价作为价格参考，直接支撑 CE 核价
L42全透明标杆，证明这条路可行复制做法到同品类（戈尔德模式）

所以"已拆解 = L2+L3+L4"只是一个聚合口径，它负责让老板一眼看到整体进度；每层的数我们始终单列——L3/L4 才代表深度和权威，是下一步要重点推的。聚合口径为了好懂，分层数据为了好行动，两者并存。

第三步：定义核心指标——拆解率的三个关键决策

"拆解率"看起来简单，定义过程中有三个关键决策：

#决策点我们怎么选的为什么
1分子怎么算L2 + L3 + L4 都算"已拆解"L2 至少拆出了材料费，是及格线；只算 L3/L4 门槛太高，起步阶段没人达标
2分母怎么算按 RFQ 去重，取最高拆解层级同一 RFQ 有多轮次、多供应商，不去重会重复统计——一个包算三次，率就虚高
3时间窗怎么定ISO 周归属，OFF=1，剔除当前不完整周当周数据不稳定（还在提交中），放进去会误导——宁可少看一周，也不看错一周

数据背后的两个硬困难：RFQ 是活的，周期又长

定口径之前，先被两个现实问题卡住——它们不解决，所有周趋势都是错的：

#困难真实现象我们的解法
1RFQ 是动态变化的184 个报价包同时存在 5 种状态（已完成 102 / 询价中 63 / ENQUIRING 12 / 未发起询价 6 / 定点中 1）；状态会流转、供应商会增减、提交会跨期——同一批 RFQ，两周前的名单和现在不一样锁定周活跃度视角：不按"创建时间"累计，按最新提交时间归周，看"当周有动作的 RFQ"，而不是"当周新建的 RFQ"
2RFQ 周期特别长最早的 RFQ-20230821-004 创建于 2023-08，到 2026-06 还在提交；这 3 个月窗口里活跃的 184 个包，创建时间跨度超过 3 年——按创建时间归周会把老包全算进"历史"，当周永远显示 0归周看最新提交时间；剔除当前不完整周（还在提交中的周不进对比）；累计口径统一写"截止本周"（174 → 184 是截止值，不是当周新增）
💡 这两个困难说明一个原则
数据对象是活的（RFQ 会变）、生命周期长（跨年），口径就必须回答"每一刻它处于什么状态"。用"最新提交时间"做时间锚点，是我们在"数据在流动"和"报告要稳定"之间找到的平衡——同一份数据，任何时候跑，都得出同一个数。

这里有一个容易忽略的点：分子把 L2 算进去，意味着"采购员自己拆的"也算达标。这在中早期是合理的——先让数据有起来，再逐步推动从 L2 升到 L3（走 SVC 审批）。如果一上来就只认 L3+，大量 L2 包会变成"不达标"，打击积极性。

第四步：SMART 自检 + 口径文档化

指标定义完，用 SMART 框架自检：

维度报价拆解率是怎么满足的
S / M 明确分子 = 已拆解报价包（L2+L3+L4），分母 = 有效报价包，可精确计算，两个人算出同一个数
A 可归因通过映射表，每个包可归因到采购组、采购员——追责和派单就有着落
R 对齐业务指标直接挂钩动作：派单清积压、分层策略、SOP 复制
T 时间窗ISO 周归属、OFF=1、剔除当前不完整周——同一周只有一种数法
口径文档化口径写成代码常量（EXCLUDE 名单、去重逻辑），可复现、可审计——口径不是口头约定，是版本管理
💡 口径文档化的意义
早期口径全靠口头约定，"上周 174 个"和这周"184 个"对不上，谁也说不清差在哪。后来把口径写进代码：去重逻辑、周归属规则、不适用品类名单全是常量——数字可以被质疑，但口径必须能辩护。
PART 3

数字对不齐：发现问题

指标上了墙，三方声音却对不齐

第一版拆解率算出来：30.4%（56 个已拆解 ÷ 184 个报价包）。拿着这个数字跟业务过了一遍，结果：

业务我们很努力了「紧固件怎么拆？胶水怎么拆？我们品类特殊，这个率对我不公平。」
老板到底行不行「推了 3 个月，拆解率才 30.4%，剩下的 70% 卡在哪？」
数据我不知道「我只知道怎么算，不知道尺子本身对不对——分母里可能混着根本不该算的包。」

三方盯着同一个数字，谁都不服谁。这时候我们意识到：问题不在执行力，在指标本身。

做了一件事：把 128 个未拆解的报价包逐个过品类名，跟业务一起识别出 4 类 20 个天然无法拆解的 RFQ（紧固件 / SPR、胶水 / 胶条、色漆 / 颜色开发、软件 / 服务 / 技术要求）。剔除后：

图 2｜账面 vs 有效拆解率：差距 = 20 个"不该算进去"的品类包

指标第一次能区分"没做"和"不该做"。紧固件、胶水这些品类，物理上无法给出 BOM / VSM 拆解——把它们算进分母，等于让采购员背一个完不成的指标。

🔑 教训
指标的第一价值不是"好看"，而是公平。一把不公平的尺子，量不出真实的业务，只会让数据与业务互相怀疑。
PART 4

一个好指标的三要素

把踩过的坑，压缩成一个可以复用的判断标准
🎯
业务意义
BUSINESS MEANING

指标必须回答一个业务问题。"拆解率"回答的是：报价成本透明化做到哪一步了？没有业务意义的数字，只是统计。

📏
口径严谨
RIGOROUS DEFINITION

分子分母、去重逻辑、时间窗、边界条件必须可复现、可辩护。同一份数据，两个人必须算出同一个数。

⚡
可行动
ACTIONABLE

指标异常时，能直接指出谁、在哪、该做什么。只报"率"不报"谁落后"的报告，没人会用。

好指标 = 业务意义 × 口径严谨 × 可行动 （乘法，任一为 0 即失效）
#某一项为 0我们在哪踩过
1业务意义 = 0账面 30.4% 把紧固件 / 胶水算进分母——业务不认。数字再准也没用。
2口径严谨 = 0同一 RFQ 多轮次、多供应商重复统计，数出来忽高忽低——数字没人信。
3可行动 = 0早期只报总体率，老板问"那谁负责？"答不上来——报告被丢进抽屉。
PART 5

实战复盘：五步演进

从"报表"到"决策"，指标是怎么一步步改出来的
STEP 1从无到有：先把数据搬上墙 · 有没有

拿到 3 个月报价明细。第一件事是定义"数什么"：报价包 = RFQ 去重、取最高拆解层级 → 184 个；拆解率 = 已拆解 ÷ 报价包。产出第一版总览报表。

产出：第一个指标"拆解率"
STEP 2先把口径做严谨：让数字可信 · 准不准

指标上墙后被业务反复挑战。四个坑逐个填：

#坑问题解法
1多轮次多供应商同一 RFQ 多条记录、多个轮次RFQ 去重，取最高拆解层级
2周归属漂移跨周提交、当周数据不稳定ISO 周、OFF=1、剔除不完整周
3组织归属缺失47 名采购员无组别采购员→采购组映射表（7 组）
4数据源不可追溯手工导出 CSV 无元数据切飞书表，报告内置数据源链接
产出：口径文档化 + 可追溯数据源 + 基线对比
STEP 3指标修正：从"拆没拆"到"该拆的拆没拆" · 深不深

业务反复说"品类特殊"。认真验证——把 128 个 L1 未拆解包逐个过品类名，与业务共创识别出 4 类 20 个天然不适合拆解的 RFQ：

图 3｜不适用品类构成：物理上无法给出 BOM / VSM 拆解的品类

新指标：有效拆解率 = 已拆解 ÷（报价包 − 不适用品类）= 56 ÷ 164 = 34.1%。副产品洞察：12 个 L3/L4 深度包全部在 6/16 制造费放开后完成——能报制造费了，深度拆解才成为可能。

产出：有效拆解率 + 不适用品类清单（EXCLUDE 常量固化）
STEP 4从指标到行动：让老板知道下一步干什么 · 到行动

指标最终要能回答老板三个问题：下一步干什么、谁去做、多久见效。给业务的话也定了调——不是考核采购员，是帮大家把活干明白：先肯定成绩（机械架构组已经跑通整条流程），再一起定目标、分任务。

目标分两层：总目标——有效拆解率从 34.1% 往 50% 走（半年维度）；分层目标——紧固件 / 胶水 / 色漆等标准件品类报 L2 材料费即达标，BOM+VSM 品类（机械件 / 电子件）要求 L3+，制造费放开后推 L4 试点。标准件和深度品类，不再用一把尺子量。

72 个包

车身外饰体量最大，拆解率仅 26.4%、深度包为 0——量最大、却最浅。

这张表就是给老板的"下一步"：目标（34.1% → 50%）、责任人（派单表）、节奏（周会）都列清楚了，分层规则和口径正名把考核口径也定下来。报告不再停在"情况如何"，直接变成下周的工作安排。

产出：Insight 洞察页（先夸 → 再打 → 给方案）+ 行动蓝图（五步）
STEP 5自动化：从"做一次"到"每周做" · 快不快

🔑 最重要的一条
分析的终点不是报告，是行动。老板要的不是"情况如何"，而是"下一步怎么办、谁去做、多久见效"。
PART 6

与业务合作的三条心法

数据不是算出来的，是跟业务"处"出来的
#心法具体怎么做的
1指标是共创的采购员→采购组映射表靠业务提供（47 人→7 组）；20 个不适用品类名单是跟业务一起过的，不是数据人自嗨。业务不认的指标，等于没有指标。
2指标要可辩护"有效拆解率"为什么公平：分母里剔除了物理上无法拆的品类。当业务拿"品类特殊"当借口时，可以拿名单反问：你属于这 4 类里的哪一类？
3汇报顺序：先夸 → 再打 → 给方案先肯定：拆解从无到有、12 个深度包、机械架构组 40% 标杆、累计 142 家供应商完成 L2+；再打差距：108 个有效欠账、92 个积压；最后给四条可执行策略。业务从"被考核"变成"一起解问题"。
💡 多方协调是关键
拆解这件事需要四方配合：采购员在 EP 操作 L2 拆解、CE 团队联动 SVC 数据走 L3 审批、供应商提供细项报价支撑 L4、EP 系统提供工具和流程保障。机械架构组能跑通整条流程，就是四方配合到位的结果。后续推广车身外饰、电池组，也要先理清四方各自的职责和卡点。
PART 7

方法论：PM 视角的两件事

把实战经验，还原成可迁移的方法

① 数据分析方式：四级递进

从"是什么"到"如何持续"，每上一层，离决策近一步：

L1 描述是什么？KPI 总览、周趋势——先看清现状30.4% · 184 包 · 142 家供应商
L2 诊断为什么？组 / 人 / 品类 / 时间多维下钻车身外饰 26.4% · 三人占 30.6%
L3 处方怎么办？差距定位 → 策略输出（四条）口径正名 · 分层 · 清积压 · 复制标杆
L4 机制如何持续？自动化 + 周会 + SOP 固化skill 一条命令 · 每周更新 · 固定链接

可视化选型：KPI 卡看现状、趋势图看节奏、堆积柱状看构成、明细表看证据——每种图只回答一个问题，不要一张图塞五个结论。

② 指标迭代：随业务阶段演进

指标体系不是一天建好的——从"有没有"到"有没有价值"，每一步都比上一步看得更清：

#阶段要回答的问题我们的对应动作
1有没有数据上墙了吗？定义报价包与拆解率，第一版报表
2准不准数字经得起挑战吗？去重 / 周归属 / 映射 / 数据源四连修
3快不快更新跟得上节奏吗？skill 自动化，每周一条命令
4深不深指标能指导业务吗？有效拆解率修正 + 洞察策略页
⚠️ 敢于推翻自己
有效拆解率其实就是推翻了自己上一版的口径（账面拆解率）。指标跟产品一样，也要迭代——如果 3 个月没换过一次口径，要么没在用，要么没在认真用。
PART 8

数据分析 Skill 建设：把方法论变成工具

分析流程不封装成工具，就无法持续

为什么要做 Skill

前几周每次更新报告，流程是：导出 CSV → 手动跑脚本 → 检查数字 → 生成 HTML → 手动上传 FDS → 发链接。一轮下来半小时到一小时，还容易出错（路径拼错、参数漏传、编码炸了）。

问题是：分析逻辑每周都一样——去重、周归属、映射、算率、生成报告。既然逻辑不变，就应该固化成工具，让机器去做重复劳动，人只管看数字和下判断。

Skill 做了什么

把整个分析流程封装成一个 skill（baojia-detail-analysis），一条命令完成从数据到报告的全流程：

📥
输入 CSV
飞书表导出 12 列原始数据
⚙️
自动处理
去重 / 映射 / 周归属 / 算率
📊
生成报告
三 Tab HTML + SVG 图表
☁️
上传 FDS
固定链接，线上即时可访问

关键设计：口径写在代码里（EXCLUDE 常量、去重逻辑、周归属规则），不是靠人记。每次跑出来的数字可复现、可审计。基线对比也自动化了——传入上一期数据，自动算 delta。

方向调整：从"全维度轰炸"到"组合图锁定"

Skill 里现在这张报告，不是一次画对的——是跟业务一轮轮磨出来的。最开始分析铺得很开：周维度、采购组维度、供应商维度、项目维度、标杆对比，一张报告塞 3 个模块 3 张图。信息是全，但业务看着累，抓不住重点。

跟业务反复对过后收敛成一个原则：每张图只回答一个问题，解决不了决策的图再好看也删。最终锁定的组合图 = KPI 双排（现状一眼看清）+ 堆积柱状（层级构成，同色板同叠加结构）+ 折线（趋势节奏）+ 明细表（证据可下钻）——四件套视觉对齐，各司其职。

后面的每一轮沟通，都在往"少而准"收敛：

#业务反馈 / 方向调整结果
1供应商标杆模块跟当前决策无关砍掉，报告瘦身
2供应商与拆解度两列信息重复整合成一列，同一报价包其他供应商层级带标签同列展示
3最新一周贡献用图不直观改用表格，数字更准、能对上明细
4多张表样式不统一表格统一样式，报告整体一致
5老板要看结论和下一步加 Insight tab：先夸 → 再打 → 给方案
6历史数据要能回看加附录 tab，W27→W32 每周数据可点击

这个过程本身就是方法论：先做宽，再收窄——初期用全维度轰炸摸清数据能回答什么问题，中期跟业务确认"哪些图真正驱动决策"，后期只保留这些图并持续打磨。Skill 固化的不是最初的版本，而是收敛后的版本；业务每有新反馈，报告就再改一版。

Skill 生态

报价细项分析只是一个起点。围绕采购数据分析，已经建了一套 skill 体系：

baojia-detail-analysis
报价细项拆解分析

本周报告的核心 skill。CSV → 三 Tab HTML 报告 + FDS 上传，含 Insight 洞察页和附录归档。

ce-pricing-completion
CE 核价完成率分析

另一条分析线。以"上会"sheet 为基准反向匹配"核价"sheet，统计完成率，输出 HTML 报告。

ep-supplier-query
EP 供应商查询

原子 skill，调 dx-ep CLI 查供应商基本信息 / 列表模糊搜 / 变更历史。

xiaomi-fds
FDS 文件上传

底层 skill，封装 FDS SDK 上传 + 设公开读 ACL，返回可直接分享的 https 链接。

设计原则：先拆原子 skill，再组合成路由门面。每个 skill 只做一件事，做到稳定，然后用组合的方式构建复杂工作流。比如"报价细项分析"= 数据处理 skill + FDS 上传 skill 的组合。

💡 Skill 建设的价值
一致性：口径固化在代码里，不会因为换人跑就变。
知识留存：skill 自带文档和参数说明，新人接手不用从头摸索。
成本趋零：每周更新从半小时降到 5 分钟，分析成本接近零，精力可以放在看数字和下判断上。
可复用：FDS 上传、供应商查询等原子 skill，其他分析场景也能直接调。
PART 9

还能往哪走：六个提升方向

指标、机制、工具都有了，下一步还能做什么
🎯
深度从"点"到"面"
DEPTH SCALING

12 个深度包集中在机械架构（6 个），车身外饰 72 个包深度为 0；L2→L3+ 转化仅 21.4%。下一步把深度拆解做成品类标配，按 BOM+VSM 品类清单逐类覆盖，而不是靠个别包自然生长。

🤝
供应商侧协同
SUPPLIER COLLABORATION

报价粒度（中粗项 vs 细项）卡在供应商手里，L4 必须有供应商配合（戈尔德就是例证）。把细项报价要求写进询价单和准入条款，让"配合度"变成可管理、可考核的变量。

📋
口径从人工到系统
RULE AUTOMATION

不适用品类名单（EXCLUDE）目前靠人逐个过品类名识别。下一步固化到品类主数据，新 RFQ 创建时自动打标，不再依赖人肉识别，也不会因换人而漏判。

⚡
从周报到实时预警
REAL-TIME ALERT

92 个积压要等每周报告出来才暴露。下一步做成实时监控：积压超阈值、活跃度连续下滑，自动预警、当周派单，把问题消灭在"发生的那一周"而不是"发现的那一周"。

🔮
从统计到预测
FORECAST

基于周活跃度趋势预测下周拆解量，反推"50% 目标什么时候能达成"，提前调配资源——而不是等数字落地了才回头解释为什么没达到。

📊
补对比维度
BENCHMARK

现在只有"自己和上周比"。引入同类项目 / 历史同期基准，趋势才有参照系——拆解率 34.1% 在行业里是什么水平，比"比上周高 2pp"更有说服力。

📌 收个尾
三个月的复盘，想强调的就一点：指标要可信、口径要公平、工具要能持续跑。六个方向都是往这个目标走——把"该拆的都拆了"，变成"拆得深、拆得快"。

要点提炼

  • 指标是产品，需要迭代——第一版注定不完美，关键是快速暴露问题并修正。账面 30.4% 到有效 34.1% 就是一次推翻重来。
  • 口径是信任的基石——数字可以被质疑，但口径必须能辩护。写进代码、版本管理，两个人算出同一个数。
  • 分析的终点是行动——老板要的不是报告，是下一步：谁去做、做什么、多久见效。
  • 多方协调才能做好——拆解不是采购员一个人的事，需要采购、CE、供应商、EP 系统四方协同。机械架构组跑通了，说明可行。
  • 把方法论变成工具——分析逻辑不变就封装成 skill，让机器做重复劳动，人只管下判断。
