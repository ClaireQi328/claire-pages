01

指标的诞生：从 PRD 到可落地指标

Metric Extraction

1.1 四问逼出命题：从 PRD 的价值主张出发PRD

报价细项 PRD 开篇就甩出一句模糊诉求：「实现成本穿透」。按四问拆解，它立刻变成可检验的命题：

追问报价细项的真实答案
Why数据割裂、标准不一、分析滞后；要做价值穿透、产能优化、沉淀核心数据资产
What报价从总价粗项穿透到工序明细；深层（BOM+VSM）拆解率从低位提升到目标值
How按 RFQ 最高拆解层级统计 L1-L4 渗透率、双 OK 率、各采购组拆解率
WithEP 提交事件埋点（Kafka to ClickHouse）+ 每周 CSV 快照 埋点
纪律PRD 的「价值穿透」若不落到「双 OK 率」「L3+ 渗透率」这样的指标，就永远停在 PPT。指标的诞生，始于把形容词翻译成名词 + 数字。

1.2 四层提炼框架埋点

埋点方案本身就是四层框架的工程实现：业务目标（量化拆解质量）→ 成功标准（双 OK 率目标）→ 度量指标（4 类场景计数）→ 数据采集（4 个埋点事件 + ClickHouse）。

图 1 · 报价细项的四层框架：从 PRD 价值主张一路下沉到埋点事件

1.3 指标树：北极星与 L1-L4 层级PRD埋点

关键发现：埋点方案的「四种报价场景」恰好就是指标树的落地叶子，与周报里的 L1-L4 拆解层级一一对应。这正是指标树从抽象到具体的范本。

图 2 · 指标树落地：场景 1-4（= L1-L4）就是树的叶子，北极星是根
轻量案例「L1 未拆解 / L2 自行 / L3 BOM 结构 / L4 BOM+VSM」这四级，既是业务对拆解深度的定义，也是埋点的四个场景事件，还是看板的分层配色。一个概念在三处复用，正是指标一致性的体现。

1.4 指标字典：报价细项的真实字段埋点

埋点方案已经把核心指标写成「指标 + 公式」的契约，这正是指标字典的工程版：

指标公式（来自埋点方案）类型
双 OK 率COUNT(scene=4) / COUNT(总报价单元)结果
BOM OK 率COUNT(scene>=3) / COUNT(总报价单元)结果
供应商改善率COUNT(改善) / COUNT(上轮有报价)过程
供应商退出率COUNT(退出) / COUNT(上轮有报价)先行（负向）
平均改善轮次AVG(首次达到 scene3 的轮次)先行
两条铁律没有责任人的指标 = 没人管的指标；没有阈值的指标 = 不会报警的指标。埋点方案的告警规则表（双 OK 率周环比 > 10% 触发 P1）就是「阈值」的工程落地。

1.5 提炼纪律：5 个灵魂拷问

  • 能回到 Why 吗？ 这个指标服务 PRD 的哪项价值？说不出就删。
  • 有唯一口径吗？ 报价包 = RFQ 去重取最高层级，全公司统一（埋点判定矩阵已固化）。
  • 有责任人吗？ 看板按采购员 / 采购组拆分，指标挂到组。
  • 有目标 & 阈值吗？ 双 OK 率目标 + 告警阈值已定义。
  • 能驱动动作吗？ 看到电池组 0% 拆解率，团队知道去找谁、干啥。
02

让指标可明确：口径、分层与三层看板

Make Metrics Clear

2.1 指标三分法：用真实数字说话看板

分析指标 HTML 的 W30 快照，天然就是三分法的范本：

类型报价细项实例（W30 快照）
结果指标整体拆解率 31.0%，深度拆解(L3+L4) 12 个（渗透率 7.1%）
过程指标已拆解 52 个、当周新增拆解供应商 22 家
先行指标询价中 RFQ 拆解率最高（20.8%）、参与供应商 293 家持续扩大
解读整体拆解率停在 31% 是「结果」，真正该盯的是「询价中 RFQ 拆解率 20.8%」这个先行指标，它预示下一周的潜力。

2.2 单一口径：埋点判定矩阵即契约埋点

同一指标全公司一个定义。报价细项用两张表把口径焊死：

维度统一口径（来自埋点方案 / 分析 HTML）
报价包RFQ 去重，取全部供应商中的最高拆解层级
已拆解L2 + L3 + L4；深度拆解 = L3 + L4
周归属按「最新提交时间」所在 ISO 自然周，剔除当前不完整周
场景判定BOM OK 且 VSM OK → scene4；BOM OK 仅 → scene3；多层级自拆解 → scene2；单层 → scene1
落地做法口径写进埋点方案文档 + 固化在 baojia skill 里，改口径走评审。这把「单一口径」从理念变成了工程约束。

2.3 三层看板：分析 HTML 的真实结构看板

分析指标 HTML 的三大模块，几乎是一比一实现了埋点方案的「三层看板」设计。这是本报告最值得 PM 借鉴的落点。

层级看板模块（来自分析 HTML）真实内容受众
L1 管理层整体 KPI 卡168 报价包 / 52 已拆解 / 31.0% / 293 供应商采购总监
L2 执行层周趋势 + 采购组对比W19-W30 柱状堆积；电驱 75% 至电池 0%采购员
L3 分析师深层 L3/L4 明细 + 迁移矩阵按报价包聚合的深层拆解供应商清单根因分析
常见错误把 200 行明细甩给管理层。报价细项把「整体 KPI」放最上面、「深层明细」放最下面，角色错配的问题从设计上就避免了。

2.4 可视化即沟通：柱状堆积 + 累计面积看板

分析 HTML 三个图表统一采用「柱状堆积 + 累计面积 + 进度折线」：层级构成用柱（分量），累计拆解用浅灰面积（总量），拆解率用绿线（单周值）。这恰好验证了 vault 的可视化铁律：层级构成用柱状堆积，累计总量用面积。

场景图表报价细项应用
各层级构成柱状堆积L1/L2/L3/L4 报价包数
累计总量面积（低存在感）累计已拆解供应商数
趋势折线当周拆解率 %

2.5 数据故事化：分析 HTML 的本周洞察看板

分析 HTML 顶部的「本周关键洞察」四句话，正是 数据 → 洞察 → 行动 的范本，不是堆数字：

  • 数据：168 报价包，环比 +4；拆解率 31.0%（-0.1pt）；深度拆解 12 个（+1）。
  • 洞察：规模在扩、拆解温和、116 个报价包仍完全未拆解，是下一阶段重点。
  • 行动：把资源压向未拆解存量 + L3/L4 深度拆解，而非只追增量。
03

用指标驱动达成：从看板到动作

Drive Achievement

3.1 北极星下沉：成本穿透深度 → 杠杆指标PRD

北极星「成本穿透深度」必须拆成可推的杠杆：询价中拆解率、SVC 账号开通率、BOM 到 VSM 衔接率。落不下去的北极星只是标语。

3.2 海盗模型 AARRR：询价中是最佳窗口看板待办

按 RFQ 状态拆解渗透率对比，发现「询价中」阶段报价包拆解率最高（20.8%），远超已完成（13.3%）与定点（0%）。它是「激活」环节的高潜窗口。

轻量案例于是运营资源前移：48 个在途询价中 RFQ 中仍有 38 个未拆解，列为当前第一推动窗口，而非等定点后再补救。指标的价值不在描述现状，而在指出该往哪用力。

3.3 四步闭环：W27-W31 五周演进看板

五周周报本身就是一次完整 PDCA：W27 建基线 → W28 看增量 → W29 做归因 → W30 对标 → W31 闭环。每一次都回到「定目标、执行、检查、改进」。

图 3 · 报价细项的五周，就是一次 PDCA 闭环的连续滚动

3.4 用产品手段促达成：埋点 + 告警 + 分步骤 UI埋点PRD

指标不会自己涨。报价细项把运营动作产品化：

产品手段报价细项真实落点
埋点（采集）4 类场景事件在供应商提交时自动触发，先行指标实时可见
触发（推送）告警系统：双 OK 率周环比 > 10% 触发 P1 飞书通知
引导（降门槛）PRD 供应商填报 UI 分 8 步；BOM 存在则结构化、否则手工，不阻碍报价
激励（牵引）按品类分层设目标，高价值强推 L4、低价值允许 L1
核心思想把正确的动作设计成系统的默认路径（分步骤 UI、自动告警），指标达成才可持续。

3.5 归因纪律：相关 ≠ 因果看板

周报曾观察到「预选供应商拆解率下降」，不能立刻下结论「意愿退步」。要区分「稀释效应」（新增正式供应商拉低均值）与「真实退步」。否则推动的动作会打错靶。

验证手段分层对比、对照实验。动手推运营动作前，先问：这个差异是因果，还是结构性稀释？

3.6 要做的事：报价细项的真实待办清单待办

把看板暴露的问题，转成可指派的动作。这是「驱动达成」最硬核的一页：

  • 补数据：历史线下报价 → 报价成本库，高价值品类（座椅、减振器、电池包）优先回溯拆解。
  • 定目标：按品类分层设拆解目标，与业务打合（高价值强推 L4、中价值 L2、低价值允许 L1）。
  • 推 SVC 开放：24 个已达 L2 的预选供应商 RFQ 具备升级基础，加速开放 SVC 账号释放拆解潜力。
  • 优化 BOM 到 VSM 衔接：L3 零增长根因是 BOM 到 VSM 断裂，推动 SVC 优化 VSM 维护体验。
  • 聚焦询价中 RFQ：48 个在途 RFQ 拆解率最高（20.8%），是当前第一推动窗口。
  • 支持低拆解率采购组：电池组 0%、车身外饰 25.8%，需针对性辅导对应采购员。
  • CE 目标价拆解对齐：推动 CE 按明细拆解目标价，实现供应商报价与内部核价双线可比。
  • SIE BOM 卡控解耦：数据先集成、业务先解耦、不强卡控，渐进推进。

4.1 自动化的四层阶梯埋点skill

图 4 · 报价细项已抵达 L1-L4 中的前三层，L3 洞察自动化是下一阶段主战场

4.2 真实路径：埋点方案的三步 + skill 参数化埋点skill

埋点方案把建设拆成「线上化采集 → 标准化口径 → 常态化运营」，实施计划分四期：一期埋点、二期 L1/L2 看板、三期 L3 迁移矩阵 + 告警、四期 BI 看板。报告生成则从手工改常量，进化到 baojia skill 参数化一键出报告。

阶段内容状态

二期L1/L2 看板开发已完成

四期BI 看板（yonghong / 数鲸）待开始

4.3 告警系统：行动自动化的雏形埋点

规则触发条件级别通知
双 OK 率异常下降周环比下降 > 10%P1飞书群 + 邮件
自拆解率持续高位连续 3 周 > 50%P2飞书群
供应商退出异常单周退出率 > 30%P1采购经理
数据采集失败埋点成功率 < 99%P1技术负责人

4.4 自动化的边界：哪些必须人介入

让机器做让人做
埋点采集、定时报表、异常标红、告警推送判断：是真异常还是噪声？
规则明确的归因初筛（迁移矩阵）沟通：对供应商 / 业务的话术与节奏
标准化建议草稿决策：资源怎么分配、优先级怎么排
原则让机器做「重复 + 可定义」的，让人做「判断 + 创造」的。自动化放大人的判断，不替代它。

PM 的数据运营思维与避坑

PM Mindset

5.1 功能思维 → 数据思维

维度功能思维（旧）数据思维（新，报价细项已实践）
关注点功能是否上线拆解率是否提升
成功标准功能可用双 OK 率 / L3+ 渗透率达标
改进依据用户反馈（零散）埋点 + 周报系统分析
迭代节奏需求驱动周度 PDCA 闭环

5.2 五个习惯 & 五个陷阱

五个习惯（报价细项印证） ① 每天看数据：埋点实时采集
② 每周写报告：5 周周报连续
③ 每月做复盘：迁移矩阵季度复盘
④ 每季定目标：品类分层目标
⑤ 每年做规划：PRD 滚动修订
五个陷阱（真实踩过 / 要避免） ① 数据淹没：116 个 L1 包别全铺开
② 虚荣指标：只看报价包总数增长
③ 相关即因果：预选率下降误判
④ 数据孤岛：线下历史成本未沉淀
⑤ 分析瘫痪：L3 零增长要立刻行动

5.3 落地 Checklist：给 PM 的 10 项

  • 立北极星：选一个代表用户价值的单一指标（如成本穿透深度）。
  • 画指标树：北极星 → 结果 / 过程 / 先行 → 可执行动作（场景 1-4）。
  • 写指标字典：每个指标填公式 + 责任人 + 阈值（参考埋点方案）。
  • 定单一口径：写进文档 + 固化进 skill / 数仓，改口径走评审。
  • 分三层看板：管理层 KPI / 执行层对比 / 分析师明细。
  • 故事化表达：每条结论走完 数据 → 洞察 → 行动。
  • 找杠杆环节：用 RFQ 状态渗透率找到询价中这个高潜窗口。
  • 闭环验证：每次运营动作都 Plan → Do → Check → Act。
  • 产品化引导：分步骤 UI + 自动告警，让正确动作成为默认路径。
  • 推自动化：先采集 + 生成，再攻洞察 + 行动。
