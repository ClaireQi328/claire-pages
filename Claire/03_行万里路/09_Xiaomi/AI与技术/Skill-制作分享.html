1 Skill 是什么？

Skill 是一套可以重复使用的任务执行方法，不是一段简单的提示词，而是一套可以被反复调用的标准作业流程。

OpenAI 定义：一种模块化、自包含的文件夹，用专业知识、工作流程和工具扩展 Agent 的能力。

❌ 没有 Skill
• 每次重新描述需求
• AI 每次用不同方法
• 结果忽好忽坏
✅ 有 Skill
• 一键调用，无需重复
• 按固定流程执行
• 输出结果稳定一致
2 Skill 与相关概念的区别
概念 定义 与 Skill 的关系
💬 Prompt 一次性的任务指令 Skill 是可反复调用的完整工作流程
🧩 Plugin 连接外部工具或服务 Skill 告诉 AI 按什么方法做事
🔗 MCP AI 连接外部数据和工具的通信协议 Skill 是对工具、知识和流程的组合编排
🤖 Agent 执行任务的 AI 主体 Skill 是 Agent 可以调用的一项能力
⚡ Workflow 任务流程 Skill 不仅包含流程，还包含说明、脚本、参考资料和模板
💡 一句话总结：Skill 是把方法、流程、知识和工具组织成可复用的能力，让 Agent 更聪明、更高效地完成任务。
3 Skill 由什么构成？
skill-name/
├── SKILL.md → 核心说明文件（必需）
├── scripts/ → 执行脚本（Python、Shell 等）
├── references/ → 参考资料（方法论、数据源等）
└── assets/ → 模板和素材（报告模板、图标等）
⚠️ 除 SKILL.md 外，其他文件都可根据实际需要选择添加。SKILL.md 是唯一必需文件。

方法 ② 推荐

💡 最佳实践：先和 AI 跑通一次真实流程，过程中不断调整，最后说"请把刚才的工作流程整理并固化成一个可重复使用的 Skill"——这样生成的 Skill 最贴合你的实际工作。
7 EP 实战案例：从需求到落地
案例一：供应商信息查询
场景
快速获取供应商全貌
采购员需要快速了解某供应商的基本信息、资质认证、联系人等，用于日常沟通或评审准备。
输入供应商名称/编码 → 模糊匹配 + 用户确认 → 结构化输出
输出
结构化供应商信息卡
包含供应商名称、编码、类型、资质（ISO9001/14001/45001）、采购员、联系人列表，支持一键下载表格。
基础信息 → 资质认证 → 联系人 → 下载表格
案例二：财务风险评估
场景
供应商财务健康体检
在定点决策前，需对供应商进行财务风险评估，识别潜在的经营风险。
EP 系统年营收 ↔ 财报营收交叉验证
设计亮点
四条核验纪律 + 量化评分
双源数据交叉比对 → 异常预警 → 风险量化评分 → 采购决策闭环。数据异常立即触发预警。
数据交叉验证 → 风险评分 → 决策建议
案例三：品类策略（五看三定）
方法论
五看 → 三定 结构化输出
五看：看行业 → 看市场 → 看客户 → 看竞争 → 看自己
三定：定目标 → 定策略 → 定路径
基于 EP 系统数据 + WebSearch 外部信息，为指定品类生成结构化报告。
数据源
EP CLI + 外部信息融合
dx-ep sor info list — SOR 信息
dx-ep rfq info list — RFQ 列表
dx-ep nomi af list — 定点申请
dx-ep supplier info query — 供应商详情
EP 数据 + WebSearch → 策略报告
案例四：RFQ 进度追踪
双视角
RFQ 维度 + 车型维度
RFQ 维度：按每个 RFQ 追踪报价、评审、定点全流程进度
车型维度：按车型聚合所有相关 RFQ 的完成情况
RFQ 状态 → 报价轮次 → 定点状态
数据链路
SOR → RFQ → 报价 → 定点
完整追踪链条：车型关联 SOR → SOR 关联 RFQ → RFQ 的供应商报价 → RFQ 的定点结果。关键推荐自动标注。
车型 SOR → 关联 RFQ → 供应商报价 → 定点决策
🎯 EP Skill 的共同模式：接收用户输入 → 调用 EP CLI 获取系统数据 → 结合外部信息 → 按固定框架分析 → 输出结构化结果。每个 Skill 都是一个端到端的业务闭环。
8 Skill 制作要点速查
要点说明
核心文件SKILL.md 是唯一必需文件，定义任务怎么做、调用条件、步骤、输出
安装位置Codex: ~/.codex/skills/　Claude Code: ~/.claude/skills/
调用方式直接输入（提示词）或通过名称（斜杠命令）
数据接入通过 CLI / MCP / API 接入业务系统数据，让 Skill 有"眼睛"和"手"
输出标准固定输出格式（表格/HTML卡片/报告），确保每次结果一致可比较
安全原则来源不明、权限过多、看不懂脚本 → 不安装
最佳实践先跑通真实任务，再固化成 Skill；从简单场景开始，逐步迭代
命名规范动宾结构、语义清晰，如"供应商查询""RFQ进度追踪""财务风险评估"
