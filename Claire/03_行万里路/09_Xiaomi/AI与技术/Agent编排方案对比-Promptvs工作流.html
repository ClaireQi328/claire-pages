样件订单 Agent - 编排方案对比

Prompt 驱动 vs 工作流编排：两种方案的详细设计、效果对比与推荐
方案A：Prompt驱动 方案B：工作流编排 效果对比 推荐：混合编排

🤖方案A：Prompt 驱动（纯 Agent 指令）

核心思路

在 Agent 的系统提示（System Prompt）中定义完整的工作流程、角色边界、执行规则和异常处理逻辑。 Agent 根据 Prompt 自主决策：什么时候调用哪个 Skill、什么时候暂停等待人工确认、遇到异常如何处理。 流程是"软编码"在 Prompt 中的，Agent 有较大的自主决策权。

优缺点

✅ 优势

  • 灵活性高：Agent 可根据实际情况自主决策，处理复杂和异常情况
  • 开发快：只需写好 Prompt，无需搭建工作流引擎
  • 自然语言交互：用户可用自然语言与 Agent 交互，如"全部选最低价"
  • 异常处理能力强：Agent 可理解异常原因，自主决定重试/跳过/通知人工
  • 迭代快：修改 Prompt 即可调整流程，无需重新部署工作流

❌ 劣势

  • 流程不可视：流程"藏"在 Prompt 中，难以直观展示和审计
  • 一致性风险：Agent 可能因上下文理解偏差，执行顺序或决策不一致
  • 调试困难：出问题时难以定位是 Prompt 问题还是 Skill 问题
  • 人工等待机制复杂：需要 Agent 主动轮询状态或等待用户输入，实现较复杂
  • 对 Prompt 质量依赖高：Prompt 写不好，整个流程就乱

🔀方案B：工作流编排（可视化工作流）

核心思路

使用 AgentSpace 的工作流编排器，通过可视化的节点+连线+条件分支，定义固定的执行流程。 每个节点是一个明确的操作（调用 Skill / 人工确认 / 条件判断 / 数据转换）， 节点之间通过连线传递数据。流程是"硬编码"在工作流定义中的，执行顺序严格可控。

优缺点

✅ 优势

  • 流程可视化：节点+连线直观展示，业务人员也能看懂
  • 执行可控：严格按定义的顺序执行，不会乱序或跳步
  • 人工等待机制成熟：工作流引擎内置"人工任务"节点，等待/超时/回调都有标准实现
  • 调试方便：每个节点的输入输出可查看，出问题容易定位
  • 可审计：工作流定义是版本化的，每次执行有完整的节点日志
  • 条件分支清晰：一价一供/多供、成功/失败等分支用连线直观表达

❌ 劣势

  • 灵活性差：流程固定，遇到未定义的异常情况难以处理
  • 开发成本高：需要设计节点、连线、数据映射，工作量大
  • 自然语言交互弱：用户难以用自然语言干预流程，如"跳过这一条"
  • 异常处理有限：只能处理预定义的异常分支，未定义的异常会卡死
  • 迭代慢：修改流程需要重新编辑工作流、测试、发布
  • 对 Skill 标准化要求高：每个节点的输入输出必须严格标准化，否则连线传参会出错

你的项目特点匹配度

🤖 Prompt 驱动匹配点
你的项目中这些特点更适合 Prompt 驱动：
  • 异常情况多：登录超时、导入失败、创建失败等，需要灵活处理
  • 自然语言交互需求：用户可能说"全部选最低价"、"跳过P001"
  • 流程仍在迭代：0915版还在优化，需要快速调整
  • 智能分流逻辑：一价多供判断、卡片/表格选择，需要理解上下文
  • 角色可见性控制：不同角色看不同内容，需要动态生成卡片
🔀 工作流编排匹配点
你的项目中这些特点更适合工作流编排：
  • 大阶段顺序固定：导入→查询→分析→选择→创建→记录，顺序明确
  • 3个人工确认节点：需要成熟的等待/超时/回调机制
  • 条件分支清晰：一价一供/多供、<5家/≥5家、成功/失败
  • 需要可视化展示：业务人员需要看懂流程，便于沟通和审计
  • 执行一致性要求高：订单操作不能乱序，必须严格按流程执行
  • Skill 已标准化：workflow_schema 统一输出，适合节点间传参

🎯推荐方案：混合编排（工作流大框架 + Prompt 小细节）

💡 核心结论

两个方案都不是最优解，推荐混合编排：

用 工作流 定义大的阶段顺序、人工确认节点、条件分支（可控、可视、可审计）；

用 Prompt 驱动的 Agent 处理每个阶段内的细节、异常、自然语言交互（灵活、智能、迭代快）。

一句话：工作流管"做什么"和"什么时候做"，Agent 管"怎么做"和"出问题怎么办"。

  • 定义条件分支（一价多供数量判断）
  • 每个 Agent 节点内部用现有的 Prompt 驱动逻辑

第四步（优化）：根据实际运行效果，逐步把稳定的逻辑从 Agent 移到工作流节点
