样件订单业务线背景梳理 与 文档合并方案

基于 12 份飞书文档（流程制度 / Skill 与 Agent 化方案 / EP 系统技术方案 / 操作手册）的合并梳理
数据来源：mi.feishu.cn 12 份业务文档梳理日期：2026-09-01
一句话结论：样件订单是小米汽车支撑研发/试制阶段样件采购的核心业务线。当前业务已跑通「需求→预算→采购→下单→验收→结算」全流程，但订单管理员仍以大量手工操作为主（日均 200 单、单笔约 10 分钟）。团队正推进样件订单 Skill / Agent 化改造（路径二试点：Skill 写逻辑 + EP 提供 CLI 接口），将「查需求→校验→分组→下单→更新→追踪」沉淀为 9 个 Skill + 15 个 CLI，这也是后续写 Skill、转 py 的落点。

一、业务线背景

1.1 业务定位

样件采购用于支撑 竞品分析、调试/测试/试验、试制（BOX car、SM车、M车、VP车）等场景下上车零部件总成及散件的采购需求（《汽车部直采样件采购流程 V1.0》适用范围）。整车工程部的研发试验测试样件（散件）单独由《整车工程部研发样件管理规则》规范。

样件订单 = 样件采购订单（EP 系统中实体为 SaPo / SaPoItem），是样件采购全生命周期管理 7 大模块之一（需求、导入、任务、RFQ、快速定点、台账、订单）。

1.2 端到端业务流程

1
需求提出
零部件实际需求人（研发产品工程师 / DRE / 试制工程师）提出样件需求；编写 SOR 明确交样要求与总体计划。
2
预算 / BR 申请
样件需求部门在预算申请系统提报阶段性样件采购申请；散件需求人申请 BR 单号并提报至二级部门接口人。
3
需求汇总与传递
整车试制：研发在 MI-PEC 系统打点单车需求，试制 BOM 工程师汇总；散件/零散：部门提报人汇总阶段性需求后在 EP 系统导入。
4
采购申请与定点
量产供应商已定点件 → 直接下单；量产供应商非量产件（散件/改制件/替代件）→ EP 快速定点流程；非量产供应商非量产件 → 快速定点 + 样件采购合同签署。
5
采购订单（PO）
供应链运营接收需求 → 在 EP 转化为 PO（SaPo）→ 审批（金额 >50w 需联合评审）→ 下发供应商确认 → SAP 下发。下单周期：新定点供应商最长 6 周，已定点供应商 3 天–1 周。
6
样件验收
整车在汽车非资产验收平台验收（整车：试制工程师；散件：需求人/汇总人）；研发阶段散件需保证「样件用途=A 散件」「未全部收货」等条件。
7
结算付款
账务负责发票校验、过账及付款，完成样件结算合同流程与对公付款。

1.3 关键系统

EP采购/订单主系统，样件模块 7 大子模块
MI-PEC试制系统，整车试制需求打点
SRM供应商关系系统
预算申请系统阶段性预算 & BR 申请

SAP订单下发与结算
小米审批流程审批（合同/订单）

1.4 职责分工

  • 零部件实际需求人：提起样件需求、系统确认收货
  • 部门提报人 / 试制 BOM 工程师：汇总需求、定期传递至采购
  • 研发产品工程师（零部件负责人）：编写 SOR、跟踪交样
  • 采购工程师：确认样件价格、签订价格相关合同
  • 供应链运营：接收需求、EP 需求转 PO、核查一致性
  • 财务 / 账务：确认审核预算与价格、发票校验过账付款
  • 需求复核人（DRE）：整车工程部样件需求复核

1.5 现状痛点（8-18 会议确认）

二、Agent 化改造项目（核心主题）

定位：样件自动下单试点（路径二）—— Skill 写逻辑，EP 提供 CLI 接口。AI 负责编排与判断，EP 固化价格等高风险逻辑，飞书承载人工确认。「人做决策，AI 做执行」。目标：把订单管理员"查需求→校验→分组→下单→更新→追踪"的重复操作沉淀为 9 个可编排 Skill（配套 15 个 CLI），先以一天一次的节奏跑通试点。

2.1 覆盖模块与三层形态

四模块：需求导入 / 创建订单 / 更新订单 / 样件询价清单

三层形态：CLI（确定性批量操作）+ Skill（规则/数据/动作打包）+ Agent（多源对接与异常兜底），并纳入"岗位虾"体系。

2.3 CLI 契约（EP 侧）

以 CLI 语义 + 字段口径 + 验收标准定义，核心覆盖：查询可下单需求、创建样件订单、查询当天提交订单、需求明细导入 等；价格判断、是否提交、草稿保存等高风险规则由 EP 系统在创建订单流程内部完成。关键改造点：① 取价逻辑（最新且最低价）；② 订单增加来源字段（SKILL_AUTO/MANUAL）用于统计复盘；③ 撤批时机调整（V2 供应商确认后才取消 V1）。
