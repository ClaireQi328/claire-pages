架构设计 v1.0

工作流编排器 Workflow Orchestrator

面向供应链B点四层架构的可视化工作流编排平台，支持多源输入、DAG 流程定义、条件分支、人工审批、异常重试与可观测执行，实现业务流程的低代码配置与自动化运转。

文档版本 v1.0
适用场景 供应链 / 审批 / 数据同步 / 事件驱动
设计日期 2026-09
01 / DESIGN GOALS

设计目标与核心原则

解决业务流程配置成本高、跨系统串联难、执行状态不可视、异常处理缺失等问题，提供一套可扩展、可观测、可回滚的编排引擎。

⚙

低代码编排

可视化拖拽画布，节点即组件，连线即依赖，业务人员可独立配置流程，无需写代码。

多系统串联

核心
📊

02 / ARCHITECTURE

整体架构

采用「接入层 → 编排层 → 执行层 → 基础设施层」四层结构，与供应链B点四层架构对齐，各层职责清晰、可独立扩展。

系统分层架构图

接入层（Access Layer）

提供可视化编排画布、流程管理控制台、OpenAPI、Webhook 接入端。负责流程定义的 CRUD、版本管理、触发入口与人工任务处理。

编排层（Orchestration Layer）

核心引擎，包含 DAG 解析器、调度器、状态机、上下文管理器。负责将流程定义编译为可执行计划，驱动节点按依赖关系执行。

执行层（Execution Layer）

节点执行器池，每种节点类型对应一个执行器。支持同步/异步执行、脚本沙箱、连接器调用、人工任务等待与回调。

基础设施层（Infra Layer）

持久化（流程定义/实例/日志）、消息队列（任务分发/事件通知）、缓存（上下文/锁）、对象存储（大文件/产物）、监控告警。

03 / CORE MODULES

核心模块详解

六大核心模块协同工作，覆盖从流程定义到执行监控的完整生命周期。

📐

流程定义模块

将画布操作序列化为标准 JSON 流程定义（Workflow Definition），包含节点列表、连线关系、节点配置、全局变量。支持版本管理与灰度发布。

🧩

DAG 解析与调度

解析流程定义为有向无环图，拓扑排序确定执行顺序，识别可并行节点。调度器按依赖关系分发任务，支持并行、串行、分支、循环模式。

🔄

状态机引擎

管理流程实例与节点实例的生命周期状态：PENDING → RUNNING → SUCCESS / FAILED / SKIPPED / CANCELLED。状态变更触发事件与回调。

📦

上下文管理器

维护执行上下文（Execution Context），存储全局变量、节点输出、环境变量。支持节点间数据传递、变量引用（${node.output.field}）与表达式求值。

🔌

连接器框架

标准化连接器接口（Connector SPI），内置 HTTP、数据库、MQ、Redis、文件、飞书、邮件等连接器。第三方系统可通过插件方式扩展。

👁

可观测模块

节点级执行日志、耗时统计、输入输出快照。集成 Prometheus 指标、ELK 日志、链路追踪（TraceID 贯穿全流程）。

04 / NODE MODEL

节点模型定义

节点是工作流的最小执行单元，采用统一的数据模型描述，支持自定义扩展。每个节点包含元信息、输入端口、输出端口、配置参数与执行逻辑。

节点数据结构（WorkflowNode）

// 流程定义中的节点描述 { "id": "node_001", "type": "http_request", // 节点类型 "name": "调用订单接口", "position": {"x":200,"y":100}, // 画布坐标 "inputs": ["prev_node.output"], // 输入引用 "config": { "method": "POST", "url": "${env.api_base}/orders", "headers": {"Authorization":"${env.token}"}, "body": "${node_001.output.data}" }, "retry": {"max":3,"interval":5000}, "timeout": 30000 }

输入输出类型体系

标准化的输入输出描述，确保节点间数据可传递、可校验、可转换。支持强类型 Schema 与动态引用。

变量引用语法

节点配置中支持 ${变量路径} 语法，执行时由上下文管理器解析替换。支持嵌套路径、数组索引、函数调用。

${env.api_base} // 环境变量 ${trigger.payload.order_id} // 触发事件数据 ${node_001.output.data.items[0].id} // 前序节点输出 ${vars.user_name} // 自定义全局变量 ${date.now('yyyy-MM-dd')} // 内置函数
06 / EXECUTION ENGINE

执行引擎设计

基于 DAG 拓扑排序的调度引擎，支持并行执行、条件分支、循环迭代、人工等待与异步回调。

STEP 1

触发接收

触发器接收事件，创建流程实例，初始化上下文

STEP 2

DAG 编译

解析流程定义，拓扑排序，识别入度为0的起始节点

STEP 3

节点调度

就绪节点分发到执行器池，支持并行分发

STEP 4

执行与回调

执行器调用连接器/脚本，完成后回写输出与状态

STEP 5

依赖更新

更新下游节点入度，入度归零则加入就绪队列

STEP 6

完成判定

所有节点终态后流程结束，输出最终结果

并行执行

无依赖关系的节点自动并行调度，通过线程池/协程池控制并发度。聚合节点（Join）等待所有前置分支完成后继续。

条件分支

Switch 节点根据表达式求值结果选择一条或多条分支执行。未选中的分支标记为 SKIPPED，不占用执行资源。

循环迭代

ForEach 节点遍历数组/集合，为每个元素创建子执行上下文，支持串行/并行循环，可配置最大并发数。

人工等待

审批节点进入 WAITING 状态，流程实例挂起，等待人工回调。回调超时可配置自动通过/拒绝/升级。

异步执行

长耗时任务（如大数据处理、视频转码）提交后立即返回，执行器注册回调端点，任务完成后通过回调恢复流程。

子流程调用

支持嵌套调用其他流程定义，子流程有独立的实例ID与上下文，完成后将结果回传给父流程。

07 / STATE MACHINE

状态机与生命周期

流程实例与节点实例均采用有限状态机管理，状态变更严格受控，确保执行可追溯、可恢复。

节点状态流转图

流程实例状态

状态含义
RUNNING执行中，至少一个节点在运行
SUCCESS所有节点成功完成
FAILED存在节点失败且未被容错处理
WAITING等待人工审批或异步回调
PAUSED人工暂停，可恢复
CANCELLED人工取消，执行终止

节点实例状态

状态含义
PENDING等待前置节点完成
READY前置完成，等待调度
RUNNING正在执行
SUCCESS执行成功
FAILED执行失败（可重试）
SKIPPED条件未满足，被跳过
08 / FAULT TOLERANCE

异常处理与容错机制

多层级容错设计，从节点级到流程级，确保异常场景下流程可恢复、数据可补偿、问题可定位。

⏱

超时控制

每个节点可配置超时时间，超时后触发重试或标记失败。全局默认超时 60s，可按节点覆盖。

🔁

自动重试

支持固定间隔/指数退避重试，可配置最大重试次数与重试条件（如仅网络错误重试）。

⬇

降级策略

节点失败后可配置降级输出（默认值/兜底数据），流程继续执行，不阻塞主链路。

↩

补偿回滚

关键节点可配置补偿动作（Compensation），流程失败时按逆序执行已完成节点的补偿逻辑。

👤

人工干预

失败节点支持人工重试、跳过、修改输入后重跑。流程实例支持暂停、恢复、取消操作。

📝

死信队列

超过最大重试次数的任务进入死信队列，保留完整上下文，支持人工排查后重新投递。

🔒

幂等保障

节点执行支持幂等键（Idempotency Key），重试时不会产生重复副作用，确保数据一致性。

🔔

告警通知

流程失败、超时、人工待办等事件触发告警，支持飞书/邮件/短信/Webhook 多渠道通知。

09 / EXTENSIBILITY

扩展机制与连接器框架

采用 SPI（Service Provider Interface）模式，节点类型与连接器均可通过插件方式扩展，无需修改核心引擎。

连接器 SPI 接口

public interface Connector { String getType(); // 连接器类型标识 ConnectorMeta getMeta(); // 元信息（名称/图标/配置Schema） ConnectorResult execute( // 执行逻辑 ConnectorContext ctx, Map<String,Object> config ); }

实现接口后打包为 JAR 放入插件目录，引擎启动时自动发现并注册。配置 Schema 用于前端动态渲染配置表单。

11 / DEPLOYMENT

部署架构与高可用

无状态服务 + 有状态中间件分离部署，支持水平扩展与灾备。

部署拓扑图

无状态服务

API 服务、调度器、执行器均为无状态设计，通过 Redis 共享状态，可任意水平扩展。K8s HPA 根据 CPU/队列长度自动扩缩容。

数据高可用

MySQL 主从复制 + 半同步，Redis Cluster 三主三从，Kafka 多副本。关键数据每日备份，支持时间点恢复（PITR）。

灰度与回滚

流程定义支持版本管理，新版本可灰度（按比例/按租户）发布。执行异常可一键回滚到上一稳定版本。
