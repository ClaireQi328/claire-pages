CLI 两条路线利弊对比
数字化部门 · 采购业务 ｜ 内部立项资料 + 公开行业趋势 ｜ 2026-09-08
当前路线
路线 A · 采购智能体（Agent / FDE）
CLI 原子能力对外暴露，Agent/Skill 编排场景，业务自由使用数据与操作
优势
  • 价值兑现快：样件下单 26.5→2 人时/天，合同 14.5→1 人时/天
  • 研发一次、FDE 复用多次，杠杆高
  • 契合 agentic AI 行业趋势
  • 沉淀原子化数据基座（统一入参/出参）
劣势
  • 系统厚度不增：规则散在编排层，不回流系统
  • 健壮性风险：开放数据/写操作，治理缺位则失控
  • 产品开发、数据分析岗位易被“做空”
备选路线
路线 B · 纯 FDE 全栈
数字化部门全链路自建业务系统，需求→PRD→研发→测试→上线
优势
  • 系统厚度强：领域模型、规则引擎沉淀在系统内
  • 健壮性好：正规开发流程、权限、审计齐全
  • 岗位职责清晰，不易被架空
  • 规则资产化，长期可复用
劣势
  • 迭代慢：链路长、依赖排期，跟不上业务变化
  • 资源重：多角色齐备才能运转
  • 离业务远，价值感知弱
  • 错过 AI 编排红利，重复开发受 AI 编码工具冲击
核心判断：不是二选一，是分层问题
CLI 原子能力（L5）是必要基座，Agent/Skill 编排是价值放大器。当前路线 A 的问题不在“开放”，而在 规则未下沉、写入与数据闭环不足、治理缺位。正确做法：保留开放与编排红利，补齐厚度与治理。
