5架构对比 · Agent 化 vs 传统 B 端 SaaS ARCHITECTURE COMPARISON
从交互范式、系统关系、能力扩展、数据处理、决策方式、流程刚性六个维度对比；Agent 化架构的核心是"替人干活的系统"而非"给人用的工具"，采购人从"操作系统"升级为"指挥系统"
对比维度 传统 B 端 SaaS Agent 化智能采购平台
交互范式 表单驱动：用户在固定页面填字段、点按钮，系统按预设流程走 自然语言驱动：用户说"帮我查这个零件的最新价格并发起 RFQ"，Agent 自动拆解意图、串联多步操作
系统关系 替换式：新系统上线意味着旧系统下线，数据迁移成本高 寄生式：通过 MCP/CLI "寄生"在 EP 系统之上，不替换、不迁移，读写现有数据增强能力
能力扩展 功能开发式：新增能力 = 新需求 → PRD → 开发 → 测试 → 上线，周期以月计 Skill 拼装式：新增能力 = 写一个 Python 函数（Skill）+ 定义 CLI，周期以周计；Agent 自动发现并编排新 Skill
数据处理 单系统结构化：数据在各自系统内，跨系统靠人工导出 Excel 再导入 跨域聚合：Agent 自动从 EP/成本库/天眼查/行情等多源拉取数据，统一视图，无需人工搬运
决策方式 人工决策：系统提供数据，人做判断；经验在个人脑中，人员流动即流失 人机协同：L4-A 全自动（Agent 独立完成）/ L4-B 半自动（Agent 执行+人确认）/ L4-C 人工主导（Agent 辅助分析）；决策逻辑沉淀为可复用规则
流程刚性 固定流程：流程在系统中写死，变更需要改代码 动态编排：LangGraph 状态机 + 条件路由，流程可配置、可断点、可人工介入；同一意图可根据数据状态走不同路径

效率提升
从"人找系统"到"系统找人"：自然语言发起，Agent 自动跨系统拉取数据、生成报告，单流程从天级压缩到小时级
02
决策质量
从"经验驱动"到"数据驱动"：16 个领域 Agent 持续监控（价格异常/供应商风险/合同到期），主动预警，决策依据可溯源可审计
03
知识沉淀
从"个人资产"到"组织资产"：Ontology 七大域知识图谱 + RAG 检索，新人直接问 AI 获得跨模块精准答案，经验不随人员流动流失
04
扩展速度
从"项目制"到"生态制"：39 个 CLI 原子能力可自由组合，新增场景 = 编排已有 CLI + 写少量 Skill，平台越用越强，能力复利增长
05
链路韧性

CORE INSIGHT · 核心洞察
传统 B 端 SaaS 是"给人用的工具"——人适应系统，在固定流程里操作； Agent 化架构是"替人干活的系统"——系统适应人，用自然语言理解意图、自动编排能力、跨系统协同执行， 把采购工程师从重复劳动中解放出来，聚焦在真正需要判断和决策的高价值环节。 这也是 B 点项目"Skill 先行、Agent 后置"原则的底层逻辑——先把每个原子能力做扎实，再用 Agent 串成能自主干活的智能体。
6关键挑战与解决方案 · 开放问题与落地路径 CHALLENGES & SOLUTIONS
客观看待当前阶段（L2 单域操作期）的三大核心挑战：多入口交互体验、数据与权限控制、Agent 深水区差距；每个挑战给出可落地的解决方案，不画大饼、不回避问题
01 多入口交互体验 · 三入口并存不是混乱，而是分层接入 MULTI-ENTRY INTERACTION
现状与痛点 · PROBLEM
开放阶段存在三种交互入口并存：
  • AI 助手（EP 内嵌对话）—— 面向采购工程师，自然语言交互
  • 本地 Agent（CLI/Skill 直接调用）—— 面向开发者/自动化脚本，命令行交互
  • 系统调用（API/MCP）—— 面向系统集成，程序化调用
痛点：用户不知道该用哪个入口；不同入口体验不一致、状态不同步；人机协同断点多（Agent 执行到一半需要人确认时，切换成本高）。
解决方案 · SOLUTION
统一编排引擎 + 状态同步：三入口共享同一套 LangGraph 编排引擎和状态管理（checkpoint），无论从哪个入口发起，任务进度、审批状态、执行结果实时同步；用户在 AI 助手发起的任务，可以在本地 CLI 查看进度，在系统 API 中获取结果。
入口分层定位：AI 助手 = "面向人"的自然语言交互（解释、追问、确认）；本地 Agent = "面向开发者"的脚本化调用（批量、定时、自动化）；系统调用 = "面向系统"的 API 集成（EP/ERP/SRM 系统间打通）。三入口不是竞争关系，而是覆盖不同使用场景。
人机协同丝滑化（HITL）：Agent 执行到需要人工确认的节点时，自动通过飞书卡片推送审批请求（含上下文摘要+可选操作按钮），用户在飞书内一键确认/驳回/修改，Agent 自动续跑；支持断点续跑（checkpoint 持久化）和操作回滚（每次 Agent 操作记录可追溯）。
渐进式自动化等级：用户可按场景选择自动化等级——L4-C 人工主导（Agent 只给建议，人执行）、L4-B 半自动（Agent 执行+人确认）、L4-A 全自动（Agent 独立完成，事后审计）；低风险/高频场景逐步从 C→B→A 升级，高风险场景始终保持人工确认。
02 数据与权限控制 · Agent 时代的安全底线 DATA & PERMISSION CONTROL
现状与痛点 · PROBLEM
39 个 CLI 已定义权限控制点，但 Agent 化后权限复杂度指数级上升：
  • Agent 跨模块调用时，权限如何传递和约束？
  • Supervisor 调度多个子 Agent 时，是否会越权访问？
  • Agent 输出中可能包含敏感数据（价格、成本、供应商信息），如何脱敏？
  • Agent 的自主决策操作，如何审计和追责？
  • 跨系统数据（EP/成本库/天眼查）如何隔离？
解决方案 · SOLUTION
统一权限网关：所有 CLI/API 调用必须经过统一权限网关，采用 RBAC（角色权限）+ ABAC（属性权限）混合模型；用户身份→角色→权限→CLI 调用范围，Agent 继承发起用户的权限上下文，不可越权。
Agent 最小权限集：每个领域 Agent 定义独立身份和最小权限集（如订单 Agent 只能调用订单相关 4 个 CLI，不能调用价格/合同 CLI）；Supervisor 只做调度不直接执行业务，子 Agent 按任务分配临时权限令牌（JWT），任务结束自动回收。
数据分级与脱敏：按数据敏感度分四级——公开（可对外）/内部（全员可见）/机密（部门可见）/绝密（指定人可见）；Agent 输出自动按查看者权限脱敏（如采购工程师看不到成本明细，只能看到价格）；RAG 检索结果按权限过滤。
全链路审计日志：每次 Agent 调用记录——调用者身份、Agent 身份、输入参数、输出结果、决策依据（引用了哪些数据/规则）、人工确认记录、时间戳；审计日志不可篡改，支持按用户/Agent/时间/操作类型追溯。
跨系统数据隔离：外部系统数据通过 MCP Server 隔离接入，Agent 不可直接访问底层数据库；每个 MCP Server 独立鉴权，数据在内存中处理不落盘；敏感数据（如成本库）仅限指定 Agent 在指定场景下访问。
03 Agent 发展差距 · 客观看待深水区，不画大饼 AGENT MATURITY GAP
现状与差距 · CURRENT STATE
当前处于 L2 单域操作期（CLI 原子能力 + 单模块 Skill），Agent 层刚起步。行业深水区尚未触碰：
  • 评测体系：如何量化评估 Agent 的任务完成率、准确率、幻觉率、安全性？
  • 记忆体系：短期记忆（会话内）、长期记忆（跨会话）、领域知识、程序性记忆如何分层？
  • 自主决策：从"人确认"到"Agent 自主决策"的信任如何建立？边界如何设定？
  • 多 Agent 协同：Agent 间通信协议、冲突解决、任务分解与聚合如何设计？
客观定位：我们在"应用编织和探索期"，距离"平台自主化"还有 2-3 年的路要走。
分阶段攻克路线 · ROADMAP
评测体系先行（Phase 2 启动）：建立采购场景金标准评测集（覆盖 5 大域 53 个节点的典型任务），自动化评测流水线（每次 Skill/Agent 更新自动跑评测），指标包括任务完成率、CLI 调用准确率、幻觉率（输出与事实一致性）、响应时间、人工干预率；引入红蓝对抗测试（红队构造恶意输入测试 Agent 安全性）。
记忆体系分层（Phase 2-3）：短期记忆 = LangGraph checkpoint（会话内状态，任务结束归档）；长期记忆 = 用户偏好/历史决策/经验教训（向量 DB 存储，按用户/部门隔离）；领域知识 = Ontology 七大域 + RAG 检索（结构化知识图谱 + 非结构化文档）；程序性记忆 = 可复用工作流模板（成功执行的流程自动沉淀为模板，下次相似任务直接调用）。
自主决策边界（Phase 3）：定义 Agent 可自主决策的场景白名单（如样件订单自动下单、合同风险自动标记），设定金额阈值和风险等级（低风险+低金额=全自动，高风险或高金额=强制人工确认）；建立 Agent 决策的"可解释性"要求——每次自主决策必须输出决策依据（引用了哪些数据/规则/历史案例），支持事后审计和人工纠错。
多 Agent 协同（Phase 3-4）：Agent 间通信采用标准化协议（任务描述+输入输出契约+状态回调），Supervisor 负责任务分解和结果聚合，子 Agent 间通过共享状态（而非直接调用）协作；冲突解决采用"优先级+投票"机制（高优先级 Agent 决策优先，同级 Agent 冲突时 Supervisor 仲裁）；从 2-3 个 Agent 协同起步（如订单+合同+价格），逐步扩展到全域协同。
