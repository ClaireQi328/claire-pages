VPPS 绑定操作指南

dx-ep CLI 1.0.10 · 2026-11-12

VPPS 是零件的结构位置编码，品类是采购分类。绑定就是把某个位置的零件挂到某个采购品类下，并指定谁来负责。

一、怎么绑定

你只需要说清楚三件事：哪个编码、绑到哪个品类、采购员是谁。SQE 和财务 CE 可以不给。

你要做的：告诉我「把 1015-B009 绑到 CAT-00009，采购员路梦瑶」

对应的命令是这样：

dx-ep mvps vpps bind \
  --vpps-code 1015-B009 \
  --category-code CAT-00009 \
  --buyer-name 路梦瑶

必须输入什么

参数必填填什么
--vpps-code必须VPPS 编码，如 1015-B009
--category-code必须品类编码，如 CAT-00009
--buyer-name必须采购工程师姓名，只能填一个人
--sqe-name可选SQE 姓名，只能填一个人
--finance-ce-name可选财务 CE 姓名，只能填一个人

姓名必须填一个真人，不能写「张三,李四」。要多人分管同一个编码，拆成两次调用，第二次覆盖第一次。

执行前先看一眼

我建议每次绑定前先查一下这个编码现在在哪。一条命令就够：

dx-ep mvps vpps list --vpps-code 1015-B009 -f json

看两个字段：

字段含义你的判断
bindStatusTO_BIND 未绑 / BIND 已绑已绑就是改绑，会从原品类移走
categoryCode当前所属品类和目标品类不同，说明是搬家
为什么非要先查

编码写错时系统不会报错——查询返回 0 条，绑定命令照样能发出去，但什么都不会发生。查一次能避免「以为绑好了其实没绑」。

还有一步可选：加 --dry-run 先看发出去的请求长什么样，不写入。

dx-ep mvps vpps bind --vpps-code 1015-B009 --category-code CAT-00009 \
  --buyer-name 路梦瑶 --dry-run

二、这两个接口能解决什么场景

绑定接口

「这批零件该归到哪个品类，帮我把人指定上」
新零件定完点，结构位置有了，但还没挂到采购品类下。用 bind 一次性完成品类归属和人员指定。当前系统里还有 7,582 个编码处于待绑定状态。
「这个零件归错品类了，挪一下」
对已经绑定的编码再执行一次 bind，指向新品类即可。原来的品类会自动失去这个成员。不需要先解绑。
「这个品类的采购换人了」
用同一个品类、同一个编码，只改 --buyer-name，重新绑一次就能覆盖人员。不需要解绑再绑。
「帮我盘点一下哪些还没绑」
查 vpps list --status 待绑定，7,582 条待处理，可按结构码前缀分批推进。

解绑接口

「这个零件不该在这个品类里」
用 unbind 把它从品类里摘出来，状态回到待绑定，之后可以重新绑到正确的地方。
「这个品类整体不要了」
不传编码就解绑该品类下全部 VPPS。这是一步清空操作，没有二次确认，执行前务必看清楚。
不传编码 = 全清

unbind 只给 --category-code 不给 --vpps-code，会把整个品类的 VPPS 关联清空。命令里没有 --all，也没有「确定吗」的提示。只要不是真的整品类作废，就一定把编码写上。

另外，解绑会连带清掉采购员、SQE、财务 CE 的关联。如果只是换人，用 bind 覆盖，不要先解再绑。

三、批量怎么做

方式一：多个编码绑同一品类

编码用英文逗号连起来，不加空格：

dx-ep mvps vpps bind \
  --vpps-code 1015-B001,1015-B002,1015-B003 \
  --category-code CAT-00284 \
  --buyer-name 程家琛

三个人员字段会应用到每一个编码。适合 5 条以内。

方式二：一个编码绑多个品类？不支持

一个 VPPS 编码只能属于一个品类。想「同时挂到两个品类」在业务上不成立，接口也不支持。

方式三：一批编码各绑各的品类

这种情况命令行做不到，因为每次调用的品类是固定的。当前没有 Excel 批量导入——设计过但没实现，--from-file 会直接报错。

可行做法是脚本循环。你有对照表的话，这样跑：

# 假设对照表是 vpps_code,category_code,buyer 三列
while IFS=, read -r code cat buyer; do
  dx-ep mvps vpps bind --vpps-code "$code" --category-code "$cat" --buyer-name "$buyer"
done < mapping.csv

每跑完一条建议回查一次，因为编码不存在时不会有任何报错。

批量前的匹配怎么核对

这是最容易出错的地方。三个检查：

检查怎么做
编码是否真实存在逐个跑 vpps list --vpps-code X，0 条的就是错的
目标品类是否生效category detail --code X，看 categoryStatus 是不是 EFFECTIVE
品类语义是否匹配看 category detail 返回的现有成员，零件类型是否同类
一个编码可能对多条记录

比如 1013-A001 同时对应「旅充线缆」和「无线充电模组（车端）」。绑定时两条一起走，无法只绑一条。如果两条语义差很远，说明历史数据有问题，先修数据。

四、给 Agent 的建议

适合交给 Agent 的四件事

场景用户会说Agent 做什么
编码核对「这几个编码在不在」批量查，输出存在/不存在清单，附当前归属品类
绑定前体检「把 A 绑到 B」查 A 的状态和旧归属，查 B 是否生效、成员是否同类，判断是首绑还是改绑
人员查询「这个品类采购是谁」查品类详情或编码列表，直接回答姓名
批量盘点「哪些还没绑」拉待绑定清单，按结构码前缀分组

写操作交给谁

建议：Agent 出命令，人来执行

三个原因：编码不存在时 CLI 不报错，Agent 容易误判成功；改绑会静默改变归属，Agent 不知道用户是否知情；解绑不传编码会清空整个品类。

如果坚持让 Agent 执行，至少加两道保护：写之前必须 dry-run 并展示结果，写之后必须回查三字段。

推荐的三步走

第一步：答复核结果，不急着动手
用户说「把 1015-B009 绑到 CAT-00009」，Agent 应该先给核查表：现在绑在哪、目标品类是什么、是首绑还是改绑、语义是否匹配。
第二步：给命令，标风险
dry-run 命令在前，正式命令在后。如果是改绑，明确写出「会从 XX 品类移出」。
第三步：执行后回查
确认 bindStatus、categoryCode、buyerName 三项都对。这一步能兜住「编码不存在却以为成功」。

四条值得写进 Agent 规则

规则内容
先查后写任何 bind / unbind 前，必查编码状态和目标品类状态
标注改绑已绑定且品类不同的，明确提示这是改绑
拒绝全清用户说「解绑这个品类」但没给编码时，要二次确认并说明会清空全部
不猜编码编码查不到就报「不存在」，列出同前缀的现有编码让用户比对

对话应该长这样

用户：把 1015-B009 绑到 CAT-00009

Agent：查了一下——

· 1015-B009「高压线束分线器-二分四」，现在绑在 CAT-00284「高压连接器」
· CAT-00009 是「底护板」，现有 5 个成员都是护板类零件
· 这会把高压线束零件搬到「底护板」，品类看起来不匹配

确认要绑到 CAT-00009 吗？另外还需要采购员姓名。
