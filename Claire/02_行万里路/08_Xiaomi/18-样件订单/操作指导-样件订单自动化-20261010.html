1.3 渐进式落地：CLI → Skill → Agent → 平台，四层递进、逐层验证

L1
CLI · 原子能力层
把 EP 能力下沉为命令行，先验证「自动能不能做」。
样件订单：dx-ep CLI 1.0.7-beta.4，staging 网关跑通 query-ready / create-order / submit-list / import-json 全套命令。
L2
Skill · 场景封装层
命令流封装为可复用技能，输入输出标准化，单环节独立可用。
样件订单：demand-import 散件专用 / demand-check 试制专用 / demand-query 查询分组 / demand-order 合并下单 / daily-report 日报。
L3
Agent · 智能编排层
技能串成业务流，自然语言发起 + 自动执行 + 人工拍板。
样件订单：AgentSpace 对话 + 定时任务；群机器人通知、回 AgentSpace 确认；人只留 2 个拍板点。
L4
平台 · 业务承载层
工作台 + 留痕 + 通知 + 多角色，形成运营闭环。
样件订单：飞书工作台执行日志唯一权威 + 需求进度表实时刷新 + 三层留痕 + 群通知分层。
三条原则：逐层验证，每层先在验证环境跑通再叠加；寄生增强，不替换 EP 系统，风险隔离；人机分工，AI 跑腿、人只拍板，每个拍板点都有预览页 / 确认页支撑。
上线路径：验证环境逐层跑通 → CLI 正式版发布即切换，查询 / 分组 / 下单 / 日报一次从测试网关落到正式接口 → Skill 与 Agent 迁移正式环境，每日推送、确认、下单、日报自动运转，人只拍板。
2使用方式
同一套能力，按场景选择入口：对话 / 定时任务 / 线下
💬 方式一 · AgentSpace 对话
打开 AgentSpace 里的 Agent，如「订单自动化」，随时用自然语言发起：查可下单需求、生成确认页、下单、出日报。不止固定流程——大模型按你的话做个性化执行，例如「只下 A 供应商的单」「跳过这批」「一品一点的直接下，一品多点的先给我确认」「按项目汇总今天的」；结果在对话框给链接和统计，人工确认也在对话框完成。
适合：日常随时发起、例外处理、临时查看、个性化需求
⏰ 方式二 · 定时任务 / 工作流
在 AgentSpace「自动化」里配置定时触发：每天固定时间自动跑完整链路「需求导入 → 查询 → 确认页 → 待人工确认 → 下单 → 日报」。群机器人把结果推给相关人。
适合：每日例行、无人值守、到点自动
🖥️ 方式三 · 线下本地 Agent
在本机终端直接跑 Skill，python 脚本，输入输出与云端一致。适合调试、自测、或在本地环境单独跑某一环节。
适合：开发调试、本地验证、离线排障
三者关系：三种方式共用同一套 Skill 和同一份配置，产物确认页和日报都上传到同一个 FDS 链接体系、日志写同一个面板——换入口不换数据，互不冲突。

4.1 任务流如何转起来

  1. 定时驱动：AgentSpace「自动化」配置 cron 任务，如每个工作日 9:30，到点自动唤起 Agent，无需人盯。
  2. 自动编排：Agent 按预设流程依次调用 Skill：查询可下单需求 → 分组 → 生成确认页 → 上传 FDS 拿链接。
  3. 群机器人通知：关键节点发飞书群卡片——「查询完成：可下单 X 条，一品一点 N 组 / 一品多点 M 组，无供应商 K 条，确认页链接」，卡片尾部带「🛰️ 前往 AgentSpace」引流链接。
  4. 回 AgentSpace 交互：人点卡片回 AgentSpace，在对话框/确认页完成「选供应商 + 确认执行」；确认后 Agent 继续下单、出日报，再推结果卡片。
为什么群机器人是唯一主动主体：AgentSpace 空间内消息、空间机器人、群机器人三处各发一遍会重复打扰。约定：主动通知只走群机器人，含引流回 AgentSpace 的链接；AgentSpace 空间内只回一句短摘要：状态+批次+链接，不重复贴全文。

4.3 任务链接，引流用

  • 每个 AgentSpace 任务有独立详情页：https://agent-space.ev.mioffice.cn/order/issues/<taskId>，taskId 为 UUID，如 WS-51 → …/order/issues/82b5bb2f-fba1-4af1-851c-bd40d7ac7dfe
  • 运行前把当前任务链接注入 AGENTSPACE_TASK_URL，群卡片尾部「🛰️ 前往 AgentSpace」自动渲染为可点击直达
  • Agent 也可以从平台「我的任务」页自动取当前任务链接注入
4三个角色怎么用
研发需求管理员 / 订单管理员 / 需求申请人，各自做什么、看到什么，能力全景的角色速查版
研发需求管理员
负责需求导入：每天早上收到「今日待导入」推送，明细 + 预览链接→ 确认后导入 → 导入结果推群。使用「需求导入 Agent」或定时任务。
订单管理员
负责查询与下单：收到「查询完成」推送 → 打开确认页盘点：一品一点直接确认，一品多点选供应商→ 回 AgentSpace 确认执行 → 收到下单结果和日报。也可随时对话发起：「查一下今天可下单需求」。
需求申请人
关注进度：不用自己盯系统，需求进度表实时显示下单状态；订单完成后自动收到通知。想看进展随时在群里问，或打开进度表看自己的需求到哪一步。
进度可见性：执行日志面板，唯一权威日志；需求进度表，按需求人维度展示下单状态；群通知，主动推送，三层留痕覆盖"谁在什么时候做了什么、结果如何"。

7.3 关键业务规则

  • 分组内核：供应商取 supplierOptions 去重稳定排序，逐条判 单供/多供/无供，六字段键聚合：originType|brNo|brLineNumber|companyEntityId|supplierId|buyerId
  • 60 天窗口：要求到货日期超出 60 天剔除，不进确认页、报告剔除数
  • 多供应商不再静默按首供处理：全部进确认页待人工选，不自动下单
  • 下单路径由用户选定：对话中指定「一品一点直接下单」或「一品多点先选供应商」；一品一点核对即执行，一品多点勾选供应商后自动合并重分组再执行
  • 无供应商项：标 needs_human: true，不自动下单，人工介入
  • 下单按订单组合并：同键多需求 → 一条 create-order，--pr-ids 逗号拼全部成员；价格取 CLI 最新最低价，EP 侧判断
  • 下单不可逆：执行前必须二次确认；结果严格分 submitted_success / submitted_as_draft / create_failed / planned，草稿/状态不明绝不报成功
  • 飞书卡片无法回调交互：确认一律引导回 AgentSpace 对话框操作

6常见问题与异常
高频问题速查
1. 我可以不跑全流程，只单独查一下吗？
可以。每种 Skill 都能单独调用：「查一下今天有哪些可下单需求」「把确认页重新生成一下」「发一下昨天的日报」。在 AgentSpace 对话里直接说即可。
2. 一品多点一定要人工选供应商吗？
是的。多供应商项不自动按首供下单，确认页里逐行选择供应商，默认勾选 EP 推荐；选完自动合并重分组，确认后执行。避免猜错供应商下错单。
3. 我怎么知道任务跑到哪一步了？
群机器人每个节点推卡片；也可以打开需求进度表按需求人维度看下单状态，或执行日志面板看完整留痕：谁、何时、做了什么、结果。
4. 飞书卡片上能直接点确认吗？
不能。飞书卡片不支持回调交互，所以卡片只做通知+引流，真正的确认回 AgentSpace 对话框做，这也是「返回 AgentSpace 交互」这一环存在的原因。
5. 定时任务跑挂了怎么办？
看群卡片里的失败原因 + 执行日志面板的失败记录；常见是 CLI 登录态过期或网关不可达，重新登录/修复后手动重跑一次即可。日志面板有 failed 记录可回溯。
6. 通知会不会太吵？
已做分层：主动通知只走群机器人一张卡，AgentSpace 空间内只回一句摘要，三处不重复。无结果也会发「查询完成：暂无可下单需求」，让群知道今天盘过了。
