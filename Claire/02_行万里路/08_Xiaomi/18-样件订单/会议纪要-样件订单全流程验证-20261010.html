一背景与方案说明

  • 项目定位：样件订单自动化数字助理，Agent 跑腿、人只在关键节点拍板
  • 技术路径四层渐进：CLI 原子能力 → Skill 场景封装 → Agent 智能编排 → 平台业务承载
  • 底层能力：dx-ep CLI，当前 1.0.7-beta.4，staging 网关验证
  • 5 个 Skill：demand-import 散件专用、demand-check 试制专用、demand-query 查询分组、demand-order 合并下单、daily-report 日报
  • 三种使用方式：AgentSpace 自然语言对话、定时任务工作流、线下本地 Agent 直跑，共用同一套 Skill 与配置
  • 方案文档：详细版 sample-order-operation-guide-20261010
  • 简化版 sample-order-achievement-20261010
  • 本次会议围绕方案做全员试用、逐环节验证与上线决策

二需求来源与职责分工

散件需求

  • 路径：研发工程师在收集表登记 → 需求导入 Skill 处理并导入 EP → 每日推送「今日待导入」+ 预览页 → 人确认后导入
  • 决议：需求导入 Skill 移交石海琳团队自行维护，我方只负责接需求往下下单

试制需求

  • 路径：需求提交方提交 → 需求检查 Skill 检查 PASS / WARN / FAIL → 导入 MiPEC
  • 卡点一：尚未做价格查询，与价格台账对比暂无法实现，等价格小 AI 就绪后有希望
  • 卡点二：AgentSpace 交互需传文件、单独跑 Skill，与系统内跑流程不同，不顺畅
  • 决议：试制需求整体往后搁置，先不投入

角色分工

  • 需求导入方（石海琳团队）：每天收一个统计，确认导入即可
  • 订单管理员（我方）：每天收可下单订单，确认、下单，并关注进度

三全流程演示与验证

1. 查询可下单需求

  • 批次号等于当天日期加流水号，自动生成
  • 本次结果：10 条需求、3 个零件、涉及多家供应商、一品多点 0 条
  • 与 EP 采购任务管理近两个月数据逐条核对：剔除无价格需求 5 条，可下单约 6 条，最终 10 条口径一致，验证通过

2. 自动分组与确认页

  • 一键生成一品一点确认单，可点查看详情看分组明细
  • 确认页只做展示、不做交互，与系统不打通
  • 正确用法：回 AgentSpace 对话回复「确认执行」，或把生成结果复制回去由 Agent 执行
  • 一品多点：在页面选供应商 → 生成确认结果 → 复制回 AgentSpace 下单

3. 自然语言交互

  • 模型为 Mimo 2.6，现场评价可用
  • 只下单某一需求行号：Agent 直接沿用已查数据执行，不重走查询 Skill，验证通过
  • 自然语言识别零件「前轮毂轴承」成功
  • 场景权衡：批量大量下单用 Agent 快；单个临时操作页面勾选更快

4. 执行下单

  • 按订单组合并同键需求，一条 create-order 下单，价格取最新最低价，结果四分类：成功 / 草稿 / 失败 / 计划
  • 本次用 dryrun 演示，成功数为 0 属预期
  • 异常项：订单 22829 提交后状态显示「已审批中」而非草稿，疑似 dryrun 或提交逻辑问题，待确认

5. 统计日报

  • 自然语言「查 9 月 1 日至今执行日报」自动按模板生成，两分钟内出结果
  • 区分手动下单与自动下单来源，有字段标识
  • 14 天无下单也能正常输出样式，模板可调

6. 留痕

  • AgentSpace 运行全局留痕，谁做了什么随时可查
  • 本地运行只在本机留痕，无全局视角

四产品决策

  • 一品一点与一品多点拆分：一品一点直接成组下单；一品多点保留但可选择不下，两者不绑定
  • Agent 收敛：一个 Agent 对一个 Skill 对话，各自封装最终版本
  • 避免 at 其他 Agent 下单时用到对方非挂载 Skill，防止下错
  • 需求池剔除：下单失败、被驳回、已删订单的需求会回到需求池，采购老师未及时处理会被再次下单，需要支持剔除
  • 提交人机制：Skill 自动获取当前操作用户作为下单人，不默认公共账号；定时任务可显式指定提交人
  • 下单期限约 60 天限制，印象中已配置，可调但需确认

五环境与技术问题

  • 401 模型不在 key 可用范围：模型配置或环境变量需切换，Agent 内可改
  • FDS 生成网页缺凭证：FDS 能力已内嵌在 Skill 中，凭证需补齐
  • 登录授权：逐个开通 AgentSpace 访问权限，现场排查小米账号、密码与环境问题
  • 多 Agent 同时触发：Skill 会获取实际操作用户作为下单人，可区分

六结论与决议

  • 流程定型五步：查可下单需求 → 自动分组 → 人工确认 → 执行下单 → 统计日报，删减复杂能力先跑通
  • 正式环境是否使用由个人自行掌握自由度
  • 试用两天熟悉后自由发挥，Skill 可在本地改通后自行上架
会议总结（齐岳）：今天大家基本都试用了一下，下周安排 CLI 尽快上线，同步将 Skill 上线到 AgentSpace 正式环境，大家就可以正常使用了，后面可以发挥空间。
