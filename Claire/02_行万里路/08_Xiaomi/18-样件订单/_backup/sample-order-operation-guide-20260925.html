1.2 角色旅程一：研发需求管理员 —— 每天 9:30 被自动叫醒，确认导入即可

👤 研发需求管理员
负责：需求导入｜接触：需求收集表 + 群推送 + 导入预览页 + 导入结果
场景 ① 早上 9:30
收到「今日待导入」群推送
群机器人定时任务触发，卡片带：今日待导入明细 + 导入预览链接 + 有效/无效统计
场景 ② 打开预览
核对待导入需求
预览页按需求逐行展示（零件、预算、数量、要求到货日期、需求人），一眼确认字段对不对
场景 ③ 确认导入
回到 AgentSpace 对话框说「确认导入」
飞书卡片无法回调交互，确认统一回 AgentSpace 完成；导入结果自动推群 + 写执行日志
之前（手动）
  • 每天手动进表格翻「样件导入状态=待导入」的记录，逐条核对字段
  • 手工拼参数、逐条导入，导入完没人知道、没有留痕
  • 忘了没人提醒——「今天没导」要等下游问了才发现
提升点
到点自动提醒预览先行核对结果留痕推群 导入这件事不再靠记性，确认动作从「逐条操作」降到「一句话拍板」。

1.3 角色旅程二：订单管理员 —— 早上收清单，白天点确认，下班前收日报

👤 订单管理员
负责：查询 → 选供应商 → 确认下单 → 日报｜接触：确认页 + AgentSpace 对话框 + 群卡片
场景 ① 上午
收到「查询完成」群推送
卡片带 6 项统计（可下单总量 / 一品一点组数 / 一品多点组数 / 无供应商条数等）+ 确认页链接（一品一点 / 一品多点分开两个链接）
场景 ② 打开确认页
盘点可下单需求
一品一点：每组可直接确认；一品多点：先逐行选供应商，选完自动合并重分组；无供应商项标黄待处理
场景 ③ 确认执行
回 AgentSpace 对话框确认
按订单组合并一条 create-order 下单；结果四分类（成功/草稿/失败/计划）自动推群 + 写日志
场景 ④ 下班前
收到统计日报
两层统计 HTML（概览 + 明细）自动生成推送，不必手搓表格对账
之前（手动）
  • 登录系统逐条查需求状态、翻供应商报价、手工整理可下单清单
  • 一品多点靠电话/群里确认供应商，口头记录容易错
  • 逐条录单、填字段、怕填错；手搓统计表对账发周报
提升点
自动盘库分组确认页直达按组合并下单日报自动生成 人从「搬运工」变成「判断者」，只做两件事：选供应商、拍板。

1.4 角色旅程三：需求申请人（研发工程师）—— 提完需求，等进度自动通知

👤 需求申请人
负责：登记需求 → 看进度 → 收结果｜接触：需求收集表 + 需求进度表 + 群通知
场景 ① 提需求
在需求收集表登记（字段不变）
不改变现有登记习惯，表结构沿用
场景 ② 等进度
打开「需求进度表」即知到哪一步
按需求人维度展示：已导入 / 已下单 / 下单失败，每天定时刷新；不再群里问、人肉跟
场景 ③ 收结果
下单完成自动收到通知
订单执行成功后自动通知需求导入人，附带订单号/供应商
之前（手动）
  • 不知道需求到哪一步，靠群里问、人肉跟进
  • 下单完成与否要等别人通知，甚至自己查系统
提升点
进度表实时可见下单完成自动通知 从「盲等 + 人肉问」变为「开表即知 + 自动推送」。

1.5 一天时间线：整条链路在一天里怎么转

09:30 · 定时任务触发研发需求管理员
群机器人推「今日待导入」（明细 + 预览链接），人确认后导入，结果推群 + 留痕。
09:40 · 查询自动跑订单管理员
查询可下单需求自动盘库分组，生成确认页（一品一点 / 一品多点分链接），推「查询完成」卡片。
白天 · 盘点与确认订单管理员
打开确认页：一品一点直接确认；一品多点逐行选供应商后自动合并；无供应商项人工介入。
确认后 · 执行下单Agent 自动
按订单组合并 create-order，结果四分类推群 + 写日志 + 更新需求进度表。
16:30 · 统计日报订单管理员
日报自动生成（概览 + 明细两层统计 HTML）推送群 + 留痕。
全天 · 进度可见需求申请人
随时打开需求进度表看自己的需求到哪一步，下单完成自动收通知。

2.3 本质变化：三类转变

① 人从「搬运工」→「判断者」
翻表、核对、查询、拼参、统计这些搬运型动作全部交给 Agent；人只保留两件事：选供应商、拍板确认。
② 操作从「逐条」→「按组合并」
同键（同品同预算同行同供应商）需求合并成一条 create-order 批量下单，操作量和出错面都大幅下降。
③ 留痕从「无」→「三层全」
执行日志面板 + 需求进度表 + 群通知，谁、何时、做了什么、结果如何都可回溯；需求人不再盲等。
一句话：上线前是「人肉逐条 + 口头确认 + 无留痕」，上线后是「Agent 跑腿 + 确认页拍板 + 全链路留痕」——人工环节从 6 个降到 2 个。

4使用方式
同一套能力，按场景选择入口：对话 / 定时任务 / 线下
💬 方式一 · AgentSpace 对话
打开 AgentSpace 里的 Agent（如「订单自动化」），用自然语言说需求：「查一下今天可下单的需求」「跑一遍查询+确认页」——Agent 按预设流程编排 Skill，结果在对话框里给你链接和统计，人工确认也在对话框完成。
适合：日常随时发起、例外处理、临时查看
⏰ 方式二 · 定时任务 / 工作流
在 AgentSpace「自动化」里配置定时触发：每天固定时间自动跑「需求导入 → 查询 → 推送」，或整链路「查询 → 确认页 → 待人工确认 → 下单 → 日报」。群机器人把结果推给相关人。
适合：每日例行、无人值守、到点自动
🖥️ 方式三 · 线下本地 Agent
在本机终端直接跑 Skill（python 脚本），输入输出与云端一致。适合调试、自测、或在本地环境单独跑某一环节。
适合：开发调试、本地验证、离线排障
三者关系：三种方式共用同一套 Skill 和同一份配置，产物（确认页/日报）都上传到同一个 FDS 链接体系、日志写同一个面板——换入口不换数据，互不冲突。

4.1 任务流如何转起来

  1. 定时驱动：AgentSpace「自动化」配置 cron 任务（如每个工作日 9:30），到点自动唤起 Agent，无需人盯。
  2. 自动编排：Agent 按预设流程依次调用 Skill：查询可下单需求 → 分组 → 生成确认页 → 上传 FDS 拿链接。
  3. 群机器人通知：关键节点发飞书群卡片——「查询完成：可下单 X 条，一品一点 N 组 / 一品多点 M 组，无供应商 K 条，确认页链接」，卡片尾部带「🛰️ 前往 AgentSpace」引流链接。
  4. 回 AgentSpace 交互：人点卡片回 AgentSpace，在对话框/确认页完成「选供应商 + 确认执行」；确认后 Agent 继续下单、出日报，再推结果卡片。
为什么群机器人是唯一主动主体：AgentSpace 空间内消息、空间机器人、群机器人三处各发一遍会重复打扰。约定：主动通知只走群机器人（含引流回 AgentSpace 的链接），AgentSpace 空间内只回一句短摘要（状态+批次+链接），不重复贴全文。

6三个角色怎么用
研发需求管理员 / 订单管理员 / 需求申请人，各自做什么、看到什么（用户旅程的速查版）
研发需求管理员
负责需求导入：每天早上收到「今日待导入」推送（明细 + 预览链接）→ 确认后导入 → 导入结果推群。使用「需求导入 Agent」或定时任务。
订单管理员
负责查询与下单：收到「查询完成」推送 → 打开确认页盘点（一品一点直接确认 / 一品多点选供应商）→ 回 AgentSpace 确认执行 → 收到下单结果和日报。也可随时对话发起：「查一下今天可下单需求」。
需求申请人
关注进度：不用自己盯系统，需求进度表实时显示下单状态；订单完成后自动收到通知。想看进展随时在群里问，或打开进度表看自己的需求到哪一步。
进度可见性：执行日志面板（唯一权威日志）+ 需求进度表（按需求人维度展示下单状态）+ 群通知（主动推送），三层留痕覆盖"谁在什么时候做了什么、结果如何"。

7.3 关键业务规则

  • 分组内核：供应商取 supplierOptions 去重稳定排序，逐条判 单供/多供/无供，六字段键聚合（originType|brNo|brLineNumber|companyEntityId|supplierId|buyerId）
  • 60 天窗口：要求到货日期超出 60 天剔除（不进确认页，报告剔除数）
  • 多供应商不再静默按首供处理：全部进确认页待人工选，不自动下单
  • 无供应商项：标 needs_human: true，不自动下单，人工介入
  • 下单按订单组合并：同键多需求 → 一条 create-order，--pr-ids 逗号拼全部成员；价格取 CLI 最新最低价（EP 侧判断）
  • 下单不可逆：执行前必须二次确认；结果严格分 submitted_success / submitted_as_draft / create_failed / planned，草稿/状态不明绝不报成功
  • 飞书卡片无法回调交互：确认一律引导回 AgentSpace 对话框操作

8常见问题与异常
高频问题速查
1. 我可以不跑全流程，只单独查一下吗？
可以。每种 Skill 都能单独调用：「查一下今天有哪些可下单需求」「把确认页重新生成一下」「发一下昨天的日报」。在 AgentSpace 对话里直接说即可。
2. 一品多点一定要人工选供应商吗？
是的。多供应商项不自动按首供下单，确认页里逐行选择供应商（默认勾选 EP 推荐），选完自动合并重分组，确认后执行。避免猜错供应商下错单。
3. 我怎么知道任务跑到哪一步了？
群机器人每个节点推卡片；也可以打开需求进度表（按需求人维度看下单状态）或执行日志面板（完整留痕：谁、何时、做了什么、结果）。
4. 飞书卡片上能直接点确认吗？
不能。飞书卡片不支持回调交互，所以卡片只做通知+引流，真正的确认回 AgentSpace 对话框做（这也是「返回 AgentSpace 交互」这一环存在的原因）。
5. 定时任务跑挂了怎么办？
看群卡片里的失败原因 + 执行日志面板的失败记录；常见是 CLI 登录态过期或网关不可达，重新登录/修复后手动重跑一次即可。日志面板有 failed 记录可回溯。
6. 通知会不会太吵？
已做分层：主动通知只走群机器人一张卡，AgentSpace 空间内只回一句摘要，三处不重复。无结果也会发「查询完成：暂无可下单需求」，让群知道今天盘过了。
