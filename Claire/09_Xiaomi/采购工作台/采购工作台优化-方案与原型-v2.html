为什么改：工作台不是功能门户，是我的工作入口

现有首页六个模块方向正确，但四个结构性问题让它停留在"信息展示"，没有成为"行动入口"。
PAIN 01

待办罗列，无轻重

各模块单据堆进列表，不分紧急度、不标 SLA、不能行内处理，每件事都要点进详情页操作一遍。

处理一条待办平均 3 次跳转
PAIN 02

工作流导航本质是表格

一个包一行单据，包一多就乱；进度按"完成环节数"粗算，看不出谁在办、卡在哪、停了多久。

负责人包多时该模块失效
PAIN 03

首页信息过载

流程、AI、动态、概览全部平铺一屏，缺少"一眼看出我做了什么、哪些要弄"的汇总视角。

老板与执行者看到的信息相同
PAIN 04

菜单找不到

菜单按系统模块组织、数量多，没有主题化分组、收藏和最近访问，新人跨职能都难定位页面。

改一个页面找半天
"我看了导航，根本看不明白。""首页是不是东西太多了？一眼都能看出来我做了什么东西、哪些东西要弄，这一块挺好的。"

改成什么样：三条原则，八个模块

🎭

原则一 · 角色化

组件库 → 角色配置 → 个人自定义，三层结构。组织默认版兜底，角色决定模块组合，个人再微调顺序与收藏。PM 看进度与负荷，CE 看核价与偏差，采购员看待办与回标。

⛓️

原则二 · 流程驱动

以 SOR→BDL→RFQ→定点→合同 业务主线为骨架，待办挂在节点上，节点点进去就是工作现场；一个流 Workspace 让新场景一次性分步骤走完。

🤖

原则三 · AI 前台化

已开发的 skill 全部前置到工作台：点击 skill 即把映射 prompt 填入 EP 智能助手并切到对应 Agent。从"能力罗列"到"查得准、答得对、能催办"。

怎么落地：先方案定组件，再按评估排期

会议结论：Miracle / IDP 组件不可搬运，EP 全部基于 Ant Design 3.26 原子组件重新组装；能拼装的先上，需新开发的提前立项。组件逐项评估见「组件清单与路线」页。

会议结论 · 回应「重复建设」关切2026-10-13 与前端 叶放 / 张平 对齐

  1. 不搬运、不另起。Miracle 工作台与 EP 底层框架、技术栈不同，代码无法迁移，只借鉴交互形态；EP 不自建第二套设计体系，全部用 EP 现有 antd 3.26 原子组件组装，样式与线上页面天然一致。
  2. 不自建第二个 AI 助手。EP 智能助手是通用 NPM 包，工作台只做「入口 + 上下文注入」：skill 点击调用助手方法填入 prompt、切换 Agent；对话运行时、鉴权改版均由助手侧演进，我们只提接口需求。
  3. 不重复开发 skill 本身。已开发的 CLI / AgentSpace skill 直接挂到 AI 能力入口展示与调用，工作台不造第二套 Agent 执行链路。
  4. 不建第二条统计链路。待办完成率、逾期数、停留时长等统计走后端开放接口供数，前端只展示；参考系统已验证该模式可行。
  5. 唯一确认的新开发件：拖拽布局设计器（涉及布局状态保存接口，P1）；首期用「显隐 + 排序 + 收藏」降级满足业务诉求。
  6. 流程结论：先方案后组件再排期——周四方案评审定模块，按「组件清单与路线」页逐行评估排期，12 月开发窗口前完成组件储备；菜单主题化改版先与业务确认必要性，避免过度设计。
