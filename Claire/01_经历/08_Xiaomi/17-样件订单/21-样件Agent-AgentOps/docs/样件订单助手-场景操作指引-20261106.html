030 秒速查

不知道现在该干什么时，先看这张表。

我现在想…去哪里/发什么看什么可以做什么
看今天还有多少要下 工作台仪表盘 / 一品多点待选表 待下单、待选供应商、临期、已过期补单 按优先级安排；先处理临期和过期；不要直接全选下单
下一品一点 发「查询一品一点需求」 卡片：预计下单几张订单、试制/散件、升版几条 点卡片「确认执行」；只下部分发「下单 <需求号>」；核对页只看不下单
下一品多点 发「查询一品多点需求」→「一品多点待选」表 每需求一行：候选供应商、选择供应商、项目、采购员 在「选择供应商」下拉选一家 → 回对话说「按表下单」→ 核对预演卡 → 确认
看刚才下得怎么样 等机器人结果卡 / 看结果页 成功、草稿、失败；失败逐需求六字段 成功不用管；草稿去 EP「我的草稿」；失败按原因处理；不要整批重下
有需求不想下 「剔除需求」多维表格 需求号、备注 填需求号；列表类查询统一排除（一点/多点/BR/来源/筛选），工作台同步清掉可操作的剔除行；指定执行某个需求号时放行；不用每次发剔除指令
下不了单/权限报错 看机器人回复 是否提示「当前账号无下单权限 / viewer:A」 换有 B 级权限账号，或找 EP/GarageHub 管理员开通

1什么时候看什么、可以做什么

按一天/一周的使用节奏排；每个时点只做这一格的事。

每天上班
5 分钟
看：工作台仪表盘 → 待下单 / 待选供应商 / 临期 / 已过期补单

做：先处理临期（7 天内）和已过期补单；确认今天必须下的项目。

不要：一上来全选下单；不要用旧「需求进度表（旧·候选行归档）」。

准备下一品一点
看：「查询一品一点需求」卡片：预计下单张数、试制/散件、升版条数

做：核对数字 → 点卡片「确认执行」；只下部分用「下单 <需求号>」。

不要：打开核对页点按钮当执行；核对页按钮只是「复制选择结果」。

准备下一品多点
看：「一品多点待选」表：候选供应商、选择供应商、项目、采购员、到货日期

做：按采购员/项目筛选 → 每个需求在「选择供应商」下拉选一家 → 回对话「按表下单」。

不要：选候选范围外的供应商；同一需求不要填多家（会被拒绝）；不要直接改候选列。

按表下单预演后
看：预演卡：订单数、供应商、需求号、件数

做：确认供应商与数量无误 → 点「确认执行」。

不要：预演卡还没看就点确认；不要重复点旧卡。

执行中
看：回执「⏳ 正在下单中」

做：等结果卡；期间可继续看仪表盘，但不要再发下单指令。

不要：重复点击确认；不要因为没立刻出结果就重下。

结果卡到了
看：成功 / 草稿 / 失败；失败明细逐需求：订单号、BR号:行、BR剩余、需求号、零件号、需求人、订单总价、差额

做：成功不用处理；草稿去 EP「我的草稿」提交；失败按原因处理。

不要：看到失败就整批重下；不要把「草稿」当成创建失败。

每天下班前
3 分钟
看：待选表是否还有「待确认」；结果卡是否有未处理失败

做：把未处理的草稿/失败记下来；核对今日订单与 EP 一致。

不要：把「待确认」留过夜（24h 会自动复位为待下单，选择会被清空）。

每周复盘
10 分钟
看：仪表盘：待下单趋势、项目/采购员分布、临期与过期；查询批次备份

做：清理长期不下的需求（进剔除表）；核对执行日志与订单结果。

不要：把仪表盘当实时数据（HTML 是快照，看最新请重新查询）。

2两条主流程

一条直接下，一条先选供应商再下；两条不要混。

一品一点 · 单供应商

一行 = 一张订单，供应商已确定；只核对，不选供应商。

1发查询查询一品一点需求
2看卡片订单数 / 试制散件 / 升版
3点确认卡片「确认执行」
4收结果结果卡逐需求明细
只下部分：回复 下单 <需求号>。核对页仅用于看明细和复制选择结果，不在页面直接下单。

一品多点 · 多供应商

一需求一行；候选供应商由系统给，选择供应商由人选。

1发查询查询一品多点需求
2进待选表选「选择供应商」
3按表下单预演卡核对
4点确认结果卡 + 状态回写
选择供应商是全局下拉，可能列出所有供应商；请以该行「候选供应商」为准，选错会被机器人拒绝，不会按默认供应商下单。

3「一品多点待选」表怎么用

一需求一行；人员字段是飞书人员，有限项字段是下拉。

列格式怎么用
采购需求单号文本一行一个需求号；不要再按需求号分组（已经一需求一行）
候选供应商多选标签系统给的可选范围，不要改；本行只应从这里选
选择供应商单选下拉人工选一家；选好后进度变为「待确认」
历史供应商已清空/停用不再维护，避免下拉出现历史噪音
进度节点单选待下单 / 待确认 / 已下单 / 草稿待提交 / 下单失败 / 异常·剔除 / 已拦截 / 已过期
项目 / 样件类型单选直接筛选/分组；选项随数据自动补齐
采购员 / 需求申请人飞书人员显示头像+姓名，可 @ 人；不是文本
需求数量 / 要求到货日期数字 / 日期用于安排优先级；临期看这里
推荐筛选：采购员 = 我 或 项目 = 当前项目；不建议按「采购需求单号」分组——一需求一行后每组只有一行。
完成后说「按表下单」；机器人只读「选择供应商」非空且进度为待下单/待确认的行。

4结果卡怎么读

先看标题颜色，再看失败明细；不要只看「完成」两个字。

✅ 成功

已提交进入审批流；不需要处理。

⚠️ 草稿 / 有需处理项

订单已创建但未自动提交；去 EP「我的草稿」，不要重下。

❌ 下单失败

订单没建出来；按原因处理（供应商编码/权限/数据）。

预算不足专项（逐需求一行）：
订单号 ｜ BR号:行 ｜ BR剩余 ｜ 需求号 ｜ 零件号 ｜ 需求人 ｜ 订单总价 ｜ 差额
4900047806 ｜ BR202606240006:235550 ｜ ¥1,064.22 ｜ EP20261104000143 ｜ P000009827001 ｜ qiaozenan ｜ ¥21,528.76 ｜ ¥20,464.54
处置：找预算负责人加额度 → 只重下剩余需求；不要整批重下。

5异常与草稿

常见失败

原因处理
非 SAP 正式供应商编码联系采购员核对供应商主数据/换供应商，不能硬下
预算行额度不足按 BR 号加额度，再只下剩余需求
非最低价订单只建草稿；去 EP 核对价格后提交，不重下
无 B 级权限换有权限账号 / 找管理员开通（viewer:A 只能查）
批次不一致重新查询后再下单；旧卡片/旧选择作废

不要做的事

❌ 失败/草稿整批重下

❌ 在核对页点按钮当执行（只是复制结果）

❌ 同一个需求选多家供应商

❌ 改「候选供应商」列或填候选外供应商

❌ 用旧「需求进度表（旧·候选行归档）」

❌ 未看数字就点「确认执行」

6字段与口径

口径定义单位
订单一品一点一个订单组（同供应商/采购员/预算行合并）张
需求采购需求单号；一品多点一需求一行条
升版需求operationType=02，历史版本无订单、可进可下单池条（可附涉及订单）
临期 / 过期到货 ≤ 今天+7 / < 今天，且未下单条
失败 / 草稿EP 创建失败 / 创建成功但自动提交失败张
异常拦截本地规则未放行（升版/数量/字段/身份）条
所有卡片里的「张」是订单，「条」是需求；升版看「条」。不要把「组」当订单——旧口径已废弃。

7权限与需要手工做一次的设置

权限

角色能做什么
viewer:A查询、看工作台/结果；不能创建订单
editor:A,B查询 + 创建订单 + 提交审批

qiyue 当前 viewer:A，真实下单前需开 B 级；权限未开时机器人会直接中文提示，不会白跑 EP。

手工设置（各 1 分钟）

1. 待选表按采购员/项目设置筛选视图（不要按需求号分组）

2. 隐藏不需要的列：交付地址、订单号、批次号等

3. 维护「剔除需求」表；历史供应商已清空停用

4. Base 仪表盘组件需要单独授权后重建；当前以 HTML 仪表盘为准

两个硬提醒
① 卡片上的「确认执行 · N 张订单」是按当前批次全量下单，不是演练；只下部分请用「下单 <需求号>」或工作台选行。
② 每笔操作记录批次号；异常时把「批次号 + 截图 + 时间」发给 qiyue，不要自己反复重试。
