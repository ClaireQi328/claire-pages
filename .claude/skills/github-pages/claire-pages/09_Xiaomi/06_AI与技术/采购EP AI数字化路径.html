Schema 化：把采购知识变成机器可消费的契约

防幻觉不靠「提示词祈祷」，而靠结构化契约。三类 Schema 贯穿全链路：本体定义「有什么」，参数 Schema 约束「能传什么」，规则 Schema 固化「什么算对」。

① 本体 Schema（L1 直接可用）— 七大域 → JSON Schema 把 Ontology 的实体/关系落成强类型 JSON Schema，作为 RAG 检索与实体校验的底座。 
# 供应商实体 Schema（节选）
Supplier:
  type: object
  properties:
    supplier_id:  { type: string, pattern: "^SUP-\d{6}$" }
    tier:         { type: integer, enum: [1, 2, 3] }
    grade:        { type: string,  enum: ["A", "B", "C"] }
    bank_account: { type: object, required: [bic, iban] }
  required: [supplier_id, company_name]
② 参数 Schema（L2 NL2CLI） 每个 CLI 参数限定类型/格式/枚举，并绑定数据库存在性校验，防止编造实体。 
part_no:
  pattern: "^[A-Z]{2,4}-[A-Z]{2,4}-\d{4}-\d{3}$"
  validate: "SELECT 1 FROM parts WHERE part_no=:v"
  on_fail: "零件号不存在，格式 XX-XX-XXXX-XXX"
supplier_id:
  pattern: "^SUP-\d{6}$"
③ 规则 Schema（L3/L4 可执行） 业务规则与编排流程声明式落盘，版本可控、可回滚。 
# L3 编排 DAG（节选）
steps:
  - id: check_sor
    cli: dx-ep sor info --material-num {{part_no}}
    next:
      - when: data.state == "ACTIVE"; goto: check_rfq
      - when: true; fail: "SOR 未激活"

信息闭环：一次请求的旅程

请求自上而下穿透「接入层 → 智能能力层 → dx-ep CLI → EP 业务系统」；执行结果与用户对推荐的采纳 / 拒绝反馈自下回流至模型与规则库，构成持续优化的闭环。

分层技术实现

L1 知识问答 让 AI 听懂采购语言RAG
目标：新人直接问，AI 基于 EP 知识库给带引用的精准答案，不编造。
距离 / 进度已启动 · 试点
当前：本体七大域图谱已梳理、3 个高频问答 RAG POC 试点 → 目标：JSON Schema v1 全量落地、问答准确率 ≥95%、检索召回 ≥90%
技术实现Query 改写 → 混合检索（向量 BM25）→ 重排 → 上下文组装+业务规则注入 → 生成（带引用）→ 实体一致性校验。组件：Milvus / bge-large-zh-v1.5 / mimo-v2.5 / bge-reranker。
Schema 约束检索片段余弦相似度 <0.6 直接丢弃；答案实体必须出现在检索结果中；相关度不足明确拒答「文档未找到」。
需要做些什么① 七大域图谱 → JSON Schema v1；② 选 3 个高频问答做 RAG POC；③ 知识运营岗常态化审核口径。
L2 单域操作 一条指令，全链路状态一目了然NL2CLI
目标：自然语言 → 预定义 CLI 命令，自动查/自动执行，参数强制校验。
距离 / 进度已启动 · 定义完成
当前：18 条 WAVE1 CLI 命名空间已定义（dx-ep <domain> <resource> <action>）→ 目标：对接 EP 后端 API、NL2CLI 转译准确率 ≥92%、5 条命令优先 POC
技术实现意图分类 → 参数提取 → Schema 校验 → 指令组装 → 执行+格式化。18+ WAVE1 命令统一命名空间 dx-ep <domain> <resource> <action>，返回 {state,message,data}。
Schema 约束指令白名单（仅 18 条）；参数正则+DB 存在性校验；操作类二次确认；temperature=0.1 低温解码。

输入: "查 MOT-ED-2025-001 的报价进度"
→ intent: QUERY
→ param:  part_no = "MOT-ED-2025-001"  # 过参数 Schema
→ cli:    dx-ep rfq quote list --part-no MOT-ED-2025-001
→ out:    "RFQ-2025-0089 第2轮，截止 2025-06-20，已发 3 家"
需要做些什么① 18 CLI 对接 EP 后端 API（后端）；② NL2CLI 引擎（LLM+Schema 约束，AI 团队）；③ 锁定 5 个 WAVE1 命令优先转译 POC。
L3 跨域协同 一个意图，串联全流程Orchestration
目标：一句话触发多步 CLI 编排（SOR→RFQ→预选→物流→定点），每步校验前置条件。
距离 / 进度待启动
当前：YAML DAG 编排范式已验证（SOR→RFQ→定点 demo）→ 目标：编排引擎上线、4 大场景模板、断点续跑 / 超时回滚
技术实现YAML DAG 声明式定义；Python+asyncio 轻量执行；Redis 存状态（断点续跑/超时回滚）；关键节点嵌飞书审批流。
Schema 约束每步执行前校验数据状态；失败提示具体断点+原因；写操作失败自动回滚；连续失败升级人工。
需要做些什么① 编排引擎（DAG 运行时）；② 4 大场景模板（定点可行性/供应商360/价格影响/订单异常）；③ 场景识别框架接入真实业务流。
L4 智能分析 从人找数据到数据找人Rule Engine
目标：基于全链路数据主动识别异常、预警风险、产出分析报告。
