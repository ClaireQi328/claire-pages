# SRM 平台化与生态设计探索

> 从"采购内部工具"到"供应链生态平台"的跃迁。基于字节 SRM 实践的平台化路径设计。

---

## 💡 核心观点

> [!tip] 一句话总结
> SRM 平台化的核心不是技术开放，而是**数据网络效应**：供应商越多 → 数据越准 → 采购决策越优 → 吸引更多供应商。

---

## 一、整体：从管道到平台

### 1.1 当前 SRM 的"管道模式"

```
现状（管道模式）：
  采购团队 ──► SRM系统 ──► 供应商（被动接收）

  特征：
  - 供应商只是"被管理对象"
  - 数据单向流动（采购方 → 系统）
  - 供应商端体验差（填表、等审批、被动通知）
  - 平台价值 = "内部提效工具"
```

### 1.2 目标：平台模式

```
目标（平台模式）：
               ┌────────────────┐
  供应商 ──────►│   SRM 平台     │──────► 内部业务方
  (主动参与)    │                │         (自服务)
  ◄────────────│  撮合/连接/赋能 │◄────────
               └────────┬───────┘
                        │
                 第三方服务接入
                 (金融/物流/认证/征信)
```

### 1.3 核心指标对比

| 维度 | 管道模式（现在） | 平台模式（目标） |
|------|----------------|-----------------|
| 供应商参与度 | 被动填表、等通知 | 主动维护信息、自主报价、自我管理 |
| 数据流向 | 单向（采购→系统） | 双向（供需双方共创） |
| 生态参与者 | 仅采购+供应商 | +金融/物流/认证/行业协会 |
| 平台价值 | 内部提效 | 生态网络效应 + 数据资产 |
| 护城河 | 功能完备度 | 供应商网络 + 数据积累 + 转换成本 |


## 二、局部：4 层开放设计

按"开放程度从低到高"分 4 层：

### 2.1 供应商信息层 — 最基础的开放

**现状痛点**（来自字节八爪鱼 II 期）：
- 供应商信息模块仅支持间采基础能力
- 信息碎片化，缺少 360° 整合
- 生产型/非生产型供应商无法分流管理

| 开放内容 | 开放对象 | 开放方式 | 价值 |
|---------|---------|---------|------|
| **供应商主数据**（基础信息、资质、认证） | 内部业务方 | 自服务查询 | 业务方自助找供应商 |
| **供应商 360° 画像** | 内部 + 授权合作伙伴 | API + 数据面板 | 采购决策有据可依 |
| **供应商能力目录**（品类、产能、技术能力） | 内部 + 供应商自维护 | 供应商门户 | 供应商主动更新，减少信息滞后 |
| **供应地图** | 内部全员 | 可视化看板 | 供应链透明度提升 |

**关键设计点**：
- **供应商自维护门户**：供应商登录后可自行更新资质、产能、案例等信息，平台做审核验证
- **信息分级**：公开信息（品类、能力）→ 受限信息（价格、合同）→ 机密信息（审计结果）
- **数据验证闭环**：供应商填报 + 平台自动校验（工商数据/征信）+ 采购方确认

### 2.2 定点关系层 — 最具杠杆的开放

**核心开放点**：

| 开放内容 | 场景 | 说明 |
|---------|------|------|
| **定点关系图谱** | 内部决策 | 哪些品类过度依赖单一供应商？替代方案在哪里？ |
| **定点合理性分析** | 合规审计 | 指定原因是否合规？（参考 11 类指定原因） |
| **替代供应商推荐** | 风险管控 | 基于能力匹配 + 历史绩效，推荐替代选项 |
| **定点健康度看板** | 管理层 | 定点覆盖率、单一来源比例、风险敞口 |

**定点关系知识图谱**：

```
供应商A ──定点──► 品类X ──关联──► 项目1
   │                │
   ├──绩效数据      ├──合同条款
   ├──风险状态      ├──价格趋势
   └──ESG评级       └──替代供应商
```

### 2.3 协同交互层 — 从"管理"到"协作"

| 交互场景 | 当前状态 | 平台化设计 |
|---------|---------|-----------|
| **寻源竞价** | 人工发标、邮件沟通 | 供应商在线竞价/反向拍卖 |
| **JIT/VMI 协同** | 电话+邮件催货 | 实时库存共享 + 自动补货指令 |
| **质量协同** | 线下整改 | 在线质量异常 → 整改跟踪 → 效果验证 |
| **赋能培训** | 无 | 供应商门户：培训课程、最佳实践 |
| **联合研发** | 邮件/飞书沟通 | 需求规格共享 → 方案评审 → 样品跟踪 |

**供应商端自服务能力矩阵**：

```
□ 信息维护    — 自主更新企业信息、资质、产能
□ 机会发现    — 查看可参与的寻源项目
□ 在线报价    — 参与竞价/投标
□ 订单协同    — 接单 → 确认 → 发货 → 对账
□ 绩效查看    — 查看自身绩效评分和改进方向
□ 融资申请    — 基于交易数据申请供应链金融
□ 培训学习    — 参与平台赋能课程
□ 风险申报    — 主动申报经营风险/产能异常
```

### 2.4 生态接入层 — 第三方服务开放

```
SRM 生态接入架构：

  ┌─────────────┐  ┌─────────────┐  ┌──────────┐
  │ 供应链金融    │  │ 第三方认证    │  │ 物流服务  │
  │ 银行/保理     │  │ ISO/IATF    │  │ 货代/TMS │
  │ 动态折扣      │  │ SGS/TUV     │  │ 仓储WMS  │
  └─────────────┘  └─────────────┘  └──────────┘
  ┌─────────────┐  ┌─────────────┐  ┌──────────┐
  │ 征信/舆情     │  │ ESG 数据     │  │ 区块链    │
  │ 企查查/天眼查 │  │ 碳足迹平台   │  │ 原材料溯源│
  │ 行业舆情监控  │  │ 供应链ESG    │  │ 合同存证  │
  └─────────────┘  └─────────────┘  └──────────┘

  API Layer: RESTful + Webhook + SDK
  安全层: OAuth 2.0 + 数据脱敏 + 审计日志
```

**开放 API 层级**：

| API 层级 | 适用对象 | 开放内容 | 准入要求 |
|---------|---------|---------|---------|
| Level 1：合作伙伴 API | ERP/MES/财务系统 | 订单同步、库存共享、发票对接 | 签约+审批 |
| Level 2：开放 API | 第三方服务商 | 征信查询、金融撮合、物流对接 | OAuth 认证+速率限制 |
| Level 3：数据服务 API | 行业/研究机构 | 匿名化的行业基准数据 | 付费订阅 |

## 三、实现路径

### 3.1 阶段规划

```
Phase 1（0-6月）：数据资产化 ──"把数据整理好"
  ├── 统一供应商主数据
  ├── 构建供应商 360° 画像
  ├── 供应地图数据治理
  └── 产出：干净的、可信的数据底座

Phase 2（6-12月）：内部开放 ──"让内部人用起来"
  ├── 供应商品类能力目录 → 内部自服务查询
  ├── 定点关系图谱可视化
  ├── 供应商绩效看板（SPM）开放给业务方
  └── 产出：内部用户满意度提升，采购效率提升

Phase 3（12-18月）：供应商端开放 ──"让供应商上平台"
  ├── 供应商自维护门户上线
  ├── 在线竞价/反向拍卖
  ├── VMI/JIT 协同功能
  ├── 供应商赋能培训体系
  └── 产出：供应商活跃度提升，协同效率提升

Phase 4（18-24月）：生态接入 ──"让第三方进来"
  ├── 供应链金融对接（保理/动态折扣）
  ├── 第三方征信/ESG 数据接入
  ├── 开放 API + 开发者文档
  ├── 沙箱环境上线
  └── 产出：生态收入 > 0，网络效应初现
```

### 3.2 关键里程碑

| 阶段 | 里程碑 | 验证标准 |
|------|--------|---------|
| Phase 1 | 主数据统一 | 供应商信息完整率 > 95% |
| Phase 2 | 内部自服务 | 采购员人均操作时长下降 30% |
| Phase 3 | 供应商活跃 | 供应商门户月活 > 50%，信息更新及时率 > 90% |
| Phase 4 | 生态初现 | 接入 ≥ 3 类第三方服务，API 调用量持续增长 |

### 3.3 冷启动策略

| 策略 | SRM 场景应用 |
|------|-------------|
| **自营先行** | 先用内部团队验证定点关系图谱、360° 画像的价值 |
| **单边补贴** | 供应商门户免费使用，降低接入门槛 |
| **垂直切入** | 从一个品类（如芯片/电池）的供应商开始试点 |
| **种子内容** | 平台预置标杆供应商数据、行业基准数据 |

## 四、落地建议

### 第一步做什么？

🎯 **从供应商 360° 画像 + 定点关系图谱开始**

原因：
1. 是你现有数据可以直接做的（不需要等供应商上平台）
2. 内部价值立竿见影（采购决策有据可依）
3. 是后续平台化的数据底座
