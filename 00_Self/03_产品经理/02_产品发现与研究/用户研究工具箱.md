# 用户研究工具箱 — 方法、模板与工具

> "If I had asked people what they wanted, they would have said faster horses."
> — Henry Ford

> 用户研究不是问用户想要什么，而是理解他们想要完成什么。

---

## 一、用户访谈（User Interview）

### 访谈脚本模板

```
# 用户访谈脚本

## 基本信息
- 访谈对象：[姓名/角色]
- 访谈时间：[时长]
- 访谈人：[主持人]
- 记录方式：[录音/笔记]

---

## 开场（2 分钟）
"你好，感谢你今天抽出时间。我们正在改进 [产品/功能]，
想要了解你的使用体验。今天的对话没有标准答案，
你的任何想法对我们都很有价值。"

---

## 背景了解（5 分钟）
1. 你平时主要用 [产品] 来做什么？
2. 你大概多久用一次？
3. 有没有其他工具/方法也能完成同样的事情？

---

## 核心问题（15 分钟）
### 情境探索
- 能描述一下你最近一次使用 [产品] 的场景吗？
- 当时你想要完成什么？
- 过程中遇到了什么困难？

### 行为探索
- 你是怎么发现这个问题的？
- 你尝试过哪些解决方法？
- 为什么选择现在的方案？

### 情感探索
- 使用过程中你的感受是什么？
- 有没有让你特别满意/不满意的地方？
- 如果可以改变一个地方，你会改什么？

---

## 收尾（3 分钟）
- 还有什么想要补充的吗？
- 有没有什么问题是我没问到但你觉得重要的？
- 感谢你的时间，我们会根据你的反馈持续改进。
```

### 访谈招募方法

| 方法 | 成本 | 速度 | 质量 | 适用场景 |
|------|------|------|------|----------|
| **现有用户池** | 低 | 快 | 高 | 产品迭代、功能验证 |
| **社交媒体招募** | 低 | 中 | 中 | 新用户研究、市场探索 |
| **专业招募平台** | 高 | 快 | 高 | 特定人群、高端用户 |
| **滚雪球推荐** | 低 | 慢 | 高 | 小众人群、B2B 用户 |
| **产品内招募** | 低 | 快 | 高 | 活跃用户、行为研究 |
| **问卷星/腾讯问卷** | 低 | 中 | 中 | 大样本筛选、初步调研 |

### 访谈分析框架

#### 编码分析步骤

| 步骤 | 说明 | 输出 |
|------|------|------|
| 1. 转录 | 将录音转为文字 | 访谈文字稿 |
| 2. 分段 | 按主题/问题分段 | 结构化文字稿 |
| 3. 编码 | 为每段打标签 | 带标签的文字稿 |
| 4. 聚类 | 将相似标签聚合 | 主题列表 |
| 5. 洞察 | 从主题中提取洞察 | 研究发现 |

#### 编码标签体系

| 标签类型 | 示例 | 用途 |
|----------|------|------|
| **行为标签** | [[搜索行为、]]#比较行为 | 理解用户如何使用产品 |
| **痛点标签** | [[找不到信息、]]#流程复杂 | 识别改进机会 |
| **需求标签** | [[需要导出、]]#需要对比 | 发现新功能需求 |
| **情感标签** | [[焦虑、]]#满意、#困惑 | 理解用户体验 |
| **情境标签** | [[通勤、]]#会议中、#深夜 | 理解使用场景 |

## 二、可用性测试（Usability Testing）

### 测试类型

| 类型 | 说明 | 成本 | 适用场景 |
|------|------|------|----------|
| **Moderated Testing** | 主持人引导用户完成任务 | 高 | 深入理解用户行为 |
| **Unmoderated Testing** | 用户自主完成任务，录制屏幕 | 中 | 大样本、快速验证 |
| **5 秒测试** | 展示页面 5 秒，询问印象 | 低 | 验证信息架构、视觉层次 |
| **A/B 测试** | 对比两个版本的用户行为 | 中 | 量化优化效果 |
| **Tree Testing** | 测试导航结构是否清晰 | 低 | 信息架构验证 |
| **Card Sorting** | 用户对内容进行分类 | 低 | 信息架构设计 |

### 可用性测试流程

| 阶段 | 步骤 | 输出 |
|------|------|------|
| **准备** | 1. 定义测试目标 | 测试计划 |
| | 2. 设计任务场景 | 任务脚本 |
| | 3. 招募参与者 | 参与者列表 |
| | 4. 准备测试环境 | 测试环境 |
| **执行** | 5. 进行测试 | 录音/录像 |
| | 6. 记录观察 | 观察笔记 |
| **分析** | 7. 分析数据 | 问题列表 |
| | 8. 优先级排序 | 改进建议 |
| **报告** | 9. 撰写报告 | 测试报告 |

### 任务设计模板

```
# 可用性测试任务

## 任务 1：[任务名称]
**目标**：用户想要完成什么
**场景**：[具体情境描述]
**成功标准**：[如何判断任务完成]
**观察要点**：[重点关注什么]

---

## 任务 2：[任务名称]
...
```

**示例**：

```
## 任务 1：查找并导出销售报告
**目标**：用户能够找到销售报告并导出为 Excel
**场景**：你刚入职，需要向领导汇报上周的销售情况
**成功标准**：用户在 3 分钟内找到报告并成功导出
**观察要点**：导航路径、搜索行为、导出流程
```

### 5 秒测试

**原理**：展示页面 5 秒，然后关闭，询问用户印象。

**问题模板**：

1. 这个页面是做什么的？
2. 你记住了什么信息？
3. 你觉得这个页面属于什么类型的产品？
4. 你会想要继续浏览吗？为什么？

**适用场景**：

- 验证首屏信息是否清晰
- 测试价值主张是否明确
- 评估视觉层次是否合理

## 三、问卷设计（Survey Design）

### 常用量表

#### 李克特量表（Likert Scale）

| 量表类型 | 选项 | 适用场景 |
|----------|------|----------|
| **5 点量表** | 非常不同意 - 不同意 - 中立 - 同意 - 非常同意 | 态度测量 |
| **7 点量表** | 在 5 点基础上增加"比较不同意"和"比较同意" | 精确测量 |
| **满意度量表** | 非常不满意 - 不满意 - 中立 - 满意 - 非常满意 | 体验评估 |
| **频率量表** | 从不 - 很少 - 有时 - 经常 - 总是 | 行为频率 |

#### NPS（Net Promoter Score）

```
问题：你有多大可能向朋友推荐 [产品]？
评分：0-10 分

分类：
- 9-10 分：推荐者 (Promoter)
- 7-8 分：被动者 (Passive)
- 0-6 分：贬损者 (Detractor)

计算：NPS = 推荐者比例 - 贬损者比例
范围：-100 到 +100
```

| NPS 分数 | 解读 |
|----------|------|
| > 70 | 世界级 |
| 50-70 | 优秀 |
| 30-50 | 良好 |
| 0-30 | 需改进 |
| < 0 | 严重问题 |

#### CSAT（Customer Satisfaction）

```
问题：你对 [产品/功能] 的满意度如何？
评分：1-5 分

计算：CSAT = (4分+5分的数量) / 总回答数 × 100%
```

### 陷阱题设计

| 陷阱类型 | 示例 | 目的 |
|----------|------|------|
| **注意力检测** | "请选择'非常同意'" | 检测用户是否认真作答 |
| **反向计分** | "我不喜欢这个产品" | 检测一致性 |
| **逻辑检验** | 问两个相关问题，检验一致性 | 检测回答质量 |

### 问卷设计清单

| 检查项 | 说明 |
|--------|------|
| ✅ 目标明确 | 每个问题都服务于研究目标 |
| ✅ 问题简洁 | 一个问题只问一件事 |
| ✅ 避免引导 | 不暗示"正确"答案 |
| ✅ 选项穷尽 | 提供"其他"选项 |
| ✅ 逻辑跳转 | 根据回答跳转到相关问题 |
| ✅ 预测试 | 小范围测试后再大规模发放 |
| ✅ 时间控制 | 总时长 < 10 分钟 |
| ✅ 激励机制 | 提供适当的激励（红包、优惠券） |

## 四、数据分析方法

### 亲和图（Affinity Diagram）

**适用场景**：整理大量定性数据（访谈记录、观察笔记）

**步骤**：

| 步骤 | 说明 |
|------|------|
| 1. 收集数据 | 将所有洞察写在便签上 |
| 2. 分组 | 将相似的便签放在一起 |
| 3. 命名 | 为每组起一个主题名 |
| 4. 排序 | 按重要性或逻辑排序 |
| 5. 洞察 | 从主题中提取关键发现 |

**数字工具**：Miro、Mural、FigJam

### 主题分析（Thematic Analysis）

**适用场景**：分析访谈数据、开放性问卷回答

**步骤**：

| 步骤 | 说明 | 输出 |
|------|------|------|
| 1. 熟悉数据 | 反复阅读数据 | 数据印象 |
| 2. 初始编码 | 为有意义的片段打标签 | 编码列表 |
| 3. 搜索主题 | 将编码聚合为主题 | 主题候选 |
| 4. 审查主题 | 检查主题是否准确反映数据 | 主题列表 |
| 5. 定义主题 | 为每个主题命名和定义 | 主题定义 |
| 6. 撰写报告 | 用主题讲述故事 | 研究报告 |

### 用户旅程地图（User Journey Map）

**适用场景**：理解用户端到端的体验

**模板**：

```
# 用户旅程地图

## 用户画像：[名称]
- 角色：[用户类型]
- 目标：[想要完成的任务]

## 阶段
| 阶段 | 行为 | 触点 | 想法 | 情感 | 痛点 | 机会 |
|------|------|------|------|------|------|------|
| 认知 | ... | ... | ... | 😐 | ... | ... |
| 考虑 | ... | ... | ... | 😊 | ... | ... |
| 购买 | ... | ... | ... | 😰 | ... | ... |
| 使用 | ... | ... | ... | 😊 | ... | ... |
| 推荐 | ... | ... | ... | 😄 | ... | ... |
```

**情感曲线**：

```
情感
 😄 |          *           *
 😊 |    *          *            *
 😐 | *                        *
 😰 |              *
 😡 |
    +------------------------------
     认知  考虑  购买  使用  推荐
```

### 其他分析方法

| 方法 | 适用场景 | 输出 |
|------|----------|------|
| **卡片分类** | 信息架构设计 | 分类结构 |
| **任务分析** | 理解用户完成任务的步骤 | 任务流程图 |
| **启发式评估** | 快速评估产品可用性 | 问题清单 |
| **竞品分析** | 了解竞争格局 | 竞品对比表 |
| **SUS 量表** | 标准化可用性评估 | 可用性分数 (0-100) |

## 八、研究伦理清单

| 原则 | 说明 |
|------|------|
| ✅ 知情同意 | 告知研究目的、数据用途、参与者权利 |
| ✅ 自愿参与 | 参与者可随时退出，不承担后果 |
| ✅ 数据保护 | 个人信息脱敏、安全存储 |
| ✅ 公平补偿 | 提供合理的参与激励 |
| ✅ 透明报告 | 如实报告研究发现，不隐瞒不利结果 |

## 九、常见错误与应对

| 错误 | 表现 | 正确做法 |
|------|------|----------|
| **引导性问题** | "你觉得这个功能好用吗？" | "你通常是怎么完成这个任务的？" |
| **样本偏差** | 只访谈活跃用户 | 确保覆盖不同用户类型 |
| **确认偏误** | 只关注支持假设的数据 | 主动寻找反面证据 |
| **过早结论** | 访谈 3 人就下结论 | 至少 5 人，达到信息饱和 |
| **忽略定量** | 只做定性研究 | 定性 + 定性结合 |
| **报告无人看** | 长篇大论的报告 | 执行摘要 + 关键发现 + 行动建议 |

## 十、快速决策指南

### 选择研究方法

| 如果你想... | 使用... |
|-------------|---------|
| 了解用户需求 | 用户访谈 |
| 验证设计方案 | 可用性测试 |
| 量化用户满意度 | NPS/CSAT 问卷 |
| 发现信息架构问题 | 卡片分类/Tree Testing |
| 了解用户行为 | 行为数据分析 (Hotjar/FullStory) |
| 快速验证想法 | 5 秒测试/假门测试 |
| 对比两个方案 | A/B 测试 |

### 样本量参考

| 方法 | 样本量 | 说明 |
|------|--------|------|
| 用户访谈 | 5-8 人/轮 | 达到信息饱和即可 |
| 可用性测试 | 5 人/轮 | 发现 80% 的问题 |
| 问卷调查 | 100+ 人 | 确保统计显著性 |
| A/B 测试 | 1000+ 人/组 | 取决于 MDE 和基线转化率 |

---

> 💡 **行动建议**：从一个简单的用户访谈开始。不需要完美的脚本，不需要专业的工具。找 3 个用户，问他们"你最近一次使用 [产品] 是为了完成什么？"，然后认真倾听。这就是用户研究的起点。
