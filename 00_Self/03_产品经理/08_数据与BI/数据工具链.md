# 数据工具链全景

产品经理需要理解数据从采集到应用的完整链路，才能在需求评审、方案选型、数据产品设计中做出正确判断。本文覆盖主流工具的定位、优劣和适用场景。

---

## 数据工具全景图

### 分层架构

```
┌─────────────────────────────────────────────────────────┐
│                     数据应用层                           │
│  BI 报表 · 可视化 · 数据产品 · 自助查询 · 数据门户      │
├─────────────────────────────────────────────────────────┤
│                     数据服务层                           │
│  API 网关 · 指标平台(Headless BI) · 数据目录 · 数据质量 │
├─────────────────────────────────────────────────────────┤
│                     数据处理层                           │
│  SQL 开发(dbt) · 任务调度 · 实时计算 · 数据治理         │
├─────────────────────────────────────────────────────────┤
│                     数据存储层                           │
│  OLAP 引擎 · 云数仓 · 数据湖 · 数据库                   │
├─────────────────────────────────────────────────────────┤
│                     数据采集层                           │
│  埋点 · 日志 · 数据同步(CDC) · 爬虫 · API 接入         │
└─────────────────────────────────────────────────────────┘
```

### 各层定位速查

| 层 | 核心问题 | PM 关注点 |
|---|---|---|
| 采集层 | 数据从哪来？怎么埋？ | 埋点方案选型、采集覆盖率 |
| 存储层 | 数据放哪里？怎么存？ | 性能 vs 成本、查询体验 |
| 处理层 | 数据怎么加工？ | ETL 流程、调度依赖、数据质量 |
| 服务层 | 数据怎么给别人用？ | API 化、指标一致性、数据目录 |
| 应用层 | 数据怎么呈现？ | BI 工具选型、可视化效果、自助能力 |

**选型决策树**：

```
需要实时 OLAP？
├── 并发要求高（>100 QPS）？
│   ├── 是 → StarRocks / Doris
│   └── 否 → ClickHouse
├── 需要实时写入？
│   ├── 是 → Doris / StarRocks / Druid
│   └── 否 → ClickHouse
└── 需要复杂 JOIN？
    ├── 是 → Doris / StarRocks
    └── 否 → ClickHouse
```

## 数据服务层

### API 网关与数据服务化

数据服务层解决的核心问题：**把加工好的数据以标准化 API 提供给业务系统和应用**。

| 方案 | 适用场景 | 优势 | 劣势 |
|------|---------|------|------|
| **自建 API 服务** | 定制化需求强 | 灵活、可控 | 开发成本高 |
| **API 网关 + 数据源** | 通用数据查询 | 统一管理、限流、鉴权 | 需要网关运维 |
| **Headless BI 指标层** | 指标一致性 | 定义一次、多处使用 | 新概念、落地有门槛 |
| **GraphQL 数据服务** | 多端差异化查询 | 按需取数、减少冗余 | 学习成本、N+1 问题 |

### 指标平台 / Headless BI

| 工具 | 开源 | 核心理念 | 适用场景 | 学习曲线 |
|------|------|---------|---------|---------|
| **MetricFlow** | ✅ | Metric Layer | dbt 生态用户 | ★★★ |
| **Cube.js** | ✅ | Headless BI | 嵌入式分析、API 优先 | ★★★ |
| **Apache Superset** (指标层) | ✅ | SQL + 指标定义 | 已有 Superset 用户 | ★★ |
| **AtScale** | 否 | 企业语义层 | 大型企业 | ★★★★ |
| **Looker (LookML)** | 否 | 模型驱动 | Google 生态 | ★★★★ |

**PM 理解**：Headless BI 的核心价值是「指标定义的 Single Source of Truth」——同一个「日活」指标，不管是 BI 看板、数据产品还是 API，都从同一份定义计算，消除口径不一致。

### 数据目录 / 数据治理

| 工具 | 开源 | 厂商 | 核心能力 | 适用场景 | 学习曲线 |
|------|------|------|---------|---------|---------|
| **DataHub** | ✅ | LinkedIn | 元数据管理、血缘、搜索 | 通用数据目录 | ★★★ |
| **Apache Atlas** | ✅ | Apache | 元数据、血缘、分类 | Hadoop 生态 | ★★★★ |
| **OpenMetadata** | ✅ | 开源社区 | 数据目录、治理、质量 | 现代数据栈 | ★★★ |
| **Alation** | 否 | Alation | 数据目录、协作 | 企业级 | ★★★★ |
| **Collibra** | 否 | Collibra | 数据治理全栈 | 大型企业 | ★★★★★ |

**选型建议**：
- Hadoop 生态 → Atlas
- 现代数据栈 → DataHub 或 OpenMetadata
- 企业级治理 → Collibra / Alation

## 总结

| 维度 | 关键结论 |
|------|---------|
| **采集** | 代码埋点精确但贵，全埋点快速但噪声明显，可视埋点是折中 |
| **存储** | ClickHouse 单表查询最快，Doris/StarRocks 并发和 JOIN 更强，云数仓省运维 |
| **处理** | dbt 让数仓建模工程化，DolphinScheduler 是国内调度首选，Flink 是实时标准 |
| **服务** | Headless BI 解决指标口径不一致，数据目录解决「数据找不到」 |
| **应用** | 国内企业首选 FineBI/QuickBI，技术团队选 Metabase/Superset，分析师选 Tableau |

**一句话总结**：数据工具选型没有银弹，关键是匹配团队规模、技术能力和预算。PM 的价值不是选最牛的工具，而是选最合适的工具，推动数据真正被用起来。
