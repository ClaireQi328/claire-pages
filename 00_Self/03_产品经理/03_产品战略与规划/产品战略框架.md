# 产品战略框架

> 战略不是选择做什么，而是选择不做什么。—— Michael Porter

---

## 一、好战略的特征（Rumelt 三要素）

Richard Rumelt 在《Good Strategy Bad Strategy》中指出，大多数所谓的"战略"其实是目标伪装成战略。好战略必须包含三个核心要素：

| 要素 | 含义 | 反面（坏战略） |
|------|------|----------------|
| **Diagnosis（诊断）** | 对挑战的深刻洞察，找到关键杠杆点 | 罗列现象而不分析根因 |
| **Guiding Policy（指导方针）** | 应对诊断的整体方向性选择 | 模糊的愿景口号，如"成为行业第一" |
| **Coherent Actions（连贯行动）** | 相互协调、彼此强化的具体举措 | 各部门各自为政，资源分散 |

### 好战略的实践检验

- ✅ 能用一句话说清楚"我们不做什么"
- ✅ 有明确的取舍（trade-off），不是面面俱到
- ✅ 行动之间有逻辑关联，不是孤立的项目清单
- ✅ 有可衡量的成功标准和时间框架

### 产品愿景 vs 产品战略

| 维度 | 产品愿景（Vision） | 产品战略（Strategy） |
|------|-------------------|---------------------|
| 时间跨度 | 3-5 年甚至更远 | 6-18 个月 |
| 回答的问题 | "世界会变成什么样？" | "我们怎么到达那里？" |
| 具体程度 | 抽象、激励性 | 具体、可执行 |
| 变化频率 | 很少变 | 每季度审视调整 |
| 产出物 | 一句话愿景声明 | 战略选择文档 + 路线图 |
| 示例 | "让每个小企业都能用上企业级工具" | "聚焦餐饮行业，通过 POS 系统切入，用低费率建立网络效应" |

**关键区分**：愿景是终点，战略是路径。没有愿景的战略是短视的，没有战略的愿景是空想。

## 二、三大战略框架详解

### 框架 1：Playing to Win（A.G. Lafley & Roger Martin）

P&G 前 CEO A.G. Lafley 与 Roger Martin 在《Playing to Win》中提出的五层级战略选择框架，是消费品和 B2B 领域最经典的战略工具之一。

#### 五层级战略选择

```
┌─────────────────────────────────────┐
│  1. Winning Aspiration（志在必赢）   │  我们要赢得什么？
├─────────────────────────────────────┤
│  2. Where to Play（战场选择）        │  在哪些市场/客户/品类竞争？
├─────────────────────────────────────┤
│  3. How to Win（制胜方式）           │  靠什么赢得竞争？
├─────────────────────────────────────┤
│  4. Core Capabilities（核心能力）    │  需要哪些能力支撑？
├─────────────────────────────────────┤
│  5. Management Systems（管理体系）   │  需要什么制度和文化保障？
└─────────────────────────────────────┘
```

#### Where to Play 维度

| 维度 | 选项示例 | 产品决策示例 |
|------|---------|-------------|
| 地域 | 全球 vs 区域 vs 本地 | 先做国内市场再出海 |
| 客户群 | 大企业 vs 中小企业 vs 个人 | 聚焦 SMB，不做 Fortune 500 |
| 品类/场景 | 核心场景 vs 延伸场景 | 只做协作，不做项目管理 |
| 渠道 | 直销 vs 渠道 vs 自助 | PLG 优先，不建销售团队 |
| 价值链环节 | 平台 vs 应用 vs 服务 | 做基础设施，不做终端应用 |

#### How to Win 两大路径

| 路径 | 本质 | 适用条件 | 产品策略 |
|------|------|---------|---------|
| **成本领先** | 同等价值更低成本 | 规模效应强、技术可复制 | 标准化产品、自助服务、低客单价 |
| **差异化** | 独特价值，客户愿意溢价 | 需求多样、品牌重要 | 深度定制、行业方案、高客单价 |

#### 实战模板：Playing to Win 画布

```

  - 地域：___________  - 客户群：___________
  - 品类：___________  - 渠道：___________

核心能力：
  1. _______________
  2. _______________
  3. _______________

管理体系：
  - 衡量指标：___________  - 激励机制：___________
  - 组织结构：___________  - 文化价值观：___________
```

### 框架 2：Wardley Mapping（价值链 + 演进 + 战略）

Simon Wardley 创建的战略映射方法，将价值链可视化并标注每个组件的演进阶段，从而推导最优战略。这是对传统 SWOT 分析的实质性升级——它不仅告诉你"是什么"，还告诉你"会变成什么"。

#### 核心概念

**价值链映射**：从用户需求出发，自上而下分解支撑该需求的所有组件。

**演进阶段**（Evolution Stages）：

| 阶段 | 特征 | 示例 | 管理方式 |
|------|------|------|---------|
| **Genesis（起源）** | 全新、不确定、高探索性 | AI Agent 框架 | 敏捷实验、容忍失败 |
| **Custom Built（定制）** | 理解需求但每个都不同 | 企业定制 ERP | 项目制、专家交付 |
| **Product（产品）** | 标准化、可复制、竞争性市场 | SaaS 工具 | 产品管理、市场竞争 |
| **Commodity（公用）** | 高度标准化、稳定、可替代 | 云计算、数据库 | 外包、运维优化 |

#### 四种战略模式

| 模式 | 含义 | 时机 | 示例 |
|------|------|------|------|
| **Pioneer（先驱）** | 投资 Genesis 阶段的新事物 | 技术拐点出现 | 早期投资 LLM 应用 |
| **Settler（定居者）** | 将 Custom 推向 Product | 市场需求明确但供给不足 | 做垂直行业 SaaS |
| **Town Planner（规划者）** | 将 Product 推向 Commodity | 市场成熟、效率为王 | 做基础设施/平台 |
| **Attacker / Defender** | 利用演进趋势攻击/防御 | 竞争格局变化 | 用免费 Commodity 组件攻击对手的 Product 利润 |

#### Wardley Map 实战示例：项目管理 SaaS 产品

```
用户需求：团队高效协作完成项目
│
├── 项目看板 [Product → Commodity]          ← 竞争激烈，差异化空间小
│   ├── 存储 [Commodity]                   ← 用云服务，不自建
│   └── 实时同步 [Product]                 ← 竞争要素，需投入
│
├── 任务管理 [Product]                      ← 核心功能，需持续迭代
│   ├── 工作流引擎 [Custom → Product]      ← 机会：行业化工作流模板
│   └── 通知系统 [Commodity]               ← 用现成方案
│
├── AI 助手 [Genesis → Custom]             ← 差异化机会！
│   ├── 自然语言交互 [Genesis]             ← 投资探索
│   └── 智能排期 [Custom]                  ← 试点验证
│
├── 集成生态 [Product]                      ← 护城河
│   ├── API [Product → Commodity]          ← 标准化但必须有
│   └── 市场/插件 [Custom → Product]       ← 长期竞争力
│
└── 数据分析 [Custom → Product]             ← 企业客户关键需求
    ├── 基础报表 [Product]                 ← 必须有
    └── 预测分析 [Genesis → Custom]        ← 差异化机会
```

**战略推导**：
- **Towns planner 策略**：项目看板、存储已经是 commodity，用最低成本获取（云服务 + 开源组件），不在此投入差异化
- **Settler 策略**：工作流引擎从 custom 推向 product，做行业模板（研发团队模板、市场营销模板、硬件团队模板）
- **Pioneer 策略**：AI 助手处于 genesis 阶段，是最有潜力的差异化方向，投入探索性团队
- **Attacker 策略**：用免费的基础看板功能吸引用户，通过 AI 功能和行业工作流建立付费转化

#### 画 Wardley Map 的步骤

1. **明确用户需求**（最上面的锚点）
2. **自上而下分解组件**（直接需求 → 间接依赖 → 基础设施）
3. **标注每个组件的演进阶段**（Genesis / Custom / Product / Commodity）
4. **识别演进方向**（所有组件都在从左向右演进）
5. **标注战略模式**（Pioneer / Settler / Town Planner）
6. **找到投资焦点**（演进拐点处、价值链瓶颈处）

### 框架 3：Strategyzer（商业模式画布 + 价值主张画布）

Alexander Osterwalder 创建的轻量级战略工具，适合创业公司和新产品从 0 到 1 阶段快速验证商业模式。

#### Business Model Canvas（商业模式画布）

| 模块 | 核心问题 | 产品决策示例 |
|------|---------|-------------|
| **Customer Segments** | 我们为谁创造价值？ | 早期创业团队、远程团队 |
| **Value Propositions** | 我们解决什么问题？ | 一站式协作，减少工具碎片化 |
| **Channels** | 怎么触达客户？ | PLG 自助注册 + 内容营销 |
| **Customer Relationships** | 怎么维护客户关系？ | 社区 + 客户成功团队 |
| **Revenue Streams** | 怎么赚钱？ | Freemium + 按席位收费 |
| **Key Resources** | 需要什么核心资源？ | 工程团队、品牌、用户数据 |
| **Key Activities** | 必须做好什么事？ | 产品迭代、增长实验、社区运营 |
| **Key Partnerships** | 谁是关键合作伙伴？ | 云服务商、集成合作伙伴 |
| **Cost Structure** | 主要成本是什么？ | 研发人力、云服务、市场获客 |

#### Value Proposition Canvas（价值主张画布）

深入验证"客户真的需要我们的产品吗"：

```
客户侧 Profile                    产品侧 Value Map
┌──────────────────┐              ┌──────────────────┐
│ Customer Jobs    │              │ Products &       │
│ (客户要完成的任务) │──────────────│ Services         │
│                  │              │ (产品和服务)      │
├──────────────────┤              ├──────────────────┤
│ Pains            │              │ Pain Relievers   │
│ (痛点和障碍)      │──────────────│ (缓解痛点)        │
│                  │              │                  │
├──────────────────┤              ├──────────────────┤
│ Gains            │              │ Gain Creators    │
│ (期望收益)        │──────────────│ (创造收益)        │
└──────────────────┘              └──────────────────┘
```

**Fit 检验**：三个匹配才算 Product-Market Fit
1. **Problem-Solution Fit**：Pain Relievers 确实解决了 Pains
2. **Product-Market Fit**：Gain Creators 确实创造了 Gains
3. **Business Model Fit**：商业模式能跑通（单位经济模型健康）

## 三、三大框架对比与适用场景

| 维度 | Playing to Win | Wardley Mapping | Strategyzer |
|------|---------------|-----------------|-------------|
| **创始人** | A.G. Lafley & Roger Martin | Simon Wardley | Alexander Osterwalder |
| **核心视角** | 选择与取舍 | 演进与趋势 | 价值与匹配 |
| **适合阶段** | 成长期 → 成熟期 | 任何阶段 | 0 → 1 验证期 |
| **适合场景** | 现有业务的战略优化 | 技术驱动的市场判断 | 新产品/新业务探索 |
| **输出物** | 战略选择文档 | 可视化地图 + 战略模式 | 画布 + 验证实验 |
| **学习曲线** | 中等 | 较高（需理解演进） | 低 |
| **最大价值** | 强制做取舍 | 预判趋势拐点 | 快速验证假设 |
| **局限性** | 对新兴市场判断力弱 | 需要持续维护地图 | 偏静态，不擅长竞争分析 |

### 如何选择

| 你的情况 | 推荐框架 | 原因 |
|---------|---------|------|
| 创业初期，还在找 PMF | Strategyzer | 快速画布、验证假设、低成本迭代 |
| 已有产品，需要制定年度战略 | Playing to Win | 强制做选择、聚焦资源 |
| 技术密集型市场，需要判断趋势 | Wardley Mapping | 可视化演进、提前布局 |
| 从 0 到 1 但市场成熟 | Strategyzer + Wardley | 画布验证 + 差异化分析 |
| 转型期，重新定义方向 | Playing to Win + Wardley | 战略选择 + 趋势判断 |

### 组合使用示例

```
阶段 1（0→1）：Strategyzer
  └── 画商业模式画布 → 画价值主张画布 → 设计验证实验

阶段 2（PMF 验证后）：Wardley Mapping
  └── 映射价值链 → 识别演进机会 → 找到差异化方向

阶段 3（规模化）：Playing to Win
  └── 明确 Where to Play → 确定 How to Win → 配置能力和资源
```

## 四、战略落地检查清单

### 战略制定阶段

- [ ] 完成市场和竞争分析（参考 [[竞品分析方法论]]）
- [ ] 明确目标客户画像（不是"所有人"）
- [ ] 用 Rumelt 三要素检验：有诊断、有指导方针、有连贯行动
- [ ] 用 Wardley Map 或 Playing to Win 画布输出战略选择
- [ ] 明确写出"我们不做什么"清单

### 战略沟通阶段

- [ ] 一页纸战略摘要（管理层对齐）
- [ ] 团队能用自己的话复述战略重点
- [ ] 战略选择与日常决策有明确关联
- [ ] 关键假设已识别并设置了验证节点

### 战略执行阶段

- [ ] 战略拆解为路线图（参考 [[路线图与优先级]]）
- [ ] 资源分配与战略优先级一致
- [ ] 建立战略 review 节奏（月度/季度）
- [ ] 有明确的 pivot / persevere 决策标准

## 五、常见陷阱

| 陷阱 | 表现 | 对策 |
|------|------|------|
| **目标伪装成战略** | "我们的战略是增长 50%" | 回到 Rumelt 三要素，写清诊断和行动 |
| **面面俱到** | 10 个优先级 = 没有优先级 | 用 Playing to Win 强制做取舍 |
| **静态战略** | 年初定的战略到年底不变 | 用 Wardley Map 追踪演进，季度 review |
| **模仿战略** | "竞品做了我们也要做" | 先问 Why，用 Value Proposition Canvas 验证 |
| **战略与执行脱节** | 战略文档锁在抽屉里 | 战略 → 路线图 → OKR → Sprint，逐层拆解 |
| **忽略能力约束** | 战略需要的能力团队不具备 | Playing to Win 第四层：Core Capabilities |
