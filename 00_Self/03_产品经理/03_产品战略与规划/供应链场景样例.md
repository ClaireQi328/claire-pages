## 一、Rumelt 三要素 — 供应链协同平台战略诊断

### 样例：某汽车零部件企业的供应链协同平台

| 要素 | 内容 | 反面（坏战略） |
|------|------|----------------|
| **Diagnosis（诊断）** | 新品上市周期 12 周（行业标杆 8 周），根因不是"系统不好"，而是 BOM 变更信息在 PLM→采购→供应商之间靠邮件传递，每次变更平均延迟 3 天，一个新品要改 3-5 次 BOM | "我们的供应链系统太旧了，要换新的" |
| **Guiding Policy（指导方针）** | 不做大而全的"供应链中台"，聚焦"新品上市协同"这一个场景，用 BOM 变更自动同步作为切入点 | "打造行业领先的数字化供应链平台" |
| **Coherent Actions（连贯行动）** | ① 打通 PLM-ERP 的 BOM 变更通道（IT）→ ② 建供应商门户接收变更通知（产品）→ ③ 试点 2 个品类跑通全流程（业务）→ ④ 基于试点数据推广到全品类（运营） | IT 做 PLM 升级、采购做供应商门户、业务做流程优化——各干各的 |

**诊断过程**：

```
表面问题：新品上市慢（12 周 vs 标杆 8 周）
  ↓ 问"为什么"
研发冻结 BOM 后还要改 3-5 次
  ↓ 问"为什么变更这么慢"
变更通知靠邮件，供应商收到时经常已经过时了
  ↓ 问"为什么靠邮件"
PLM 和供应商之间没有系统直连
  ↓ 根因：信息断点在 PLM→供应商 这一段
  ↓ 杠杆点：打通这个断点，其他问题（错版生产、呆滞料）会自动缓解
```

## 二、Playing to Win — 仓储管理系统(WMS)产品战略

### 样例：初创 WMS 产品的战略选择

```
志在必赢：3 年内成为中小型电商仓储的首选 WMS

战场选择：
  - 地域：先做长三角，不做全国（物流基础设施成熟）
  - 客户群：日单量 500-5000 的中小电商（太小没付费能力，太大要定制）
  - 品类：服装+日用品（SKU 多、退货率高，痛点最强）
  - 渠道：ISV 渠道 + 电商服务市场，不做直销大客户
  - 价值链：只做仓库内（收货→上架→拣货→打包→发货），不做运输

制胜方式：
  差异化——"开箱即用的智能波次"
  不靠价格战（竞品已经很便宜），靠"3天上线、不用培训"的易用性

核心能力：
  1. 电商订单聚合能力（对接淘宝/京东/拼多多/抖音）
  2. 智能波次算法（按快递线路、SKU 位置自动合并）
  3. 实施交付能力（标准化实施 SOP，3 天上线）

管理体系：
  - 衡量指标：客户上线周期（目标 <3天）、月活仓数、NPS
  - 激励机制：实施团队按"上线速度"和"客户满意度"考核
  - 组织结构：产品+实施一体化小团队，不做大销售部
  - 文化价值观：快、简单、客户说了算
```

### How to Win 取舍分析

| 我们做 | 我们不做 | 为什么 |
|--------|---------|--------|
| 智能波次 | 全功能 WMS | 波次是中小电商最大痛点，全功能打不过富勒、唯智 |
| 电商订单聚合 | 制造业 WMS | 电商场景标准化程度高，制造业太定制 |
| 自助实施 | 驻场实施 | 人效太低，用产品化降低实施成本 |
| SaaS 订阅制 | 一次性 License | 客户生命周期价值更高，现金流更稳定 |
| 服装+日用品 | 冷链/危化品 | 行业门槛高，不适合初创团队 |

## 三、Wardley Mapping — 供应链数字化价值链演进

### 样例：供应链控制塔产品的 Wardley Map

```
用户需求：实时掌控供应链全局状态，快速响应异常
│
├── 异常预警 [Genesis → Custom]              ← 差异化机会！
│   ├── 预测算法 [Genesis]                   ← AI/ML 投入
│   └── 规则引擎 [Product]                   ← 用现成方案
│
├── 可视化看板 [Product → Commodity]          ← 竞争红海
│   ├── BI 工具 [Commodity]                  ← 用开源（Metabase/Grafana）
│   └── 地图可视化 [Product]                 ← 基础功能
│
├── 数据集成 [Custom → Product]              ← 核心壁垒
│   ├── ERP 对接 [Custom]                    ← 每家 ERP 不同，积累适配器
│   ├── TMS 对接 [Custom → Product]          ← 接口逐步标准化
│   └── IoT 数据 [Genesis → Custom]          ← 温控、GPS 等传感器
│
├── 协同处置 [Genesis → Custom]              ← 高价值区
│   ├── 工单流转 [Product]                   ← 通用能力
│   └── 供应商协同 [Custom]                  ← 行业知识密集
│
└── 基础设施 [Commodity]
    ├── 云计算 [Commodity]                   ← 直接用云服务
    ├── 数据库 [Commodity]                   ← 不自建
    └── 消息队列 [Commodity]                 ← 标准组件
```

### 战略推导

| 战略模式 | 对应组件 | 具体行动 |
|---------|---------|---------|
| **Town Planner** | BI 工具、云计算、数据库 | 不自建，用开源+云服务，把精力省下来 |
| **Settler** | 数据集成（ERP/TMS 对接） | 从"一个客户一个适配器"推向"标准化连接器"，形成产品 |
| **Pioneer** | 异常预警（预测算法）、协同处置 | 投入探索团队，这是 3 年后的差异化来源 |
| **Attacker** | 用免费的可视化看板吸引客户，通过数据集成和协同处置建立付费转化 | |

**关键洞察**：

- 📍 **数据集成**正在从 Custom → Product 演进：谁先把 ERP 对接标准化，谁就有护城河
- 📍 **异常预警**还在 Genesis 阶段：早期投入，等到 Product 阶段就是先发优势
- 📍 **可视化看板**已经是 Commodity：别在这上面花精力差异化，用开源就好

## 五、Porter 五力 — 供应链计划系统竞争分析

### 样例：需求预测 SaaS 的五力分析

| 波特五力 | 强度 | 具体分析 | 产品策略影响 |
|---------|:---:|---------|------------|
| **行业内竞争** | 🔴 高 | SAP IBP、Kinaxis、o9 Solutions 三强鼎立；国内有数策、悠桦林 | 不能正面硬刚，找细分切入点 |
| **新进入者威胁** | 🟡 中 | AI 公司（如第四范式）跨界进来，用"AI 预测"作为卖点 | 加速 AI 能力建设，不能被技术代差颠覆 |
| **替代品威胁** | 🔴 高 | Excel（70%的企业还在用）、ERP 内置预测模块（免费但不好用） | 最大对手不是竞品，是 Excel；产品要比 Excel 简单 10 倍 |
| **买方议价力** | 🔴 高 | 大客户（如车企）采购强势，要求定制化、压价格 | 分层定价：标准化版给中小客户，定制版给大客户 |
| **供方议价力** | 🟡 中 | 依赖天气数据、市场数据等第三方数据源 | 与数据供应商签长期协议，降低依赖风险 |

**核心洞察**：

> 最大的竞争不是来自 Kinaxis 或 o9，而是来自 **Excel + 人的经验**。产品策略应该是"比 Excel 简单，比人准"。

## 九、Kano 模型 — 采购系统需求分类

### 样例：供应商管理系统的 Kano 分析

| 功能 | Kano 类型 | 识别方式 | 产品策略 |
|------|----------|---------|---------|
| 供应商信息管理 | **Must-be** | "这个不是应该有的吗？" | 必须做到位，但不靠它差异化 |
| 在线下单/确认 | **Must-be** | "没有这个怎么用？" | 做好，但不是卖点 |
| 自动三单匹配 | **One-dimensional** | "准确率越高我越满意" | 持续优化准确率（从 95%→99%） |
| 供应商风险预警 | **Attractive** | "啊？还能提前告诉我供应商要出问题？" | 核心差异化卖点！ |
| 供应商门户（微信） | **Attractive** | "供应商居然不用装 App？" | 降低供应商使用门槛的杀手锏 |
| 复杂审批工作流 | **Indifferent** | "我用企业微信审批就行了" | 不投入，集成企业微信/飞书 |
| 社交功能（供应商圈） | **Reverse** | "我为什么要让供应商互相认识？" | 绝对不做 |

**关键洞察**：

> 自动三单匹配是 **One-dimensional**——做得越好客户越满意，是持续投入的方向。
> 供应商风险预警是 **Attractive**——客户没想到你能做这个，做好了就是惊喜，是差异化来源。

## 十、MoSCoW — 供应链控制塔 V1.0 版本范围

### 样例：与某快消品企业签约的 V1.0 范围界定

| 分类 | 功能 | 原因 |
|------|------|------|
| **Must Have** | 运单实时追踪（对接顺丰+京东+通达系） | 客户 80% 的货物走这几家 |
| **Must Have** | 异常自动预警（延迟、丢件、温控超标） | 这是客户买控制塔的核心理由 |
| **Must Have** | 数据看板（在途量、准时率、异常率） | 领导要看的基础指标 |
| **Should Have** | 多仓库存可视 | 客户有 5 个仓，想一屏看到 |
| **Should Have** | 移动端异常推送 | 仓库经理经常不在电脑前 |
| **Could Have** | 供应商协同工单 | 锦上添花，有更好 |
| **Could Have** | 历史数据趋势分析 | 有用但不是紧急的 |
| **Won't Have** | 需求预测联动 | 太复杂，放 V2.0 |
| **Won't Have** | 碳排放追踪 | 客户没提，不在这期做 |
| **Won't Have** | 多租户（SaaS 化） | 先做私有化部署的单客户版 |

**资源分配**：Must 60% + Should 25% + Could 15%

## 十一、组合使用 — 完整供应链产品规划流程

```
阶段 1：战略诊断（Rumelt 三要素）
  └── 诊断供应链核心痛点 → 找到杠杆点
  └── 样例：BOM 变更延迟是新品上市慢的根因

阶段 2：战场选择（Playing to Win）
  └── Where to Play：选客户、选场景、选价值链环节
  └── How to Win：成本领先 or 差异化
  └── 样例：WMS 聚焦中小电商+服装品类+智能波次

阶段 3：趋势判断（Wardley Mapping）
  └── 画价值链 → 标注演进阶段 → 找投资焦点
  └── 样例：数据集成正在 Custom→Product，是建护城河的窗口期

阶段 4：商业模式验证（Strategyzer）
  └── 画 Business Model Canvas → 验证 Value Proposition Fit
  └── 样例：供应商协同平台的最大风险是供应商是否愿意上来

阶段 5：竞品定位（Porter 五力 + 功能矩阵）
  └── 理解竞争格局 → 找差异化切入点
  └── 样例：最大对手不是 SAP，是 Excel

阶段 6：需求分类（Kano）
  └── Must-be / One-dimensional / Attractive 分类
  └── 样例：自动三单匹配是持续投入方向，风险预警是差异化卖点

阶段 7：路线图（Now-Next-Later + Theme）
  └── 按 Theme 组织，按确定性分层
  └── 样例：可见性 Theme（40%）+ 协同 Theme（30%）+ 数据基座 Theme（30%）

阶段 8：优先级排序（RICE + MoSCoW）
  └── RICE 量化排序 → MoSCoW 界定版本范围
  └── 样例：智能波次 RICE=160 排第一，Must；供应商门户排 Could 放后面
```
