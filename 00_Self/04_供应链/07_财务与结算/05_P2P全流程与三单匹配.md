## 一、P2P 是什么

**P2P（Procure-to-Pay，采购到付款）** 是从"发起采购需求"到"完成供应商付款"的完整业务流程。

> P2P 不是简单的"下单-收货-付款"，它包含预算控制、合同执行、实物管理、财务核算、资金支付五个维度的交叉管理。

### 为什么说它是"最后一公里"

```
很多企业的采购管理：
✅ 寻源定点做得好（选对了供应商）
✅ 价格谈判做得好（谈了个好价格）
✅ 合同管理做得好（签了严谨的合同）

❌ 但结算环节：
- 三单匹配全靠人工Excel
- 对账差异堆积如山
- 付款延迟导致供应商投诉
- 暂估金额与实际偏差巨大
- 资金计划永远不准
```

### 2.2 各节点详解

| 节点 | 输入 | 处理 | 输出 | 系统模块 |
|------|------|------|------|----------|
| ①需求提交 | 需求计划 | 预算检查、需求审批 | 采购申请(PR) | 需求管理 |

| ⑧付款执行 | 结算单 | 付款审批、银行付款 | 付款凭证 | 资金管理 |

## 三、三单匹配（Three-Way Matching）

### 3.1 什么是三单匹配

> 三单匹配是 P2P 中最关键的财务控制环节：将 **采购订单(PO)**、**收货单(GR)**、**供应商发票(IR)** 进行自动比对，确保"付的钱 = 买的东西 = 收的货"。

```
        PO（采购订单）
        ┌──────────┐
        │ 物料A    │
        │ 数量: 100│
        │ 单价: 10 │
        │ 总价:1000│
        └─────┬────┘
              │
    ┌─────────┼─────────┐
    ↓         ↓         ↓
   GR        PO        IR
 (收货单)   (采购单)   (发票)
    ↓         ↓         ↓
 ┌──────┐ ┌──────┐ ┌──────┐
 │数量98 │ │数量100│ │数量100│
 │单价10 │ │单价10 │ │单价10 │
 │总价980│ │总价1000││总价1000│
 └──────┘ └──────┘ └──────┘
    ↓         ↓         ↓
    └─────────┼─────────┘
              ↓
        匹配结果：差异200（少收2件）
```

### 3.2 匹配规则

| 匹配维度 | PO | GR | IR | 容差规则 |
|----------|----|----|-----|---------|
| 数量 | 100 | 98 | 100 | GR ≤ PO，IR ≤ GR（或≤PO） |
| 单价 | 10 | - | 10 | IR单价 = PO单价 |
| 总价 | 1000 | 980 | 1000 | IR总价 ≤ PO总价 × 容差率 |
| 税率 | 13% | - | 13% | IR税率 = 合同约定税率 |

### 3.3 匹配状态

| 状态 | 含义 | 后续动作 |
|------|------|----------|
| ✅ 完全匹配 | 三单一致（在容差内） | 自动进入付款流程 |
| ⚠️ 部分匹配 | 有差异但在容差内 | 人工确认后放行 |
| ❌ 匹配失败 | 超出容差 | 需要调查原因、调整后重新匹配 |
| 🔄 待匹配 | 等待三单齐全 | 暂估入账 |

### 3.4 容差设置

```yaml
# 典型容差配置
tolerance:
  quantity:
    po_vs_gr: 5%      # 允许收货少5%
    po_vs_ir: 5%      # 允许发票少5%
  price:
    po_vs_ir: 1%      # 允许价格偏差1%
  amount:
    po_vs_ir: 2%      # 允许总金额偏差2%
    min_amount: 50元   # 差异低于50元忽略
  tax:
    strict: true       # 税率必须严格匹配
```

## 四、异常处理机制

### 4.1 常见异常场景

| 异常 | 表现 | 处理方式 |
|------|------|----------|
| **收货少于PO** | GR数量 < PO数量 | 正常：部分收货，剩余继续跟踪 |
| **发票多于收货** | IR数量 > GR数量 | 异常：退回发票，要求核实 |
| **价格不一致** | IR单价 ≠ PO单价 | 核实是否调价，走价格变更流程 |
| **无PO收货** | 有GR无PO | 紧急采购补流程，或退回 |
| **无收货开票** | 有IR无GR | 退回发票，等收货后重新提交 |
| **重复发票** | 同一发票号重复提交 | 系统自动拦截 |

### 4.2 异常升级机制

```
L1 自动处理（容差内）  → 系统自动放行
L2 采购员处理          → 1个工作日内解决
L3 采购经理处理        → 3个工作日内解决
L4 财务总监介入         → 5个工作日内解决
L5 VP/总经理审批        → 特殊情况
```

### 5.2 三单匹配引擎设计

```python
# 三单匹配核心逻辑（伪代码）
def three_way_match(po, gr, invoice):
    result = MatchResult()
    
    # 1. 数量匹配
    gr_qty = sum_gr_items(gr)
    inv_qty = sum_invoice_items(invoice)
    po_qty = sum_po_items(po)
    
    if inv_qty > po_qty:
        result.add_error("发票数量超过PO数量")
    elif gr_qty < inv_qty:
        result.add_warning("收货数量少于发票数量，等待收货")
    
    # 2. 价格匹配
    for item in invoice.items:
        po_item = po.find_item(item.material)
        if abs(item.unit_price - po_item.unit_price) > tolerance.price:
            result.add_error(f"价格差异: {item.material}")
    
    # 3. 总金额匹配
    if abs(invoice.total - gr.total) > tolerance.amount:
        result.add_warning(f"金额差异: {invoice.total - gr.total}")
    
    # 4. 税率匹配
    for item in invoice.items:
        if item.tax_rate != po.find_item(item.material).tax_rate:
            result.add_error(f"税率不匹配: {item.material}")
    
    # 5. 确定匹配状态
    if result.errors:
        result.status = "MATCH_FAILED"
    elif result.warnings:
        result.status = "PARTIAL_MATCH"
    else:
        result.status = "FULL_MATCH"
    
    return result
```

## 六、最佳实践

### 6.1 流程优化

| 优化点 | 做法 | 效果 |
|--------|------|------|
| 自动PO生成 | PR审批通过后自动生成PO | 减少人工操作，缩短周期 |
| 供应商门户 | 供应商自助提交发票、查看对账 | 减少财务工作量 |
| 智能匹配 | AI识别发票异常，自动推荐匹配 | 匹配效率提升50%+ |
| 自动付款 | 匹配通过自动排入付款计划 | 付款及时率提升到98% |
| 预警机制 | 交期延误、价格异常自动告警 | 问题前置处理 |

### 6.2 关键指标

| 指标 | 目标 | 说明 |
|------|------|------|
| PO处理时效 | < 2天 | 从PR到PO的平均时间 |
| 三单匹配率 | > 95% | 自动一次匹配通过率 |
| 发票处理时效 | < 3天 | 从接收到匹配完成 |
| 付款及时率 | > 98% | 按账期准时付款 |
| 采购异常率 | < 3% | 需要人工干预的比例 |

## 七、常见坑

| 坑 | 描述 | 解法 |
|----|------|------|
| **GR/IR 不同步** | 收货和发票来自不同系统，数据不一致 | 统一数据源，建立数据对账机制 |
| **框架协议执行率低** | 合同签了但实际采购走非合同通道 | PO强制关联合同，无合同不能下单 |
| **供应商不配合对账** | 供应商不及时提交发票 | 建立供应商评分，对账及时率纳入KPI |
| **跨月结算混乱** | 月末最后几天的业务归属不清 | 统一收货截止日，跨月业务计入下月 |
| **暂估长期不清** | 暂估入账后忘记冲销 | 设置暂估超期预警（60天） |
