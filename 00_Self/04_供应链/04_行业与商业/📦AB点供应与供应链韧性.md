# AB 点供应与供应链韧性

> 💡 **核心结论**：AB 点供应的本质不是"找个备胎"，而是**构建一张可切换的供应网络**。在多工厂 × 多源 × 多业务属性的复杂场景下，真正的挑战不是"选 A 还是 B"，而是**在什么条件下切、切多少、切了之后上下游怎么跟上**——这需要一套完整的规则引擎 + 数据管道 + 协同机制。

---

## 💡 Highlights

> [!tip]- 核心发现
> - AB 点的核心价值 = **可切换性（Switchability）**，不是简单的冗余
> - 多工厂场景下，A/B 点不是"物料级"而是 **"工厂×物料"矩阵级**——同一个料号在不同工厂可能有不同的 A/B 点
> - 系统实现的关键：**配额引擎 + 切换规则 + 成本联动 + 产能校验**四位一体
> - 上下游协同：BOM 替代兼容 → 工艺路线切换 → 质量追溯 → 财务结算联动

## 一、什么是 A/B 点供应？

### 1.1 定义

> **A/B 点供应**：同一种物料（或可互替代的物料）由两家或多家合格供应商同时供货，通过预设规则动态分配采购量的供应策略。

| 术语 | 含义 |
|------|------|
| **A 点** | 主供应商，承担大部分采购量（通常 60-80%） |
| **B 点** | 次供应商，承担剩余采购量（通常 20-40%），关键时刻可切换为主供 |
| **C 点**（扩展） | 第三供应商，少量试跑或战略性储备（5-10%） |
| **VMI 点** | 供应商在客户处设仓库，按消耗结算 |

### 1.2 一个生动的例子

> **你家做饭的大米**——
>
> 你一直从超市 A 买五常大米（A 点），但你也知道楼下小卖部也卖同款（B 点）。
>
> 平时：你 90% 从超市 A 买（近、质量稳定、有会员折扣），10% 从小卖部应急。
>
> 某天超市 A 关门装修：你立刻 100% 从小卖部买——**无缝切换，家里不断粮**。
>
> 但如果你从来不去小卖部买，等超市 A 关门了才发现小卖部的米：
> - 可能品种不一样（质量差异）
> - 可能价格涨了 30%（没谈过价）
> - 可能没库存（没建立关系，临时买不到）
>
> **这就是 AB 点的本质**：B 点不是"备胎"，而是**一直在跑、随时能切的"热备"**。

### 1.3 AB 点 vs 单源 vs 多源

| 策略 | 供应商数量 | 配额分配 | 切换能力 | 适用场景 |
|------|:---------:|---------|---------|---------|
| **单源** | 1 | 100% | ❌ 无 | 标准件、供应商极可靠 |
| **AB 点** | 2-3 | 固定比例（如 70:30） | ✅ 有，规则明确 | 关键物料、需要韧性 |
| **多源** | 3+ | 动态优化 | ✅ 有，但管理复杂 | 杠杆物料、市场竞争充分 |

**AB 点是"有纪律的多源"**——不是越多越好，而是**2-3 家 + 明确规则 + 持续验证**。

## 二、AB 点对供应链韧性的四重作用

### 2.1 作用一：供应连续性保障

```
单源断供：                        AB 点断供：
  ┌─────┐                           ┌─────┐  ┌─────┐
  │ A点 │ ──断供──→ ❌ 停线           │ A点 │  │ B点 │
  └─────┘                           └──┬──┘  └──┬──┘
                                       │断供     │
                                       ↓        ↓
                                  ❌ 停线？  ✅ 切到 B 点
                                             产能可能降 30%
                                             但不停线！
```

**量化价值**：

| 指标 | 单源 | AB 点 | 改善 |
|------|:----:|:-----:|:----:|
| 断供导致停线概率 | ~100%（如果 A 断供） | ~20-30%（B 点产能有限） | **降 70-80%** |
| 平均恢复时间 | 4-12 周（找新供应商） | 1-2 周（B 点扩产） | **快 3-6 倍** |
| 年化风险暴露值 | ¥750 万 | ¥150 万 | **降 80%** |

### 2.2 作用二：价格博弈能力

> 有 B 点 ≠ 用 B 点来"压价"（这是初级采购的思维）
>
> 有 B 点 = **谈判时有"Walk Away"的能力**（这是高级采购的思维）

**生动的例子**：

> **没有 B 点的谈判**：
>
> 供应商 A："今年原材料涨了 15%，我们也要涨 12%。"
>
> 你："太高了，能不能 8%？"
>
> 供应商 A："不行，12%，否则交期没法保证。"
>
> 你："……好吧。"（因为你没有替代方案）
>
> **有 B 点的谈判**：
>
> 供应商 A："今年原材料涨了 15%，我们也要涨 12%。"
>
> 你："理解。但 B 供应商报价只涨了 7%，而且他们今年交付评分 98%。我们考虑把配额从 70:30 调整到 50:50。"
>
> 供应商 A："……我们可以谈谈，8% 怎么样？"

### 2.3 作用三：需求弹性缓冲

当需求突然上升时，AB 点可以**双线并行扩产**，比单源快一倍：

```
需求从 10,000/月 → 15,000/月（+50%）

单源：A 需扩产 50% → 产能爬坡 3-6 个月
AB 点：A 从 7,000 → 10,000（+43%），B 从 3,000 → 5,000（+67%）
       两边同步爬坡，总时间缩短 30-40%
```

### 2.4 作用四：创新竞争引擎

> AB 点不只是"保供"——它还是**技术进步的驱动力**。

| 机制 | 说明 |
|------|------|
| **技术对标** | A 点和 B 点互相竞争，推动技术迭代 |
| **成本竞赛** | 双方都知道有竞争对手，降本动力更强 |
| **方案多样性** | 不同供应商的工艺方案可能截然不同 |
| **风险分散** | 技术路线押宝风险——A 走路线 1，B 走路线 2 |

## 三、复杂场景——多工厂 × 多源 × 多业务属性

### 3.1 复杂度拆解

这是 AB 点落地最难的部分。真实企业不是"1 个工厂、1 个料号、2 个供应商"那么简单：

```
复杂度维度：
  ├── 工厂维度：工厂 1（上海）、工厂 2（武汉）、工厂 3（欧洲）
  ├── 物料维度：同料号在不同工厂可能用不同规格/版本
  ├── 供应商维度：A 点只能供工厂 1，B 点可以供 1 和 2
  ├── 业务属性维度：自制/外购、VMI/非 VMI、国产/进口
  └── 合规维度：不同市场的认证要求、碳足迹要求
```

### 3.2 典型场景矩阵

| 场景 | 描述 | 复杂度 | 典型行业 |
|------|------|:------:|---------|
| **1 工厂 × 2 供应商** | 最简单的 AB 点 | ⭐ | 小型制造 |
| **3 工厂 × 2 供应商** | 供应商能力不完全重叠 | ⭐⭐⭐ | 汽车、电子 |
| **5 工厂 × 3 供应商 × 2 业务模式** | VMI 和非 VMI 混合 | ⭐⭐⭐⭐ | 大型集团 |
| **全球 10+ 工厂 × 多供应商 × 多合规要求** | 跨国车企的现实 | ⭐⭐⭐⭐⭐ | 蔚来、小米出海 |

### 3.3 "工厂×物料×供应商"三维矩阵

这是系统设计的核心数据模型——**AB 点不是物料级的属性，而是"工厂×物料×供应商"三元组的属性**：

```
示例：铝合金型材（物料号 AL-001）

                    工厂 1（上海）    工厂 2（武汉）    工厂 3（匈牙利）
供应商 A（忠旺）       A 点 70%         A 点 60%          ❌ 未认证
供应商 B（诺贝丽斯）    B 点 30%         B 点 20%          A 点 80%
供应商 C（海德鲁）      ❌ 未认证        C 点 20%          B 点 20%
```

**关键洞察**：

> 同一个料号，在上海工厂 A 是 A 点，在匈牙利工厂可能根本没有认证。
>
> 这意味着 **MRP 跑采购需求时，配额计算必须按"工厂×物料×供应商"三维来做**，而不是物料级的全局配额。

### 3.4 业务属性带来的额外约束

| 业务属性 | 对 AB 点的影响 | 系统处理 |
|---------|---------------|---------|
| **VMI vs 非 VMI** | VMI 供应商需要在工厂旁设仓库，切换成本高 | 配额引擎需感知 VMI 模式 |
| **自制 vs 外购** | 自制件没有 AB 点（只有一个"供应商"——自己） | 工艺路线需支持自制/外购切换 |
| **国产 vs 进口** | 关税、交期、合规完全不同 | 配额引擎需考虑总成本（TCO） |
| **认证状态** | 供应商 A 已认证，B 还在认证中 | 配额引擎需过滤未认证供应商 |
| **模具/工装绑定** | 供应商 A 的模具只能给 A 用，不能转给 B | 产能校验需考虑模具约束 |
| **独家协议** | 某些品类签了独家，不适用 AB 点 | 合同条款需前置过滤 |

### 4.2 数据层：主数据模型

**核心实体关系**：

```
┌──────────┐    ┌──────────────┐    ┌──────────┐
│  工厂     │───▶│  供应关系     │◀───│  供应商   │
│ (Plant)  │    │ (Sourcing    │    │(Supplier)│
│          │    │  Relation)   │    │          │
│ 工厂ID   │    │ 工厂×物料×供应│    │ 供应商ID  │
│ 区域     │    │ 商 三元组     │    │ 区域     │
│ 业务模式 │    │ 配额比例     │    │ 认证状态  │
│ 合规要求 │    │ 认证状态     │    │ VMI能力   │
└──────────┘    │ VMI标记      │    │ 产能上限  │
                │ 优先级       │    └──────────┘
                └──────┬───────┘
                       │
              ┌────────▼────────┐
              │     物料         │
              │   (Material)    │
              │ 料号            │
              │ 技术规格        │
              │ 替代关系        │
              │ BOM 用量        │
              └─────────────────┘
```

**关键数据表**：

```sql
-- 供应关系表（核心）
CREATE TABLE sourcing_relation (
    id              BIGINT PRIMARY KEY,
    plant_id        VARCHAR(10),    -- 工厂
    material_id     VARCHAR(20),    -- 物料
    supplier_id     VARCHAR(20),    -- 供应商
    ab_flag         CHAR(1),        -- A/B/C 标记
    quota_pct       DECIMAL(5,2),   -- 配额百分比
    is_vmi          BOOLEAN,        -- 是否 VMI
    cert_status     VARCHAR(10),    -- 认证状态: certified/pending/expired
    cert_expire_date DATE,          -- 认证到期日
    max_capacity    DECIMAL(12,2),  -- 月度最大产能
    priority        INT,            -- 优先级 (1=A, 2=B, 3=C)
    switch_lead_time_days INT,      -- 切换准备天数
    effective_from  DATE,           -- 生效日期
    effective_to    DATE,           -- 失效日期
    UNIQUE (plant_id, material_id, supplier_id)
);

-- 物料替代关系表
CREATE TABLE material_alternative (
    id              BIGINT PRIMARY KEY,
    plant_id        VARCHAR(10),
    primary_material VARCHAR(20),   -- 主物料
    alt_material    VARCHAR(20),    -- 替代物料
    alt_type        VARCHAR(10),    -- 替代类型: full/partial/performance
    usage_ratio     DECIMAL(5,2),   -- 替代比例（1 个主料 = ? 个替代料）
    is_interchangeable BOOLEAN,     -- 是否双向可替代
    approval_required BOOLEAN,      -- 切换是否需要审批
    VALIDATE (alt_type IN ('full', 'partial', 'performance'))
);

-- 切换事件日志表
CREATE TABLE switch_event_log (
    id              BIGINT PRIMARY KEY,
    event_time      TIMESTAMP,
    plant_id        VARCHAR(10),
    material_id     VARCHAR(20),
    from_supplier   VARCHAR(20),    -- 切换前供应商
    to_supplier     VARCHAR(20),    -- 切换后供应商
    switch_type     VARCHAR(20),    -- 触发类型: manual/auto/emergency
    trigger_reason  TEXT,           -- 触发原因
    quota_before    DECIMAL(5,2),   -- 切换前配额
    quota_after     DECIMAL(5,2),   -- 切换后配额
    impact_amount   DECIMAL(12,2),  -- 影响金额
    approved_by     VARCHAR(50),    -- 审批人
    status          VARCHAR(10)     -- pending/executed/rolled_back
);
```

### 4.3 执行层：配额引擎设计

**配额计算流程**：

```
MRP 需求产生
    │
    ▼
┌─────────────────────────┐
│ 1. 获取有效供应关系       │  按"工厂×物料"查询 sourcing_relation
│    过滤：认证有效、产能>0  │  排除：未认证、已过期、产能为0
└────────────┬────────────┘
             │
             ▼
┌─────────────────────────┐
│ 2. 应用配额规则          │  读取 quota_pct
│    检查 VMI 约束         │  VMI 供应商优先分配
│    检查最小批量           │  MOQ 约束
└────────────┬────────────┘
             │
             ▼
┌─────────────────────────┐
│ 3. 产能校验              │  总需求 vs 各供应商最大产能
│    超出部分重新分配       │  如果 A 点产能不够，溢出给 B 点
└────────────┬────────────┘
             │
             ▼
┌─────────────────────────┐
│ 4. 成本优化（可选）       │  TCO 比较，在配额范围内微调
│    在约束条件下优化       │  约束：A 点不低于 30%，B 点不低于 15%
└────────────┬────────────┘
             │
             ▼
┌─────────────────────────┐
│ 5. 生成采购订单          │  按供应商拆分 PO
│    记录配额执行日志       │  写入 switch_event_log
└─────────────────────────┘
```

### 4.4 决策层：切换规则引擎

**切换触发条件**：

| 触发类型 | 条件 | 动作 | 审批要求 |
|---------|------|------|---------|
| **绩效驱动** | A 点 OTIF < 90% 连续 2 周 | 配额从 70:50 调整为 50:50 | 品类经理审批 |
| **产能不足** | A 点产能利用率 > 95% | 溢出需求自动转给 B 点 | 系统自动 |
| **质量异常** | A 点 PPM > 100（目标 < 50） | 暂停 A 点新订单，B 点承接 | 质量+采购双审批 |
| **价格异常** | A 点报价高于 B 点 > 8% | 触发配额调整评审 | 采购总监审批 |
| **紧急事件** | A 点工厂火灾/自然灾害 | 紧急切换到 B 点 100% | 总经理特批 |
| **认证到期** | A 点认证 30 天内到期未续 | 自动降低配额，提醒续证 | 系统提醒 |
| **战略调整** | 新市场开发需要本地供应商 | 引入 C 点，逐步提升配额 | 战略评审 |

**规则引擎设计**：

```yaml
# 切换规则配置示例
switch_rules:
  - rule_id: "R001"
    name: "OTIF 低于阈值自动降配额"
    trigger:
      metric: "OTIF"
      operator: "<"
      threshold: 90
      duration_weeks: 2
    action:
      type: "quota_adjust"
      from: { supplier: "A", quota: 70 }
      to: { supplier: "A", quota: 50 }
      increase_supplier: "B"
    approval: "category_manager"
    cooldown_days: 30  # 触发后 30 天内不再触发

  - rule_id: "R002"
    name: "质量红线 - 紧急暂停"
    trigger:
      metric: "PPM"
      operator: ">"
      threshold: 200
      duration_days: 3
    action:
      type: "pause_supplier"
      target: "A"
      redirect_to: "B"
    approval: "quality_and_procurement"
    is_emergency: true

  - rule_id: "R003"
    name: "产能溢出自动分配"
    trigger:
      metric: "capacity_utilization"
      operator: ">"
      threshold: 95
    action:
      type: "overflow"
      overflow_to: "B"
      maintain_minimum: { supplier: "A", min_pct: 30 }
    approval: "auto"
```

### 4.5 与上下游系统的联动

**上游（需求侧）→ AB 点配额引擎 → 下游（执行侧）**：

```
┌─────────────────────────────────────────────────────────────┐
│                           上 游                              │
│  S&OP → MRP → 采购需求（PR）                                  │
│  需求计划告诉配额引擎：这个月需要 10,000 件                     │
└──────────────────────────┬──────────────────────────────────┘
                           │ 采购需求
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                     AB 点配额引擎                             │
│                                                              │
│  输入：工厂=上海, 物料=AL-001, 需求=10,000                     │
│  查询：sourcing_relation WHERE plant='上海' AND material='AL-001'│
│  结果：供应商A=70%, 供应商B=30%                                │
│  产能校验：A 最大 8,000, B 最大 5,000 → OK                     │
│  输出：PO-A=7,000, PO-B=3,000                                │
└──────────────────────────┬──────────────────────────────────┘
                           │ 拆分后的 PO
              ┌────────────┼────────────┐
              ▼            ▼            ▼
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│   ERP/SRM    │  │  供应商协同   │  │  质量追溯    │
│  采购订单    │  │  ASN/交货通知 │  │  来料检验    │
│  收货入库    │  │  库存可视     │  │  质量评分    │
│  发票匹配    │  │  产能承诺     │  │  反馈配额    │
└──────────────┘  └──────────────┘  └──────────────┘
```

**关键联动点**：

| 上下游 | 联动内容 | 系统实现 |
|--------|---------|---------|
| **BOM → 配额** | BOM 中标识哪些物料有替代关系 | 物料主数据中维护替代组 |
| **工艺路线 → 切换** | 不同供应商的加工参数可能不同 | MES 中维护多供应商工艺路线 |
| **质量 → 配额** | 质量评分低的供应商自动降配额 | QMS → 配额引擎 API |
| **财务 → 结算** | 不同供应商的付款条件、币种不同 | AP 模块自动按供应商匹配付款条件 |
| **仓储 → 收货** | VMI 供应商直供 vs 非 VMI 需入库 | WMS 按供应商类型走不同收货流 |
| **计划 → 需求** | MRP 按配额拆分给不同供应商 | MRP 配额安排（SAP MEQ1） |

## 五、BOM 层面的替代兼容设计

### 5.1 替代类型分类

| 替代类型 | 含义 | 切换难度 | 示例 |
|---------|------|:--------:|------|
| **完全替代** | A 和 B 完全可互换，不改任何设计 | ⭐ | 标准紧固件、通用电阻 |
| **性能替代** | 功能相同但参数略有差异，需验证 | ⭐⭐ | 不同品牌的 MCU（引脚兼容但性能不同） |
| **设计替代** | 需要修改设计才能使用替代料 | ⭐⭐⭐ | 不同封装的传感器 |
| **工艺替代** | 物料可替代但生产工艺需调整 | ⭐⭐⭐ | 不同供应商的铝合金（热处理参数不同） |

### 5.2 BOM 中的替代关系设计

```
传统 BOM：
  总成 → 部件 → 零件 → 原材料
  （一棵树，每个节点只有一个料号）

带替代的 BOM：
  总成 → 部件 → 零件 → 原材料组
                         ├── 原材料 A（首选）
                         ├── 原材料 B（替代，需验证）
                         └── 原材料 C（替代，完全互换）
```

**SAP 中的实现**：

| 方法 | 说明 | 适用 |
|------|------|------|
| **替代料（Substitution）** | BOM 中直接指定替代料号 | 完全替代 |
| **替代组（Alternative Item Group）** | 同组内多个料号可互换 | 性能替代 |
| **版本 BOM（Alternative BOM）** | 整个 BOM 用不同版本 | 工艺替代 |
| **配额安排（Quota Arrangement）** | MRP 运行时按配额选供应商 | 同料号多供应商 |

### 5.3 替代验证流程

```
新替代关系建立
    │
    ▼
┌───────────────┐
│ 1. 工程验证    │  研发确认功能/性能等效
│  (EV 测试)     │  输出：验证报告
└──────┬────────┘
       │
       ▼
┌───────────────┐
│ 2. 小批试产    │  100-500 件试跑
│  (Pilot Run)   │  观察良率、工艺稳定性
└──────┬────────┘
       │
       ▼
┌───────────────┐
│ 3. 量产验证    │  批量使用 1-3 个月
│  (Mass Prod)   │  确认质量、交付、成本
└──────┬────────┘
       │
       ▼
┌───────────────┐
│ 4. 正式纳入    │  BOM 更新替代关系
│  (Qualify)     │  配额引擎可使用
└───────────────┘
```

## 六、上下游协同的五个关键问题

### 6.1 上游：需求变化如何传递到 AB 点？

```
S&OP 会议确定：下月产量 10,000 台 → 30,000 台（新品爆单）

传统做法：
  采购打电话给 A 点："紧急，能不能多供 20,000？"
  A 点："我产能不够，最快下下月。"
  停线 2 周。

AB 点做法：
  配额引擎自动计算：
    原配额：A=21,000(70%), B=9,000(30%)
    新需求：A 需 21,000, B 需 9,000（增量全部给 B，因为 A 产能满载）
    → B 点：9,000 → 21,000（+133%），需要确认产能
    → 同时通知 C 点准备启动验证
  系统自动发预警给 B 点和采购经理。
```

### 6.2 下游：切换时生产怎么跟上？

| 切换场景 | 生产影响 | 应对措施 |
|---------|---------|---------|
| 同料号不同供应商 | 工艺参数可能需微调 | MES 提前下发新供应商的工艺参数 |
| 替代料号切换 | BOM 需更新，工装可能需调整 | 工程变更通知（ECN）+ 生产准备检查表 |
| VMI → 非 VMI 切换 | 收货流程变化，入库检验增加 | WMS 提前配置新收货路径 |
| 跨工厂切换 | 物流路径变化 | TMS 更新运输计划 |

### 6.3 质量追溯：切了之后出了问题怎么办？

```
场景：A 点质量出问题，切到 B 点后，B 点的零件在客户端出了质量事故

追溯链：
  客户投诉 → 成品序列号 → 生产批次 → B 点来料批次 → B 点生产批次
                                                          │
                                              ┌───────────┼───────────┐
                                              ▼           ▼           ▼
                                         原材料批次   工艺参数    检验记录

系统要求：
  1. 每个零件必须标识供应商来源（条码/RFID）
  2. 生产 MES 记录每个零件用的哪个供应商的料
  3. 切换时必须有"首批检验"记录
  4. 质量问题可以精确定位到"供应商×批次×时间段"
```

### 6.4 财务结算：不同供应商怎么算？

| 差异点 | A 点 | B 点 | 系统处理 |
|--------|------|------|---------|
| 单价 | ¥10.00 | ¥10.50 | PO 自动按供应商取价 |
| 账期 | 60 天 | 45 天 | AP 按供应商匹配付款条件 |
| 币种 | CNY | EUR | 多币种结算 + 汇率管理 |
| VMI 结算 | 月度消耗结算 | - | VMI 库存 → 自动开票 |
| 折扣 | 年采 100 万返 2% | 无 | 合同条款 → AP 自动计算 |

### 6.5 供应商关系：B 点会不会"躺平"？

> **最常见的陷阱**：B 点配额只有 20%，量少成本高，供应商不重视，质量下降，最终被淘汰——然后你又变成单源了。

**解决机制**：

| 机制 | 说明 |
|------|------|
| **最低配额承诺** | 合同约定 B 点不低于 20%，即使 A 点更优 |
| **轮换机制** | 每年有一次配额轮换评审（A/B 角色可能互换） |
| **绩效驱动调整** | B 点绩效好 → 配额从 20% 提到 35%（动态激励） |
| **联合降本** | 帮 B 点优化工艺，降低其成本，使其更有竞争力 |
| **战略备件承诺** | 即使量少，也签年度协议，给 B 点"安全感" |

## 七、实战案例

### 7.1 汽车行业：博世 ESP 系统的 AB 点

> 博世的 ESP（电子稳定程序）是汽车行业最核心的安全件之一。
>
> 2021 年芯片缺货时：
> - 博世自身是 Tier 1，供货给大众、宝马等 OEM
> - 博世的芯片来自恩智浦（NXP）、英飞凌等
> - 当 NXP 断供时，博世切到英飞凌——但芯片不完全 pin-to-pin 兼容
> - 需要重新做 PCB 布局 → 需要 OEM 重新认证
> - **整个切换周期：6-9 个月**
>
> **教训**：安全件的 AB 点必须是**提前验证过的、随时可切的**，不能等出事了才找替代。

### 7.2 消费电子：苹果的"双供应商策略"

> 苹果是 AB 点策略的极致执行者：
>
> | 零部件 | A 点 | B 点 | 备注 |
> |--------|------|------|------|
> | OLED 屏幕 | 三星 | LG Display | 三星为主，LG 逐步提升 |
> | 芯片代工 | 台积电 | 三星（有限） | 台积电为主，三星作为战略备份 |
> | 组装 | 富士康 | 立讯精密 | 富士康为主，立讯快速崛起 |
> | 镜头 | 大立光 | 舜宇光学 | 高端用大立光，中端用舜宇 |
>
> **苹果的"秘密"**：
> 1. 不只是 AB 点——它是**"能力备份"**，不只是"产能备份"
> 2. 苹果会**主动扶持 B 点**——派工程师、投资设备、分享技术
> 3. **B 点的终极目标是成为 A 点**——这样才能形成真正的竞争

### 7.3 新能源：宁德时代 vs 比亚迪电池

> 小米 SU7 的电池策略：
>
> | 车型 | A 点 | B 点 | 说明 |
> |------|------|------|------|
> | SU7 标准版 | 宁德时代（磷酸铁锂） | 比亚迪弗迪 | 双供应商保供 |
> | SU7 Max | 宁德时代（麒麟电池） | 暂无（独家） | 技术壁垒，暂时单源 |
>
> **挑战**：
> - 宁德时代的麒麟电池是独家技术，短期内没有 B 点
> - 小米的应对：自研电池技术 + 与中创新航等二线厂商合作开发
> - **长期目标**：任何核心部件都不依赖单一供应商

## 八、落地路线图

| 阶段 | 时间 | 目标 | 关键动作 |
|------|------|------|---------|
| **Phase 1：识别** | 0-3 月 | 找出需要 AB 点的品类 | 分析 Top 50 物料的供应集中度、风险等级 |
| **Phase 2：建模** | 3-6 月 | 建立"工厂×物料×供应商"矩阵 | 清理主数据，建立供应关系表 |
| **Phase 3：验证** | 6-12 月 | B 点完成认证和小批试产 | 质量验证、工艺验证、产能验证 |
| **Phase 4：运行** | 12-18 月 | 配额引擎上线，日常按配额执行 | MRP 集成、PO 自动拆分 |
| **Phase 5：智能化** | 18-24 月 | 切换规则引擎 + 场景模拟 | 自动切换、韧性仪表盘 |

## 九、核心观点总结

> [!important] 三句话记住这份研究
>
> 1. **AB 点的本质是"可切换性"**——不是找个备胎放着，而是**持续运行、随时验证、规则明确**的热备机制
>
> 2. **多工厂场景下 AB 点是三维矩阵**——"工厂×物料×供应商"的配额关系，不能用物料级的全局配额来管理
>
> 3. **上下游协同是落地的关键**——BOM 替代兼容 → 工艺路线切换 → 质量追溯 → 财务结算，四个环节缺一不可
