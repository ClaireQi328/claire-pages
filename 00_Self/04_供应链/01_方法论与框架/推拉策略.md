# 供应链推拉策略

> 💡 **10年+视角**：推（Push）和拉（Pull）不是非此即彼的选择，而是**在一个供应链中同时存在**。关键问题是：推拉分界点（Decoupling Point）放在哪里？这个点的位置，决定了你的供应链是"成本优先"还是"响应优先"。

---

## 一、Push vs Pull 的本质区别

| 维度 | 推式（Push） | 拉式（Pull） |
|------|------------|------------|
| **驱动信号** | 预测（Forecast） | 实际需求（Actual Demand） |
| **计划方式** | 按预测生产/采购 | 按消耗补货 |
| **库存位置** | 分散在各环节 | 集中在分界点 |
| **风险** | 预测错误 → 库存积压 | 需求超出缓冲 → 断货 |
| **适用** | 需求稳定、LT 长 | 需求波动大、LT 短 |
| **典型代表** | 传统制造业（汽车、重工） | 快消、电商（ZARA、亚马逊） |

---

## 二、推拉分界点（Decoupling Point）

> 📖 出处：Sharman, 1984; Hoekstra & Romme, 1992

### 2.1 定义

> **推拉分界点**：供应链中"预测驱动"和"需求驱动"的分界位置。分界点之前是推式，之后是拉式。

### 2.2 分界点位置图谱

```
原材料 ──→ 零部件 ──→ 半成品 ──→ 成品 ──→ 配送 ──→ 客户
                                         
   ◄─────── Push（推） ──────►│◄──── Pull（拉） ────►
                              │
                         分界点（DP）

分界点越靠上游 → Push 越长 → 成本低但响应慢
分界点越靠下游 → Pull 越长 → 响应快但成本高
```

### 2.3 典型行业的分界点位置

| 行业 | 分界点位置 | 典型企业 | 策略 |
|------|----------|---------|------|
| **重型制造** | 原材料/铸件 | 卡特彼勒 | 纯 Push |
| **汽车** | 车身/油漆后 | 丰田（BTO 前） | Push + 拉动装配 |
| **3C 电子** | 模块/组件 | 戴尔 | 模块 Push，配置 Pull |
| **服装** | 面料/裁片 | ZARA | 面料 Push，成衣 Pull |
| **快消** | 成品仓 | 宝洁 | 成品 Push，补货 Pull |
| **定制家具** | 板材 | 索菲亚 | 板材 Push，定制 Pull |
| **纯定制** | 原材料 | 手工西装 | 几乎纯 Pull |

## 三、五种供应链策略模型

> 📖 综合 Chopra & Meindl + Fisher + Christopher 的框架

| 策略 | Push-Pull 比例 | 适用产品 | 核心能力 |
|------|:---:|---------|---------|
| **纯推式** | 100:0 | 大宗商品、基础原材料 | 成本控制 |
| **推拉结合** | 70:30 | 汽车、家电 | 平衡成本与响应 |
| **延迟策略** | 50:50 | PC 配置、涂料 | 模块化 + 定制 |
| **拉推结合** | 30:70 | 时装、手机新品 | 柔性产能 + 快速补货 |
| **纯拉式** | 0:100 | 定制产品、按需生产 | 敏捷响应 |

## 四、延迟策略（Postponement）

> 📖 出处：Alderson, 1950; Bucklin, 1965; Lee & Tang, 1997

延迟策略是推拉结合最精妙的应用——把产品差异化尽可能推迟。

### 4.1 四种延迟类型

| 类型 | 延迟什么 | 示例 |
|------|---------|------|
| **形式延迟** | 产品形态（颜色、配置） | 涂料现场调色、PC 按单组装 |
| **物流延迟** | 配送时间和地点 | 中心仓延迟发货到区域仓 |
| **贴牌延迟** | 品牌标识 | OEM 工厂最后环节贴标 |
| **生产延迟** | 最终组装/包装 | 戴尔按单组装、ZARA 裁片后快速成衣 |

### 4.2 延迟策略的经典案例

**戴尔电脑（Dell Direct Model）**：

```
推式阶段（标准化）：
  CPU 芯片 ──→ 内存条 ──→ 硬盘 ──→ 主板组件
  （按预测采购通用组件，大量备库存）

拉式阶段（定制化）：
  客户下单 → 选择配置 → 组装 → 测试 → 发货
  （按订单组装，48小时内交付）

结果：
  - 库存周转天数：4 天（竞争对手 30-60 天）
  - 零部件通用化率 > 80%
  - 客户获得"定制"体验，但供应链是标准化的
```

**ZARA 的延迟策略**：

```
推式阶段：
  面料采购和染色（通用面料，按预测备料）
  基础裁剪（裁片按预测储备）

拉式阶段：
  设计师观察市场趋势 → 2周内完成设计-打样-生产-上架
  按门店实际销售数据补货（每周 2 次）

结果：
  - 从设计到上架：2 周（行业平均 6-9 个月）
  - 库存周转率：行业最高
  - 售罄率 > 85%（行业平均 60%）
```

## 五、精益 vs 敏捷 vs Leagile

> 📖 出处：Martin Christopher & Denis Towill, 2000

| 策略 | 英文 | 核心思想 | 适用 | 驱动方式 |
|------|------|---------|------|---------|
| **精益** | Lean | 消除浪费、追求效率 | 稳定需求、功能型产品 | Push |
| **敏捷** | Agile | 快速响应、柔性交付 | 波动需求、创新型产品 | Pull |
| **精敏** | Leagile | 前端精益 + 后端敏捷 | 大多数实际场景 | Push-Pull |

```
Leagile 模型：

精益上游                     敏捷下游
（效率优先）                  （响应优先）
┌─────────────┐  ┌──────────────────┐
│ 标准化组件   │──│ 定制化组装/配送    │
│ 按预测生产   │  │ 按订单执行         │
│ 成本控制     │  │ 客户服务           │
└─────────────┘  └──────────────────┘
         ↑
    解耦点（Decoupling Point）
```

## 六、推拉分界点的决策框架

### 6.1 决策矩阵

| 因素 | 推向 Push | 推向 Pull |
|------|----------|----------|
| 需求可预测性 | 高 → Push | 低 → Pull |
| 产品生命周期 | 长 → Push | 短 → Pull |
| 产品价值 | 低 → Push | 高 → Pull |
| 提前期 | 长 → Push | 短 → Pull |
| 客户容忍等待 | 高 → Push | 低 → Pull |
| 产品多样性 | 低 → Push | 高 → Pull |

### 6.2 定量分析框架

```
分界点位置 = f(预测准确率, LT比, 库存成本率, 缺货成本率)

简化的决策规则：
  如果 预测准确率 > 80% 且 LT < 2周 → 分界点可以更靠近客户端（Pull更长）
  如果 预测准确率 < 60% 且 LT > 8周 → 分界点必须更靠近供应端（Push更长）
```

## 七、实战建议

| # | 建议 | 说明 |
|:-:|------|------|
| 1 | **不要追求"纯 Pull"** | 除非是纯定制产品，否则总有一部分是推式的 |
| 2 | **分界点不是固定的** | 产品生命周期不同阶段，分界点应该动态调整 |
| 3 | **通用化是延迟的前提** | 没有模块化设计，延迟策略无法实施 |
| 4 | **信息共享缩短有效 LT** | 供应商看到你的实时销售数据，等效于缩短了信息 LT |
| 5 | **分界点处的库存是"战略库存"** | 不是浪费，是实现响应速度的投资 |
