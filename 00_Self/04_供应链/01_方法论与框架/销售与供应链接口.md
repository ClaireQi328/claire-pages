# 销售与供应链的接口

> 💡 **10年+视角**：供应链和销售是一枚硬币的两面——销售管"卖出去"，供应链管"供得上"。但现实中，这两个部门往往是"对立"关系：销售嫌供应链交不出货，供应链嫌销售预测不准。**打通销售-供应链接口，是供应链管理中最重要也最困难的组织协同问题。**

---

## 一、销售与供应链的核心矛盾

| 销售视角 | 供应链视角 |
|---------|----------|
| "客户要的怎么没有？" | "你预测的怎么不准？" |
| "这个客户必须保！" | "所有客户都说必须保" |
| "新品必须下周上市！" | "BOM 都没定怎么做？" |
| "促销力度再大一点！" | "促销后库存谁来背？" |
| "库存太少了客户跑了！" | "库存太多了资金占用！" |

**根因**：两者的 KPI 天然冲突——

| 销售 KPI | 供应链 KPI |
|---------|----------|
| 营收增长 | 库存周转 |
| 客户满意度（OTIF） | 运营成本 |
| 市场份额 | 缺货率 |
| 新品上市速度 | 生产效率 |

→ **S&OP 就是解决这个矛盾的核心机制**

---

## 二、O2C（Order-to-Cash）全流程

> O2C 是销售和供应链的"交汇点"——从客户下单到收到回款的全过程。

```
销售机会 → 报价 → 合同 → 订单 → 信用检查 → 库存/生产分配
    ↓                                         ↓
                                          发货 → 物流跟踪 → 客户签收
                                                             ↓
                                          开票 → 应收账款 → 回款 → 现金确认
```

### 2.1 O2C 各环节的销售-供应链分工

| 环节 | 销售负责 | 供应链负责 | 交汇点 |
|------|---------|----------|--------|
| **报价** | 客户沟通、定价策略 | ATP/CTP 确认 | 交期承诺 |
| **合同** | 条款谈判 | 交付条款可行性 | 交期/数量/价格 |
| **订单** | 订单录入 | 库存分配/生产安排 | 订单确认 |
| **发货** | 通知客户 | 仓库拣货+物流 | 发货通知 |
| **开票** | 确认收入 | 提供发货凭证 | 三单匹配 |
| **回款** | 催款 | 无 | 应收账款 |

### 2.2 ATP / CTP 的关键作用

```
客户问："我要 1000 件，什么时候能交？"

销售的冲动回答："下周就能交！"（先接单再说）

供应链的正确做法：
  1. ATP（可承诺量）：查现有库存 + 在途 = 有 600 件可承诺
  2. CTP（可承诺交期）：剩余 400 件需要生产，最早 3 周后交付
  3. 回复客户："600 件下周交，400 件 3 周后交"

→ ATP/CTP 是销售承诺的"刹车系统"，防止过度承诺
```

## 三、销售渠道模式与供应链影响

### 3.1 渠道类型

| 渠道 | 定义 | 供应链特点 |
|------|------|----------|
| **直销（Direct）** | 厂家直接卖给终端客户 | 需求信号清晰、LT 短 |
| **分销（Distribution）** | 通过经销商/代理商销售 | 需求信号失真、库存分散 |
| **电商（E-commerce）** | 线上平台销售 | 需求波动大、履约时效要求高 |
| **OEM/ODM** | 为品牌方代工生产 | 大客户依赖、计划性较强 |
| **零售（Retail）** | 线下门店销售 | POS 数据、补货频率高 |

### 3.2 渠道模式对供应链的影响

```
直销模式：
  客户 ──→ 厂家
  ✅ 需求信号真实
  ✅ 库存集中管理
  ❌ 覆盖面有限

分销模式：
  客户 ──→ 经销商 ──→ 厂家
  ❌ 需求信号失真（经销商囤货/冲量）
  ❌ 库存分散在渠道
  ✅ 覆盖面广、资金风险转移

电商模式：
  消费者 ──→ 平台 ──→ 厂家/仓
  ✅ 实时需求数据
  ❌ 波动极大（大促、直播带货）
  ❌ 退货率高（服装 30-40%）
```

### 3.3 渠道库存管理

| 问题 | 根因 | 对策 |
|------|------|------|
| **渠道压货** | 销售冲 KPI，把货压给经销商 | 渠道库存可视 + 返利改为按动销 |
| **渠道窜货** | A 区域的货卖到 B 区域 | 区域编码追溯 + 窜货处罚 |
| **渠道虚报需求** | 经销商夸大需求抢配额 | 限制渠道库存上限 |
| **渠道退货** | 压货过多导致退货 | 合理库存目标 + 退货条款 |

## 四、S&OP 中的销售角色

### 4.1 销售在 S&OP 各步骤中的职责

| S&OP 步骤 | 销售角色 | 输出 |
|-----------|---------|------|
| **数据准备** | 提供最新客户订单和 pipeline | 客户订单池 |
| **需求评审** | 陈述市场变化、客户反馈、竞品动态 | 共识需求预测 |
| **供应评审** | 参与讨论供需缺口的销售影响 | 需求优先级排序 |
| **Pre-S&OP** | 评估方案对客户/营收的影响 | 方案偏好 |
| **S&OP 会议** | 决策需求侧策略（促销/定价/客户取舍） | 最终决议 |

### 4.2 销售预测 vs 统计预测

| 维度 | 统计预测 | 销售预测（Override） |
|------|---------|-------------------|
| **数据来源** | 历史数据 + 模型 | 客户反馈 + 市场判断 |
| **优势** | 客观、可重复 | 捕获模型无法感知的信号 |
| **劣势** | 无法预测新品/市场突变 | 主观偏差、乐观倾向 |
| **最佳实践** | 作为基线（Baseline） | 在基线上调整（Override） |

**最佳实践**：
```
最终预测 = 统计基线 × (1 + 销售调整系数)

规则：
  - 销售调整幅度 > ±20% 需要提供书面理由
  - 调整幅度 > ±50% 需要总监审批
  - 每月回顾销售调整的准确率，纳入销售 KPI
```

### 4.3 销售预测的常见偏差

| 偏差类型 | 表现 | 根因 |
|---------|------|------|
| **乐观偏差** | 预测偏高 | 销售天然乐观 + 争取更多资源 |
| **保守偏差** | 预测偏低 | 怕完不成 KPI 被罚 |
| **月底冲量** | 月底集中下单 | KPI 按月考核 |
| **新品过估** | 新品预测过高 | 对市场预期过于乐观 |
| **客户博弈** | 夸大需求争取优先供应 | 信息不对称 |

## 五、销售与供应链协同的关键机制

### 5.1 五大协同机制

| 机制 | 做法 | 解决什么问题 |
|------|------|------------|
| **S&OP 月度会议** | 销售+供应链+财务共同参与 | 供需对齐 |
| **共享 KPI** | OTIF 是销售和供应链的共同 KPI | 目标对齐 |
| **ATP/CTP 机制** | 销售承诺前必须查 ATP | 防止过度承诺 |
| **需求计划委员会** | 独立的需求计划团队，平衡销售和供应链 | 客观性 |
| **渠道库存可视** | 实时看到渠道库存和动销数据 | 消除信息不对称 |

### 5.2 共享 KPI 设计

| KPI | 销售承担 | 供应链承担 | 说明 |
|-----|:------:|:--------:|------|
| **OTIF** | 50% | 50% | 共同对交付负责 |
| **库存周转** | 30% | 70% | 销售对渠道库存负责 |
| **预测准确率** | 40% | 60% | 共同提升预测质量 |
| **营收达成** | 70% | 30% | 供应链要保障供应 |

## 六、行业案例

### 6.1 华为的"铁三角"

```
华为的销售-供应链协同模型：

客户经理（AR）── 负责客户关系和商务
    │
解决方案经理（SR）── 负责技术方案
    │
交付经理（FR）── 负责供应链交付
    │
三者组成"铁三角"，共同对客户满意度负责

效果：
  - 客户承诺由交付经理（供应链）把关
  - 不会出现销售乱承诺、供应链做不到的情况
  - OTIF 从 85% 提升到 95%+
```

### 6.2 ZARA 的销售-供应链一体化

```
ZARA 的模式：销售数据实时驱动供应链

门店经理 ──→ 每天反馈销售数据和客户偏好
    ↓
设计团队 ──→ 2 周内完成设计-打样-生产
    ↓
供应链 ──→ 按门店销售数据每周 2 次补货
    ↓
效果：
  - 库存周转率行业最高
  - 售罄率 >85%
  - 降价比例 <15%（行业平均 30%+）
```

| 系统 | 功能 | 与供应链的接口 |

| **CRM** | 客户关系管理、销售 pipeline | 需求信号 → 需求预测 |
| **CPQ** | 配置-报价-合同 | ATP 查询 → 交期承诺 |
