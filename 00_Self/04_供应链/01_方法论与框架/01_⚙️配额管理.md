# 供应链配额管理

> 💡 **10年+视角**：配额管理是供应链中最"不起眼"但"影响巨大"的机制。你可能没听过这个词，但你一定经历过——芯片缺货时供应商只给你 60% 的量、仓库间库存分配不均导致一边缺货一边积压、销售目标分配不合理导致区域冲突——这些都是配额管理问题。**配额的本质是"稀缺资源的分配规则"。**

---

## 一、什么是配额管理

### 1.1 定义

> **配额（Quota/Allocation）**：在资源有限的情况下，按照预设规则将总量分配给多个需求方的管理机制。

### 1.2 配额存在的根本原因

```
资源 < 需求 → 需要分配规则

资源可以是：
  - 供应商产能（晶圆代工产能有限）
  - 物料供应（芯片缺货）
  - 仓库空间（仓位有限）
  - 运输能力（车辆/舱位有限）
  - 销售目标（营收需要分配到区域/人）
  - 预算（采购预算有限）
```

### 1.3 配额管理在供应链中的六大应用场景

| # | 场景 | 资源 | 分配对象 | 触发条件 |
|:-:|------|------|---------|---------|
| 1 | **采购配额** | 采购量 | 多个供应商 | 多源采购策略 |
| 2 | **产能配额** | 供应商产能 | 多个客户 | 产能不足/长协 |
| 3 | **缺货分配** | 有限库存 | 多个客户 | 供不应求 |
| 4 | **库存分配** | 中心仓库存 | 多个区域仓/门店 | 多级库存管理 |
| 5 | **销售配额** | 销售目标 | 区域/渠道/个人 | 年度/季度目标分解 |
| 6 | **预算配额** | 采购预算 | 品类/部门 | 预算控制 |

## 二、采购配额（Sourcing Quota）

### 2.1 定义

> 同一种物料由多家供应商供货时，按配额比例分配采购量。

### 2.2 配额分配的典型规则

| 规则 | 说明 | 适用场景 |
|------|------|---------|
| **固定比例** | 如 A:60%, B:40% | 稳定的双源策略 |
| **绩效加权** | 按 QCDS 评分动态调整 | 持续改善驱动 |
| **成本优先** | 价格低的多分 | 杠杆物料 |
| **风险分散** | 确保每家都有最低量 | 战略物料保供 |
| **产能约束** | 按供应商最大产能分配 | 产能紧张时 |
| **阶梯式** | 小量给新供应商试跑 | 新供应商导入 |

### 2.3 SAP 配额管理（Quota Arrangement）

```
SAP MM 模块中的配额管理：

MEQ1 - 维护配额安排
  物料：芯片 XYZ
  ┌─────────────┬──────┬──────┬────────┐
  │ 供应商       │ 配额  │ 配额% │ 优先级  │
  ├─────────────┼──────┼──────┼────────┤
  │ 供应商 A     │  60  │ 60%  │   1    │
  │ 供应商 B     │  30  │ 30%  │   2    │
  │ 供应商 C     │  10  │ 10%  │   3    │
  └─────────────┴──────┴──────┴────────┘

MRP 运行时自动按配额分配：
  总需求 10,000 件
  → 供应商 A: 6,000 件
  → 供应商 B: 3,000 件
  → 供应商 C: 1,000 件
```

### 2.4 配额调整的触发条件

| 触发 | 调整方向 | 示例 |
|------|---------|------|
| 质量问题 | 降低配额 | A 供应商 PPM 突然升高 → 配额从 60% 降到 30% |
| 交付延迟 | 降低配额 | B 供应商 OTIF 从 98% 降到 85% |
| 成本优势 | 提高配额 | C 供应商降价 10% → 配额从 10% 提到 30% |
| 新供应商导入 | 逐步提高 | 从 5% 试跑 → 20% → 40% |
| 战略保供 | 保持最低配额 | 即使贵也要保持 B 至少 20% |

### 2.5 采购配额的常见问题

| 问题 | 根因 | 对策 |
|------|------|------|
| **配额形同虚设** | 计划员习惯性全给一家 | 系统强制按配额拆分 PO |
| **配额不更新** | 设定后几年没调 | 季度评审机制 + KPI 驱动 |
| **新供应商无法导入** | 老供应商配额太高，新供应商量不够降本 | 设置"试跑配额"（5-10%） |
| **供应商抱怨不公平** | 配额规则不透明 | 公开配额规则 + 绩效反馈 |

## 三、产能配额（Capacity Allocation）

### 3.1 定义

> 供应商（尤其是产能紧张的供应商）将有限产能分配给多个客户的机制。

### 3.2 半导体行业的产能配额（最典型）

```
台积电 5nm 产能：每月 12 万片晶圆

客户产能需求：
  苹果：   60,000 片/月
  NVIDIA： 30,000 片/月
  高通：   25,000 片/月
  AMD：    20,000 片/月
  其他：   30,000 片/月
  ─────────────────
  总需求： 165,000 片/月  >> 产能 120,000 片/月

分配机制：
  1. LTA（长期协议）优先 → 苹果、NVIDIA 有 LTA
  2. 预付款优先 → 付了定金的优先排产
  3. 战略重要性 → 苹果是第一大客户，最优先
  4. 历史合作 → 老客户优先于新客户
```

### 3.3 产能配额的分配方法

| 方法 | 说明 | 优缺点 |
|------|------|--------|
| **Pro-rata（按比例）** | 按历史采购量等比例缩减 | ✅ 公平 ❌ 不区分优先级 |
| **优先级分层** | 战略客户→大客户→中小客户 | ✅ 保核心 ❌ 小客户断供 |
| **Take-or-Pay** | 承诺采购量保底，超出部分竞争 | ✅ 锁定需求 ❌ 灵活性差 |
| **拍卖/竞价** | 价高者得 | ✅ 收益最大 ❌ 关系恶化 |
| **混合模式** | 保底+竞价+优先级 | ✅ 平衡 ❌ 复杂 |

### 3.4 汽车行业的芯片产能配额（2021年教训）

```
2021年芯片缺货时的配额分配链：

芯片原厂（如 NXP）
  │
  ├── 分配给 Tier 1（博世、大陆）── 有 LTA，供应有保障
  │     └── 分配给 OEM（大众、宝马）── 受 Tier 1 配额限制
  │
  └── 通过代理商分配给中小客户 ── 几乎拿不到货

OEM 的应对：
  1. 直接与芯片原厂签 LTA（跳过 Tier 1）
  2. 增加安全库存（从 2 周提到 8 周）
  3. 芯片标准化（减少芯片型号，提高单型号采购量）
  4. 双源设计（同一功能用两家芯片）
```

## 四、缺货分配（Shortage Rationing）

### 4.1 定义

> 供应不足时，如何将有限的库存/产能分配给多个需求方。

### 4.2 分配策略

| 策略 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| **按历史量等比缩减** | 所有客户统一打 8 折 | 公平 | 不区分优先级 |
| **优先级分层** | A 类客户 100%→B 类 80%→C 类 50% | 保核心客户 | 小客户流失 |
| **先到先得** | 谁先下单谁先得 | 简单 | 导致客户恐慌性下单 |
| **战略导向** | 战略客户/高利润产品优先 | 最大化战略价值 | 合规风险 |
| **公平份额算法** | DRP 算法按需求比例分配 | 系统化 | 需要准确数据 |

### 4.3 DRP 公平份额分配算法

```
场景：中心仓有 1,000 件库存，3 个区域仓需要补货

区域仓 A：需求 500，现有库存 100，目标库存 600 → 缺口 500
区域仓 B：需求 300，现有库存 50，目标库存 350 → 缺口 300
区域仓 C：需求 400，现有库存 200，目标库存 400 → 缺口 200
总缺口：1,000

等比分配：
  A：1,000 × (500/1000) = 500
  B：1,000 × (300/1000) = 300
  C：1,000 × (200/1000) = 200

加权分配（按紧急度）：
  权重 A=1.5, B=1.2, C=1.0
  加权缺口：A=750, B=360, C=200 → 总 1,310
  A：1,000 × (750/1310) = 573
  B：1,000 × (360/1310) = 275
  C：1,000 × (200/1310) = 152
```

### 4.4 缺货分配的"博弈"

> 🔬 缺货分配是牛鞭效应的重要成因之一（见 [[06_牛鞭效应]]）

| 博弈行为 | 机制 | 后果 |
|---------|------|------|
| **夸大需求** | 客户报 150% 的真实需求，争取更多配额 | 需求信号失真 |
| **Double Booking** | 同时向多家供应商下单，谁先到货用谁的 | 重复占用产能 |
| **恐慌性囤货** | 担心缺货加大安全库存 | 加剧短缺 |
| **关系运作** | 通过高层关系争取更多配额 | 非市场化分配 |

## 五、库存分配（Inventory Allocation）

### 5.1 多级库存分配

```
场景：新品上市，首批库存有限，如何分配到各区域？

新品首批到货：10,000 台

分配维度：
  ├── 按区域历史销量占比
  ├── 按区域战略重要性
  ├── 按门店等级（旗舰店>普通店）
  └── 按预售/预约数据

示例分配：
  华东（35%）：3,500 台
  华南（25%）：2,500 台
  华北（20%）：2,000 台
  华中（12%）：1,200 台
  西南（8%）：800 台
```

### 5.2 电商库存分配

| 场景 | 分配策略 | 示例 |
|------|---------|------|
| **大促备货** | 按历史大促数据分配到各仓 | 双11前按各仓去年销量分配 |
| **预售锁定** | 预售订单锁定库存，不参与分配 | 小米新品预约制 |
| **紧急调拨** | A 仓缺货从 B 仓调拨 | 京东跨仓调拨 |
| **渠道隔离** | 线上/线下库存分开管理 | 防止渠道冲突 |

## 六、销售配额（Sales Quota）

### 6.1 定义

> 将销售目标分配到区域、渠道、团队、个人的过程。

### 6.2 分配方法

| 方法 | 说明 | 优缺点 |
|------|------|--------|
| **自上而下（Top-Down）** | 高层定目标，逐级分解 | ✅ 战略对齐 ❌ 脱离实际 |
| **自下而上（Bottom-Up）** | 一线提报，汇总审批 | ✅ 贴近市场 ❌ 保守偏差 |
| **混合式** | Top-Down 目标 + Bottom-Up 校准 | ✅ 平衡 ✅ 推荐 |
| **市场潜力法** | 按市场规模+竞争格局分配 | ✅ 科学 ❌ 数据要求高 |
| **历史基数法** | 上年完成 × 增长系数 | ✅ 简单 ❌ 鞭打快牛 |

### 6.3 销售配额与供应链的接口

```
销售配额 → 销售预测 → 需求计划 → 供应链执行

如果销售配额不合理：
  └── 区域 A 配额过高 → 虚报需求 → 供应链多备货 → 区域 A 库存积压
  └── 区域 B 配额过低 → 需求被低估 → 供应链少备货 → 区域 B 缺货
  └── 季末冲量 → 月底集中下单 → 供应链产能波动

最佳实践：
  销售配额 ≠ 需求预测
  销售配额是"目标"，需求预测是"判断"
  两者应该独立制定，然后在 S&OP 中对齐
```

## 八、配额管理的最佳实践

| # | 实践 | 说明 |
|:-:|------|------|
| 1 | **规则透明** | 配额规则公开，让所有参与方理解 |
| 2 | **定期评审** | 至少季度评审一次配额合理性 |
| 3 | **数据驱动** | 基于绩效数据调整配额，而非拍脑袋 |
| 4 | **系统固化** | 用系统（SAP/APS）自动执行配额，减少人为干预 |
| 5 | **预留弹性** | 保留 10-20% 的弹性空间应对突发 |
| 6 | **博弈预防** | 设计机制防止客户/供应商夸大需求 |
| 7 | **战略对齐** | 配额要服务于供应链战略（保供/降本/风险分散） |
