# 供应链数据直连：实时数据采集架构

> 💡 产能管理的决策质量 = 数据质量 × 算法质量。数据不实时、不准确，再好的算法也是"垃圾进垃圾出"。**数据直连是产能管理的"命脉"。**

---

## 一、传统模式 vs 数据直连模式

| 维度 | 传统模式 | 数据直连模式 | 差距 |
|------|---------|------------|------|
| **数据延迟** | 人工填报（周报/月报） | IoT 实时采集（秒级） | 7 天 → 秒级 |
| **数据准确性** | 人工录入，误差 10-30% | 系统自动采集，误差 <1% | 70% → 99% |
| **覆盖范围** | 抽样数据 | 全量数据 | 点 → 面 |
| **响应速度** | 事后发现 | 实时预警 + 自动触发 | 天 → 分钟 |
| **决策依据** | 经验判断 | 数据驱动 | 主观 → 客观 |

---

## 二、数据来源与采集方式

| 数据源 | 采集方式 | 频率 | 延迟 | 数据内容 | 价值 |
|--------|---------|------|------|---------|------|
| **设备 PLC** | IoT 网关 → OPC UA | 秒级 | <5s | 设备状态、产量、节拍 | 实时 OEE |
| **SCADA** | 工业网络 → MQTT | 秒级 | <5s | 温度、压力、能耗 | 过程监控 |
| **MES** | API / 数据库同步 | 分钟级 | <1min | 工单进度、质量、报工 | 执行状态 |
| **EDI（供应商）** | EDI 830/862/856 | 日级 | <1day | 产能声明、ASN、交期 | 供应商产能 |
| **SRM 平台** | API 实时调用 | 实时 | <1min | 供应商确认、配额 | 采购协同 |
| **APS/SCP** | 消息队列（Kafka） | 小时级 | <1h | 排程结果、计划变更 | 计划协同 |
| **ERP** | API / RFC 调用 | 实时 | <5min | 订单、BOM、库存 | 主数据 |
| **IoT 传感器** | MQTT / 边缘计算 | 秒级 | <1s | 温湿度、振动、位移 | 预测性维护 |

## 四、关键数据流详解

### 4.1 数据流 1：设备 → 产能管理（实时 OEE）

```
设备 PLC
  │
  ├─ 数据：设备状态（运行/停机/故障）、当前产量、节拍时间
  │
  ↓
IoT 网关（边缘计算）
  │
  ├─ 处理：数据清洗、协议转换、本地缓存
  │
  ↓
MQTT Broker（消息中间件）
  │
  ├─ 路由：按 topic 分发（如 factory/line1/equipment/stamp01）
  │
  ↓
产能管理平台（流处理）
  │
  ├─ 计算：实时 OEE = 可用率 × 表现性 × 良品率
  ├─ 告警：OEE < 80% → 触发预警
  ├─ 聚合：产线级 OEE = Σ 设备 OEE
  │
  ↓
产能看板（前端展示）
  └─ 展示：实时 OEE、趋势图、预警信息
```

**OEE 实时计算示例**：

```
时间：14:30，产线 A

设备 1（冲压机）：
  运行时间：6.5h / 7.5h = 86.7%（可用率）
  实际产出：7200 件 / 理论 7800 件 = 92.3%（表现性）
  良品：7100 / 7200 = 98.6%（良品率）
  OEE = 86.7% × 92.3% × 98.6% = 78.8% 🟡

设备 2（焊接机器人）：
  运行时间：7.0h / 7.5h = 93.3%
  实际产出：400 件 / 理论 420 件 = 95.2%
  良品：398 / 400 = 99.5%
  OEE = 93.3% × 95.2% × 99.5% = 88.4% 🟢

产线 A 整体 OEE = (78.8% + 88.4%) / 2 = 83.6% 🟢
```

### 4.2 数据流 2：供应商 → 产能管理（产能声明）

```
供应商 ERP/SRM
  │
  ├─ 数据：零件产能、已承诺量、剩余可用量、交期确认
  │
  ├─ 方式 A：EDI 830/862（标准报文，汽车行业主流）
  │   └─ 供应商 EDI 系统 → VAN → OEM EDI 网关 → 解析 → 产能管理
  │
  ├─ 方式 B：SRM API（API 直连）
  │   └─ OEM SRM 调用供应商 API → 获取产能数据 → 产能管理
  │
  └─ 方式 C：供应商门户填报（低成熟度）
      └─ 供应商登录 SRM 门户 → 手动填报 → 产能管理

产能管理接收后：
├─ 更新供应商产能看板
├─ 计算供应商产能利用率
├─ 对比需求 vs 供应商产能 → 识别缺口
└─ 触发预警/配额调整建议
```

**EDI 报文与产能数据映射**：

| EDI 报文 | 方向 | 内容 | 频率 |
|---------|------|------|------|
| **830（Planning Schedule）** | OEM → 供应商 | 需求预测（12-18 月滚动） | 周/月 |
| **862（Shipping Schedule）** | OEM → 供应商 | 短期发货计划（1-4 周） | 周 |
| **856（ASN）** | 供应商 → OEM | 发货通知（装箱明细） | 每次发货 |
| **810（Invoice）** | 供应商 → OEM | 发票 | 每次发货 |
| **997（Functional Ack）** | 双方 | 报文确认 | 每次接收 |

## 五、数据质量治理

数据直连不等于数据准确——需要持续治理：

| 问题 | 表现 | 治理措施 |
|------|------|---------|
| **数据不一致** | MES 报 100 件，ERP 报 95 件 | 主数据源唯一 + 对账机制 |
| **数据延迟** | IoT 数据丢失 5 分钟 | 边缘缓存 + 补传机制 |
| **数据错误** | 设备传感器漂移 | 定期校准 + 异常值过滤 |
| **数据缺失** | 供应商未填报产能 | 催报机制 + 信用扣分 |
| **数据冗余** | 同一数据多个来源 | 主数据管理 + ETL 去重 |

**数据质量 KPI**：

| 指标 | 定义 | 目标 |
|------|------|------|
| **完整性** | 实际采集数据点 / 应采集数据点 | >99% |
| **准确性** | 准确数据点 / 总数据点 | >98% |
| **及时性** | 数据延迟 < 阈值的比例 | >95% |
| **一致性** | 跨系统数据一致的比例 | >99% |

## 六、技术选型参考

| 层级 | 技术选项 | 推荐场景 |
|------|---------|---------|
| **IoT 网关** | OPC UA + MQTT | 工业设备接入 |
