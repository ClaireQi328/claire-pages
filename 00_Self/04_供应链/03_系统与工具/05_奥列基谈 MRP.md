# 奥列基谈 MRP

> 💡 **10年+视角**：MRP 是 ERP 计划体系的"心脏"。你用的 SAP、Oracle、金蝶，底层跑的都是 MRP 逻辑。理解 Orlicky 的原始思想，不是为了怀古，而是为了在系统出问题时知道该调哪个参数——而不是只会"重跑 MRP"。

---

## 一、这本书为什么重要

### 1.1 历史背景

| 维度 | 说明 |
|------|------|
| 首版 | 1975 年，Joseph Orlicky 在 IBM 工作期间撰写 |
| 里程碑 | 首次系统化提出"独立需求 vs 相关需求"的区分 |
| 影响 | 直接催生了整个 MRP/ERP 产业，SAP、Oracle 的计划模块都基于此理论 |
| 最新版 | 第 4 版（2011），由 Carol Ptak 和 Chad Smith 更新，加入了 DDMRP 内容 |

### 1.2 核心问题

Orlicky 回答了一个根本问题：**不同的需求类型，需要完全不同的计划方法。**

```
需求类型
├── 独立需求（Independent Demand）
│   └── 来自市场/客户，不可预测，用"预测 + 安全库存"应对
│       例：成品手机、汽车整车
│
└── 相关需求（Dependent Demand）
    └── 由父项推导，可精确计算，用"MRP 逻辑"应对
        例：手机屏幕、汽车发动机
```

> 🎯 **这个区分的价值**：独立需求用统计方法（EOQ、ROP），相关需求用确定性方法（BOM 展开 + LT 偏移）。很多企业在实践中混淆两者，导致要么库存过高，要么频繁缺料。

## 二、MRP 核心理论

### 2.1 MRP 系统三大输入

```
┌─────────────────────────────────────────────────────┐
│                   MRP 运算引擎                        │
├───────────────┬───────────────┬─────────────────────┤
│   MPS          │   BOM          │   库存状态记录       │
│   主生产计划    │   物料清单      │   Inventory Status  │
│               │               │                     │
│ "做什么、      │ "用什么、      │ "有什么、            │
│  做多少、      │  用多少"      │  还差多少"           │
│  何时做"       │               │                     │
└───────┬───────┴───────┬───────┴──────────┬──────────┘
        │               │                  │
        ▼               ▼                  ▼
    ┌───────────────────────────────────────────┐
    │         MRP 输出：计划订单 / 采购申请         │
    └───────────────────────────────────────────┘
```

| 输入 | 核心数据 | 作用 |
|------|---------|------|
| **MPS（主生产计划）** | 成品的计划生产量和时间 | MRP 的"发动机"，驱动所有计算 |
| **BOM（物料清单）** | 父子项关系、单位用量 | 决定"需要什么"和"需要多少" |
| **库存状态** | 现有量、在途量、已分配量、安全库存 | 决定"还差多少" |

### 2.2 MRP 核心计算逻辑

**净需求公式**：

```
净需求 = 毛需求 − 现有库存 − 在途订单 + 安全库存

其中：
  毛需求 = 父项计划量 × 单位用量（BOM 展开）
  现有库存 = 当前可用量（不含已分配量）
  在途订单 = 已下单未到货的采购订单 / 生产工单
```

**时间偏移（Lead Time Offsetting）**：

```
需求日期 ──────────────→ [成品需要日期]
                          ↑
                    LT = 14天（生产）
                          ↑
              [半成品开工日期] ← 需求日期 - 14天
                          ↑
                    LT = 7天（采购）
                          ↑
              [原材料下单日期] ← 半成品开工日期 - 7天
```

> ⚠️ **10年教训**：LT 参数是计划体系里最容易被忽视的"定时炸弹"。很多企业的 LT 参数 3 年没更新，供应商早就改了交期，系统还在用旧数据跑计划。建议**至少每季度更新一次关键物料的 LT 参数**。

### 2.3 BOM 展开示例

以智能手表为例：

```
成品: 智能手表 SW-200 (需求 1,000 台, Week 30)
│
├── 主板组件 (1,000 个) — 自制, LT=5天
│   ├── PCB 主板 (1,000 块) — 采购, LT=14天
│   ├── SoC 芯片 (1,000 颗) — 采购, LT=28天  ← 瓶颈！
│   └── 内存芯片 (1,000 颗) — 采购, LT=21天
│
├── 触摸屏 (1,000 块) — 采购, LT=21天
│
├── 传感器模组 (2,000 个) — 采购, LT=18天
│   └── ⚠️ 注意单位用量 = 2
│
├── 电池 (1,000 个) — 采购, LT=10天
│
└── 表壳组件 (1,000 套)
    ├── 表壳体 (1,000 个) — 自制, LT=3天
    └── 表带 (1,000 条) — 采购, LT=7天

关键路径：SoC 芯片 LT=28天 → 需要在 Week 30 前 28+5 = 33天下单
即 Week 22 就必须下达采购订单
```

## 三、批量策略（Lot Sizing）

这是 MRP 里最实用也最容易被滥用的部分。

| 策略 | 英文 | 原理 | 适用场景 | 优缺点 |
|------|------|------|---------|--------|
| **逐批法** | L4L (Lot-for-Lot) | 需要多少订多少 | 高价值件、定制件 | ✅ 库存最低 ❌ 订单多 |
| **固定批量** | FOQ (Fixed Order Qty) | 每次订固定数量 | 标准件、MOQ 约束 | ✅ 降低订单成本 ❌ 可能积压 |
| **经济批量** | EOQ (Economic Order Qty) | 平衡订购与持有成本 | 高频消耗品 | ✅ 成本最优 ❌ 假设需求均匀 |
| **周期批量** | POQ (Period Order Qty) | 合并 N 个周期的需求 | 中等价值件 | ✅ 灵活 ❌ 周期选择需经验 |
| **最小-最大** | Min-Max | 低于 Min 补到 Max | 维护备件 | ✅ 简单 ❌ 参数设定粗糙 |

**EOQ 公式**：

```
EOQ = √(2 × D × S / H)

其中：
  D = 年需求量（件/年）
  S = 单次订购成本（元/次）
  H = 单位持有成本（元/件/年）

示例：某电阻年需求 100,000 个，订购成本 200 元/次，持有成本 0.5 元/个/年
  EOQ = √(2 × 100,000 × 200 / 0.5) = √(80,000,000) ≈ 8,944 个
```

> 🎯 **实战建议**：EOQ 在教科书里很好看，但实际中几乎没人完全按 EOQ 订货——因为供应商有 MOQ、包装规格、折扣阶梯。EOQ 是"起点"，不是"答案"。

## 四、MRP 的经典问题与应对

### 4.1 系统波动性（Nervousness）

**问题描述**：MPS 的微小变化，通过 BOM 展开放大，导致底层物料的计划订单频繁变动——这就是"牛鞭效应"在计划系统内部的体现。

```
MPS 变化 ±5%
    ↓ BOM 展开
半成品需求变化 ±10%
    ↓ BOM 展开
原材料需求变化 ±20%
    ↓
采购订单反复变更 → 供应商不满 → 交付不稳定
```

**应对方法**：

| 方法 | 原理 | 效果 |
|------|------|------|
| 计划冻结期 | 冻结期内不允许自动变更 | ⭐⭐⭐⭐⭐ 最常用 |
| 时间栏（Time Fence） | 划分冻结区/协商区/自由区 | ⭐⭐⭐⭐ |
| 批量合并 | 用 POQ 合并短周期需求 | ⭐⭐⭐ |
| DDMRP 缓冲 | 用缓冲吸收波动 | ⭐⭐⭐⭐ 推荐 |

### 4.2 准确性问题（Garbage In, Garbage Out）

MRP 对输入数据极度敏感：

| 输入 | 常见问题 | 影响 |
|------|---------|------|
| MPS 不准 | 销售预测偏差大 | 整条链跟着错 |
| BOM 不准 | 工程变更未及时更新 | 多订或少订物料 |
| 库存不准 | 实物与系统差异 | 该补没补、不该补多补 |
| LT 不准 | 参数过时 | 下单时间错误 |
| 损耗率缺失 | 实际损耗 > 系统参数 | 短缺 |

> ⚠️ **10年教训**：在推动 MRP 准确性之前，先把**库存准确性**做到 99%+。如果实物和系统对不上，再好的计划逻辑也是白搭。

### 4.3 MRP 的假设限制

| 假设 | 现实 | 后果 |
|------|------|------|
| LT 是固定值 | LT 实际是分布（均值+方差） | 系统性低估风险 |
| 产能无限 | 产能是有限的 | 生成不可行的计划 |
| 需求已知 | 需求有不确定性 | 频繁重排 |
| BOM 是静态的 | 工程变更频繁 | 计划与实际脱节 |

→ 这些限制催生了 **MRP II → ERP → APS → DDMRP** 的演进。

## 五、从 MRP 到 DDMRP：计划体系的进化

### 5.1 演进路径

```
1960s  MRP     → 物料需求计划（独立/相关需求区分）
1980s  MRP II  → 制造资源计划（加入产能、财务）
1990s  ERP     → 企业资源计划（全企业集成）
2000s  APS     → 高级计划与排程（有限产能优化）
2010s  DDMRP   → 需求驱动物料需求计划（缓冲驱动）
2020s  AI+DDMRP → 智能计划（AI 驱动的动态缓冲）
```

### 5.2 DDMRP 的革命性突破

| 维度 | 传统 MRP | DDMRP |
|------|---------|-------|
| 驱动信号 | 预测（MPS） | 实际消耗（Pull） |
| 库存策略 | 按需计算 | 缓冲色带（绿/黄/红） |
| 计划频率 | 批量运行（日/周） | 持续触发 |
| 系统波动 | 高（牛鞭效应） | 低（缓冲吸收） |
| 核心公式 | 净需求 = 毛需求 − 库存 − 在途 | 补货信号 = 库存 + 在途 − 已确认需求 |

## 六、实战清单：MRP 健康度检查

> 📋 每季度检查一次，确保 MRP 系统跑出来的东西靠谱：

| 检查项 | 标准 | 常见问题 |
|--------|------|---------|
| 库存准确性 | ≥ 99%（A 类物料） | 盘点差异、系统未更新 |
| BOM 准确性 | ≥ 98% | 工程变更未同步到 ERP |
| LT 参数更新 | 季度更新 | 参数与实际偏差 > 20% |
| MPS 达成率 | ≥ 95% | 计划频繁变更 |
| MRP 例外消息处理率 | ≥ 90% | 例外消息太多被忽略 |
| 计划订单采纳率 | ≥ 85% | 计划员大量手动调整 |
| 损耗率参数 | 每半年验证 | 参数过时导致短缺 |
