# MOC 写作规范

> Claire 明确要求：**MOC 不能只是索引列表**。

## 标准

每次创建/更新 MOC 文件时，必须包含以下内容：

| 要素 | 说明 |
|------|------|
| **下属内容总结** | 每个链接的文件/文件夹，写出它讲了什么、核心结论是什么 |
| **凝练** | 不是复制原文，是提炼要点，让人不用点进去就知道值不值得读 |
| **Callout** | 用 `> [!tip]` / `> [!note]` / `> [!warning]` 等格式呈现关键知识点、易错点、答题框架等 |
| **横向网络** | 跨文件的共性整理（如 API 速查、模型选型、指标对比等） |
| **学习路径** | 如果是知识类 MOC，给出推荐的阅读/学习顺序 |

## 反面示例

```markdown
# ❌ 这不是 MOC，只是索引
- [[文件A]]
- [[文件B]]
- [[文件C]]
```

## 正面示例

```markdown
# ✅ 内容型 MOC

## 文件A：xxx

> [!tip] 核心知识点
> - 要点 1
> - 要点 2

| 维度 | 内容 |
|------|------|
| 场景 | ... |
| 关键操作 | ... |

## 文件B：yyy
...

## 横向对比
| 文件 | 模型 | 评估指标 |
|------|------|----------|
| A | 线性回归 | MSE |
| B | 随机森林 | R² |
```

## 生效时间

2026-07-27 起，所有新建/重写的 MOC 均遵循此规范。
