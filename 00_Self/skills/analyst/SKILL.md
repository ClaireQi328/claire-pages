# Analyst — 结构化分析框架

> 融合 McKinsey / BCG / Bain / Deloitte / Harvard 等顶级咨询公司方法论的高阶分析引擎。

## Quick Start

**方式一：穷追式提问（grillme）**
```
帮我 grillme 这个方案：我们要在东南亚建仓
```

**方式二：五步决策框架（nailit）**
```
帮我 nailit 这个问题：CDN 成本优化方案选型
```

**方式三：自动路由（推荐）**
```
帮我分析一下：叮咚买菜的前置仓模式能否复制到美团买菜？
```

---

## 模式一：Grillme — 穷追式提问

对一个计划/方案进行**不间断追问**，逐一拆解设计树的每个分支，直到你和 AI 之间建立共识理解。

**机制**：
- 每次只问**一个问题**
- 附带**推荐选项**（options）
- 逐个分支深入，不跳步
- 解决依赖关系后再推进

**启动句式**：
> "我对 [方案X] 有一些想法，帮我 grillme"

**输出**：逐轮问答记录，最终形成一份「共识备忘录」。

## 模式二：Nailit — 五步决策框架

> 融合 Gap 分析（实然→应然）、SCOR 咨询叙事、运筹学优化 三大维度的统一决策框架。

### Step 1：As-Is & Constraints — 我们现在在哪

| 维度 | 核心问题 |
|------|----------|
| **As-Is** | 我们目前客观上是什么样？有哪些资源、能力、人才？ |
| **Constraints** | 硬边界是什么？不可逾越的预算、合规红线、截止日期？ |
| **Scope** | 什么在范围内，什么不在？ |

**咨询工具箱**：
- **MECE 原则**（McKinsey）：确保分析"相互独立、完全穷尽"
- **VRIO 分析**（Barney）：评估资源/能力是否具备持续竞争优势
- **价值链分析**（Porter）：拆解内部活动，识别价值创造环节

### Step 2：To-Be & Objective — 我们要去哪

| 维度 | 核心问题 |
|------|----------|
| **To-Be** | 理想状态是什么？完美结果长什么样？ |
| **Objective** | 成功指标是什么？最大化什么、最小化什么？ |
| **Payoff** | 预期回报是否值得付出？如何衡量？ |

**咨询工具箱**：
- **北极星指标**：找到一个最能代表核心价值的指标
- **7S 框架**（McKinsey）：Strategy / Structure / Systems / Shared Values / Skills / Style / Staff — 确保目标与组织七要素对齐
- **三层面增长**（McKinsey）：H1（核心）/ H2（新兴）/ H3（探索）— 明确时间维度的目标分层

### Step 3：Gap & Cause — 为什么做不到

| 维度 | 核心问题 |
|------|----------|
| **The Gap** | As-Is 和 To-Be 之间的物理距离是什么？ |
| **The Cause** | 根因是什么？过滤噪音后的真正瓶颈？ |
| **The Lever** | 哪个根因解决后能关闭最大差距？ |

**咨询工具箱**：
- **Issue Tree**（McKinsey）：用逻辑树拆解问题，确保 MECE
- **TOC 约束理论**（Goldratt）：找到系统瓶颈，聚焦单一约束突破
- **5 Whys**：连续追问五个"为什么"直到根因
- **帕累托分析**（80/20）：识别贡献 80% 结果的 20% 关键因素

### Step 4：Decision Variables & Options — 我们能控制什么

| 维度 | 核心问题 |
|------|----------|
| **Levers** | 我们手里有哪些可以拉动的杠杆？（包括非显而易见的） |
| **Options** | 这些杠杆可以组合出哪些方案？ |

**咨询工具箱**：
- **利润池分析**（Bain）：识别行业利润分布，找到最优切入点
- **经验曲线**（BCG）：量化规模效应和学习效应对成本的影响
- **Kano 模型**：区分基本型 / 期望型 / 兴奋型需求，避免过度投资

### Step 5：Optimal Recommendation — 怎么赢

| 维度 | 核心问题 |
|------|----------|
| **Filter** | 哪些方案违反硬约束？直接淘汰 |
| **Optimize** | 存活方案中，哪个最接近 Step 2 的 Objective？ |
| **Test** | 如何设计低成本 MVP 来验证最大假设？ |

**咨询工具箱**：
- **GE-麦肯锡矩阵**：行业吸引力 × 竞争地位，多维度评估方案
- **决策矩阵**（Weighted Scoring）：加权评分，量化对比多个方案
- **预验尸分析**（Pre-Mortem）：假设方案已失败，反推风险点

## 咨询方法论速查表

> 详细内容见 `references/consulting-frameworks.md`

### McKinsey 系

| 方法论 | 核心思想 | 适用场景 |
|--------|---------|---------|
| **MECE** | 相互独立、完全穷尽 | 任何结构化分析的基础 |
| **7S 框架** | 组织七要素对齐诊断 | 组织变革、并购整合 |
| **三层面增长** | H1/H2/H3 时间维度分层 | 战略规划、增长路径 |
| **Issue Tree** | 逻辑树拆解问题 | 复杂问题分解 |
| **80/20 法则** | 聚焦关键少数 | 资源分配、优先级排序 |
| **金字塔原理** | 结论先行、以上统下 | 沟通汇报、方案呈现 |

### BCG 系

| 方法论 | 核心思想 | 适用场景 |
|--------|---------|---------|
| **BCG 矩阵** | 市场增长率 × 相对份额 | 业务组合分析、投资决策 |
| **经验曲线** | 累计产量 → 成本下降 | 定价策略、规模决策 |
| **优势矩阵** | 竞争优势类型分类 | 竞争定位 |

### Bain 系

| 方法论 | 核心思想 | 适用场景 |
|--------|---------|---------|
| **利润池** | 行业利润分布地图 | 价值链定位、盈利模式 |
| **NPS** | 净推荐值 | 客户满意度、增长驱动 |
| **简化聚焦** | 少做 > 多做 | 战略取舍、资源集中 |

### 经典理论（Harvard / 独立学者）

| 方法论 | 来源 | 核心思想 | 适用场景 |
|--------|------|---------|---------|
| **五力模型** | Porter | 行业竞争结构 | 行业分析、进入决策 |
| **价值链** | Porter | 内部活动拆解 | 成本优化、差异化定位 |
| **蓝海战略** | Kim & Mauborgne | 价值创新 | 竞争战略、新产品定位 |
| **JTBD** | Christensen | 客户任务视角 | 产品创新、需求挖掘 |
| **TOC** | Goldratt | 约束即系统 | 供应链瓶颈、产能优化 |
| **VRIO** | Barney | 资源基础观 | 内部能力评估 |
| **PESTLE** | — | 宏观环境扫描 | 战略背景分析 |
| **Kano 模型** | Kano | 需求三分类 | 产品定义、优先级 |

### 供应链专项

| 方法论 | 核心思想 | 适用场景 |
|--------|---------|---------|
| **SCOR** | 计划/采购/制造/交付/退货 | 供应链全景诊断 |
| **DDMRP** | 需求驱动的物料计划 | 库存优化、牛鞭效应 |
| **S&OP** | 销售与运营计划对齐 | 需求供给平衡 |
| **七步战略采购** | Kearney | 系统化采购决策 | 供应商选择、品类管理 |

## 框架选择路由

> 根据问题类型，自动推荐最佳框架组合

| 问题类型 | 推荐框架组合 | 优先级 |
|---------|-------------|--------|
| 🔴 **战略定位** | nailit + 五力 + BCG 矩阵 + 蓝海 | 高 |
| 🔴 **供应链优化** | nailit + SCOR + TOC + 经验曲线 | 高 |
| 🔴 **数字化转型** | nailit + 7S + 数字化成熟度 + 价值链 | 高 |
| 🟡 **市场进入** | nailit + Ansoff + JTBD + PESTLE | 中高 |
| 🟡 **组织变革** | nailit + 7S + 利益相关者分析 | 中高 |
| 🟡 **成本优化** | nailit + 价值链 + 利润池 + 80/20 | 中高 |
| 🟡 **供应商管理** | nailit + 七步采购 + VRIO | 中高 |
| 🟢 **产品优先级** | nailit + Kano + RICE | 中 |
| 🟢 **竞争分析** | nailit + 五力 + 竞品战卡 | 中 |
| 🔵 **沟通汇报** | 金字塔原理 + 80/20 | 基础 |

**路由规则**：
1. 默认使用 nailit 五步作为主框架
2. 根据问题类型，从路由表中选取 2-3 个辅助框架
3. 辅助框架嵌入 nailit 对应 Step 中使用
4. 用户明确指定框架时，优先使用指定框架

## 输出规范

### 文件管理

- 在 `Z_DevLog/` 建新文件夹存放分析结论
- 文件夹命名：`{日期}_{主题关键词}`
- 主报告：`{主题}.md`
- 支撑数据：`data/` 子文件夹

### 报告格式

```markdown
# {主题} 分析报告

> 分析框架：nailit + {辅助框架}
> 分析日期：{YYYY-MM-DD}
> 数据截止：{YYYY-MM-DD}

## Executive Summary
（3 句话总结：现状→差距→建议）

## Step 1: As-Is
## Step 2: To-Be
## Step 3: Gap & Cause
## Step 4: Decision Variables
## Step 5: Optimal Recommendation

## 附录
- 数据来源
- 框架说明
- 敏感性分析
```

### 数据标注

- 每个数据表标注来源和时间口径
- 预测值标注 E（Estimate）
- 区分"整体"和"细分"口径
- 格式：`> 📊 数据来源：XXX，时间：YYYY`

## 触发条件

当用户输入包含以下关键词时，优先触发本 Skill：

| 中文 | 英文 |
|------|------|
| 分析、拆解、诊断 | analysis, diagnose |
| 评估、论证、可行性 | feasibility, assessment |
| 方案选型、对比 | comparison, trade-off |
| 战略、规划 | strategy, planning |
| 优化、改进 | optimization |
| 帮我分析、帮我拆解 | help me analyze |

**不触发场景**：
- 简单名词解释（用搜索引擎）
- 信息查询（用 deep-research）
- 纯数据查询（用 datum-sql）
