## **2. 背景与目标**

### **2.1 背景**

在SRM系统的定点流程中，采购员发起RFQ询报价后，需要CE（Cost Engineer）人员对供应商报价进行成本核价分析，确认各费用项（材料费、制造费、管理费等）的合理性，为最终定价提供成本依据。当前EP系统中缺少标准化的CE核价流程，核价过程依赖线下沟通，效率低且缺乏可追溯性。

### **2.2 目标**

- 在RFQ询报价管理下新增「成本管理」模块，实现CE核价任务的标准化管理
- CE核价任务与RFQ 1:1绑定，支持多轮次零件更新时自动触发核价
- 支持CE核价数据的录入、导入导出、审批和历史追溯
- 通过飞书通知和待办任务提升协作效率

### **2.3 角色定义**

| 角色 | 说明 | 来源 |
|-|-|-|
| CE（Cost Engineer） | 负责成本核价分析的财务人员 | EP系统角色【Finance】 |
| 采购员 | 发起RFQ、查看核价结果 | EP系统角色【采购】 |
| 管理员 | 全量数据查看、转派操作 | EP系统角色【管理员】 |

\> **注意：** EP系统中存在三个财务相关角色，本次使用 **Finance** 角色（对应业务的CE角色），而非Finance BP角色。

## **6. 状态机定义**

### **6.1 核价任务状态机**

| 状态 | 说明 | 触发条件 |
|-|-|-|
| 待核价 | 核价任务已生成，尚未提交 | 任务生成时；新轮次有零件更新时；审批被驳回时 |
| 审批中 | CE已提交核价，等待审批人审批 | CE点击「提交核价」 |
| 已核价 | 核价任务已提交且审批通过，不存在未核价零件 | 审批人点击「同意」 |

#### **状态流转图**

```Plain Text
                    ┌──────────────────────────────────────────┐
                    │                                          │
                    ▼                                          │
               ┌─────────┐   提交核价   ┌─────────┐  同意    ┌─────────┐
               │  待核价  │───────────→│  审批中  │────────→│  已核价  │
               └────┬────┘            └────┬────┘         └─────────┘
                    │                      │ 驳回
                    │                      │
                    │   ┌──────────────────┘
                    │   │
                    │   ▼
                    │ ┌─────────┐
                    │ │  已驳回  │
                    │ └────┬────┘
                    │      │ CE修改后重新提交
                    │      │
                    │      ▼
                    │ ┌─────────┐   提交核价   ┌─────────┐
                    └─│  待核价  │◄──重置状态──│  审批中  │
                      └─────────┘            └─────────┘

     触发条件（自动流转到「待核价」）：
     ├── 新轮次发布 + 零件有更新 → 关闭旧审批流，状态重置为「待核价」
     └── 审批被驳回 → 状态重置为「待核价」
```

#### **状态流转规则表**

| 编号 | 当前状态 | 触发条件 | 目标状态 | 操作人 | 说明 |
|-|-|-|-|-|-|
| CE-S01 | — | RFQ发布第一轮 | 待核价 | 系统 | 自动生成核价任务 |
| CE-S02 | 待核价 | CE点击「提交核价」（必填项校验通过） | 审批中 | CE | 同时生成审批待办 |
| CE-S03 | 审批中 | 审批人点击「同意」 | 已核价 | CE审批人 | 审批通过 |
| CE-S04 | 审批中 | 审批人点击「驳回」 | 待核价 | CE审批人 | 驳回后CE可重新修改提交 |
| CE-S05 | 审批中 | RFQ发布新轮次 + 零件有更新 | 待核价 | 系统 | 自动关闭旧审批流 |
| CE-S06 | 已核价 | RFQ发布新轮次 + 零件有更新 | 待核价 | 系统 | 重新进入核价流程 |
| CE-S07 | 已核价 | 生成定点上会单 | 已核价（锁定） | 系统 | 核价按钮置灰，不可再编辑 |
| CE-S08 | 任意状态 | RFQ生成定点通知单 | 已完成 | 系统 | 终态，不可操作 |

\> **关键逻辑：**

\> - 新轮次发布时，仅当**零件有更新**（增加/减少/变更）才触发状态重置；

\> - 新轮次发布但**零件无变化**时，核价任务状态不变；

> - 零件减少不发送飞书通知，零件+工厂维度新增/变更时发送通知。

### **6.2 与RFQ轮次的联动关系**

| RFQ事件 | 核价任务变化 | 说明 |
|-|-|-|
| RFQ发布第一轮 | 生成核价任务（状态：待核价） | 1:1生成 |
| RFQ发布新轮次，零件有更新 | 关闭旧审批流，状态重置为「待核价」 | 审批人无需再审 |
| RFQ发布新轮次，零件无变化 | 核价任务状态不变 | 不触发任何操作 |
| RFQ生成定点上会单 | 核价按钮置灰，不可编辑 | 但可转派CE |
| RFQ生成定点通知单 | 核价任务状态→「已完成」 | 终态 |

### **7.4 出厂价计算逻辑**

```Plain Text
出厂价计算优先级：接口导入 ＞ 手动输入 ＞ 前端自动计算

自动计算规则：
出厂价 = 材料费 + 制造费 + 管理费

触发时机：
  - 任意一次修改材料费/制造费/管理费均会触发自动计算
  - 如果手动填写了出厂价，再次修改子项时也会触发自动计算（覆盖手动值）
```

## **8. 提交核价**

### **8.1 提交校验**

| 校验项 | 规则 | 失败提示 |
|-|-|-|
| 必填项检查 | 材料费、制造费、管理费、出厂价、模具总费用不为空 | "您有必核价项未填写，请完成填写后再提交" |
| 出厂价校验 | 出厂价 > 0 | 同上 |
| 出厂价一致性 | 出厂价 = 材料费 + 制造费 + 管理费（若未手动输入） | 同上 |

校验失败时，页面红框高亮标示必填项。

### **8.2 审批流程**

```Plain Text
CE提交核价
    │
    ▼
弹框选择审批人（CE自行选择，可选范围：角色【Finance】，过滤CE自己）
    │
    ▼
进入审批流
    │
    ├── 审批人点击「同意」 → 状态变为「已核价」
    │
    └── 审批人点击「驳回」 → 状态回退为「待核价」，CE可修改后重新提交
```

### **8.3 审批页面内容**

| 区域 | 内容 |
|-|-|
| RFQ基本信息 | RFQ编号、RFQ名称、关联SOR单号、是否多项目、采购工程师、当前轮次 |
| 核价列表 | 零件号 + 各项核价数据 |
| 备注 | CE提交时填写的备注 |

### **8.4 审批过程中的转单**

> 如果审批过程中发生转单（转派CE核价人员），按照最新的核价人员来展示审批页面。

### **9.2 导入**

| 项目 | 说明 |
|-|-|

| 唯一键 | 以**零件号**为导入的唯一key值 |

**导入流程：**

```Plain Text
选择文件 → 点击导入
    │
    ├── 无文件 → 报错提示
    │
    └── 有文件
         │
         ├── 解析成功 → 页面反馈"导入完成"，数据自动填充
         │
         └── 解析失败 → 页面反馈"解析失败，请下载报错文件"
```

# Deepseek

## **1. 概述**

### **1.1 背景**

在定点 RFQ 流程中引入 CE（Cost Engineering）核价环节，由 CE 人员对零件成本进行分项评估（材料费、制造费、管理费、出厂价、模具费、开发费），经审批后作为定点决策的成本依据。

### **1.2 核心关系**

\- RFQ : 核价任务 = **1 : 1**（一张 RFQ 对应一张核价任务，核价任务无独立轮次概念）

- 核价任务随 RFQ 第一轮发布而创建，随定点通知单生成而终态
- 核价以「零件号 + 工厂」为唯一粒度，一轮次中同一零件-工厂只出现一行

### **1.3 角色定义**

| 角色 | 编码 | 说明 |
|-|-|-|
| CE 核价人员 | `Finance` | 执行核价的一线人员，填写成本明细，提交审批 |
| CE 核价审批人 | `Finance` | 审批核价结果（与核价人员同角色池，但提交时需过滤自己） |
| CE 老板 | `Finance` 上级 | 可查看全量核价任务数据，不参与编辑 |
| 采购员 | `Purchaser` | 查看名下核价任务，不可编辑 |
| 管理员 | `Admin` | 查看全量核价任务，支持转单操作 |

> 备注：EP 系统存在 3 个财务相关角色 — `finance`（CE 角色，本次使用）、`finance BP`（财务 BP 角色，本次不使用）、第三个角色本次也不涉及。

## **2. 状态机**

### **2.1 状态定义**

| 状态 | 英文标识 | 说明 |
|-|-|-|
| 待核价 | `PENDING` | 核价任务已生成，存在未提交的核价数据 |

### **2.3 状态转换规则**

| 当前状态 | 触发事件 | 目标状态 | 说明 |
|-|-|-|-|
| (无) | RFQ 第一轮发布 | `待核价` | 1:1 生成核价任务 |

| `审批中` | 审批人驳回 | `待核价` | 回到待核价，CE 可修改后重新提交 |

| \`审批中\` | 新轮次发布 + 零件更新 | \`待核价\` | **自动终止当前审批流**，审批人无需再审旧数据 |

| `已核价` | CE 再次提交核价 | `审批中` | 未生成定点通知单前均可修改并重新提交 |

| \`已核价\` | 新轮次发布 + 零件更新 | \`待核价\` | **自动终止旧审批流**，重置状态 |

| `已核价` | 定点通知单生成 | `已完成` | 终态，不可再编辑 |

| `待核价` | 定点通知单生成 | `已完成` | 终态（理论上不应出现，做兜底） |

| `审批中` | 定点通知单生成 | `已完成` | 终态（理论上不应出现，做兜底） |

#### **3.5.2 RFQ 基本信息区**

| 字段 | 来源 | 可编辑性 |
|-|-|-|
| RFQ 编号 | 核价任务继承 | N |
| RFQ 名称 | 核价任务继承 | N |
| 关联 SOR 单号 | 核价任务继承 | N |
| 是否多项目 | 核价任务继承 | N |
| 采购工程师 | 核价任务继承（随 RFQ 转派同步更新） | N |
| 当前轮次 | RFQ 实时轮次（不区分已结束/未结束） | N |
| CE 核价审批人 | 人员下拉框，角色 `Finance` | Y（可核价时） |

**CE 核价审批人字段规则**：

- 初次打开：下拉框默认空，CE 自行选择
- 再次打开：默认带出上次提交时选择的审批人
- 可编辑条件：核价任务状态 ∈ {`待核价`, `已核价`}（即非 `已完成` 且非 `审批中`）
- 提交时：审批人信息结构化入库，同步更新列表/详情页的数据权限（给新审批人赋查看权限，移除旧审批人权限）

#### **3.5.3 核价明细列表**

**数据粒度**：零件号 + 工厂 = 一行（系统自动按此维度去重聚合）

**字段定义**：

| 字段 | 类型 | 必填 | 小数位 | 可为0 | 默认值 | 说明 |
|-|-|-|-|-|-|-|
| 序号 | 系统 | — | — | — | 按零件号排序 | — |
| 零件号 | 只读 | — | — | — | RFQ 继承 | — |
| 零件名称 | 只读 | — | — | — | RFQ 继承 | — |
| 工厂 | 只读 | — | — | — | RFQ 继承 | — |
| 材料费 | 输入 | Y | 3 | Y | 空 | 初始化为空 |
| 制造费 | 输入 | Y | 3 | Y | 空 | 初始化为空 |
| 管理费 | 输入 | Y | 3 | Y | 空 | 初始化为空 |

| 出厂价 | 输入 | Y | 3 | **N** | 空 | 不可为 0 |

| 模具总费用 | 输入 | Y | 3 | Y | 空 | 初始化为空 |

| 开发总费用 | 输入 | N | 3 | Y | 0 | 未填/未传值均作 0 |

**数据填充优先级**（高 → 低）：

```Plain Text
接口导入 / 手动提交  >  手动填写  >  前端自动计算（材料费 + 制造费 + 管理费）
```

**自动计算逻辑**：

1. 任意一次修改材料费 / 制造费 / 管理费，都会触发自动计算：`出厂价 = 材料费 + 制造费 + 管理费`

2. 如果用户已手动填写了出厂价，再次修改子项时，也会触发自动计算并**覆盖**手动填写的出厂价

1. 如果用户手动修改出厂价，则以手动值为准（直到下次修改子项触发重新计算）

**上一轮数据继承**：

- 如零件-工厂在上一轮次已有核价数据，默认带出上一轮的核价结果

\- 新轮次中新增的零件-工厂行：数据为空，**行背景以特殊颜色高亮标示**

**轮次更新效果**：

- 零件-工厂增加 → 高亮新增行 + 发送飞书通知
- 零件-工厂减少 → 不通知，列表中移除对应行
- 零件-工厂数量不变 → 不影响

#### **3.5.4 备注**

- 文本框，500 字符上限
- CE 可编辑（可核价状态下）
- 提交时随核价数据一同记录

#### **3.5.5 CE 核价历史**

记录每次提交的日志：

| 字段 | 格式 / 说明 |
|-|-|
| 提交时间 | `YYYY-MM-DD HH:mm:ss` |
| 提交人 | CE 姓名 |
| 提交轮次 | `第 X 轮` |
| 备注 | 提交时的备注内容 |

\> 「保存」操作只持久化数据，**不产生历史记录**；仅「提交核价」产生历史记录。

#### **3.5.6 按钮行为**

| 按钮 | 行为 | 条件 |
|-|-|-|
| 取消 | 返回列表页，丢弃未保存修改 | 始终可用 |
| 保存 | 保存当前数据（审批人 + 明细 + 备注），不产生历史记录 | 状态 ∈ {`待核价`, `已核价`} |
| 导入 | 导入 Excel 核价数据（详见 §3.6） | 状态 ∈ {`待核价`, `已核价`} |
| 导出 | 导出 Excel 核价数据（详见 §3.6） | 始终可用 |
| 提交核价 | 校验 → 选审批人 → 进入审批流（详见 §3.7） | 状态 ∈ {`待核价`, `已核价`} |

### **3.6 导入导出**

#### **3.6.1 导出**

\- **格式**：Excel（\`.xlsx\`）

\- **内容**：当前核价任务的全部零件-工厂行（含已填的成本数据）

\- **文件命名**：\`CE-YYYYMMDD-NNN.xlsx\`（与核价任务编号一致）

\- **可用条件**：CE 角色，始终可导出（\`已完成\` 状态也可导出留档）

#### **3.6.2 导入**

\- **格式**：Excel（\`.xlsx\`），需与导出模板一致

\- **匹配 Key**：零件号（唯一标识）

\- **行为**：

1. 导入过程中，页面锁定，不允许操作
2. 解析成功 → Toast 提示「导入完成」，列表数据刷新
3. 解析失败 → 提示「解析失败，请下载报错文件」，提供失败文件下载
4. 失败文件命名：`CE-YYYYMMDD-NNN-fail.xlsx`

\- **空文件校验**：无文件时点击导入，Toast 提示「请选择文件」

\- **可用条件**：CE 角色，状态 ∈ {\`待核价\`, \`已核价\`}

#### **3.6.3 导入模板**

模板字段（列顺序应与导出保持一致）：

```Plain Text
零件号 | 零件名称 | 工厂 | 材料费 | 制造费 | 管理费 | 出厂价 | 模具总费用 | 开发总费用
```

> 注意：模板不含模具总费用和开发总费用列（如果使用精简版模板）；导入时如缺少这两列，对应字段按默认值 0 处理。

### **3.7 提交核价流程**

#### **3.7.1 提交前校验**

1. 遍历所有必填字段（材料费、制造费、管理费、出厂价、模具总费用）

2. 任意必填项为空 → **阻止提交**

- Toast 提示：「您有必核价项未填写，请完成填写后再提交」
- 未填项以红色边框高亮

3. 出厂价 = 0 → **阻止提交**（出厂价不可为 0）

1. 校验通过 → 弹出审批人选择弹窗

#### **3.7.2 选择审批人**

\- **弹窗标题**：选择审批人

\- **可选人员**：角色 \`Finance\` 的全体成员，**过滤掉当前 CE 核价人员自己**（与转单接口逻辑一致）

\- **选择后**：提交进入审批流，核价任务状态 → \`审批中\`

#### **3.7.3 审批页面内容**

审批人看到的审批页面包含：

- RFQ 基本信息：RFQ 编号、RFQ 名称、关联 SOR 单号、是否多项目、采购工程师、当前轮次
- 核价明细列表（只读）
- 备注（只读）

#### **3.7.4 审批操作**

| 按钮 | 行为 | 后续 |
|-|-|-|
| 同意 | 审批通过 | 状态 → `已核价`，通知 CE 核价人员 |
| 驳回 | 审批驳回 | 状态 → `待核价`，通知 CE 核价人员（含驳回原因），发送待办 |

#### **3.7.5 审批中异常场景**

| 场景 | 处理 |
|-|-|
| 审批中，新轮次发布 + 零件更新 | 自动终止当前审批流，状态 → `待核价`，审批人无需再审旧数据 |
| 审批中，新轮次发布 + 零件无更新 | 审批流继续，不受影响 |
| 审批中，CE 被转派 | 审批流中的 CE 信息按最新 CE 人员展示 |
| 审批中，CE 再次提交（不适用） | `审批中` 状态下不可提交 |

### **3.8 转派 CE 核价人员**

#### **3.8.1 入口与流程**

1. 列表页 / 详情页 → 点击「转派」按钮
2. 弹出「转派人员」弹窗
3. 人员列表取自角色 `Finance`
4. 选择目标 CE → 确认转派

#### **3.8.2 转派后置处理**

| 处理项 | 说明 |
|-|-|
| 核价任务 CE 核价人员 | 更新为新 CE |
| RFQ 中 CE 核价人员字段 | 同步更新 |
| 数据权限 | 新 CE 获得查看/编辑权限，旧 CE 权限移除 |
| 审批流中的展示 | 按最新 CE 人员展示（即使审批中） |
| 单步待办 | 移除旧 CE 的待办，给新 CE 发送「待核价」待办 |
| 飞书通知 | 通知新 CE：「您有一条 CE-20260303-001 的核价任务…」 |

#### **3.8.3 关联转派**

\- RFQ 采购员转派 → CE 核价任务中的「采购工程师」字段**同步更新**

#### **3.8.4 转派可用性**

| 状态 | 可否转派 |
|-|-|
| `待核价` | Y |
| `审批中` | Y（审批流中按新人员展示） |
| `已核价` | Y |
| `已完成` | Y（即使已生成定点通知单） |

## **5. 接口要点（概要）**

### **5.1 核价任务相关**

- 创建核价任务：RFQ 首轮发布后触发，1:1 生成
- 查询核价任务列表：支持筛选 + 行级数据权限过滤 + 分页
- 查询核价任务详情：返回 RFQ 基本信息 + 核价明细 + 历史记录

### **5.2 核价明细相关**

- 保存核价明细：保存（不提交）→ 仅持久化数据，不触发历史记录和通知
- 提交核价：校验必填 → 写入历史记录 → 创建审批流 → 发送通知和待办
- 导入核价明细：解析 Excel → 按零件号匹配更新
- 导出核价明细：生成 Excel → 返回文件流

### **5.3 审批流相关**

- 提交审批：创建审批单 → 状态 `审批中` → 待办 + 通知
- 审批同意 / 驳回：更新状态 → 写入历史 → 待办 + 通知
- 新轮次自动终止：关闭旧审批单 → 状态 `待核价` → 通知 CE（零件有更新时）

### **5.4 转派相关**

- 转派 CE：更新 CE 核价人员 + 同步 RFQ + 更新数据权限 + 待办 + 通知
- RFQ 采购员变更：同步更新核价任务中的采购工程师字段

**---**

## **6. 边界与异常场景**

| 场景 | 处理 |
|-|-|
| 新轮次发布，零件无更新 | 核价任务不变，状态不变，不通知 |
| 新轮次发布，零件减少 | 核价任务零件列表更新，不通知 |
| 新轮次发布，零件增加 | 核价任务零件列表更新，新增行高亮，通知 CE |
| 审批中，零件发生更新 | 自动终止审批流 → `待核价`，通知 CE |
| 已生成定点通知单 | 状态 → `已完成`，不可编辑，但仍可转派和导出 |
| CE 在审批中时转派 | 审批流中按新 CE 展示 |
| 提交时审批人变更 | 旧审批人权限移除，新审批人赋权 |
| 导入的零件号在核价任务中不存在 | 记录到失败文件，该行跳过 |
| 导入文件为空（无数据行） | 提示「文件中无有效数据」 |
