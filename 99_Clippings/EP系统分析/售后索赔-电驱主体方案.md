# 电驱售后索赔问题

> 
**电驱索赔流程说明**
常规二次索赔，索赔流由**小米景明👉小米汽车👉供应商**，索赔单主体为**小米汽车**，索赔链路为**小米汽车👉供应商**
电驱主体业务，索赔流由**供应商👉电驱主体👉小米汽车👉小米景明👉用户**，索赔链路必须严格遵循小米汽车👉 电驱主体👉供应商的层级结构，索赔单主体选择**电驱主体**，索赔链路为电驱主体👉供应商
**业务主要难点**
1. 基于法务与交易流一致性要求，**索赔链路必须严格遵循“小米汽车👉电驱主体👉供应商”的层级结构**，无法跳过电驱主体直接向供应商索赔
2. 门店无法精确定位电驱总成下故障子件，导致索赔无法闭环。建议**解决方案是依赖SQE质量工程师在QMS系统中分析并挂载主因件信息，再由SQMS系统根据主因件匹配供应商进行后续索赔**
**系统核心支持**
**方案一：SQE归因过程中明确问题发生部分（电驱/电池/整车），指明索赔件后创建二次索赔单**
1. **SAP**创建**电驱商务主体**，同时引入电驱主体为**内部供应商**；支持小米景明👉小米汽车👉电驱主体的索赔，及电驱主体👉供应商索赔。
2. **DMS**一次索赔增加【是否为电驱件】选项，作为流转至电驱分支的判断依据
3. **QMS**供SQE录入实际索赔子件，子件是匹配供应商的关键信息
4. **SQMS**对接QMS，如为供应商问题，自动创建二次索赔单；并根据【是否电驱件】适配主体
**方案二：电驱主体/电驱工厂成立后，电驱台账及框架迁移至新主体/新工厂，根据优先级自动匹配**
1. **SAP**创建**电驱商务主体**，同时引入电驱主体为**内部供应商**；支持小米景明👉小米汽车👉电驱主体的索赔，及电驱主体👉供应商索赔。
2. 台账/框架迁移至电驱新主体/新工厂
3. 如台账匹配到新工厂，则根据电驱👉整车的优先级默认使用电驱新主体进行索赔

## 方案一：SQE诊断根因过程中，确认主体

### SQE 驱动的精准归因模式

**核心逻辑：** 依靠 QE 在 SQMS 系统的介入，手动明确“责任边界”后再触发后续流转。

- **优点：**

  - **高准确性：** 电驱系统故障通常极其复杂，门店无法定位子件是客观事实。由 SQE 介入归因，能有效避免因系统误判导致的“错索赔”或“漏索赔”。
  - **流程解耦：** 索赔链条的触发依赖于明确的判定结果，系统逻辑相对简单，对现有台账体系的冲击较小。
  - **合规风险低：** 每一笔流向电驱主体的索赔都有 SQE 的归因证据支撑，完美满足法务与交易流一致性要求。
