01小米汽车阀点体系解码

小米汽车整车项目节点 = IPMT 决策点（会议 · 管投资） × M 阀点（节点 · 管实现成熟度）；两者是同一节点的两个侧面——先过技术成熟度门槛，再上投资决策会，本报告合并展示、不再拆成两行。
决策线IPMT · 投资与商业成功 技术线M 阀点 · 实现成熟度 融合Mi-VDP × 汽车 IPD 双面会议 × 阀点 = 1 个节点

🗺️ 阀点全景 · 事件时间轴（只读视图，按时间横向铺开）

一节点一卡（会议 × 阀点双面合一）· 可左右滚动 · 点击任意卡片 → 下方主从明细同步选中该节点

读法：每张卡片 = 一个节点 = 一次 IPMT 决策会 + 一道 M 阀点（紫点 = 会议与阀点双面合一；灰点 = 退市节点 LDCP，仅做计划管控、不上会）。M 阀点是 IPMT 决策的输入与前提：技术成熟度不过，不上投资决策会。卡片按时间归槽、槽间等距排列以避免遮挡，因此横向间距不代表严格时间比例，真实月份见卡片「第 N 月」（Charter 与 M4 相差 1 个月，显示为区间）。点击卡片可在下方节点明细查看该节点的会议面 / 节点面 / 交付物基线 / 两场评审的 RASIC。

📋 各节点过阀目标（M 阀点侧 = 交付物基线）

来源：小米汽车《整车项目阀点评审管理办法 V1.1》"过阀目标"章节。这是每个节点"应当被满足"的交付物集合，是节点交付物基线的权威定义；IPMT 决策点（会议）与 M 阀点（节点）为同一节点的两个侧面，此处按合并节点逐行列示。

02节点 × 角色 × 活动 责任矩阵（RASIC）

这张矩阵回答：在某个评审环节（节点）上，不同角色分别要做什么。行 = 评审环节，列 = 角色，格子 = 责任类型。
R执行 A最终负责 S支持 I被告知 C被咨询 规律节点越关键，决策层级越高
R 执行 A 最终负责 S 支持 I 被告知 C 被咨询 RA 双担（同一角色同担两责，双色拼接） 行 = 评审环节 · 列 = 角色

每个合并节点对应两场评审：先「M 阀点评审」过技术成熟度，再上「汽车 IPMT 正式评审」过投资决策（逐节点视图见「03 节点查询器」的 RASIC Tab）。基准：文档"会议机制表"与正文职责描述（业务自评由领域负责人决策、铁三角评审由铁三角决策、M阀点由 M 阀点决策组织决策、IPMT 两评由 IPMT 委员会决策、归档由交付物负责人/项目经理/IPMT运营办公室执行）。

看清一个规律：责任是"逐层上交"的——业务自评在领域层闭环（R/A 在交付物负责人 + 领域负责人），铁三角评审上浮到总监层，M 阀点交给专职决策组织，最后 IPMT 委员会掌握投资生杀权。这就是"节点越关键，决策层级越高"的结构化体现。

04洞察与开放问题

1门径是壳，责任到人才是魂
  • 五家流程形态高度相似（阶段门径），差异发生在谁在节点上拍板、谁对交付物负责
  • 小米用 RASIC 把责任显性化到角色
  • 蔚来用交付物驱动 + FMEA / Safety 委员会把质量责任前置到设计端
2双线是复杂产品的必选项
  • 把商业 / 投资可行性与技术 / 质量成熟度拆成两条独立评审线，避免互相绑架
  • 华为 IPD、小米汽车、蔚来 NPDP 殊途同归
  • 纯软件 / 消费电子场景可简化
3配置化是复用而非重写
  • 节点 / 角色 / 交付物的形状高度通用，变的是名称与阈值
  • 一套引擎 + 多份配置，远胜为每个项目重做表格
  • 前提：稳定 id 做主键、显示名本地化

🌊 通用 GVDP（瀑布 / 门径 · 教科书）

展开完整参数（与上方 13 维度矩阵同源）
体系基因GVDP（Global Vehicle Development Process），GM 2007–2008 形成 2.0；上汽等沿用。典型瀑布/门径。
阶段与节点5 大阶段：架构→战略(G10–G8)→概念(G8–G7)→开发(G7–G5)→产品及生产成熟(G5–G1)。8 主里程碑 G10→G1；细化 15 个关键里程碑（A4–A1、G9–G1、G0、GC）。

🚗 大众 PEP（平台化时钟 · 节点最细）

展开完整参数（与上方 13 维度矩阵同源）
体系基因PEP（Produkt Entstehungsprozess 产品诞生过程），德系严谨；国内主机厂一般从 PF 节点介入。

读法：触发节点计划时间前 14 天自动建会（会议实例 = 节点 + 届次，改期/复会都生成新届次）；会前把材料、议程、人三件事办实；会中议程驱动、决议三态、纪要实时落档；会后行动项到人、节点状态流转、逾期升级。底部为三个系统支撑：交付物中心 / 飞书 / EP 首页 Module1。

📅 图② 会议安排 · 六项能力

能力点机制联动 / 校验
自动建会节点计划时间 T-14 天触发，生成会议实例（唯一 ID = 节点 ID + 届次）节点计划表
议程模板按节点类型预置议程项：M 阀点评审 / 汽车 IPMT 正式评审各一套，过阀目标逐项成议程交付物基线清单
参会人推导按节点 RASIC 推导：R/A 必须参加，S/C 可选，I 列席RASIC 矩阵（f2）

安排阶段的硬规则：材料不齐不该开会——T-3 天锁定后仍未基线的交付物，要么由 A 批准带着问题上会（记为有条件通过的前置），要么自动触发改期建议。

🧑‍⚖️ 图③ 会议管理 · 议程驱动 + 决议三态

决议触发条件系统动作
通过交付物基线齐全 + 红黄绿达标（无红灯项）节点过阀；交付物确认「已基线」；生成纪要快照归档
有条件通过个别项黄灯，且有明确行动项与复会条件节点有条件过阀；行动项进待办；下次会议自动复核
驳回关键项红灯 / 一票否决（M 阀点评委 / IPMT 主任）节点回退；相关交付物回退「草稿」；重新提交后复会
📋纪要归档
  • 会中实时记录：飞书文档，决议 + 行动项结构化
  • 会后 24h 内定稿，定稿即基线快照（PDF 存 FDS）
  • 纪要与会议实例绑定，随节点可追溯
🚫会议纪律（防跑偏）
  • 禁临时加项：新议题走复会或另立会
  • 一票否决必须留痕：否决人 + 理由
  • 缺席 R/A 需提前批准，否则会议延期
