② 能力分层模型（对齐 AI×EP 五层体系）

将两套方案的能力映射到统一的 五层模型，便于判断「现在有什么 / 缺哪一层 / 由谁（人 / Agent / CLI）承载」。

L1
数据看板层
统计指标、交付物分布、角色待办（齐岳）。轻量化与全能均已具备。
L2
文档协同层
飞书为主归档、规范路径 schema、锁版状态机。轻量化与全能均已具备。
L3

项目下钻、全链路追溯可点击、上会/合同/策略自动 link。仅全能具备；轻量化不含。
L4
智能 Agent 层
AI 能力地图（L1 数字员工 ~ L5 CLI/API）、多 Agent 编排、LLM 辅助核价/生成。两套均未落地，为规划态。
L5
CLI/API 直连层
dx-ep 7 域（supplier/sor/rfq/nomi/sapo/process）+ 飞书 MCP 真实读写。两套均未真实接入，现均为 mock。

⑥ 关键技术决策

  • 单文件 HTML 原型 vs Vite 工程：轻量化用零构建单文件（快、易分享）；全能用 Vite 工程（可维护、可扩展）。两者最终均走 vite-plugin-singlefile 产出单文件，发布链路统一。
  • mock 先行 vs 真实集成先行：当前选择 mock 先行，先把信息架构与交互动线跑通，避免被后端接口阻塞；代价是自动联动/锁版为模拟态，需在 P0/P1 替换为真实后端。
  • 飞书为主归档：交付物以飞书云文档为单一可信源，规范路径（EP交付物/{项目}/{平台}/{节点}/{工作项}/{文档名}_v{版本}_{状态}）作为索引，锁版后路径冻结。
  • 能力分层对齐 AI×EP 五层：统一 L1–L5 语言，使「现在缺哪层」一目了然，便于规划 Agent 与 CLI 承载边界。
