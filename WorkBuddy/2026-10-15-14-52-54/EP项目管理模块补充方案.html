7 · 数据模型映射（飞书 100+ 字段 → 规范模型）

飞书大表字段分散在 100+ 列（含大量公式/附件/lookup）。EP PM 模块收敛为 5 张核心表，字段做"业务语义归一"：

规范表核心字段与飞书大表对应关系
projectscode / name / factory / eea_version / sop_date / ep_project_id / sap_plant_code车型项目(多选) → 拆为独立 project；架构/平台 → eea_version
milestonesphase(M5..EOP) / planned_date / actual_date / status里程碑节点（原飞书无独立表，靠公式推算）→ 独立引擎表，可编辑
work_item_templates
(139)		name(=业务名称) / deliverable_type / section / phases / interface_area / start_days / owner_roles / input_names / output_namesSOR包/采购组/研发组/开发类型/是否定点… 拆为"模板属性 + 实例属性"；"交付物名称"→"业务名称"
work_itemstemplate_id / project_id / milestone_id / status / progress / planned_* / actual_* / owner_ids / priority / doc_links / change_log每条 SOR 包在每项目每里程碑实例化；采购员/DRE/SIE/SQE → owner_ids(open_id)
work_item_dependenciespredecessor_id / successor_id / dependency_typeinput_names/output_names → 结构化依赖边（替代展示型关联）
💡 收敛原则：飞书"采购通则/技术协议/质量协议/三方协议/定点价格协议"等 5 类协议，统一抽为 work_items 的子类型（deliverable_type=阀点交付物），用状态+签署时间驱动，而非散落 100 列。

11 · 风险 & 待确认项

  • 🔴 EP purchaselist 页面字段未知：ep.ev.mioffice.cn 走 SSO 我无法访问，§9 集成与字段映射需你提供真实页面截图/字段确认。
  • 🟠 飞书大表 → EP 迁移成本：2166 条历史 SOR 包含大量公式/附件/lookup，需设计一次性 ETL + 增量双写过渡期。
  • 🟠 依赖环与冲突：139 工作项 × 多里程碑实例化后，跨项目资源冲突检测（V2.0 目标）算法复杂度高，建议 P3 再攻坚。
  • 🟡 权限模型落地：字段级（角色×项目×字段）需后端强校验，前端动态渲染仅是体验层。
  • 🟢 专业组/零件系统标签：建议先冻结两级字典（见 §8），避免自由录入导致分类发散。
