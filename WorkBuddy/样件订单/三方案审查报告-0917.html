一、先说测试报告：12/12 全绿不等于稳定

换句话说：这条链路的「写」路径（create-order / import）在生产上一行都没跑过。测试报告作为冒烟证据可用，作为稳定性证据不足。

八、最小可上线路径（按此顺序）

  1. 先别合三为一，先定内核。建议：以方案2 的 dexin 分组/剔除/日志规则为内核（它来自已跑通的 PowerShell 版本，业务规则最可信），套上方案1 的 state 落地，卡片作为可选外挂（方案3 的 card_sender + 环境变量密钥）。
  2. 清空并 ignore 运行产物：state/、output/ 加入打包排除；state 文件名加机器/环境标识，create 时校验「本环境生成 + 24 小时内」，否则拒绝执行。
  3. 把 dry-run 翻成 true 作为默认，并在 SKILL.md 里写明开关含义；只在人工确认后由 Agent 显式传入 --no-dry-run。
  4. 订单结果判定改为 returncode + JSON 字段优先，正则只作兜底；区分成功/草稿/失败三态，Partial 不得计入 SUCCESS。
  5. 补幂等：以 pr_ids 集合为单位记录「已下单」到本地 ledger 或多维表格，create 前先过滤。
  6. 剔除组必须可追溯：写入执行日志 + 日报 + 卡片，并给一条人工兜底命令（导出被剔除组清单）。

  8. 补一次真实链路测试：用 1 条真实需求走通 preview→push→query→create(dry-run)→日报，并对日报断言「记录条数 > 0」。
