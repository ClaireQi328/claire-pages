三、🔴 新增的两个致命问题（端到端跑不通）

3.1 agentspace：confirm 方法存在，但没有注册成命令

证据链：

  • confirm() 方法确实存在，在 query_and_order.py:283，负责写入 confirmed=True（:301）
  • 但 main() 的 choices 是 ["query", "create", "run"]（:738）——confirm 不在其中
  • query() 写 state 时的字段是 batch_id / operator / queried_at / cutoff_date / total_fetched / excluded_by_date / items（:204-212）——没有 confirmed 键
  • create() 在 :358 校验 confirmed，为假则直接 FAILED
  • run(auto_confirm=True)（:632-651）直接调 create()，中间也不补 confirmed

实机复现（构造与 query() 完全一致的 state 后执行 create）：

{
  "stage": "order_create",
  "status": "failed",
  "errors": [ "state文件未经过人工确认，禁止直接下单。请先运行 analyze 确认分组结果。" ]
}

注意这个报错本身也是错的：analyze 这个命令在整个文件里既没有方法也没有子命令（方法清单：query / confirm / create / _latest_state_file / run）。是上一版遗留的名字。

结论：无论走 query → create、run 还是 run --auto-confirm，create 都必然失败。方案1 的自动下单链路是断的。

3.2 dexin：全链路没有任何地方写 confirmed=true

auto_order.py:361 要求 indata["confirmed"] == True，但：

  • query_ready.py:332-335 输出的 payload 只有 queryTime / filterCondition / totalCount / data——无 confirmed
  • 整个 dexin-*/ 目录 grep confirmed，除 auto_order 的读取外没有任何写入点
  • auto_order 的子命令只有 ["order"]，没有 confirm 类命令或 --confirm 参数
  • dexin 的 SKILL.md 完全没有提到确认这一步（对比 feishu 的 SKILL.md 明确写了「create 必须在 confirm 之后执行」）

结论：除非 Agent 手工编辑 JSON 手写 confirmed: true，否则 auto_order 必然失败。而这一点文档没写、也没在流程里体现。
