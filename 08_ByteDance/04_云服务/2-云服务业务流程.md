# 🔄 云服务业务流程

> 云服务业务流程 = 从「需求规划」到「计费结算」的端到端闭环。

---

## 💡 Highlights

> [!tip]- 核心要点
> - **五大阶段**：需求规划 → 资源采购 → 部署交付 → 运维监控 → 计费结算
> - **与传统采购的区别**：云服务是「持续运营」而非「一次性交付」
> - **关键 SLA**：可用性 99.95%+、故障恢复 < 4h、数据持久性 99.9999999%

---

## 一、端到端业务流程总览

```
需求规划 → 资源采购 → 部署交付 → 运维监控 → 计费结算
   ↑                                              |
   └──────────── 持续优化反馈 ←────────────────────┘
```

---

## 二、阶段一：需求规划

### 2.1 需求来源

| 来源 | 说明 | 典型需求 |
|------|------|---------|
| 业务线需求 | 抖音/TikTok/飞书等业务部门 | 新增 GPU 集群、扩容存储 |
| 技术演进 | 架构升级、技术栈迁移 | 从裸金属迁移到容器化 |
| 成本优化 | FinOps 驱动的降本需求 | 闲置资源回收、竞价实例替换 |
| 合规要求 | 数据主权、等保、跨境 | 新增国内可用区、数据本地化 |

### 2.2 需求评估

| 评估维度 | 关键指标 | 说明 |
|----------|---------|------|
| 资源规模 | CPU 核数 / GPU 卡数 / 存储 TB | 峰值 + 冗余（建议预留 30%） |
| 性能要求 | 延迟 / 吞吐量 / IOPS | 区分在线/离线场景 |
| 可用性 | RPO / RTO / SLA 等级 | 核心业务 99.99%+ |
| 预算 | TCO / 月度预算 / 年度预算 | 包含隐性成本（运维、带宽） |
| 合规 | 数据驻留 / 等保级别 / 行业要求 | 金融/医疗/政务有特殊要求 |

### 2.3 方案设计

根据需求评估结果，选择合适的云服务架构：

| 场景 | 推荐方案 | 说明 |
|------|---------|------|
| 互联网业务 | 公有云 + CDN | 弹性伸缩，按需付费 |
| 金融/政务 | 混合云（私有云 + 公有云） | 核心数据本地，弹性业务上云 |
| AI 训练 | GPU 集群 + 高性能存储 | 大规模并行计算 |
| 全球化 | 多地域部署 + 全球加速 | 就近接入，合规驻留 |

## 三、阶段二：资源采购

### 3.1 采购模式

| 模式 | 说明 | 适用场景 | 成本 |
|------|------|---------|------|
| 包年包月 | 预付费，锁定资源 | 基线负载、稳定业务 | 最低（3-5 折） |
| 按量计费 | 后付费，按秒计费 | 弹性业务、测试环境 | 中等 |
| 竞价实例 | 低价竞拍空闲资源 | 离线计算、批处理 | 最低（1-2 折），但可能被回收 |
| 预留实例 | 承诺用量换折扣 | 可预测的长期负载 | 较低 |
| 资源包 | 购买额度包 | 存储、流量等可预测用量 | 较低 |

### 3.2 采购流程（参考 [[08_ByteDance/01_产品介绍/SCM 产品介绍]]）

```
需求提报(PR) → 寻源(RFx) → 供应商评估 → 合同签订 → 订单下达(PO) → 到货验收
```

**云服务采购的特殊性**：

| 环节 | 传统硬件采购 | 云服务采购 |
|------|------------|-----------|
| 寻源 | 竞争性招采、AVAP | 云服务商直供 / 代理商 / 聚合平台 |
| 交付 | 物流发货、到货验收 | API 开通、资源分配 |
| 结算 | 月度对账、发票付款 | 自动扣费 / 月度账单 |
| 生命周期 | 采购→上架→维修→报废 | 开通→使用→释放 |

### 3.3 供应商选择

| 采购渠道 | 优势 | 劣势 | 适用 |
|----------|------|------|------|
| 云服务商直供 | 产品最新、技术支持专业 | 价格较高、谈判空间有限 | 大型企业 |
| 云服务代理商 | 价格优惠、服务灵活 | 标准化程度低 | 中小企业 |
| 聚合平台 | 一站式采购、多云管理 | 平台费用 | 多云策略企业 |

## 四、阶段三：部署交付

### 4.1 部署方式

| 方式 | 说明 | 适用 |
|------|------|------|
| 控制台部署 | Web 界面手动创建 | 小规模、测试环境 |
| API/SDK | 编程方式创建资源 | 自动化、CI/CD |
| Terraform | 基础设施即代码（IaC） | 多环境、版本管理 |
| 容器编排 | K8s / Docker Compose | 微服务架构 |

### 4.2 交付验收标准

| 验收项 | 标准 | 检查方式 |
|--------|------|---------|
| 资源规格 | 与订单一致 | 控制台/API 查询 |
| 网络连通性 | 延迟 < 目标值 | ping / traceroute |
| 性能基准 | CPU/内存/IO 达标 | 压力测试 |
| 安全配置 | 安全组、加密、审计 | 安全扫描 |
| 监控告警 | 监控指标正常、告警配置完成 | 模拟告警 |

## 五、阶段四：运维监控

### 5.1 运维体系

| 层级 | 工具/平台 | 关键指标 |
|------|---------|---------|
| 基础设施监控 | 云监控 / Prometheus | CPU、内存、磁盘、网络 |
| 应用监控 | APM / 链路追踪 | 响应时间、错误率、吞吐量 |
| 日志管理 | 日志服务 / ELK | 日志采集、检索、分析 |
| 安全监控 | 态势感知 / WAF | 攻击检测、漏洞扫描 |
| 成本监控 | FinOps 平台 | 资源利用率、成本趋势 |

### 5.2 SLA 管理

| SLA 等级 | 可用性 | 年度停机时间 | 赔偿标准 |
|----------|--------|-------------|---------|
| 标准 | 99.95% | ≤ 4.38h | 月费 10%-30% 赔偿 |
| 高级 | 99.99% | ≤ 52.6min | 月费 25%-100% 赔偿 |
| 企业 | 99.995% | ≤ 26.3min | 定制赔偿方案 |

### 5.3 故障处理流程

```
告警触发 → 自动诊断 → 故障定级 → 应急响应 → 根因分析 → 改进措施
                        ↓
                   P0(5min) → P1(15min) → P2(1h) → P3(4h)
```

## 六、阶段五：计费结算

### 6.1 计费模式

| 计费项 | 计费方式 | 说明 |
|--------|---------|------|
| 计算 | 按规格 × 时长 | CPU/内存/GPU 按小时或月 |
| 存储 | 按容量 × 时长 | 按 GB/月，区分冷热存储 |
| 网络 | 按流量或带宽 | 出站流量计费，入站免费 |
| API 调用 | 按次数 | 万次为单位 |
| 增值服务 | 按功能 | 安全、加速、AI 推理等 |

### 6.2 结算流程（参考 [[08_ByteDance/05_供应链流程/收货发票付款]]）

```
用量采集 → 账单生成 → 账单确认 → 发票开具 → 付款结算
```

**云服务结算的特殊性**：
- 自动化程度高：用量采集和账单生成由系统自动完成
- 结算周期灵活：按小时/天/月，支持预付费和后付费
- 多维度账单：按产品、按项目、按部门分账

### 6.3 成本优化策略

| 策略 | 说明 | 预期节省 |
|------|------|---------|
| 资源右 sizing | 根据实际负载调整规格 | 20%-40% |
| 竞价实例 | 非关键业务使用竞价 | 60%-80% |
| 预留实例 | 承诺用量换折扣 | 30%-50% |
| 存储分层 | 热/温/冷/归档分层 | 50%-70% |
| 自动伸缩 | 按负载自动扩缩容 | 20%-30% |

---

## 七、持续优化反馈

云服务不是「一锤子买卖」，需要持续优化：

| 优化方向 | 频率 | 内容 |
|----------|------|------|
| 架构评审 | 季度 | 评估架构合理性，识别优化点 |
| 成本审计 | 月度 | 分析账单，识别浪费 |
| 安全评估 | 季度 | 漏洞扫描、合规检查 |
| 容量规划 | 半年度 | 预测未来需求，提前采购 |
| 技术升级 | 年度 | 评估新技术，推动架构演进 |
