# 🔄 端到端供应链流程

> 三条业务线（IHSC/芯片、IoT、服务）共享同一套端到端骨架，但每个环节的执行细节因品类而异。

---

## 💡 Highlights

> [!tip]- 核心要点
> - **8 大环节**：需求与品类规划 → 寻源与供应商准入 → 合同签订 → 采购订单 → 发货交付 → 收货验收 → 结算对账 → 付款执行
> - **3 个横向贯穿**：定价与贸易条款、Rebate/Discount、Buy&Sell 模式
> - **1 个纵向支撑**：供应商全生命周期管理（准入→绩效→退出）
> - **核心差异**：IHSC 重序列号追溯，IoT 重齐套管理，服务重里程碑验收

## ① 需求与品类规划

> 供应链的「起点」。需求不清，后面全白搭。

### 1.1 需求来源

| 来源 | 说明 | 典型场景 |
|------|------|---------|
| 业务线需求 | 抖音/TikTok/飞书等业务部门 | 新增 GPU 集群、IoT 新品量产 |
| 技术演进 | 架构升级、芯片迭代 | DDR4→DDR5 内存切换 |
| 容量规划 | 基于业务增长预测 | 数据中心扩容、CDN 节点新增 |
| 合规/政策 | 出口管制、国产替代 | GPU 受限后的替代方案 |
| 成本优化 | 降本增效 | 竞价采购、供应商整合 |

### 1.2 需求提报流程

```
需求方提出 → 采购受理 → 需求评审 → 预算确认 → 需求发布
```

| 步骤 | 关键动作 | 产出 |
|------|---------|------|
| 需求提出 | 填写 PR（采购申请）：物料编码、规格、数量、交期 | PR 单 |
| 采购受理 | 分配寻源经理，确认品类归属 | 寻源任务 |
| 需求评审 | 评估合理性、可行性和优先级 | 评审结论 |
| 预算确认 | 财务 BP 确认预算科目和金额 | 预算锁定 |
| 需求发布 | 发布至 SRM 系统，启动寻源 | 需求公告 |

### 1.3 品类规划

> [!info] PM 视角
> 品类规划决定了「和谁买、怎么买、买多少」。不同品类的采购策略差异巨大——GPU 是战略品类（稀缺、高价值），螺丝钉是常规品类（标准化、低价）。

品类规划的核心框架（Kraljic 矩阵）：

| 品类类型 | 特征 | 采购策略 | 典型品类 |
|----------|------|---------|---------|
| **战略品类** | 高价值 + 高风险 | 长期合作、深度绑定 | GPU、CPU、Foundry |
| **杠杆品类** | 高价值 + 低风险 | 竞争性采购、压价 | 服务器整机、DRAM |
| **瓶颈品类** | 低价值 + 高风险 | 保供优先、备选供应商 | 特种氟化液、定制芯片 |
| **常规品类** | 低价值 + 低风险 | 标准化采购、简化流程 | 包材、通用连接线 |

**品类规划产出**：
- 品类策略卡（品类名称、年度预算、供应商策略、风险等级）
- 采购目录维护（详见 [[采购品类与目录]]）

## ② 寻源与供应商准入

> 「和谁买」的决策环节。寻源质量决定了后续所有环节的基础。

### 2.1 寻源方式

| 方式 | 说明 | 适用场景 | 竞争程度 |
|------|------|---------|---------|
| 竞争性招采 | 公开/邀请招标 | 大额、标准化品类 | 高 |
| 竞争性评估 | 多供应商比价 | 中等金额 | 中 |
| 两阶段评估 | 先技术后商务 | 技术复杂的品类 | 中 |
| 单一来源 | 仅一家供应商 | 专利产品、紧急采购 | 无 |
| 指定供应商 | 业务指定 | 战略合作（详见 [[08_ByteDance/06_供应商管理/指定供应商]]） | 无 |
| 小金额采购 | 简化流程 | 小额低风险 | 低 |

### 2.2 RFx 流程

| 类型 | 全称 | 用途 | 信息深度 |
|------|------|------|---------|
| RFI | Request for Information | 市场摸底、供应商能力调研 | 浅 |
| RFP | Request for Proposal | 方案征集（技术+商务） | 深 |
| RFQ | Request for Quotation | 价格比选 | 中 |

**RFx 标准流程**：

```
编制 RFx 文件 → 发布邀请 → 供应商响应 → 技术评估 → 商务比价 → 中选公告
```

| 步骤 | 关键动作 | 产出 |
|------|---------|------|
| 编制文件 | 确定品类规格、评估标准、报价模板（CBOM） | RFx 文件 |
| 发布邀请 | 通过 SRM 系统发布，设置截止时间 | 邀请记录 |
| 供应商响应 | 供应商在线报价/提案 | 报价文件 |
| 技术评估 | 技术团队评估方案可行性 | 技术评分 |
| 商务比价 | 系统自动比价，成本分析 | 比价报告 |
| 中选公告 | 确定中选供应商，发布 PVF（寻源结果） | 中选通知 |

### 2.3 供应商准入

| 准入方式 | 流程 | 适用 |
|----------|------|------|
| 常规准入 | 资质审核 → 现场考察 → 评估打分 → 审批 | 新供应商 |
| 限制准入 | 简化流程，有金额和时效限制 | 小额/临时供应商 |

**准入评估维度**：

| 维度 | 评估内容 | 权重 |
|------|---------|------|
| 基础资质 | 营业执照、行业资质、安全认证 | 基础门槛 |
| 技术能力 | 核心技术、专利、研发团队 | 30% |
| 质量体系 | ISO 9001/IATF 16949、良率 | 25% |
| 产能与交付 | 产能规模、交期承诺、柔性能力 | 20% |
| 财务状况 | 营收、负债率、现金流 | 15% |
| 合规性 | 环保、社会责任、数据安全 | 10% |

**供应商身份分类**（详见 [[08_ByteDance/06_供应商管理/原厂代理贸易商]]）：

| 身份 | 说明 | 风险 |
|------|------|------|
| 原厂 | 制造商直供 | 最低 |
| 代理商 | 原厂授权经销 | 低 |
| 贸易商 | 非授权中间商 | 较高 |

## ③ 合同签订

> 锁定双方权利义务的法律环节。

### 3.1 合同类型

| 类型 | 说明 | 适用 |
|------|------|------|
| 框架协议 | 约定合作范围和通用条款 | 长期合作 |
| 订单合同 | 针对具体订单的采购合同 | 单次采购 |
| 战略合作合同 | 深度绑定，含排他/优先条款 | 核心供应商 |

### 3.2 合同核心条款

| 条款 | 关键内容 |
|------|---------|
| 标的 | 物料名称、规格、技术标准 |
| 价格 | 单价、币种、价格调整机制 |
| 数量 | 最小起订量、总量承诺、弹性范围 |
| 交付 | 交期、交货地点、运输方式 |
| 贸易条款 | Incoterms 条款（详见 [[贸易条款]]） |
| 付款 | 付款周期、付款方式、预付/后付 |
| 质量 | 质量标准、验收标准、不良品处理 |
| 违约 | 交期延误、质量不达标的赔偿 |
| 知识产权 | 技术保密、专利归属 |
| 合同期限 | 有效期、续约条件 |

### 3.3 AVAP 模式（B&S 业务特有）

AVAP（Approved Vendor Approved Price）是 Buy&Sell 业务的关键创新：

```
寻源中选 → AVAP 价格锁定 → 自动同步销售价格库 → 自动同步 Rebate 价格库
```

- 采购价与销售价联动，确保 B&S 模式下的利润空间
- 详见 [[Buy_Sell模式]] 和 [[08_ByteDance/01_产品介绍/SCM 产品介绍]]

## ④ 采购订单执行

> 合同落地为可执行的订单。

### 4.1 订单创建流程

```
需求确认 → 订单创建 → 订单审批 → 订单发布 → 供应商确认 → 到货计划
```

| 步骤 | 关键动作 | 系统支持 |
|------|---------|---------|
| 需求确认 | 关联 PR，确认物料/数量/交期 | SCM 需求模块 |
| 订单创建 | 关联合同，填写供应商/币种/贸易条款 | SCM 订单模块 |
| 订单审批 | 按金额分级审批 | 审批流引擎 |
| 订单发布 | 推送至供应商门户 | SRM 门户协同 |
| 供应商确认 | 供应商确认交期和数量 | SRM 供应商端 |
| 到货计划 | 供应商填写预计到货时间 | SCM 到货计划 |

### 4.2 订单变更管理

| 变更类型 | 触发条件 | 处理方式 |
|----------|---------|---------|
| 数量变更 | 需求增减 | 变更单 + 审批 |
| 交期变更 | 供应商延迟/提前 | 变更单 + 双方确认 |
| 价格变更 | 市场波动、合同调价 | 价格变更单 + 审批 |
| 取消订单 | 需求取消 | 取消单 + 违约处理 |

### 4.3 订单类型差异

| 订单类型 | 业务线 | 特点 |
|----------|--------|------|
| IDC 设备订单 | IHSC | 高价值，需序列号管理 |
| Buy&Sell 订单 | IHSC（ODM） | 采购订单→销售订单联动 |
| IoT 物料订单 | IoT | 齐套管理，多品类组合 |
| 服务采购订单 | 服务 | 里程碑验收，非实物交付 |

## ⑤ 发货与交付

> 供应商「发货」→ 采购方「收货」之间的物流环节。

### 5.1 ASN & DN 体系

> [!info] PM 视角
> ASN/DN 是发货-收货环节的「黄金搭档」。ASN 负责预告，DN 负责落地。

| 单据 | 时机 | 核心信息 | 法律效力 |
|------|------|---------|---------|
| ASN | 发货前 1-3 天 | 预计数量、时间、运输方式 | 无（预告） |
| DN | 发货时随货 | 实际数量、序列号、签字确认 | 有（验收凭证） |

**映射关系**：

| 映射 | 适用场景 | 说明 |
|------|---------|------|
| 1:1 | 服务器整机（高价值） | 单批次，追溯性强 |
| 1:n | 机房耗材（高频小额） | 分批发货，灵活 |
| 1:n | 跨区域多地点配送 | 1 个 ASN 预告全量 |

详见 [[ASN和DN]]

### 5.2 物流管理

| 环节 | 内容 | 系统支持 |
|------|------|---------|
| 物流方式选择 | 陆运/空运/海运/专线 | 根据品类和紧急程度 |
| 物流跟踪 | 物流公司/单号/实时位置 | SCM 物流追踪模块 |
| 到货通知 | 预计到货提醒 | 系统自动推送 |
| 签收确认 | 签收单/电子签收 | SCM 签收模块 |

### 5.3 贸易条款影响

贸易条款决定了「谁负责运输、谁承担风险、谁付运费」：

| 条款 | 运输责任 | 风险转移 | 常用场景 |
|------|---------|---------|---------|
| EXW | 买方全程 | 卖方工厂 | 国内采购 |
| FOB | 买方海运 | 装船时 | 国际采购（常用） |
| CIF | 卖方海运 | 装船时 | 国际采购（含保险） |
| DDP | 卖方全程 | 目的地交货 | 高价值设备 |

详见 [[贸易条款]]

### 5.4 异常处理

| 异常类型 | 处理方式 |
|----------|---------|
| 延迟发货 | 催货 → 紧急寻源 → 违约扣款 |
| 数量短缺 | 记录差异 → 补发/取消 → 对账调整 |
| 物流损坏 | 拍照取证 → 保险理赔 → 退换货 |
| 错发货 | 拒收 → 退货 → 重新发货 |

## ⑥ 收货与验收

> 货物到达后的「检查-入库」环节。

### 6.1 收货流程

```
到货通知 → 外观检查 → 数量核对 → 质量检验 → 入库上架 → 收货确认
```

| 步骤 | 关键动作 | 系统支持 |
|------|---------|---------|
| 到货通知 | 物流到达提醒 | 系统推送 |
| 外观检查 | 包装完整性、标签核对 | WMS 收货模块 |
| 数量核对 | 实物数量 vs DN 数量 | 扫码核对 |
| 质量检验 | IQC 来料检验（抽检/全检） | QMS 质量模块 |
| 入库上架 | 分配库位、上架 | WMS 库位管理 |
| 收货确认 | 系统确认收货，生成 GRN | SCM 收货单 |

### 6.2 验收标准差异

| 业务线 | 验收重点 | 特殊要求 |
|--------|---------|---------|
| IHSC（服务器） | 序列号逐一核对、配置验证 | 开箱通电测试 |
| IHSC（部件） | 批次号追溯、良率抽检 | 来料检验报告 |
| IoT（整机） | 外观+功能+包装完整 | 3C 认证核查 |
| IoT（电子件） | 批次管理、RoHS 合规 | 可焊性测试 |
| 服务 | 里程碑/交付物验收 | 签字确认验收报告 |

### 6.3 差异处理

| 差异类型 | 处理方式 | 系统动作 |
|----------|---------|---------|
| 数量差异 | 记录实收数量，触发补发/退货 | 差异报告 |
| 质量不合格 | 判退/让步接收/返工 | IQC 判定 |
| 包装破损 | 拍照留证，联系物流理赔 | 异常记录 |
| 错收物料 | 拒收，通知供应商 | 退货申请 |

### 6.4 退货管理

```
退货申请 → 供应商确认 → 退货单创建 → 物流安排 → 退货签收 → 对账调整
```

## ⑦ 结算与对账

> 收货完成后，进入财务结算环节。

### 7.1 三单匹配

> [!info] PM 视角
> 三单匹配（PO-ASN-发票）是结算环节的「守门员」。匹配成功才能付款，匹配失败必须查明原因。

```
PO（采购订单） ⟷ ASN/DN（发货交付） ⟷ 发票
         ↓                  ↓                ↓
      订单金额          收货金额          发票金额
         └──────── 三方一致 ────────────┘
                     ↓ 匹配成功
                 自动生成付款申请
```

**匹配维度**：

| 维度 | 匹配内容 | 容差 |
|------|---------|------|
| 物料 | 物料编码、规格 | 精确匹配 |
| 数量 | 收货数量 vs 发票数量 | ±2% |
| 价格 | 订单单价 vs 发票单价 | 精确匹配 |
| 金额 | 总金额 | ±1% |
| 税率 | 税种、税率 | 精确匹配 |

### 7.2 发票处理

| 步骤 | 说明 | 系统支持 |
|------|------|---------|
| 发票接收 | 纸质/电子发票 | SCM 发票模块 |
| OCR 识别 | 自动提取发票信息 | AI 识别引擎 |
| 发票验真 | 对接税局系统校验 | 自动验真接口 |
| 三单匹配 | PO-收货-发票自动比对 | 匹配引擎 |
| 差异处理 | 标记差异，人工核实 | 差异报告 |

### 7.3 对账流程

```
供应商发起对账 → 系统自动核对 → 差异标记 → 双方确认 → 生成对账单
```

**对账周期**：

| 业务线 | 对账频率 | 说明 |
|--------|---------|------|
| IHSC（大额） | 月度 | 月度对账，季度 Rebate |
| IoT（多批次） | 月度 | 批次汇总对账 |
| 服务 | 按里程碑 | 里程碑验收后对账 |

### 7.4 红冲机制

| 红冲类型 | 触发条件 | 处理方式 |
|----------|---------|---------|
| 数量红冲 | 实收与入库数量不一致 | 虚拟采购单调整库存 |
| 单价红冲 | 单价需要调整 | 空进空出，调整成本 |
| 退货红冲 | 质量问题退货 | 红字发票，冲减应付 |

详见 [[收货发票付款]]

## ⑧ 付款执行

> 供应链的「终点」——供应商收到钱。

### 8.1 付款流程

```
付款申请生成 → 审批流程 → 付款执行 → 银行转账 → 付款确认 → 账务核销
```

| 步骤 | 说明 | 系统支持 |
|------|------|---------|
| 付款申请 | 对账完成后自动生成 | SCM 结算模块 |
| 审批流程 | 按金额分级审批 | 审批流引擎 |
| 付款执行 | 生成付款指令 | 财务系统 |
| 银行转账 | 银企直连，自动转账 | 银行接口 |
| 付款确认 | 银行回执确认 | 自动对账 |
| 账务核销 | 应付账款核销 | ERP 核销 |

### 8.2 付款方式

| 方式 | 说明 | 适用 |
|------|------|------|
| 电汇 | 银行转账 | 最常用 |
| 银行承兑汇票 | 银行信用背书 | 大额采购 |
| 商业承兑汇票 | 企业信用 | 信用良好的供应商 |
| 信用证 | 银行担保 | 国际采购 |

### 8.3 付款条款

| 条款 | 说明 | 典型设置 |
|------|------|---------|
| 支付节点 | 预付款/后付款 | 大额设备预付 30% |
| 结算周期 | 月结/非月结 | 月结 30 天/60 天/90 天 |
| 日期类型 | 工作日/非工作日 | 工作日顺延 |
| 付款折扣 | 提前付款折扣 | 2/10 net 30（10 天内付 2% 折扣） |

### 8.4 付款异常处理

| 异常 | 处理方式 |
|------|---------|
| 三单不匹配 | 暂停付款，差异核实 |
| 发票问题 | 退回重开 |
| 供应商争议 | 协商→仲裁 |
| 资金不足 | 排期付款，通知供应商 |

## 横向贯穿：定价与贸易

> 从第一个环节到最后一个环节都涉及定价。

### 定价体系

| 定价维度 | 说明 | 适用 |
|----------|------|------|
| 采购定价 | 寻源确定的采购单价 | 所有品类 |
| 销售定价 | B&S 模式下的内部售价 | ODM 业务 |
| 阶梯定价 | 量越大价越低 | 标准化品类 |
| 成本加成 | 成本 + 固定利润率 | 定制化品类 |
| 竞价定价 | 供需决定价格 | 紧缺资源（GPU） |

## 横向贯穿：Rebate & Discount

|------|------|---------|

## 横向贯穿：Buy&Sell 模式

> ODM 业务的核心采销模式——采购部件 → ODM 组装 → 销售成品。

```
BDSG 采购部件 → 供应商供货 → ODM 组装 → SG 销售成品 → 交付签收 → 结算
```

- AVAP 模式：采购价与销售价联动
- 库存双向可见：采购侧和销售侧同步
- 详见 [[Buy_Sell模式]]

## 三业务线流程差异速查

| 环节 | IHSC/芯片 | IoT | 服务 |
|------|----------|-----|------|
| ①需求 | GPU/CPU 战略囤货 | 新品 BOM 齐套 | 服务 SLA 需求 |
| ②寻源 | 全球寻源、长交期 | 多供应商比价 | 资质+方案评估 |
| ③合同 | 框架+AVAP | 框架+订单 | 服务合同+SLA |
| ④订单 | 高价值、序列号 | 多品类齐套 | 里程碑驱动 |
| ⑤发货 | 1:1 ASN/DN | 1:n 分批发货 | 无实物物流 |
| ⑥收货 | 通电测试+序列号 | IQC 抽检+RoHS | 交付物验收 |
| ⑦结算 | 月度三单匹配 | 批次汇总对账 | 里程碑对账 |
| ⑧付款 | 月结 30-60 天 | 月结 30 天 | 按里程碑付款 |
