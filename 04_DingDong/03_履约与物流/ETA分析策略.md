# ETA 分析策略

## 1. 叮咚 ETA 的特殊性

### 1.1 即时零售 vs 外卖的 ETA 差异

| 维度 | 外卖（饿了么/美团） | 即时零售（叮咚买菜） |
|------|---------------------|---------------------|
| 商品类型 | 餐饮（热食为主） | 生鲜（多温区：常温/冷藏/冷冻） |
| 仓内作业 | 出餐（餐厅侧，平台不可控） | 分拣+打包+出库（前置仓内，平台可控） |
| 订单结构 | 单店单笔 | 多品类合单 |
| 配送模式 | 专送+众包 | 专送为主（自有骑手+蜂鸟） |
| 高峰特征 | 午/晚用餐高峰 | 早高峰（7-9点）+ 晚高峰 + 周末全天 |
| ETA 精度要求 | ±5 分钟 | ±3 分钟 |

### 1.2 ETA 全链路分段

| 分段 | 时间范围（典型值） | 关键影响因素 |
|------|-------------------|-------------|
| 分拣时间 | 3–15 min | 订单行数、SKU 存储位置、仓内人员配置 |
| 打包出库 | 1–5 min | 温区分装、复核效率、出库排队 |
| 骑手取货 | 1–3 min | 骑手到仓距离、等待取货排队 |
| 骑手配送 | 5–20 min | 距离、天气、交通、电梯等待 |
| 缓冲冗余 | 2–5 min | 系统安全边际 |

## 2. 数据源矩阵

| 数据域 | 数据源 | 关键字段 | 更新频率 | 用途 |
|--------|--------|---------|---------|------|
| 订单 | OMS | 下单时间、SKU 数量、订单金额、地址 | 实时 | 输入特征 |
| 仓内作业 | WMS | 分拣开始/结束时间、打包时间、出库时间 | 实时 | 仓内时间预估 |
| 骑手 | TMS | GPS 轨迹、接单时间、到店时间、送达时间 | 实时 | 配送时间预估 |
| 天气 | 第三方 API | 温度、降水、风力 | 小时级 | 补偿系数 |
| 促销 | 运营系统 | 促销类型、预计增量 | 日级 | 峰值预测 |
| 仓内产能 | 人员排班系统 | 在岗人数、预计产能 | 30min | 产能约束 |

## 3. 精度指标体系

### 3.1 分层指标

| 层级 | 指标 | 计算公式 | 目标值 |
|------|------|---------|-------|
| 仓内 | 仓内时间 MAE | mean(预估-实际) | < 2 min |
| 仓内 | 分拣准时率 | 实际≤预估的订单占比 | > 85% |
| 配送 | 配送时间 MAE | mean(预估-实际) | < 3 min |
| 配送 | 配送准时率 | 实际≤预估的订单占比 | > 90% |
| 全链路 | ETA MAE | mean(预估-实际) | < 4 min |
| 全链路 | ETA 准时率 | 实际≤预估的订单占比 | > 85% |
| 全链路 | ETA MAPE | mean(预估-实际/实际) | < 15% |
| 用户体验 | 超时投诉率 | 投诉超时订单/总订单 | < 2% |
| 用户体验 | ETA 变更率 | 预估时间变更的订单占比 | < 10% |

### 3.2 分场景评估

| 场景维度 | 切分方式 | 关注点 |
|---------|---------|-------|
| 时段 | 早高峰(7-9) / 午间(11-13) / 晚高峰(17-20) / 平峰 | 高峰时段仓内积压导致的精度下降 |
| 天气 | 晴 / 雨 / 雪 / 极端高温低温 | 恶劣天气下配送时间的尾部膨胀 |
| 订单规模 | 1-3 件 / 4-8 件 / 9+ 件 | 大单分拣时间非线性增长 |
| 区域 | 核心城区 / 远郊 / 新开站 | 新站历史数据不足的冷启动问题 |
| 促销 | 日常 / 促销期 / 大促 | 产能瓶颈下的系统性低估 |

## 4. 业务应用场景

| 应用场景 | 决策内容 | ETA 角色 | 优先级 |
|---------|---------|---------|-------|
| **下单前预估** | 商品页展示"预计 XX:XX 送达" | 用户转化率直接影响 | P0 |
| **订单节流** | 仓内积压时限制接单量 | 基于仓内时间预估做准入控制 | P0 |
| **运力调度** | 骑手分配和路径规划 | 配送时间预估作为调度约束 | P0 |
| **ETA 变更通知** | 送达时间变更时推送用户 | 超时风险预判 → 主动沟通 | P1 |
| **超时补偿** | 自动发放优惠券/积分 | 超时判定标准依赖 ETA | P1 |
| **仓内排班** | 根据预估订单量调整人员 | 仓内时间预估反推产能需求 | P2 |
| **选址评估** | 新开仓 ETA 覆盖率分析 | 模拟不同仓址的 ETA 分布 | P2 |

## 5. 优化路径

### 5.1 三阶段路线图

| 阶段 | 时间 | 核心动作 | 预期效果 |
|------|------|---------|---------|
| **短期：规则调优** | 0-3 月 | 天气/大促补偿系数、时段分桶、异常值截断 | MAE 降低 5-8% |
| **中期：特征工程** | 3-6 月 | 引入仓内实时作业状态、骑手画像、动态供需比 | MAE 降低 10-15% |
| **长期：端到端模型** | 6-12 月 | 多任务学习、后处理算子 | MAE 降低 15-20% |

### 5.2 短期：规则调优

| 优化项 | 具体做法 | 实现复杂度 |
|--------|---------|-----------|
| 天气补偿 | 雨天配送时间 +X%，雪天 +Y% | 低 |
| 大促补偿 | 618/双11 期间仓内时间 ×1.3 安全系数 | 低 |
| 时段分桶 | 将 24h 划分为 8-12 个时段桶 | 低 |
| 异常值截断 | 仓内时间 > 30min 截断 | 低 |

### 5.3 中期：特征工程

| 优化项 | 具体做法 | 实现复杂度 |
|--------|---------|-----------|
| 仓内实时积压 | WMS 实时推送当前待分拣单量 | 中 |
| 仓内人均效率 | 近 1 小时人均分拣单数 | 中 |
| 骑手画像 | 骑手历史配送效率、区域熟悉度 | 中 |
| 动态供需比 | 实时骑手在岗数 / 当前待配送单数 | 中 |

### 5.4 长期：端到端模型

参考 [[04_DingDong/03_履约与物流/履约时间预估|履约时间预估]] 中饿了么的技术方案：

| 技术方向 | 做法 | 对标 |
|---------|------|------|
| 多任务学习 | 仓内时间模型和配送时间模型共享底层特征 | 饿了么出餐+配送多任务 |
| 骑手序列编码 | 注意力机制编码可能接单的骑手序列 | 饿了么 Nearest Courier Index |
| KNN 配送段 | 基于历史相似订单的配送段时间预估 | 饿了么配送段 ETA |
| 后处理算子 | 自适应 Box-Cox 逆变换处理长尾分布 | 饿了么后处理算子 |
| 仓内作业建模 | 基于 WMS 实时数据的仓内作业时间预测 | 叮咚特有 |

## 6. 竞品对标

| 维度 | 叮咚买菜 | 盒马鲜生 | 美团买菜 | 朴朴超市 |
|------|---------|---------|---------|---------|
| 履约承诺 | 29 分钟达 | 30 分钟达 | 30 分钟达 | 30 分钟达 |

## 7. 风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| 仓内数据质量差 | WMS 时间戳缺失/不准确 | 数据清洗 + 异常检测 + 缺失值插补 |
| 新站冷启动 | 无历史数据 | 迁移学习（从相似区域站点迁移） |
| 极端天气 | 配送时间分布剧变 | 天气补偿系数 + 人工干预兜底 |
| 大促峰值 | 产能瓶颈导致系统性低估 | 大促专用模型 + 动态节流 |
| 用户感知偏差 | ETA 准确但用户觉得"慢了" | 展示预计时间点而非倒计时 |
