## 2. 需求背景

### 2.1 问题陈述

| # | 问题 | 影响 | 量化损失 |
|---|------|------|---------|
| P1 | ToB订单仍依赖人工处理，分单、调度全靠经验 | 效率低、出错率高 | 人均处理上限30单/天，错单率5% |
| P2 | 多温层订单需要多次配送，客户签收体验差 | 客户投诉多，流失率高 | NPS仅32分，季度流失率8% |
| P3 | 仓间库存不互通，缺货无法跨仓调拨 | 有库存但无法满足订单 | 缺货率12%，损失GMV约200万/月 |
| P4 | 对账全靠Excel，月结耗时长、差错多 | 财务人效低，客户信任度低 | 5人天/月对账，差异率3% |

### 2.2 用户角色

| 角色ID | 角色名称 | 职责描述 | 使用频率 | 关键诉求 |
|--------|---------|---------|---------|---------|
| ROLE_BIZ | 业务员/销售 | 客户下单、订单跟踪、异常处理 | 每日高频 | 下单便捷、状态实时可查 |
| ROLE_OPS | 运营专员 | 商品管理、价格配置、活动运营 | 每日高频 | 操作效率、数据可视化 |
| ROLE_WH | 仓库管理员 | 分拣打包、出库确认、库存管理 | 每日高频 | 任务清晰、异常及时预警 |
| ROLE_DLV | 配送调度员 | 排线调度、配送跟踪、签收管理 | 每日高频 | 智能排线、实时轨迹 |
| ROLE_FIN | 财务人员 | 对账、结算、开票 | 每周/每月 | 自动对账、差异追溯 |

## 4. 状态机

### 4.1 订单状态机

| 状态编码 | 状态名称 | 允许的前置状态 | 触发动作 | 说明 |
|---------|---------|--------------|---------|------|
| CREATED | 已创建 | - | 客户提交订单 | 初始态 |
| SPLITTING | 分单中 | CREATED | 系统开始分单 | 处理中 |
| SPLITTED | 已分单 | SPLITTING | 分单完成，生成子订单 | - |
| PARTIALLY_CONFIRMED | 部分确认 | SPLITTED | 部分子订单已确认 | 中间态 |
| ALL_CONFIRMED | 全部确认 | SPLITTED, PARTIALLY_CONFIRMED | 所有子订单已确认 | - |
| PICKING | 分拣中 | ALL_CONFIRMED | 仓库开始分拣 | - |
| PICKED | 已分拣 | PICKING | 分拣完成 | - |
| PACKED | 已打包 | PICKED | 打包复核完成 | - |
| SHIPPING | 配送中 | PACKED | 出库交接配送 | - |
| DELIVERED | 已送达 | SHIPPING | 骑手标记送达 | - |
| SIGNED | 已签收 | DELIVERED | 客户确认签收 | 终态(正常) |
| CANCELLED | 已取消 | CREATED, SPLITTING, SPLITTED | 客户/系统取消 | 终态(异常) |

**订单状态流转图**：

```
┌─────────┐    ┌──────────┐    ┌──────────┐    ┌────────────────────┐
│ CREATED │───▶│ SPLITTING │───▶│ SPLITTED │───▶│ PARTIALLY_CONFIRMED │
└────┬────┘    └─────┬────┘    └─────┬────┘    └─────────┬──────────┘
     │               │               │                    │
     │               │               ▼                    ▼
     │               │    ┌──────────────────┐    ┌──────────────┐
     │               │    │ ALL_CONFIRMED    │◀───│ ALL_CONFIRMED│
     │               │    └────────┬─────────┘    └──────────────┘
     │               │             ▼
     │               │    ┌──────────┐    ┌──────────┐    ┌──────────┐
     │               │    │ PICKING  │───▶│ PICKED   │───▶│ PACKED   │
     │               │    └──────────┘    └──────────┘    └─────┬────┘
     │               │                                          ▼
     │               │    ┌──────────┐    ┌──────────┐    ┌──────────┐
     │               │    │ SIGNED   │◀───│ DELIVERED│◀───│ SHIPPING │
     │               │    └──────────┘    └──────────┘    └──────────┘
     │
     ▼
┌───────────┐
│ CANCELLED │  (从 CREATED/SPLITTING/SPLITTED 可取消)
└───────────┘
```

## 5. 业务规则

| 规则ID | 规则名称 | 规则描述 | 触发条件 | 处理方式 | 优先级 |
|--------|---------|---------|---------|---------|--------|
| BR-001 | 温层拆单 | 不同温层商品必须拆分为独立子订单 | 订单包含多温层商品 | 系统自动拆单 | P0 |
| BR-002 | 库存预留 | 下单后库存立即锁定，保留30分钟 | 订单创建 | INV锁定库存 | P0 |
| BR-003 | 库存超时释放 | 锁定超30分钟未支付，自动释放库存 | 超时 | 系统自动释放 | P0 |
| BR-004 | 同仓优先 | 优先选择能覆盖最多SKU的仓库 | 分单时 | 系统评分决策 | P0 |
| BR-005 | 最小起送量 | 单笔订单金额不低于50元 | 下单时 | 前端校验 | P0 |
| BR-006 | 配送时间窗口 | 客户可选配送时段：9-12/14-17/17-20 | 下单时 | 前端展示可选时段 | P0 |
| BR-007 | 截单时间 | 当日配送订单需在前一天20:00前提交 | 下单时 | 前端校验 | P0 |
| BR-008 | 重量上限 | 单笔订单重量不超过500kg | 下单时 | 前端校验+提示 | P1 |
| BR-009 | 缺货处理 | 缺货商品标记，不阻塞有货商品配送 | 库存不足 | 拆分子订单+通知客户 | P0 |
| BR-010 | 温度异常 | 配送温度偏差>2°C持续10分钟触发预警 | 配送中 | 推送预警给调度员 | P0 |
| BR-011 | 签收时效 | 送达后客户需在2小时内签收确认 | 送达后 | 超时自动签收+短信提醒 | P1 |
| BR-012 | 异议时效 | 签收后24小时内可提出质量异议 | 签收后 | 客户端提交异议工单 | P1 |
| BR-013 | 自动对账 | T+1自动对账，差异<1%自动调账 | 每日02:00 | 系统自动执行 | P1 |
| BR-014 | 差异升级 | 差异率1~5%人工审核，>5%升级主管 | 对账后 | 工单推送 | P1 |
| BR-015 | 信用额度 | 客户累计未结算金额不超过信用额度 | 下单时 | 额度校验 | P0 |
| BR-016 | 价格有效期 | 合同价格在有效期内自动生效 | 下单计价 | 价格引擎校验 | P0 |
| BR-017 | 批量折扣 | 单品单次采购量>100件自动触发阶梯价 | 下单时 | 价格引擎计算 | P1 |
| BR-018 | 订单取消 | 配送中订单不可取消，需走退货流程 | 取消请求 | 前端拦截+提示 | P0 |
| BR-019 | 退货退款 | 签收异议确认后支持部分/全额退款 | 异议确认 | 财务审批+退款 | P1 |
| BR-020 | 黑名单 | 3次以上恶意拒收的客户自动加入黑名单 | 拒收统计 | 限制下单+人工审核 | P2 |
