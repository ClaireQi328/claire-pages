### 2.2 三层下钻

| 层级 | 展示内容 | 交互方式 |
|------|---------|---------|
| **仓级** | 全网各仓库容利用率、温区分布、预警状态 | 点击仓库名称进入下一层 |
| **区级** | 单仓内各温区/品类区的库容利用率、SKU 分布 | 点击温区/品类区进入下一层 |
| **库位级** | 具体库位的 SKU 占用情况、库存量、到期时间 | 支持搜索 SKU 编码直达 |

| 指标 | 计算方式 | 展示形式 | 刷新频率 |

| 今日出库量 | 当日累计出库件数 | 数字 + 环比 | 1 小时 |
| 库存金额 | 当前在库库存总金额 | 数字 + 趋势 | 日更 |

## 三、库容预警机制

### 3.1 三级预警体系

| 等级 | 标识 | 触发条件 | 通知范围 | 处置时效 | 自动动作 |
|------|------|---------|---------|---------|---------|
| **L1 黄色** | 🟡 | 利用率 85% ~ 92% / 单品类库容预警 | 仓管 + 仓经理 | 24 小时 | 系统推送 + 建议方案 |
| **L2 橙色** | 🟠 | 利用率 92% ~ 98% / 冷藏温区满载 / 临期品超阈值 | 仓经理 + 运营总监 | 12 小时 | 自动冻结非 S 级入库 + 派单 |
| **L3 红色** | 🔴 | 利用率 > 98% / 任意温区溢出 / 安全库存告急 | 运营总监 + VP | 4 小时 | 强制调拨 + 紧急清退 + 管理层通报 |

### 3.2 预警规则配置（YAML 示例）

```yaml
# 库容预警规则配置
rules:
  - id: capacity_utilization_high
    name: 库容利用率过高
    level: L2
    condition:
      metric: capacity_utilization_rate
      operator: ">="
      threshold: 0.92
      duration: "30min"        # 持续 30 分钟才触发
    actions:
      - notify: [warehouse_manager, ops_director]
      - freeze_inbound: {sku_level: [B, C]}
      - create_work_order: {priority: high}
    cooldown: "4h"             # 同一仓库 4 小时内不重复触发

  - id: cold_zone_full
    name: 冷藏温区满载
    level: L3
    condition:
      metric: cold_zone_utilization
      operator: ">="
      threshold: 0.98
    actions:
      - notify: [ops_director, vp]
      - emergency_transfer: true
      - escalation: true
    cooldown: "2h"

  - id: expiry_risk
    name: 临期品占比过高
    level: L2
    condition:
      metric: near_expiry_ratio
      operator: ">="
      threshold: 0.15            # 临期品占比 > 15%
    actions:
      - notify: [category_manager, warehouse_manager]
      - auto_markdown: {days_before_expiry: 3}
      - create_work_order: {type: clearance}
    cooldown: "24h"
```

### 3.3 处置工作流

```
预警触发 → 系统自动诊断根因 → 生成处置建议 → 推送给责任人
                                                ↓
                                    仓管确认/调整方案 → 执行处置
                                                ↓
                                    系统验证效果 → 预警解除 / 升级
                                                ↓
                                    归档记录 → 周报复盘
```

## 四、SKU 级库容规划工具

### 4.1 自动计算流程

| 步骤 | 输入 | 处理逻辑 | 输出 |
|------|------|---------|------|
| **1. 销量预测** | 近 28 天销量 + 促销日历 | 时序模型 + 人工调整 | 未来 14 天日均销预测 |
| **2. 周转参数** | SKU 分级 + 温区策略 | S/A/B/C 对应不同周转天数 | 目标周转天数 |
| **3. 库容计算** | 日均销 × 周转天数 + 安全库存 | 公式计算 + 最小调拨单位约束 | 单 SKU 目标库容（件数/面积） |
| **4. 库位推荐** | SKU 尺寸 + 温区 + 分级 | 优化算法：高频就近 + 同品集中 | 推荐库位列表 |
| **5. 差异分析** | 当前库位 vs 推荐库位 | 对比差异，排序优先级 | 调整工单（需人工确认） |

### 4.3 库位分配算法逻辑

| 约束层级 | 约束类型 | 规则 | 优先级 |
|---------|---------|------|--------|
| **硬约束** | 温区匹配 | 冷冻品 → 冷冻区，冷藏品 → 冷藏区 | 1（不可违反） |
| **硬约束** | 容量不超载 | 库位剩余容量 ≥ SKU 存储量 | 2（不可违反） |
| **软约束** | 高频就近 | S/A 级 → 靠近出库口的黄金库位 | 3 |
| **软约束** | 品类集中 | 同品类集中，减少跨区 | 4 |
| **软约束** | 先进先出 | 同 SKU 新批次放后排/下层 | 5 |
| **优化目标** | 最小化拣货路径 | 在满足约束下最短总路径 | 全局优化 |

### 6.1 功能清单

| 功能 | 描述 | 操作场景 | 离线支持 |
|------|------|---------|---------|

| **库位绑定** | 扫描库位码，将商品绑定到指定库位 | 上架作业 | 部分 |
| **移动盘点** | 接收盘点任务，扫描库位逐个确认实盘数 | 日盘/周盘/抽盘 | 是 |
| **异常上报** | 拍照 + 文字上报现场异常（破损/串货/温控异常） | 任何场景 | 是（图片后传） |
| **任务看板** | 查看个人待办任务、完成进度、绩效统计 | 日常使用 | 是 |

### 6.2 入库扫码流程

```
① 扫描运单号/预约单号
        ↓
② 系统展示 PO 明细（品名、数量、温区）
        ↓
③ 逐件/逐托扫码确认
   ├─ 匹配成功 → 绿色 ✅，累计 +1
   ├─ 条码不存在 → 红色 ❌，异常上报入口
   └─ 数量差异 → 黄色 ⚠，允许备注原因
        ↓
④ 确认完成 → 生成入库单
        ↓
⑤ 引导上架 → 扫描目标库位码 → 绑定完成
```

### 6.3 盘点任务管理

| 任务类型 | 触发方式 | 频率 | 范围 | 差异处理 |
|---------|---------|------|------|---------|
| **日盘** | 系统自动派发 | 每日 | S 级 SKU 全量 | 差异 > 5% 即时复盘 |
| **周盘** | 系统自动派发 | 每周 | A 级 SKU 全量 | 差异 > 3% 触发调查 |
| **月盘** | 手动发起 | 每月 | 全仓全量 | 差异 > 1% 生成调整单 |
| **抽盘** | 系统随机 | 随机 | 随机 10% 库位 | 发现问题扩大盘范围 |
| **专项盘** | 异常触发 | 事件驱动 | 指定 SKU/库位 | 专项调查报告 |

> [!quote] 产品设计原则
> 1. **数据驱动**：每个功能都有明确的数据输入和可量化的输出
> 2. **闭环管理**：发现问题 → 分析根因 → 执行处置 → 验证效果
> 3. **渐进式复杂度**：Dashboard 一目了然，需要深挖时逐层下钻
> 4. **移动优先**：仓管员 80% 的时间在现场，移动端体验决定系统落地效果
